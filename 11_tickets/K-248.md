## 目的

本線の先頭で、CI の spec の組の G57（範囲の台本の試験）が赤。ほかのチケットの出す前の手元の検査が全部この赤で止まる。

1. **赤を直す**：`python3 scripts/ci/ci_scope_test.py RealRepoTest.test_K107_CS_032_no_unmapped_readers_in_repo` が `apps/web/tests/features/F5/k247-band-settle.spec.ts` を「未登録の読み手」として赤にする。この画面の試験は `readFileSync(join(HERE, file))` で同じ置き場の承認と完了の画面の試験 7 つ（approve・complete・execute・guard・queue・return・live）を読むのに、`scripts/ci/ci_scope.json` の data_links にも reads_ok にも無い。data_links に載せ、読む先が変わったらこの試験も範囲に入る形にする
2. **仕組みの穴を閉じる**：その試験を足したチケットの CI でも出す前の手元の検査でも G57 が流れず、緑のまま本線に入った。読む印を持ちうるコードを変えたチケットでは G57 が必ず流れるようにする。同じ形の抜けを gates の全行で数え、同じ直しで閉じられる物は閉じる

## なぜ G57 が流れなかったか（書く段が確かめた）

- G57 の段の if は `contains(steps.scope.outputs.gates, ',57,')`。gates は `ci_scope.py` の `gates_for` が、変えたファイルを `ci_scope.json` の gates の 57 の glob に当てて決める（scope=ticket のとき）
- 出す前の手元の検査（ticket-flow の preflight_jobs: [static, spec]）も、CI の定義の段を同じ if のまま、同じ台本の出力（gates）で読む。だから CI と手元の両方で同じに外れた
- gates の 57 は `scripts/ci/ci_scope*`・`ticket_affects*`・`vitest_related*`・`pnpm-workspace.yaml`・`**/package.json`・`package.json` だけ。G57 の CS-032（`unmapped_readers`・`no_test_path_reads`）は `walk_files` で apps と packages の .ts・.tsx・.mjs を全部歩くのに、その歩く先が当たりに無い
- 前のチケットの差分（11_tickets の 4 つ・apps/web/tests/features/F5 の画面の試験 7 つ）を本物の決まりで `gates_for` に通すと `['27', '38', '56']`。57 が無い
