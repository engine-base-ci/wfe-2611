## 目的

調べ（`.ticket-flow/research/security-credentials-2026-11-20.md`・読むだけ・本線 0c91285f）で見つかった、預けたログイン情報のまわりの前からの穴 2 つを、段 4 の新しい口（K-352 の預ける口・K-353 の上書き）が本線に入る前後のどちらでも効く形で閉じる。

1. **会社をまたぐ結びつき（HIGH：台帳に複数の会社の行が在れば）**：`app.credential_service(p_name, p_domain)`（0047・security definer）は台帳 `service_registry`（会社ごとの表・tenant_id not null）を会社の条件なしで引き、いちばん古い行の id を返す。預ける口 K-352 はこの関数で行の `service_id` を決める（K-352 の実施事項 ⑦）。`credentials.service_id` は FK だけで会社の一致を見ない。結ばれると、確かめの仕事を積む関数（0065 の `credential_login_check_enqueue` の 23 行目）や本番に切り替える判定（0070 の 75 行目）・K-355 の新しい確かめの関数が、別の会社の台帳の可否（automation_verdict_id）を読む。別の会社が台帳に「api」と書けば、規約で禁止のサービスの確かめが通り、「forbidden」と書けば別の会社の確かめが止まる
2. **金庫に置いた後の証跡が落ちると金庫に物が残る（MEDIUM）**：秘密の関門 `packages/secrets/src/index.ts` の `store` は、金庫に置いた（vault.put）後の証跡（repo.audit）が try の外で、落ちると参照を返さずに例外になる。呼ぶ口（K-352・K-353）は参照を受け取れないので失効させられず、消せない暗号文が金庫に残る

この葉は DB の関数と引き金、秘密の関門の 1 か所だけを直す。口の振る舞い（K-352・K-353 の md）は変えない（どちらの口も、この葉の後は同じ呼び方のまま安全になる）。

分類: CRUD

## 外に影響する手順

- S1: DB の関数の作り直し・違反の行の結びつきを外す・引き金を作る（migration 1 本・1 つの取引）[残る] — 失敗すると取引ごと戻り、関数・行・引き金は前のまま（起動の migrate が止まる）（K348-DB-009）。成功すると違反の行の service_id は null のまま残る（結びつきだけを外す）
