## 目的

ログインと安全（自分の設定 › ログインと安全）の「入っている端末」の 3 つの口。

- `listMySessions`（GET /api/v1/me/sessions）：入っている端末の一覧（今の端末・場所・最後に使った時刻）
- `revokeMySession`（DELETE /api/v1/me/sessions/:id）：1 つの端末を切る。**PC（Bridge）のときは PC の接続を切り、動いている仕事を止める**
- `revokeOtherSessions`（POST /api/v1/me/sessions/revoke-others）：この端末以外をすべて切る（PC の接続も）

**端末の 1 行**＝`sessions` の 1 行。1 つの部品のセッション（`auth_session_id`）は 1 つの会社にだけ結ぶ（`auth_session_id` は一意・0004。ほかの会社へは K-851 の切り替えが行の会社を替える）。PC も行ごとに 1 行。同じログイン（`tenant_memberships.auth_user_id` が同じ・D-125.150）の全部のワークスペースの人の行から端末を並べ、今いない会社に結んだ端末も見る・切る（PC はアカウントのもの・D-128.156）。目録の直し：この 3 口の画面の印を mfa-setup → account にする（K-800 が持つ・この葉は確かめるだけ）。

**画面が使う答えの形**（K-842 の正）：

```
listMySessions        200 { data: { sessions: [{ id, kind: "web"|"bridge"|"api", name, place: string|null, issued_at, last_seen_at, current: boolean }],
                                events: [{ id, kind, occurred_at, device: string|null, place: string|null }] } }
revokeMySession       200 { data: { revoked: true } }
revokeOtherSessions   201 { data: { revoked: <切った端末の数> } }
```

並びは今の端末を先頭・あとは最後に使った順。`events` は「最近の安全の記録」：同じログインの全部のワークスペースの security_events（消していない）の新しい順 10 件。`kind` は kind_id・`device` は detail の device（無ければ to_device・それも無ければ null）・`place` は ip_region（D-154.79）。`name` は端末の名前（sessions.device_label）、`place` は場所の印（sessions.ip_region・今は国・地域の字。下絵の「東京」のような町の名前は持てない＝画面の葉 K-842 が出せる形で出す）。「見覚えは？」の印は口で決めず画面が `last_seen_at` から出す。

## 前提と制約

分類: AUTH, PERM

- **だれが呼べるか**：本人だけ（member の束）。**切る口 2 つ（revokeMySession・revokeOtherSessions）は本人確認の取り直しが要る**（契約を `stepUp: "always"` に直す・下絵「本人確認して切る」・代表の勧め／まとめ役の決め。一覧は要らない）。取り直しが直前 15 分の内でなければ入口が 403・STEP_UP_REQUIRED（口の中では見直さない）。画面は今の取り直しの小窓で通ったら 1 回だけやり直す（K-363 と同じ形）。入口の共通（401・429・同意し直し 403・道の id の形 422・NUL 422）が先に効く
- **今の端末**：口は入口と同じ印の引き方（`d.auth.api.getSession({ headers: a.c.req.raw.headers })`・K-312）で、部品のセッションの id（`session.id`）と利用者の id（`user.id`）を引く。解けなければ 401。`current` は `auth_session_id` が部品のセッションの id と同じ端末。口の工場（make）は材料の auth を最初に触らない（k144 の準備が auth なしで make を呼ぶため）
- **一覧**：同じログインの全部の人の行（`app.account_members`）の、失効していない・消していない `sessions` を 1 行ずつ並べる（1 つの部品のセッションは 1 つの会社の 1 行だけなので、まとめる仕事は無い）。`id` は `sessions.id`。別の人・別のログインの端末は出ない
- **1 つ切る**：`:id` が自分のログインの生きている端末の行であること（無い・切ってある・ほかの人・別の会社の人の行は**同じ 404**・欄と details を付けない）。**今の端末は切れない**：409・E-ME-030（「この端末は切れません。ログアウトを使ってください」＝仮）。画面・API の端末はその行を失効（理由 `self_revoked`＝この葉が足す・「自分で切った」。今いない会社に結んだ端末も同じ）。PC は K-362 の `app.device_revoke`（理由 `device_removed`・その PC が受け取って動いている仕事を止める）をそのまま使う（同じ判定を 2 か所に書かない）。安全の記録 `sessions_revoked` を残す
- **この端末以外をすべて切る**：今の端末（部品のセッション）のほかの全部。PC は 1 台ずつ `app.device_revoke`、そのほかは `app.revoke_sessions_for_auth_user_except`（0113・K-312 が使う関数）。答えの `revoked` は切った端末の数（＝失効させた `sessions` の行の数。画面・API・PC とも 1 行で 1）。切る物が無ければ 0 で 201（記録は増えない）
- **認証の側の後片付け**（K-312 と同じ作り）：切ったあと、部品の側のセッションの期限を今にして効かなくする（`internalAdapter.listSessions(userId)` → 切った端末の token に `updateSession(token, { expiresAt: 今 })`）。Kaname の `sessions` が失効の正なので、落ちても 200／201 のまま（ログに `[me-sessions] 認証の側の片付けに失敗` を 1 行・印を出さない）
- **同時**：行を `for update` で取る。同じ端末を 2 人が同時に切ると、1 回は 200・もう 1 回は 404
- **PC の仕事**：切った PC が受け取って動いている・聞いている仕事（running・asking）は止め、待っている仕事・ほかの PC の仕事は変えない（K-362 のとおり）
- 読む口の答えは `Cache-Control: private, no-store`。DB の失敗は 503・E-PAGE-003（何も切れない）
- 断る番号は控え帳どおり（404 は欄・details を付けない／409 は欄・details を付けない／503）。道の id の形は入口が 422（k144 の行 K144-API-1180）

### DB の関数（20261126003600_me_sessions.sql）

`security definer`・`set search_path = public, app, pg_temp`・`revoke all … from public`・`grant execute … to kaname_app`。先頭で `insert into revoke_reasons (key, label) values ('self_revoked', '自分で切った') on conflict do nothing`。

| 関数 | 形 |
|---|---|
| `app.me_sessions_list(p_current_auth_session text) returns jsonb` | 同じログイン（`app.account_members(app.user_id())`）の全部の会社の生きている行を 1 行ずつ、今の端末を先頭・最後に使った順で `[{ id, kind, name, place, issued_at, last_seen_at, current }]` を返す（`id` は `sessions.id`） |
| `app.me_security_events() returns jsonb` | 同じログイン（`app.account_members(app.user_id())`）の人の `security_events`（deleted_at が null）を occurred_at の新しい順に 10 件、`[{ id, kind: kind_id, occurred_at, device: coalesce(detail->>'device', detail->>'to_device'), place: ip_region }]` で返す（読むだけ・D-154.79） |
| `app.me_session_revoke(p_session uuid, p_current_auth_session text) returns jsonb` | 行を `for update` で取り、自分のログインの生きている端末でなければ `{"error":"not_found"}`・今の端末なら `{"error":"current"}`。PC なら `app.device_revoke`・それ以外はその行を失効（`self_revoked`）。安全の記録を残し `{"ok": true, "auth_session_id": …}` |
| `app.me_sessions_revoke_others(p_auth_user_id text, p_keep text) returns jsonb` | 切る端末の数を先に数え、PC を 1 台ずつ `app.device_revoke`、残りを `app.revoke_sessions_for_auth_user_except(p_auth_user_id, p_keep, 'self_revoked')`。`{"ok": true, "revoked": n, "auth_session_ids": […]}` |
