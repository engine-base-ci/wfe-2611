## 目的

AI に任せる（K-62）と承認して完了する（K-63）を合わせ、「チケットを AI に任せる → PC が仕事を受けて終える → 承認待ちに出る → 承認する → 任せた人の PC が実行して終える → 完了にする」まで、一続きの操作として通れるかを確かめる。歩く骨格の 3 つ目の中間テスト（D-128.131）。

## 完了の条件

- [ ] 下の筋 10 本が全部、本物のブラウザ（Playwright）・本物の DB・本物の口と、試験の PC の上で緑
- [ ] 中の操作のチケットの単体のテストが先に緑（この試験は、揃えた最後のチケット K-63 が取り込む前に流す）
- [ ] 手元の CI（.github/workflows を act で・D-128.147）の段に入っている（web の組の G59。`tests/skeleton` の下に置くので G59 がそのまま流す）

## 前提と制約

- 中の 1 本 1 本の分岐は単体のテストが受け持つ（下の「単体が受け持つ分岐」に行 ID を書き、ここでは重ねない）。ここは、つないだときにだけ出るもの（PC の結果が承認待ちに正しく渡る・承認が実行の仕事になって任せた人の PC に届く・完了でチケットとセッション（続きの id）が閉じる・差し戻しで作り直しに戻る・別の人の PC には届かない・承認の記録が取り消せない扱いで残る）を見る
- 口は網の手前で差し替えない（page.route で答えを作らない。届く頭 x-forwarded-for だけを足す）。PC は試験の PC（K-58 の `_lib/test-pc.ts`）で立て、AI の答えは決まった答えを返す差し替え（`_lib/f5-flow.ts` の `AI`）を使う（本物の AI・Claude Code は呼ばない）
- 時刻は DB の時刻を動かす（待たない・D-128.130）：PC の最後の知らせ（K-58 の `clock.ts` の lastBeatAgo）・承認の時刻（`f5-flow.ts` の approvedAgo）。画面の 3 秒ごとの読み直しは、登録の後に `page.clock.install()` を入れ、`runFor(3000)` で次の読み直しを前に出す（K-62・K-63 の単体と同じ形。時計は止めない：止めるとページの setTimeout(cb, 0) も動かず、読み直しの結果が画面に渡らない）
- 画面の文は、受け持つ帯の中だけで探す：帯は段で分ける（D-128.178）：作る段（はじめの作成も差し戻しの後の作り直しも）は K-62 の帯（region「AI に任せる」）だけ。承認待ちと承認の後の状態（実行待ち・実行中・止まった・完了の案内・完了）は K-63 の帯（どの状態でも region「承認と実行」・K-63 が決めた。承認待ちはその中に「あなたの承認を待っています」が出ている形で探す）
- 承認では本人確認を取り直さない（D-128.177）。前の下書きの「15 分以内の本人確認が要る」は D-128.177 で要らなくなったので、本人確認を済ませる道具は作らない
- 骨格では承認は全部「取り消せない」扱い（D-128.177）なので、承認待ちの画面の行は「中身を見る」で、承認はチケットの詳細の帯の「承認して送る」から押す（D-128.36）。行で承認する道は K-63 の単体（K63-UI-002）が持つ
- 実施事項・完了の条件の読み書きの口（updateTicketSection）はまだ無い。チケットは作る口（K-60 の createTicket）で実施事項を 2 項目（`- 見積を作る`・`- 先方に送る`）にして作る
- 消す口（F4）と開き直す口（後の F5／F7）はまだ無い。チケットを消す筋（M3-08）は行の deleted_at だけを、任せ直す筋（M3-10）は段だけを DB で置く（K-62・K-63 の単体と同じ置き方）
