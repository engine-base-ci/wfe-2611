分類: TOOL

- 健康診断の台本（staging_health.py）は鍵を使わない・送らない。当てるのは公開の口だけで、方法は GET と OPTIONS だけ（K200-SH-013）。DB には入らない
- **DB の形は、別の小さな台本が読む**（PM の決め 2026-11-14・精査 B-2）：`/health` の migration の一覧は配ったコードの定数で、DB に当たっているかではない。`scripts/ci/staging_db_migrations.mjs` が、環境の値の名前 `STAGING_DATABASE_ADMIN_URL` で staging の DB につなぎ、読むだけの取引の中で `app.schema_migrations` の名前を 1 回読んで、名前の並びの JSON を標準出力に出す（書かない・K200-SH-016）。健康診断の台本は、その出力のファイルを `--applied` で受けて、リポジトリの migration の一覧と比べる。`--applied` が無い回（接続の値が無い手元・K-202 の前）は、その 1 項目だけ「見ていない」と必ず出し、ほかが全部通っても終わりの値を 3 にする（0 にしない・K200-SH-015）

## リスクと懸念

- migration を足さない版の配りの遅れ・Build の失敗は、この台本では見えない。そのときは Vercel の画面の最新の配り（K-201 の見方）で見る
- **画面の版と、画面が指している口は見えない**：画面は別の Vercel のプロジェクトで、`/login` が 200 でも古い版かもしれず、別の口を指していても分からない（CORS は口の側の設定を見るだけ）。K-201 の画面の確かめと、K-65 の最初の筋で出る
- **メールの送る鍵が入っているかは見えない**（staging は鍵が無くても起動する）。K-203 の後の人の確かめか、K-65 の筋 02 で出る
- DB が休止していても、起動済みの口は `/health` 200 を返し続ける（起動時の確かめは 1 回だけ）。DB も見る回（K-204）では、DB を読む台本がつながらずに赤になるので分かる。手元の回（終わりの値 3）では分からない
- 配り直した直後の数十秒は、古い版が答えることがある（003 が赤になったら、少し待って流し直す）
- `/api/auth/ok` が 404 を返す形に変わると、CORS の確かめが赤になる（認証の部品の版を上げたとき）
- DB を読む台本は管理者の接続を使う（読むだけの役は staging に無い）。読むだけの取引と文 1 つで守る（016）。接続の文字列は環境の値でだけ受け、引数・出力・ファイルに出さない
