## 目的

メンバーの 1 人の画面の「外す」（キャンバス EdMemberRemove・下絵 md-remove・md-remove-each・md-remove-none・md-remove-last-admin）を開いたとき、**外す前に何が起きるかを見せる口**（読むだけ）。外す口（K-816 の孫 K-848）が使う引き継ぎの先は、画面が `listMembers`（前からの口）で選ばせる。

見せる物：担当しているチケットの一覧（渡し中の印つき）・外すと取り消される渡し・承認する人が替わる承認・マネージャーが 0 人になるグループ・すぐ消える物の数・残る物・戻せる期限（30 日・D-154.26）・**外せない理由**（自分・最後の管理者）。

## 前提と制約

分類: LIST, PERM

- **画面が使う答えの形**（K-822 の正）：`{ data: { member: { id, name }, blocked_by: null | "self" | "last_admin", tickets: [{ id, number, title, stage, handing }], handovers_cancelled: [{ id, ticket_id, number, side: "from" | "to" }], approvals_reassigned: [{ ticket_id, number }], sole_approver: [{ scope_id, name }], deleted: [{ key, count }], kept: [{ key }], restorable_until } }`。鍵はちょうど 9（K-800 の 7 つに member・blocked_by を足す。契約の .d で作り直す）
- 入口は管理者の束（members の edit・K-800 の登録）。マネージャー・メンバー・閲覧のみ・止めた人は 403・ログインなしは 401。**権限を個別に付けた人**（members の edit）は通る（D-128.97）。この行（K815-API-010・011・013 の個別に付けた人の 200 と blocked_by last_admin）は **DB の守りとして残す**：人ごとの「できること」を作らない（D-154.10）ので製品の画面からは個別に付けられず、blocked_by last_admin が出るのは管理者でない人に個別に付けた人が呼んだときだけ（管理者が呼べば相手は最後にならない）。試験は DB に直に入れた権限の行で確かめる
- 相手の判定は K-800 の `app.admin_target`：外した人・消した人・別の会社・招待中・AI は null → 404・E-MEM-002（欄・details なし）。止めた人は下見できる
- **自分と最後の管理者は断らず 200 で理由を返す**（`blocked_by`：self・last_admin）。画面（md-remove-last-admin）が理由を出して主ボタンを押せなくするため。断る（409）のは外す口（K-848）。最後の管理者の数え方は K-800 の `app.admin_is_last_admin`（止めた管理者は数えない）
- **tickets**＝担当（assignee_member_id）が外す人で、完了していない・消していないチケット（**下書きも数える**：外す K-848 は下書きの担当も引き継ぐので、数えないと外した人に下書きが残る。1 人の画面の K-810 の assigned も同じ数え方にそろえた・まとめ役の決め）。番号順。`stage` は会社ごとの段の名前（ticket_stages.name）。`handing`＝待っている渡し（state waiting）が付いている
- **handovers_cancelled**＝待っている渡しのうち、外す人が渡した側（from）か受ける側（to）の物（グループ宛て・申し出も含む）。決まった・取り消し済みは出さない。外すとき段 9 の関数が取り消す（K-848）
- **approvals_reassigned**＝外す人が担当するチケットの、まだ決まっていない承認（decision 空・withdrawn_at 空）。**承認は今の担当者が受け持つ**（D-150.21・0095）ので、担当を移すと承認する人も引き継ぎ先に替わる。この口は見せるだけ
- **sole_approver**＝外す人が `scope_memberships.role = 'manager'` で、同じグループのマネージャーが外す人 1 人だけのグループ（外すとマネージャーが 0 人になる警告・D-074）。兼務の人は 2 つの層に出る（D-154.15）
- **deleted**＝すぐ消える物の数（K-849 の消す条件と同じ）。順は memories・conversations・credentials・pc（生きている PC の接続の数。画面 K-822 の字「PC の接続」と同じ物。K-849 が切る sessions は画面・PC・API の全部の種類なので、pc の数とは数える物が違う＝画面のセッションは数に出さない）・invitations。**kept**＝messages・decisions・artifacts・group_memories（数は持たない）。restorable_until＝呼んだ時刻の 30 日後
- 読むだけ：証跡・受け箱・状態を変えない。人数が多くてもページを持たない（1 人の担当は多くて数百）。`Cache-Control: private, no-store`
- DB の失敗は 503・E-PAGE-003（控え帳）。道の値が uuid でない・知らない問い合わせは入口が 422
