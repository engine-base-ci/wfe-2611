## 目的

2026-11-08 に staging が立ったことは確かめてある。そのあと本線にたくさん入ったので、今も最新の版で立っているかを、代表が画面で見る（リポジトリからは見えない）。あわせて、取り込む前の枝が staging の DB を書き換えないようにする。

## 完了の条件

- [ ] Vercel の `kaname-api` と `kaname-web` の、いちばん上の Production の配りが Ready（緑）で、日付が今日か昨日
- [ ] Supabase の `kaname-staging` が休止（Paused）でない
- [ ] `kaname-api` に `RESEND_BASE_URL` という名前の設定が「ある／無い」を実装の担当に伝えた（値は伝えない）
- [ ] 作業中の版（main 以外の枝）の配りを止めた（D-140.4）
- [ ] GitHub のリポジトリが非公開（Private）であることと、Settings に「Environments」が出るか出ないかを、実装の担当に伝えた

## 前提と制約

- 費用：出ない（見るだけ・無料の設定）
- 鍵・パスワード・接続の文字列の値は、チャット・ファイル・コミット・このチケットに書かない。入れる先は Vercel の環境変数（Sensitive）・Infisical・GitHub の Actions の secrets だけ（infra/STAGING.md §1）

## 実施事項

1. https://vercel.com を開く → プロジェクト `kaname-api` → 上の「Deployments」。いちばん上の行で、右に「Production」の印がある行を見る。丸が緑で「Ready」なら良い。赤で「Error」なら、その行を押して出る画面の住所（ブラウザの上の欄）を実装の担当に伝える（中の文は貼らなくてよい）
2. 同じことを `kaname-web` でもする
3. `kaname-api` → 「Settings」→ 左の「Environment Variables」。一覧に `RESEND_BASE_URL` という名前があるか無いかだけを見る（値は開かない）
4. `kaname-api` → 「Settings」→ 左の「Git」→「Ignored Build Step」。選ぶ所で「Only build production」を選んで「Save」。`kaname-web` でも同じ（これで main に入った物だけが配られる）
6. https://github.com/engine-base/kaname を開く →「Settings」。①「General」のいちばん下の「Danger Zone」の「Change repository visibility」に「This repository is currently private」と出ているか見る ② 左の一覧に「Environments」という言葉が在るか無いかを見る（開かなくてよい。在るか無いかだけ）
5. https://supabase.com/dashboard を開く → `kaname-staging`。「Project is paused」と出ていたら「Restore project」を押す（数分かかる）。出ていなければ何もしない

## テスト仕様と確認の結果

| 確かめること | 期待結果 |
|---|---|
| Vercel の 2 つのプロジェクトの最新の Production の配り | どちらも「Ready」と出る |
| Supabase のプロジェクト | 「Project is paused」が出ない |
| Ignored Build Step | 「Only build production」が選ばれた形で残る（開き直しても同じ） |
| GitHub のリポジトリ | 「This repository is currently private」と出る（public と出たら、何もせずにすぐ実装の担当に伝える） |

## 成果物

- なし（見た結果を実装の担当に伝える：Ready か Error か・RESEND_BASE_URL がある／無い・リポジトリは private か・Environments が在る／無い）
