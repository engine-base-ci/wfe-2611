## リスクと懸念

- 本線の上の回は「書き込みのコミットで入ったか」を見ない。本線に入る前にチケットの回の G61 が見ている、が前提。本線に、取り込みの台本を通らないコミットが直に入ると（本線を進めるのは取り込みの台本だけ、の守りの外）、手で足した印でも、記録が pass なら全部の回は緑になる。記録のファイルも一緒に手で置かれると見分けられない（今のチケットの回の守りは変わらない）
- 取り込む先（`--target-ref`）は CI の入力 target か、空なら既定の枝の名前。全部の回を既定の枝でない本線で流すと、HEAD が取り込む先の先祖でなくなり、今と同じ「すり替え」で赤になる（今日の回は target が main で、HEAD は main の先頭だった）
- 新しい道の守りは「取り込む先が本物の本線の枝」に寄る。**塞いだ分**：取り込む先に `HEAD`・sha・生の ref・`@` `~` `^`・短い書き方（`FETCH_HEAD`・`head`・`tags/…` など）を渡す（K196-RM-010・011）／main という名前の tag（K196-RM-012）
- **残る分 (a)**：手で、取り込む先に自分の枝の名前を付けて流した回（`-f target=<自分の枝>`。CI の写しでは `origin/<自分の枝>` が HEAD と同じなので、本線の上の回になる）。台本の中からは、渡された名前が既定の枝かどうかを確かめられない。守り：取り込みが見るのは、回を出す台本（ticket-flow の ci.py）が出した回の記録だけで、その台本が渡す入力は scope・ticket・base の 3 つ（target は渡さない＝いつも既定の枝）。手で流した回は記録に残らない
- **残る分 (b)**：枝の中で CI の定義の式（取り込む先の渡し方）を書き換えた回、組の中で本線と同じ名前の手元の枝を作って自分を指させた回。台本が出した回でも起きる。守り：同じ段で先に流れる前からの試験 K143-CI-016（`scripts/ci/ci_results_test.py` の 431 行）が式 `${{ inputs.target \|\| github.event.repository.default_branch }}` を固めていて、CI の定義は作り手（`05_flow/build_testplan.py`）と合うかを生成物の検査が見る。この 2 つを枝の中で一緒に書き換える所までは、このチケットでは止めない（組の中で走る枝のコードは、どの参照も書き換えられる。引く順を origin が先にしても同じ）
- 枝の名前が 16 進の 7〜40 桁だけ（例 `deadbeef`）の本線は、取り込む先として受けない（sha と見分けられない）。今の本線の名前（main）は当たらない
- 前からの穴だった「`_resolve` が main という名前の tag を枝より先に引く」は、取り込む先についてはこのチケットで塞ぐ（K196-RM-012）。比べる元（`--ledger-base-ref`）は sha で渡るので、引き方は変えていない
- 比べる元が使えない赤で行ごとの確かめを流さないので、その回は、ほかの赤（手で書いた PASS など）が同時にあっても 1 件しか見えない。比べる元を直して流し直すと出る
