## 目的

ゲストは、今ある「招く」の流れで役割「ゲスト」（DB の値は `requester`・D-128.46）を選んで足す（D-155.35・D-155.37）。ゲストは「株式会社〇〇（ゲスト）」の**ゲストのグループ**に入る。この葉は、段 9 の招く・メンバーの画面（本物 `features/F10/invite/`・K-420）に、下絵 `/dev/mock/f11` の「【段 12 の足し】」の所を移して口につなぐ：

- メンバーの画面の見出しの下に **タブ「メンバー N／ゲスト N」**（URL は `?tab=guests`・URL を状態にする）。ゲストのタブは**ゲストのグループごと**に人が並ぶ（依頼が届く社内のグループ・招待中の残りの日つき）。見出しの行は「＋ ゲストのグループを作る」「＋ 招く」。人の行（招待中を除く）にも「⋯」（一時的に止める・外す。止めている人は 戻す・外す。この葉では押せない形・押せる形にするのは K-931・answer=03b52b9684c4。スマホでもゲストの行に出し、役割の札はスマホでは出さない）。グループの行に「＋ このゲストのグループに招く」と「⋯」（名前を直す・消す。この葉ではキャンバスに在る物を隠さず**押せない形**で出す。押せる形にするのは K-928・D-145.9）
- **招くの小窓**：役割の選び肢に「ゲスト」。選ぶと「グループ」の欄が「ゲストのグループ」（既にあるゲストのグループから選ぶ・最後に「＋ 新しいゲストのグループを作る」）に替わる。**依頼が届くグループの欄と、リンクで招く形は出さない**（D-155.38・招待は依頼の届け先を持たない）。選んだグループの届け先は「このグループの依頼は 営業 に届く（作るときに決めた物）」と読むだけで出す
- **ゲストのグループを作る小窓**（名前・依頼が届く社内のグループ・D-155.40）：招くの小窓の「＋ 新しいゲストのグループを作る」から開く（作ると招くの小窓に戻って作ったグループが選ばれる）／ゲストのタブの「＋ ゲストのグループを作る」から開く（作ると一覧に増える）

ゲストが入る道（参加）は K-877、ゲストのグループの名前を直す・消すは K-928（口は K-927）、口は K-876。

  - `createGuestGroup`（POST /guest-groups・入力 `{ name, request_scope_id }`）＝201 `{ data: { group: { id, name, request_scope: { id, name } } } }`。同じ名前は 409・E-GST-002、届け先の社内のグループが無い・消した・別の会社は 404・E-GST-003、権限が無ければ 403

- ゲストの招待は本人確認の取り直し（stepUp）を要らない（K-876・管理者として招くときだけ取り直す）
- 読む口は開いたときに**並べて 1 回ずつ**（getWorkspaceMembers と listGuestGroups・タブの数を出すため）。タブを押しても読み直さない。開き直したとき・送ったとき・作ったときだけ読み直す
