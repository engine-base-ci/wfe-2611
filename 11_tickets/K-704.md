## 目的

会社の管理者が「チケットの設定 › 種別」で、種別を足す・直す（名前・色・本文のひな形）・並べる・消すための口と DB の関数を作る（切り方 0.13・下絵 v2 の set-kinds）。読む口は段 5 の `listTicketKinds`（K-560）をそのまま使い、答えに `color_key` を 1 つ足す。色は見分けの色 8 つの鍵で持ち（土台-settings.md の 2 章）、種別の `color`（16 進）は鍵から DB の引き金が合わせる。

設計の全体（口の道・入力・答えの形・断る番号・置き場・権限）は **`07_functional/段10-F9/土台-settings.md`**（K-705・K-706・K-707・K-715 も読む）。この葉は種別の 4 本と、`listTicketKinds` の鍵 1 つを持つ。

## 前提と制約

分類: CRUD, PERM

- **口は 4 本・新しい専用の答え**。道・入力・答え・上限・権限は土台-settings.md の 3 章のとおり（足す POST /ticket_kinds・直す PATCH /ticket_kinds/:id・消す DELETE /ticket_kinds/:id・並べる POST /ticket_kinds/order）。**並べる口が PUT でなく POST なのは、契約の作り手（`05_flow/screen_api.py`）に PUT の前例が 0 件のため**
- **入力の形（契約に書く＝422）**：足す＝`name`（前後の空白〔全角・タブ・改行〕を落として 1〜40 字・NUL は入口が 422）と `color_key`（8 つの字のどれか）が要り、`body_template` は文書の木（`type` が `doc`・`content` が配列）か null で任意。直す＝同じ 3 つのうち 1 つ以上（空の体は 422・`name` は NFKC にしない）。並べる＝`kind_ids`（uuid の並び・1 つ以上）。ひな形の木の深い確かめ（節の種類・深さ・大きさ）は口が段 5 の `validateDoc`（`@kaname/contracts`・K-561）で行い、false なら 422・欄 `body_template`。`text`・知らない鍵が付けば 422
- **断る番号**（土台-settings.md の 3 章・控え帳 2026-11-20）：同じ名前（消していない種別の中。前後の空白を落とした字で比べる）409 E-KND-001／11 個目 409 E-KND-002（`ticket_limits` の 23514 を関数が先に数えて返す）／使っているチケットが在る 409 E-KND-003（`detail: { ticket_count }`・消したチケットも数える）／並びが今と合わない 409 E-KND-004／最後の 1 つ 409 E-KND-005／無い・消した・別の会社 404 E-PAGE-001（欄・details なし）／権限なし 403／ログインなし 401／上限 429／DB の失敗 503 E-PAGE-003
- **種別を足したときの初めの形**：本文のひな形は無し（null）でよい・色は選んだ鍵・`is_builtin` は false・並びは今の最大の次（10 刻み）・項目（会社が足す項目）は出ない（項目は K-706 の `kind_ids` で結ぶ）。足した種別は段 5 の作る面（`listTicketKinds`）にすぐ出る
- **消すとき**：使っているチケットが 1 枚も無く、最後の 1 つでもなければ、`deleted_at` を入れる（行は残す。**消したチケットも数える**＝ごみ箱から戻したチケットの行き場を失わせない）。消した種別の `custom_field_kinds` の行は触らない（項目のマスタの読みは生きている種別だけを数える）。種別の名前は消した後なら使い回せる（一意の索引は消していない行だけ）
- **直すとき**：送った欄だけ変える。色を変えると `color`（16 進）も DB の引き金が合わせる。種別を使っているチケットは何も変わらず、新しい名前・色で出る。`is_builtin` の種別も名前・色・ひな形は直せる・消せる（最後の 1 つを除く）
- **並べる**：`kind_ids` が今の生きている種別の全部と過不足なく一致するときだけ（足りない・余る・重なる・消した種別・別の会社の種別は 409 E-KND-004・何も変えない）。並びは渡した順に 10 刻み
- 外へ出ない：メールもお知らせも出さない。AI も PC も呼ばない
- ログに種別の名前・ひな形の中身を出さない（会社の id・口の名前・例外の種類だけ）
- **共有の試験 `k144-contract.test.ts` をこの葉は変えない**（運ぶのは葉のファイル `k144.d/K-704.ts` だけ。印の無い行を直さない）
- **生成の試験（tests: の `apps/api/test/generated/…`）は切る段の枝に無い**（口が契約に入るまで作れない）。**作る段の最初に**、契約の断片（`05_flow/screen_api.d/K-704.py`・`scripts/ci/contract_shape.d/K-704.py`）を足して作り手（`python3 scripts/ci/build_registries.py && python3 scripts/tickets/regen_all.py`）で生成の試験を作り、**実装より先に 1 つのコミットにする**（その後は変えない）。**先の葉の契約を前提にした前からの試験は、この葉の carry に入れない**（carry は共通の土台 `settings.harness.ts` と自分の k144.d の行だけ）
