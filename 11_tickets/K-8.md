## 目的

分身の「覚えたいこと」と、運営の新しい表（操作・値段の案）を作る。覚えたいことは本人だけ、値段の案は作った人と決める人を分ける。

## 完了の条件

- [x] migration（`packages/db/migrations/0076_clone_ops.sql`）と RLS（`packages/db/policies/0076_clone_ops.sql`）
- [x] repository の TABLES に入っている・場合表が全部通る
- [x] 自分の案は自分で決められない（決められる人が 1 人のときだけ例外）を DB で守る
- [ ] CI が緑のまま

## 前提と制約

- 表は ER 図 §16 と「足す列」が正。足すだけで、消す・名前を変える migration は作らない
- 全部の表に `tenant_id` と RLS。RLS を飛ばす鍵はサーバーで使わない（ZT3）
- 自分の表の読む守りに「その表を id で引く関数」を使わない（作った行がその場で見えず INSERT … RETURNING が弾かれる）

## 実施事項

- [x] 表：`learning_candidates` `operations` `ops_plan_proposals`
- [x] 列：覚えたいことの入口（覚えて・直したところ・差し戻し・話の中で・同じ流れ・完了）・案の形（守ること・やり方・覚えていること）・状態（待っている・覚えた・覚えない・あとで・例外の OK 待ち）。点検の列は `check_result`（check は SQL の言葉と重なる）
- [x] RLS の範囲：覚えたいことは本人。会社の OK を待つもの・自分が決めたものは OK を出せる人（既定は管理者）にも。運営の表は運営だけ（形からの当てはめ）
- [x] 第1フェーズの操作は汎用のブラウザ操作 1 つ（D-126.19）を初めの行に入れた
- [x] 値段の案：理由は必須・差し戻しの理由も必須・消せない
