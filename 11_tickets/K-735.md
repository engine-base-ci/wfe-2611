## 目的

承認した後、PC がまだ仕事を受け取っていない間だけ、承認した本人が承認を取り下げて承認待ちに戻せるようにする（D-153.21・D-125.105）。正の絵は下絵 `/dev/mock/f5/withdraw-*`（代表が 2026-11-23 に OK）。**字・並び・ボタンは下絵が正**。

- 承認と実行の帯の実行待ちの箱（承認の後の実行が queued）に［承認を取り下げる］→ 確かめの小窓「承認を取り下げます」→ 口 `withdrawApproval`（K-733）→ チケットを読み直す（承認待ちに戻り、承認の帯が出る）＋帯の下の 1 行「〈名〉が承認を取り下げました（承認待ちに戻りました）」
- 間に合わなかった（409・E-APR-010：PC がもう受け取って動かしている）は帯の上の知らせ「もう実行が始まっています。止めるには［止める］を押してください」を出し、読み直す（実行中の帯の［止める］は K-734）

口は新しく作らない（`apis: []`）。帯と器は触らず、K-730 の差し込み口の先 `features/F5/more/fills/withdraw.tsx`（`ExecuteQueuedFill`）の中身だけを本物に替える。

## 前提と制約

分類: AI, PERM

- **出す条件**：承認の後の実行（`run.phase === "execute"`）が `queued`（PC がまだ受け取っていない）で、見ている人がその実行を積んだ人（`run.by.member_id` が `me()` の `member_id`）のとき。承認の後の実行を積むのは承認した人（0096 の `created_by`）なので、これが「承認した本人」。ほかの人・ほかの状態は受けた箱（`box`）をそのまま返す（口の 403・409 は最後の砦）
- **箱**：PC が開いている（`run.pc !== "asleep"`）なら、受けた箱の代わりに `Band tone="wait"`：題「実行待ち ・ PC が受け取るのを待っています」・要約「承認 〈MM/DD HH:MM〉 ・ PC が受け取るまでは承認を取り下げられます」（時刻は実行の `started_at`、無ければ「承認 …」を付けず「PC が受け取るまでは承認を取り下げられます」）・acts［承認を取り下げる］（outlined）。PC が閉じている（`asleep`）なら、今の箱（題「実行待ち ・ PC が閉じています」・「PC をつなぐ」）の acts に［承認を取り下げる］を足した形
- **確かめの小窓**（components/k の `Confirm`・`tone="primary"`）：題「承認を取り下げます」・本文「〈番号 題名〉。PC がまだ受け取っていないので、承認待ちに戻せます。戻したあと、もう一度決められます」・足「やめる」「取り下げる」・スマホで下から出す印（`k-more-sheetmark`）
- 小窓の「取り下げる」→ `call("withdrawApproval", { params: { id: <実行の承認の id> }, body: {}, screenId: "tickets" })`。承認の id は、実行の 1 件の答え（ActionRunView・K-485 の `app.action_run_json`）が `approval_id` を持たないので、**決めた履歴の口 `listApprovalHistory`（K-750）**を `{ decision: "approve", limit: "20" }` で 1 回読み（鍵 `["k735","withdrawable",ticketId]`・上の出す条件のときだけ・`retry: false`）、`ticket_id` がこのチケットで `can_withdraw` が true のいちばん新しい行の `id` を使う（取り下げの条件は K-733 と同じ式・K-750）。行が無い・読めないときは［承認を取り下げる］を出さない（受けた箱のまま）。待つ間は主ボタンが処理中で小窓は閉じない・二度押しでも口は 1 回
- 201：小窓を閉じ、`pushTrail(ticketId, "〈自分の名〉が承認を取り下げました（承認待ちに戻りました）")`・実行の一覧・`timelineKey` を読み直させ `onChanged()`（チケットを読み直す。答えの `approval_id` の新しい承認待ちが getTicket の approval に出る）
- 409・E-APR-010：小窓を閉じ、帯の上の知らせ（`pushNotice`）に正本の文「もう実行が始まっています。止めるには［止める］を押してください」・読み直す（帯は実行中の形になる）。409・E-APR-011・E-APR-012・403・404・503：知らせに正本の文（`messageOf`）・読み直す。401 は入り直し
- 文は全部文字として出す。生の色・大きさを書かない
