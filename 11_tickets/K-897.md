## 目的

K-896 が積んだ「案の仕事」を取った PC（Bridge・K-929）が、AI に作らせた結果を Kaname に返す口 `reportClientRequestDraft`（POST /bridge/jobs/:id/client-request-draft・`:id` は仕事の id・体は `{ draft }` か `{ failed }`・PC の印で叩く・200 `{ data: { state } }`）を作る（D-155.11）。

- 成功：`{ draft: { ticket, reply, questions, route? } }`。依頼の `draft` に**決まった形だけ**を保存し、`draft_state = 'ready'`・`questions` に聞きたいことを入れ、仕事を `done` にする。開いた依頼を読むと案が出る（K-892・画面は K-899）
- 失敗：`{ failed: "<理由>" }`。`draft_state = 'failed'`・仕事を `stopped`（理由つき）にする。「案が来なかった」文を出して押し直せる（K-896）
- 依頼が先に決まっていた（チケットにした・断った）・押し直されて別の仕事が結んである場合は、結果を捨てて 200 `discarded`（案は保存しない・仕事は閉じる）
- **AI の出力は信用しない**：先方の書いた字から AI が作った文なので、これも「データ」。形・長さ・日付を確かめ、決まった欄だけ保存する。HTML や指示として扱わない（そのまま字として画面に出る・K-899）

## 前提と制約

分類: AI, TOOL

- 入口：口の役は PC の印だけ（`def.auth = "device"`・画面のログインの人は 403・ログインなしは 401・失効した PC の印は 401）。上限は PC ごとに数える（K-355 と同じ）
- 仕事の確かめ（DB の関数 `app.bridge_client_request_draft_result(p_session, p_job, p_draft, p_failed)`）：PC の印のセッションが生きている Bridge・`bridge_jobs` の行（`id = :id`）が **その PC が受け取った仕事（`app.bridge_job_of(p_session, p_job)`・本線 0092：その PC の `taken_session_id` の物、列が空なら PC の持ち主のアカウント全体の物）・種類 `client_request_draft`・状態 `running`（取った後）** でなければ、何も書かず null → 404・E-GST-150（欄・details なし・在るかを漏らさない）。**同じ結果をもう一度送ると仕事はもう `done`／`stopped` なので 404**（PC の再送は無視できる）
- 体（strict）：`draft` か `failed` の**ちょうど 1 つ**（両方・どちらも無いは 422）。`draft` は `{ ticket: { title, kind?, owner?, due?, cost?, route_name? }, reply, questions, route? }`：`ticket.title` は前後の空白を取って 1〜200 字・`kind` 40 字・`owner` 80 字・`cost` 40 字・`route_name` 80 字まで・`due` は日付（YYYY-MM-DD）・`reply` は 0〜10000 字（空でもよい）・`questions` は 0〜5 個（1 つ 1〜300 字）・`route` は `{ name（80 字まで）, reason（200 字まで）}`。**知らない欄は 422**（保存するのは決めた欄だけ）。`failed` は前後の空白を取って 1〜400 字
- 保存：`client_requests.draft = { ticket, reply, questions?, route? }`（決めた欄だけ・`route.scope_id` のような id は受けない＝届け先の案は名前と理由だけで、選ぶのは人）・`draft_state = 'ready'`・`draft_at = now()`・`questions` 列に `questions`。仕事は `done`（`result = 'ready'`）。証跡 `client_request.draft_ready`（payload は `request_id` と `job_id` だけ・案の中身は載せない）
- 失敗：`draft_state = 'failed'`・`draft = null`・仕事は `stopped`（`stopped_reason` は理由の先頭 400 字）・証跡 `client_request.draft_failed`（`request_id`・`job_id`）
- 捨てる：依頼が `ticketed`・`declined`・または依頼の `draft_job_id` がこの仕事でない（押し直された）なら、案は保存せず・仕事を `done` にして、200 `{ state: "discarded" }`
- 1 つの取引（`app.bridge_client_request_draft_result`）。途中で落ちたら全部戻る（503・E-PAGE-003）
- 案の中身はメール・お知らせに載せない（何も送らない）
- 関門の宣言（頭の欄 choke_points）は [C2]
