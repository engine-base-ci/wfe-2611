## 目的

前からある表（人・ワークスペース・預けたログイン情報・権限の言葉・中を見るの許可・運営の人・お知らせ・障害・問い合わせ）に、第1フェーズの列を足す。運営が中を見るのを、開いた本人だけに絞る。

## 完了の条件

- [x] migration（`packages/db/migrations/0078_people_tenant_ops.sql`）で列が足され、まっさらな DB に全部入る（78/78）
- [x] 中を見るの許可の RLS（`packages/db/policies/0078_people_tenant_ops.sql`）を「運営の人が理由を書いて開く・会社は誰が見たかを見られる」にした
- [x] 場合表が全部通る（1548/1548）・DB の試験が全部通る
- [ ] CI が緑のまま

## 前提と制約

- 足すだけ（消す・名前を変える migration は作らない）。前からある行が新しい決まりに合わないことがあるので、行の決まりは NOT VALID で足した（新しい行から効く）
- 運営がしたことを相手のワークスペースの記録にも書く（D-128.108）のは、運営の口（KN-28）で app.record_audit を呼んで守る

## 実施事項

- [x] `members`：call_name（20 文字まで）・avatar_ref・language・theme・week_start・timezone・setup_dismissed_at・suspended_at・suspended_by。名前は 100 文字まで
- [x] `tenants`：logo_ref・client_visibility_default（全員・担当グループだけ）・request_routing・deletion_requested_at
- [x] `credentials`：destinations・read_only・client_id・purpose・expires_at・use_count・last_used_at
- [x] `abilities`：billing（プランと支払い）・export（書き出す）・delete_workspace（ワークスペースを消す）
- [x] `support_access_grants`：reason（必須）・inquiry_id・closed_at・1 時間まで・開いた運営の人（ops_member_id）が必須
- [x] `ops_members.caps`（問い合わせ・中を見る・お金・止める・お知らせ・配るもの・値段の案・値段を決める・運営の人。決まった言葉だけ）
- [x] `notices`：state・affects・placements・maintenance_from／to・emailed_admins_at。`status_incidents`：notice_id・state・body。`inquiries`：context・later_until
- [x] ★`app.ops_grant_ok` を、許可を開いた運営の人だけに効くようにした（今までは、その会社に有効な許可が 1 つあれば、どの運営の人でも中を読めた）。閉じた許可も効かない
- [x] 見本と前からの試験（rls.test.ts）の許可に、理由と開いた人を入れた
