## 目的

staging の API を出す場所を用意する（infra/STAGING.md S2）。Build のたびに migration と置き場の用意が流れる（本番と同じコード）。

## 完了の条件

- [ ] Vercel のプロジェクト `kaname-api`（Root Directory `apps/api`）がある
- [ ] 環境変数を Production と Preview の両方に Sensitive で入れた（名前は infra/STAGING.md §3 の表。値はここに書かない）
- [ ] 最初の Deploy が通った

## 前提と制約

- リポジトリは GitHub の engine-base/Kaname（あり）
- 料金：Hobby で始める。顧客に触らせる前に Pro（月 20 USD・Hobby は商用不可）
- 鍵・パスワード・接続文字列の値は、チャット・ファイル・コミットに書かない。入れる先は Vercel の環境変数（Sensitive）か Infisical だけ（infra/STAGING.md §1）

## 実施事項

1. Vercel → Add New → Project → engine-base/Kaname → Root Directory `apps/api`・Framework Preset `Other`（Build は apps/api/vercel.json が決める）
2. 役割のパスワード 2 つ（`KANAME_APP_DB_PASSWORD`・`KANAME_AUTH_DB_PASSWORD`）・`AUTH_SECRET`・`SECRETS_MASTER_KEY` を乱数で作る（`openssl rand -base64 32`）。K-78 の接続のパスワードにも同じ値
3. Settings → Environment Variables に、K-78・K-79・K-81 の値と上の乱数を入れる（Production と Preview・Sensitive）
4. `NODE_ENV=staging`・`BASE_URL`（この API の URL）・`WEB_BASE_URL`（K-82 の後）
5. Deploy
