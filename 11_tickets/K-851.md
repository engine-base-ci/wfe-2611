## 目的

左上の「ワークスペースを切り替える」（K-844）が使う 2 つの**新しい口**（契約に無い・この葉が足す・D-154.81）。

- `switchWorkspace`（POST /api/v1/me/workspaces/:id/switch）：今いるワークスペースを、同じログインが入っている別のワークスペースに替える。今の端末（部品のセッション）の `sessions` の行を、その会社の同じログインの人の行に**結び直す**（次の要求から入口がその会社で解く）
- `listMyInvitations`（GET /api/v1/me/invitations）：確かめ済みのログインのメールに届いた、待っている・期限内の招待（切り替えの小窓の「届いた招待 N ›」）

今はログインのセッションが 1 つの会社に結ばれて作られ（`app.open_session`・`sessions.auth_session_id` は一意）、ほかの会社に移る道が無い。

**画面が使う答えの形**（K-844 の正）：

```
switchWorkspace     200 { data: { tenant_id, switched: boolean } }       （今いる会社を指したら switched false で何も変えない）
listMyInvitations   200 { data: { invitations: [{ id, workspace_name, inviter_name: string|null, expires_at }], total } }
```

招待は期限の近い順に 20 件まで（`total` は全部の数）。招待の印（token）は返さない（DB はハッシュしか持たない）。届いた招待を押した先は代表の答えを待つ（D-154.81・K-844 は押せない形）。

- **新しい口の手順**：切る段（c/段11）で契約の断片 `05_flow/screen_api.d/K-851.py` を下の「契約」の形どおりに置き（carry: で運ぶ・PERMS の「member（本人だけ）」は契約の言葉 self で書いた）、作り手（`python3 scripts/tickets/regen_all.py` の build_functional → build_api → build_testplan → gen_ears_tests）で生成の試験 2 つを作ってコミットした。持ち込みの作り手が葉でも同じ物を作る。作る段は出た名前に合わせて ears-elsewhere.d/K-851.json の covers の鍵を合わせ、余る名前は na に理由を書く
- **だれが呼べるか**：本人だけ（member の束）。本人確認の取り直しは要らない（D-154.18 の並びに無い）。入口の共通（401・429・同意し直し 403・道の id の形 422・strict の体 422・NUL 422）が先に効く。取り直しの時刻（`sessions.step_up_at`・0081）は今の端末のセッションの行に付き、切り替えは同じ行の会社を替えるだけなので、切り替えても持ち越す（ほかの端末には効かない）：A の会社で取り直してすぐ B に切り替えると、B の管理の操作も 15 分は取り直しなしで通る（同じ人・同じ端末の取り直しなので D-154.18 のとおり・資料 `08_api/phase1/05_自分の設定とPC.md` の切り替えの行に 1 行書く）
- **今の端末**：口は入口と同じ印の引き方（`d.auth.api.getSession({ headers })`・K-312・K-836）で部品のセッションの id と利用者の id を引く。部品のセッションの id が無い・その `sessions` の行が無い／切れている → 401
- **切り替える**（`app.me_switch_workspace(p_tenant uuid, p_auth_session text) returns jsonb`）：今の行を `for update` で取る。行き先は、同じログイン（`tenant_memberships.auth_user_id` が同じ・D-125.150）の `p_tenant` の人で、`tenant_memberships.status` が active・`members.deleted_at` と `members.suspended_at` が null・`tenants.deleted_at` が null のもの。無ければ `{"error":"not_found"}`（**無い・別のログインの会社・止められた・抜けた・招待中・会社を消した は同じ 404**・欄と details を付けない）。今の会社と同じなら何も変えず `{"switched": false}`。違えば行の `tenant_id`・`member_id` を行き先に替え `last_seen_at` を今に（`issued_at`・`auth_session_id`・端末の名前・本人確認の取り直しの時刻はそのまま・行を増やさない）。ほかの端末・PC の行は変えない
- **記録しない**：切り替えは会社の記録・安全の記録・受け箱に載せない（自分の表示の操作・D-154.55）
- **同時**：同じ端末の行を `for update` で順に通す（2 つ同時なら後に通った会社に結ばれる・行は 1 つのまま）
- **届いた招待**（`app.me_invitations(p_auth_user_id text) returns jsonb`）：`kaname_auth."user"` の `email` と `"emailVerified"`。確かめ前なら 0 件。`invitations` のうち `lower(btrim(email)) = lower(btrim(<ログインのメール>))`・`accepted_member_id`・`revoked_at`・`deleted_at` が null・`expires_at > now()`・会社が消えていない・同じログインがその会社に有効な人を持たない（`tenant_memberships` の active か suspended）。`workspace_name` は `tenants.name` の前後の空白を削った物・`inviter_name` は `created_by` の人の `display_name`（無ければ null）。期限の近い順に 20 件と全部の数
- 読む口の答えは `Cache-Control: private, no-store`。DB の失敗は 503・E-PAGE-003（何も変わらない）
- 断る番号は控え帳どおり（404 は欄・details を付けない／503）。新しいエラーの番号は足さない
