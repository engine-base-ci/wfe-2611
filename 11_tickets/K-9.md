## 目的

前からある表（承認・守ること・覚えていること・業務の型・分身）に、第1フェーズの列を足す。承認する人が、グループの外でも自分に来た承認とチケットを読めるようにする。

## 完了の条件

- [x] migration（`packages/db/migrations/0077_approvals_clone.sql`）で列が足され、まっさらな DB に全部入る（77/77）
- [x] 承認の RLS（`packages/db/policies/0077_approvals_clone.sql`）を「承認する人・頼んだ人・チケットを読める人・マネージャー」にした
- [x] 承認する人を「関わっている人」（app.ticket_involved）に足した（K-3・K-4 の申し送り）
- [x] 場合表が全部通る（1553/1553）・DB の試験が全部通る（141 件）
- [ ] CI が緑のまま

## 前提と制約

- 足すだけ（消す・名前を変える migration は作らない）
- 業務の型は第1フェーズ（節目①）では運営の全社向けだけ。会社・層・個人の型は節目②（KN-21）

## 実施事項

- [x] `approvals`：ticket_id・kind（AI の成果物・上位の承認・決まりの例外・やり方を広げる）・subject・level・parent_approval_id・escalated_by_policy_id・decision（承認・自分で直す・差し戻し・止める）・decided_at・return_targets・return_reason・next_actor・memory_candidate・human_checks・irreversible・step_up_at・withdrawn_at・bulk_batch_id
- [x] 承認の決まり：差し戻しは理由が要る・取り返しのつかない承認は直前の本人確認が要る（D-125.139）・まとめて承認は人が見る項目なし／取り消せる操作だけ（D-128.86）
- [x] `policies`：text・applies_to（すべて・取引先・種別）・client_id・kind_id・source_ref・version・paused_at・use_count・last_used_at・例外（exception_of_policy_id・exception_approval_id）・kind（守ること・上に回す）・escalate_when・escalate_to。上に回す決まりは「何のとき」と「誰へ」が要る
- [x] `memories`：auto・use_count・last_used_at・visibility（自分だけ・勧めた）
- [x] `skills`：scope_id・owner_member_id（scoped にする）。`skill_versions`：fields・state・checked。全社向けの型はどの会社の人も読める（チケットを作るときに選ぶ・D-126.13）
- [x] `clones.auto_memory`（既定 入・D-128.90）
- [x] ★`gen_rls.py`：今の一覧に無い守りを外すようにした。承認の表に前の守り（グループの人なら書ける）が残っていて、人の名前で承認を頼めた（守りは「どれかが通れば通る」ので、古い守りが残ると黙って穴になる）
- [x] テスト仕様書の承認の行（RLS-D05-008）を新しい守りに書き直した。照合の道具（qa-ladder）が KN- の番号も認める
- [x] ★前からの穴：運営だけの表（service_registry_versions・skill_test_runs）に 0014 の「会社の人が読める・書ける」守りが残っていた。外して、DB の守りが仕様と同じで余分も不足も無いことを試験にした（`packages/db/test/rls_drift.test.ts`・余分な守りを 1 つ足すと赤になる）
