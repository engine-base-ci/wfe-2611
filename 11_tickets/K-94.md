## 目的

K-57・K-60 は depends_on の K-52・K-53 がまだ無いのに、先に取り込もうとしていた。人が依存を思い出す形では漏れる（K-57・K-60 の取り込みの途中で見つけた。途中で見つけたものはその場で直さずチケットにする・D-128.147）。

## 完了の条件

- [ ] コミットの K-番号のチケットの depends_on に、まだ完了していない（取り込まれていない）実装のチケットがあれば CI が赤（チケットを切るだけ・文書だけのコミットは除く）
- [ ] PM の取り込みの手順（pm_merge.sh）が、取り込む前にこの検査を流す
- [ ] workflow の全部（act）が緑

## 前提と制約

- 完了の印はチケットの stage（完了）と、実装のコミットが枝にあること
- **文書だけのコミットの見分け方**：そのコミットで変えたファイル（`git diff-tree --no-commit-id --name-only -r <sha>`）が全部、文書と生成物の置き場に入るなら「文書だけ」として見ない。置き場は `01_hearing/`・`11_tickets/`・`07_qa/test-plan/`・`07_qa/test-specs/**/*.md`・`03_architecture/catalog.*`・`08_api/*.md`・`README.md` と、scripts/ci/generated.json の作り手の outputs。1 つでもそれ以外（apps/・packages/・scripts/・.github/・migration など）を変えていれば「実装のコミット」として依存を見る
- コミットの K-番号が複数あるときは、どの番号の依存も満たしていること

## 実施事項

- [ ] スクリプト `scripts/ci/ticket_order_gate.py` を足す：`START..HEAD`（ticket_commit_gate.py と同じ起点）の各コミットについて、上の見分け方で実装のコミットだけを取り、メッセージの K-番号のチケット（11_tickets/tickets.json）の depends_on が、そのコミットより前に「完了」かつ実装のコミットが枝にあることを確かめる。`--selftest` で、依存が未完了の写しを作って赤になることを見る
- [ ] workflow の段：05_flow/build_testplan.py の SPEC_GATES に `G56 取り込む順（depends_on の実装が先に枝にある・K-94）`（job: spec・blocking）を足して、.github/workflows/v3-gate.yml を作り直す（手で直さない）
- [ ] pm_merge.sh の取り込みの前に `python3 scripts/ci/ticket_order_gate.py` を流す
- [ ] ai-team-delivery と engineering-rules（ai-driven-process.md）に同じ検査を汎用で入れる
