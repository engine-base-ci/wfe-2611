## 目的

2026-11-15、処理の場所を東京にする直し（口と画面の vercel.json に `regions: ["hnd1"]`・健康診断に処理の場所の項目）が本線に入り staging に配られた。その後 PM が測った事実：

- 画面（kaname-web・Next.js）：答えの頭 `x-vercel-id: hnd1::hnd1::…`＝東京に変わった
- 口（kaname-api）：`x-vercel-id: hnd1::iad1::…`＝**米国東部のまま**。健康診断は「★ 処理の場所（口）が iad1（決まりは hnd1・DB と同じ場所）」と正しく赤を出した
- 速さ（5 回の真ん中・直す前と変わらず）：`/health` 0.20 秒・`/api/v1/auth/terms/current`（DB を読む）0.81 秒・`/login` 0.36 秒

口は `framework: null` で、`apps/api/build-vercel.mjs` が Build Output API の形（`.vercel/output/functions/api.func` と `.vc-config.json`）を自分で組み立てている。この形では関数の場所は関数の設定 `.vc-config.json` の `regions` で決まる。今の `.vc-config.json` は runtime・handler・launcherType・shouldAddHelpers・maxDuration だけで、`regions` が無い。代表が「読み込みが遅すぎる」と指摘した原因の本体（口が DB を読むたびに太平洋を往復する）がここに残っている。

このチケットは、組み立ての台本が場所の決まり（`scripts/ci/staging_region.json`）を読んで `.vc-config.json` に `regions` を書くようにし、読めないときは組み立てを止める。

## 前提と制約

  - Build Output API の関数の設定（https://vercel.com/docs/build-output-api/primitives の「Serverless function configuration」）：`.vercel/output/functions/<name>.func/.vc-config.json` は必須で、Base config の欄は `handler`・`runtime`（必須）・`memory`・`architecture`・`maxDuration`・`environment`・**`regions`（String[]・「List of Vercel Regions where the Vercel Function will be deployed to」）**・`supportsWrapper`・`supportsResponseStreaming`。Node.js は加えて `launcherType`（必須・"Nodejs"）・`shouldAddHelpers`・`shouldAddSourcemapSupport`・`awsLambdaHandler`。だから場所は文字列の並び `["hnd1"]` で書く
  - 配りの設定 `.vercel/output/config.json`（https://vercel.com/docs/build-output-api/configuration ）の欄は version・routes・images・wildcard・overrides・cache・framework・crons・services・daemons で、場所の欄は無い。関数の場所は関数ごとの `.vc-config.json` で持つ形
