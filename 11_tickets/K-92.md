## 目的

ログイン中の人がチケットの画面（`/tickets`）を開くと、**自分が見てよいチケットが一覧で並ぶ**。開いた直後は「自分に関わるもの」（担当者が自分・自分が答える渡し）を**期限の近い順**に出す（D-128.11：これが毎日のホーム）。タブで「すべて」（見えるチケット全部・更新の新しい順）に切り替えられる。列は 番号・題名・種別・状態・担当者（AI に任せているときはロボットの印と「〈担当者〉のAI」）・期限・更新 の 7 つ（D-128.15 を D-128.25・D-128.26 で改めた形）。期限を過ぎて終わっていないものには炎の印（D-125.61）。行を押すと詳細 `/tickets/[id]`（K-60）が開く。

同じ口で、**チケットを作る面（K-60）の「親のチケット」の候補**を題名か番号で探して出す（D-128.152）。0 件のときは空の一覧の真ん中に「自分で書く」（K-60 の作る面への入口・D-125.145）。

**読むだけのチケット**で、確定する時点（書き込み）は無い。一覧に何が出るかは、読んだ時点のチケットと見える範囲で決まる（作った直後・渡された直後・消された直後に読み直すと、すぐ反映される）。

### 決めた判断

- 開いたときは「自分に関わるもの」を期限の近い順（D-128.11）。「自分に関わる」は、担当者が自分・自分が答える渡し（ticket_involved）。承認する人（D-128.11 の 3 つ目）は承認のチケット（K-63）が ticket_involved に足したときに自然に入る
- 列は 7 つ（D-128.15 の 8 つから、実行者の欄をなくし担当者と呼ぶ・D-128.25・D-128.26）。AI に任せているものは担当者の横のロボットの印（D-128.16）
- 期限を過ぎて終わっていないものに炎（D-125.12・D-125.61）。「終わった」は状態の key が done
- 消したものは一覧に出さない（戻すのは記録の画面から・D-128.84）。取り込みの下書きは取り込んだ本人にだけ（D-128.119）
- 番号は変わらない（D-125.60・D-128.115）ので、番号で絞ると同じ 1 件が出る
- 下の「聞きたいこと」は、推奨の案で作り方を書いた。違う答えなら作り方を直してから実装に入る

### 聞きたいこと

1. **題名か番号で絞る（q）を入れるか**：一覧の検索は F7 の search（K-67）。K-60 の親の候補は件数が多いと探せない。**推奨：このチケットに `q`（題名の部分一致か番号）だけを入れる。言葉で全部を探す・保存する絞り込みは K-67**
2. **消したもの・下書きを外す層**：**推奨：口で外し（このチケット）、行の守り `tickets_read` にも `deleted_at is null` と `app.ticket_draft_ok` を足す（2 層にする）**。行の守りを変えると戻す画面（F7）が消したものを読めなくなるので、戻す画面は security definer の関数で読む形にする（K-67 側の作業が増える）。もう 1 つの案は口だけ（1 層）
3. **期限間近の印**：D-125.61 は「何日前からかは会社が決める」だが、その設定の置き場が無い。**推奨：このチケットは期限切れの炎だけ。期限間近は会社の設定を作るチケット（F10）で足す**
4. **「自分に関わるもの」に、自分が作ったチケットを入れるか**：D-128.11 は 担当者・自分の AI が動いている・自分が承認する の 3 つで、作った人は入っていない。**推奨：入れない（作って他の人に渡したものは「すべて」で見る）**。K-60 の「作ると一覧に 1 件」は、担当者が自分なら「自分に関わるもの」に、他の人なら「すべて」に出る
