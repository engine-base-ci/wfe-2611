## 目的

管理者が、メンバーの 1 人を**ワークスペースから外せる**ようにする（行為 A62「抜ける人の依存を片付ける」・D-154.6）。外す小窓で、**担当しているチケットの引き継ぎ先を管理者が選び**（全部を同じ人に／1 件ずつ）、**選んだ人にそのまま移る**（相手の「受ける」は待たない・段 9 の「黙って書き換えない」の例外＝管理者が選ぶので黙ってではない）。渡し中は外す前に取り消される。外すとすぐ入れなくなり、分身も止まる。書き出しは無い（D-154.4）。

## 前提と制約

分類: PERM, CRUD

- **口の答えの形**：下見＝`previewMemberRemoval`（`GET /api/v1/members/<id>/remove-preview`・K-815 の「画面が使う答えの形」）→ `{ data: { member: { id, name }, blocked_by: null｜"self"｜"last_admin", tickets: [{ id, number, title, stage, handing }], handovers_cancelled, approvals_reassigned, sole_approver, deleted, kept, restorable_until } }`。外す＝`removeMember`（**`POST /api/v1/members/<id>/remove`**・DELETE ではない・D-154.28）の体 `{ transfer_to_member_id? , transfers?: [{ ticket_id, to_member_id }] }`（全部同じ人は前者・1 件ずつは後者・両方あれば後者が勝つ）・答え 200 `{ data: { member_id, tickets_moved, handovers_cancelled, restorable_until } }`（K-848）。担当が無い人は体 `{}`
- **開く**：詳細の頭の「ワークスペースから外す」（直に `?do=remove`）で、まず下見を 1 回読み、`blocked_by` が `last_admin`（または `self`）なら**小窓を開かず**、上の赤い箱 `Callout` 題「外せません」・文「<名前>は、いまの管理者の最後の 1 人です。先にほかの人を管理者にしてから、外してください」（自分は「自分は外せません。抜けるのは自分の設定から」）を出す（下絵 md-remove-last-admin・外す口は呼ばない）。`detail-dialogs.tsx` の `DO_DIALOGS` に `  remove: `RemoveBox`,` を 2 字下げの 1 行で足す（K-819 が置いた登録口。K819-UI-018 がこの形の字を読んで、足した操作のボタンを押せる形に数える）。下見が 503 のときは小窓を開かず赤い箱「確かめられませんでした」（正本の文）
- **小窓**（K-801 の `RemoveDialog`・字は下絵のとおり）：題「<名前> さんをワークスペースから外す」・副題「外すと入れなくなり、<名の頭>のAI も止まる」。担当がある：「担当しているチケット <N> 件の引き継ぎ先」・「全部を同じ人に」「1 件ずつ決める」・全部の選び（`getByLabel` の名前「全部の引き継ぎ先」）／1 件ずつは行ごとに「<番号> の引き継ぎ先」の選び・チケットの行「<番号> ・ <段>」と題。担当が 0 件：「担当しているチケットはありません。引き継ぎは要りません」。渡し中（`handing`）の行ごとに注意の箱「渡し中の <番号> は、外す前に取り消される（<引き継ぎ先> さんへの渡しは成り立っていない）」。「すぐ消える（戻せない）」「残る」の字・「外したことは記録に残る。30 日のあいだは同じメールで招き直すと、グループと役割だけ戻る」（部品のまま）。**「すぐ消える」「残る」は件数を持たない固定の字**：下見の答えの `deleted`・`kept` は数を出さない（下絵 md-remove* が件数なしの字で、代表 OK の絵を替えない。下見を読むのは `blocked_by`・`tickets`・`handing` を使うため。数を出すかは後で決める・リスク）。足は「やめる」「本人確認して外す」
- **引き継ぎ先の候補**：メンバーの並び（`getWorkspaceMembers`・口を増やさない）の人から、**有効で（止めていない）・会社の役割が閲覧のみ・依頼する側でなく・外す本人でなく・招待中でない人**（D-154.39）。人は id で 1 度だけ（兼ねる人を重ねない・D-154.15）。初めの選び＝外す人の主のグループのマネージャー（いれば）・いなければ先頭。1 件ずつは、初めは全部の選びと同じ
- **外す**：「本人確認して外す」→ 体は全部＝`{ transfer_to_member_id }` だけ・1 件ずつ＝`{ transfers }` だけ（下見の `tickets` の順に全部）・担当 0 件＝`{}`。**本人確認の取り直しは今の部品 `StepUp`（features/F1/security/step-up.tsx・パスキーなら指 1 本の stepUpWithPasskey も同じ部品の中・D-154.3）を使い、K-363 と同じ形：口が 403 STEP_UP_REQUIRED（kind `step_up`）→ `getMySecurity` を 1 回読んで `StepUp` を開く → 通ったら同じ体で **1 回だけ**やり直す・やめたら何も送らない**。理由の字＝「<名前> をワークスペースから外す前に、本人か確かめます」（仮）。成功：`/members` に移り、知らせ「<名前> さんを外しました。担当のチケット <N> 件は <引き継ぎ先> さんに移りました。30 日のあいだは、同じメールで招き直すと戻せます」（1 件ずつは「担当のチケット <N> 件の引き継ぎ先を選んだ人に移りました」・担当 0 件は「担当のチケットはありませんでした」・仮）・並びを読み直す（外した人はどのグループの行からも消える）。**全部か無しか**：口が断れば何も移らない（画面は何も変えたと言わない）
- **失敗の出し分け**（答えの code と detail で決める）：409 E-MEM-020（下見のあとで担当が変わった）→ 下見を読み直して行を新しくし、小窓の赤い箱「担当しているチケットが変わりました。もう一度確かめてください」（引き継ぎ先の選びは残る）／404 E-MEM-021（引き継ぎ先が居ない）・409 E-MEM-022（止めた・外す本人・detail の名前）・409 E-MEM-023（閲覧のみ・detail の名前）→ 小窓の赤い箱（名前入り）＋メンバーの並びを読み直して候補を新しくする（小窓は閉じず中身は残る）／409 E-MEM-004（最後の管理者）・409 E-MEM-005（自分）→ 小窓を閉じて上の赤い箱／404 E-MEM-002（もう居ない）→ 小窓を閉じて「見つかりません」／403 FORBIDDEN・503 E-PAGE-003 → 小窓の赤い箱（押し直せる）
