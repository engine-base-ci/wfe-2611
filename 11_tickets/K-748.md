## 目的

承認待ちを、種類で絞り、並べ替えられるようにする（D-153.10・D-153.30。今は札が押せない形で、口は期限の近い順だけ）。`listApprovalQueue`（GET /api/v1/approvals/queue・K-161）に次を足す。

- **`kind`**（絞り込み）：`artifact`（AI の成果物）・`handover`（渡された）。付けなければ全部
- **`sort`**（並べ替え）：`due`（期限の近い順・今の並び）・`waiting`（承認待ちになった順＝新しく承認待ちになった物が先・D-153.30）・`title`（題名の順）。付けなければ `due`
- **札の横の数** `meta.counts`：`{ total, artifact, handover }`（今は `{ total }`）。**絞っても全体の数のまま**（札の数が絞り込みで変わらない）

段 9 の K-405 が作り直す `app.approval_queue`・`app.approval_queue_count`（承認待ちの条件はこの 2 つが持つ）は**触らない**。`kind`・`sort` が付いたときだけ、新しい DB の関数 `app.approval_queue_page` が `app.approval_queue` を呼んで束ね、絞る・並べる・頁に切る。付けないときは今の道のまま（続きの鍵も今の形）で、数だけ `app.approval_queue_counts` で 3 つ出す。続きの鍵は、`kind`・`sort` を付けた要求では「何件目から」の鍵（`o|<件数>` を base64url にした字）にする。まとめて承認・続けて裁く・決めた履歴（K-750）は別の葉。画面は K-749。

- 新しい DB の関数 3 つ（migration 1 本・列は足さない・どれも `p_member` を受けず呼んだ人を `app.user_id()` で引く）：
  - `app.approval_queue_all(p_max integer default 1000) returns jsonb`（**中だけ・誰にも grant しない**）：`app.approval_queue(201, …)` を鍵（最後の行の `due_on`・`created_at`・`id`）で続きを繰り返し読み、最大 `p_max` 件を 1 つの並び（今の並び）で返す。メンバーでなければ空
  - `app.approval_queue_counts() returns jsonb`：`{ total: app.approval_queue_count(), artifact, handover }`（artifact・handover は `app.approval_queue_all` の行を `kind` で数える。`kind` の違う行は total にだけ入る）
  - `app.approval_queue_page(p_kind text, p_sort text, p_limit integer, p_offset integer) returns jsonb`：`{ rows, more, counts }`。`p_kind` は null・`artifact`・`handover`、`p_sort` は null（＝`due`）・`due`・`waiting`・`title`、それ以外は `{error:'bad_query'}`（口は入口が先に 422 にするので、直に呼ばれたときの 2 層目）。`app.approval_queue_all` の行を `kind` で絞り、並べる：`due`＝今の並びのまま／`waiting`＝`created_at` の新しい順（新しく承認待ちになった物が先）・同じなら `id`／`title`＝`title` の順・同じなら `id`（文字の並びは DB の既定のまま）。`p_offset` 件を飛ばし `p_limit` 件（1〜200）を返し、続きが在れば `more`。`counts` は絞る前の全体の数（`app.approval_queue_counts` と同じ）。1 回の読みで束ねる
- **文の数を増やさない**（K-234・K-236・k237 の台帳 8 文・取引 1）：付けない要求は、今の「数を読む 1 文」`select app.approval_queue_count()` を `select app.approval_queue_counts() as c` に替えるだけ（文の数は同じ）。付けた要求は、読む前の片付け 1 文のあと `select app.approval_queue_page(…) as v` の 1 文だけ（今より少ない）
- 上限：絞る・並べるときの 1 回の読みは最大 1000 件（`app.approval_queue_all` の `p_max`）。1 人の承認待ちがそれを超えることは今の想定に無く、超えたときは頁が 1000 件まで・`artifact`・`handover` の数が 1000 件分までになる（`total` は正しい）。リスクに書いた
- 続きの鍵の取り違え（付けた要求の鍵を付けない要求に・その逆・壊れた鍵）は 422（欄 cursor・「続きの印が不正です」・今の文）。`kind`・`sort` が付いたときの鍵は `o|<0 以上の整数>` だけ。入口は鍵を base64url の形だけ確かめる（今のまま）
- 関門の宣言は無し（`choke_none`：読むだけ）。口の登録は直さない（`approveHooks` の `listApprovalQueue` は今のまま・中身だけ `queue.ts` が変わる）。材料は `pool` だけ
- 送る量・uuid・上限の入口の共通の確かめ（K-144）と同意し直しの止め（K-53）はそのまま
