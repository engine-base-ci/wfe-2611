## 目的

グループの一覧の口 listScopes の契約には問い合わせ `layer_id`（その層のグループだけに絞る）が在るのに、口（K-60 が作った）は読まずに全部を返している。絞ったつもりの画面に全部を見せてしまう。前の切りで一覧の口のチケット（K-92）が「誰も持っていなかった機能」として足していた受け持ちを、口が違うので 1 本に分けた（PM の決め・番号は PM が渡した）。

## 完了の条件

- [ ] 下の 5 行（K249-API-001〜005）が本物の DB の上で緑
- [ ] チケットの CI が緑

## 前提と制約

分類: LIST, PERM

- 先に要るチケット：K-60（listScopes・取り込み済み）・K-213（親の並び）
- 見える範囲は今の行の守りのまま（見えるグループだけ）。層の絞り込みは見えるグループの中で効く
- 入口が uuid を確かめる（D-129.42）。uuid でなければ 422
- 試験を書いた後は変えない（D-128.125）

## 確かめたこと（切る段・2026-11-16）

1. 契約：05_flow/screen_api.py 304 行（GET /scopes・行為 A117）。問い合わせ layer_id は契約に在る（build_api.py 916 行・registry の uuidParams）。口の持ち主は K-60（生成した試験 get_scopes.test.ts も K-60）なので、このチケットの apis: には書かない（既にある口の振る舞いを足すだけ）
2. 口：apps/api/src/features/F4/create-ticket/hooks.ts の listScopes は `a.repo.table("scopes").list(a.ctx, { limit: LIST_MAX })` で全部を読み、layer_id を見ていない
3. 表：scopes.layer_id（migration 0002）・layers（tenant_id・key・label・order_no）

層の絞り込みを読まずにグループを並べる口のコード（このチケットが直す 1 か所）：

```search
git grep -n 'table("scopes").list(a.ctx' -- apps/api/src
1
```
