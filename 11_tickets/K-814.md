## 目的

メンバーの 1 人の画面の「一時的に止める」「戻す」（下絵 md-suspend・md-resume）が呼ぶ 2 つの口を作る。

- `suspendMember`（POST /api/v1/members/:id/suspend）：その人を一時的に止める。**入れなくなり、分身（その人の PC の AI）も動かなくなる**。担当はそのまま（D-154.20・下絵の字「担当はそのままです」）。**止めた瞬間に、その人の画面・PC・API のセッションを全部切る**（G-14・D-125.140）
- `resumeMember`（POST /api/v1/members/:id/resume）：止めた人を戻す。入れるようになる（**切ったセッションは戻らない**ので、本人は入り直す）

どちらも本人確認の取り直しが要る（契約の `stepUp: "always"`・D-154.18）。画面は今の取り直しの小窓（`features/F1/security/step-up.tsx`・パスキーは `passkey.ts` の `stepUpWithPasskey`）で取り直し、通ったら 1 回だけやり直す（K-363 と同じ形）。**外す・抜けるのセッションの切り方は、この葉の共通の関数 `app.admin_cut_sessions` を使う**（外す・抜けるの消す関数 K-849 は理由だけ変えて呼ぶ）。

口の登録・断る番号（errors）は K-800 が持つ。入力と答えの形は K-800 の「契約」の節で決めた形で、この葉の口の分をこの葉が契約（.d）に書く。この葉は `members/suspend.ts`・`members/resume.ts` の空の形を本物にして `ready = true` にする。

**画面が使う答えの形**（K-821 が使う）：どちらも 200 `{ data: MemberStateChanged }`・鍵はちょうど 3：member_id・suspended（真偽）・suspended_at（ISO 8601 か null）。画面は答えで帯と「戻す」を出し分け、一覧と 1 人の画面を読み直す。

## 前提と制約

分類: PERM, CRUD

- **だれが呼べるか**：契約の PERMS のまま（members の edit・会社全体＝管理者の束と個別に付けた人。マネージャーは呼べない・D-128.97）。入口が先に 403。DB の関数も頭で `app.admin_lock()` の後に `app.admin_can('members', 'edit')`（K-800 の決めの順・守りは入口と関数の 2 層）。体は受けない（空）。**「members の edit を個別に付けた人」の行（K814-API-011）と、最後の管理者の 409（K814-API-004）は DB の守りとして残す**：人ごとの「できること」を作らない（D-154.10）ので製品の画面からは個別に付けられず、最後の管理者の 409 に届くのは管理者でない人に個別に付けたときだけ（ほかの管理者が呼べば相手は最後にならず、自分は E-MEM-005 が先）。製品の道では出ない番号だが、関数の守りとして行を残す（試験は DB に直に入れた権限の行で確かめる）
- **相手**：`app.admin_target`（K-800）が null なら 404・E-MEM-002（無い・別の会社・外した・消した・AI。欄・details なし）。止める相手は state が active（止めている人を止める → 409・E-MEM-009）、戻す相手は state が suspended（止まっていない人を戻す → 409・E-MEM-010）
- **止められない人**：**自分**→ 409・E-MEM-005（「自分は止められません。抜けるのは自分の設定から」）。**最後の管理者**（`app.admin_is_last_admin`・止めた管理者は数えない）→ 409・E-MEM-004。戻すに自分・最後の管理者の条件は無い
- **止める中身**（1 取引・**セッションを切るのは状態を書くより前**＝D-154.33）：① `app.admin_cut_sessions(p_member, 'suspended')`：その人の生きているセッションを**全部の種類**（web・bridge・api）で失効（revoked_at・revoke_reason_id 'suspended'・`app.revoke_all_sessions`＝0004 を呼ぶ）し、**その人の PC の仕事**（bridge_jobs の state_id が queued・running・asking（確認待ち）のどれか）を cancelled にして `stopped_reason` に人に見せる文を入れる。文は理由で分ける：止める（p_reason 'suspended'）は「担当の人が一時的に止められたので、この仕事はやめました」、外す（'member_removed'・K-848 → K-849）は「担当の人がワークスペースから外されたので、この仕事はやめました」、本人が抜ける（'member_left'・K-838 → K-849）は「担当の人がワークスペースを抜けたので、この仕事はやめました」（代表の答え 29536ded573d・b9c92c9eccf3・e0920e503c99。確認待ちも止めるのは、戻した後に古い確認に答えられないように）。終わった・止まった・やめた仕事は触らない。答えは `{sessions_cut, jobs_cancelled}` の件数 ② members.suspended_at を今に・suspended_by を呼んだ人に（`members_suspended_ck`：両方そろえる・0078）③ tenant_memberships.status を 'suspended' に（行がある人だけ）④ 証跡 `member.suspend`（payload は `{sessions_cut, jobs_cancelled}` の件数だけ）。**順の訳**：③ の status の更新で役割の束の引き金（0080 `tenant_memberships_bundles` → `app.apply_role_bundles`）が束の権限の行を消し、その削除で権限の引き金（0004 `permissions_revoke_sessions`）が理由 `permission_changed` でセッションを先に全部切る。① を後に置くと、切る時点で生きているセッションが 0 になり、理由 suspended の件数が数えられない（K814-API-002）
- **戻す中身**（1 取引）：members の suspended_at・suspended_by を空に・tenant_memberships.status を 'active' に・証跡 `member.resume`（payload は空の `{}`）。status を active にすると、役割の束の引き金（0080）が束の権限の行を作り直す（戻した人はまた操作できる・K814-API-008）。**切ったセッションは戻さない**（入り直し）・取り消した仕事は戻さない
- **入れなくなること**：止めた人のログインは、ログインの門（0108 `app.login_gate` が members.suspended_at と所属の status suspended を見て 'member_suspended' を返す）が断る。この葉は門を変えない。入口の「止められた人」の扱い（各関数が 403）も変えない
- **担当・所属はそのまま・束の行は止めている間だけ無い**（D-154.33）：止める・戻すで tickets の担当・scope_memberships・個別の権限の行（bundle_role が null）は変えない。役割の束の権限の行（bundle_role あり）は、止めている間は束の引き金 0080 が消し（status が active でない人には作らない）、戻すと作り直す。どちらも止めた人の行だけで、ほかの人に効かない
- **同時**（D-154.21）：`app.admin_lock()` で順に通す。同じ人を 2 人が同時に止めても、後の 1 本は前の確定を待って 409・E-MEM-009（証跡 1 行）
- **記録は追記だけ**（D-154.25）：`member.suspend`・`member.resume`（名前・メールを入れない）
- 入口の共通が先に効く：401・429・同意し直し 403・本人確認 403・道の id の形 422・NUL 422
- 断る番号は控え帳どおり（404 は欄・details なし／409 は欄・details なし／503・E-PAGE-003）

## リスクと懸念

- PC の側が止められた人の印をいつ断るか：PC は次の取りに来る要求で、PC の印の確かめ（`app.bridge_device_check`・段 4 の `20261119120300_device_browser_check.sql` の系）がセッションの失効を見て断る。動いている最中の仕事は、PC 側が結果を返すときに断られ、cancelled のまま残る。作る段で `apps/bridge` の取りに来る間隔（今の値）を確かめて、止めてから PC が止まるまでの上限をこの md の申し送りに書く
- 運営（F12）の「止める」と会社の管理者の「止める」は別の物（members.suspended_at を共有する）。運営が止めた人を管理者が戻す・その逆の整合は F12 の葉で決める（この葉は members.suspended_by が自分の会社の人かだけ見る＝見ない）
