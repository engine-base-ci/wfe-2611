## 目的

自分の設定 › プロフィールの顔（下絵 me-avatar）が使う口。画像を 1 つ受け取って置き場に置き、自分の顔にする。「文字に戻す」も同じ口（右上の顔・メンバーの一覧・分身の部屋に出る）。

- 写真を置く：`multipart/form-data` の `file` 欄 1 つ（ロゴの口 K-828 と同じ受け方・K-828 が契約の入口に足す multipart の道を通る）
- 文字に戻す：`reset=true` の欄だけで `file` なし（契約に新しい口を足さない。写真を消す DELETE は作らない）

**画面が使う答えの形**（K-839 の正）：201 `{ data: { avatar: { kind: "image"|"text", initial, url: string|null } } }`（K-833 の getMe の `member.avatar` と同じ形）。画面は答えで顔を差し替え、読み直さない。大きすぎる誤りの字は E-ME-010（下絵 me-avatar の字「写真は 5 MB までです。小さい写真を選んでください」）。

## 前提と制約

分類: FILE, PERM

- 入口の権限は本人だけ（契約のまま・member の束）。会社・人を指す欄を持たない。**顔の写真は今いる会社の自分の行（members.avatar_ref）だけ**に効く（置き場が会社ごとのため・K-833 の読む口は今の会社の行の avatar を返す）。同じログインの別の会社の行・ほかの人の顔は変えない
- **種類は中身の先頭の印（マジックバイト）で見る**：PNG（89 50 4E 47 0D 0A 1A 0A）・JPEG（FF D8 FF）・WebP（`RIFF` ＋ 4 バイト ＋ `WEBP`）だけ。content-type と名前は信じず、ファイルの名前は ref にも使わない。SVG・GIF・空・画像でない物は 422・E-ME-011。見分ける関数は K-828 が置く `apps/api/src/features/F10/image-kind.ts` の `imageKind` を使う（この葉は作らない・変えない）
- **契約の入口**：op.ts は今、体を 1 MB までの字として読み JSON で読むので、このままでは 5 MB の写真は入口で 413・multipart は 422・バイトが壊れる。K-828 が足す multipart の道（hooks の `multipart: { maxFileBytes, tooLarge }`・入口がバイトのまま `maxFileBytes ＋ 64 KB` まで読み、FormData を `HookArgs.form` で渡す・JSON と strict の形を飛ばす）をこの口も使う
- **大きさは 5 MB（5×1024×1024 バイト）まで**。判定は**ファイルの大きさ**（`file.size`）で行う：ちょうどは通り、+1 は 413・E-ME-010。体全体の長さは境の印と頭の分だけ長いので、体の先の確かめ（入口・読み切らない）は余白つき（5 MB ＋ 64 KB・超えたら hooks の tooLarge＝413・E-ME-010）。ファイルの大きさは種類より先に見る
- **体の形**：`file` か `reset=true` のどちらか 1 つ。どちらも無い・両方・reset が `true` 以外の字は 422（欄 file）
- **置き場は関門 C4**（`objects.put`）：置けなければ 502（E-ME-012）で avatar_ref を変えない（前の顔のまま）。画面の字（下絵に無いので仮）：「写真を置けませんでした。少し待ってやり直してください」
- **順番**：置く → DB の取引（avatar_ref を新しい ref に・前の ref を返す）→ 前の実体を消す（後片付け）。DB が落ちたら置いた新しい実体を消して 503（E-PAGE-003）。前の実体を消せなくても 201 のまま（ログに 1 行 `[me-avatar] 前の写真を消せなかった`・宛ての値は出さない）。文字に戻すは DB（avatar_ref を空に）→ 前の実体を消す
- **同時の置き換え**は自分の行の更新で順に通る。残るのは後に通った方
- **記録**：顔の保存は会社の記録（audit_events）に載せない（K-833 と同じ・D-154.55）
- 外に出す期限つき URL は読む口（K-833）が作る。この口の答えも同じ作り
