## 目的

実ブラウザの試験（Playwright）は act の容れ物の中で画面無し（headless）で動くので、決める人が見られない。決める人（2026-11-09）：「僕も実機の操作のテストは僕自身でも人間でもするので、そこがわかる表もちゃんと作っておいて。動作テストがいる場合の時だけでいいので、人間が確認できる同じようなテスト項目をずらっと並べて、あなたと僕とがそれぞれ同じテストを進めるみたいな感じで」。

人が手で触って OK／NG を付ける正本は Google スプレッドシート「確認」（1 タブ＝1 チケット・`scripts/ci/build_qa_xlsx.py` が作る xlsx を取り込んで育てる）。いまの作り手は 10 月の手順ファイル（07_tasks/handoff/T-A-xx.md）を源にしていて、K-51〜K-65 の実ブラウザの試験の行（07_qa/test-specs/k/*.md の K*-UI-*・歩く骨格の中間テスト K54-M1／K58-M2／K64-M3・統合テスト K65-INT）が載っていない。機械の結果の欄も無い。

## 完了の条件

- [ ] 源を仕様の表にする：07_qa/test-specs/k/*.md と journeys の行のうち、実ブラウザで人が同じ操作をできる行（操作手順と期待結果がある K*-UI-*・K*-M*-*・K*-INT-*。口だけの行 K*-API-* と「操作要素の漏れ」の機械だけの行 *-000 は載せない）を、使う流れの順（flow.json の背骨・build_qa_xlsx.py の既存の並べ方）に 1 タブ＝1 画面（か 1 チケット）で出す
- [ ] 列：ID／画面／前提条件／操作手順／期待結果／**機械の結果**（07_qa/ci-results の記録から：PASS・FAIL・未実行と、CI の回の印と日付・K-143 の ci_results.py を読む）／**人の結果**（OK・NG・未）／人の気づき／確かめた日・名前。機械の列は手で書かない（CI の記録から機械で埋める・D-129.51）
- [ ] 「はじめに」のタブに、立ち上げ方（手元の URL・試験用の人のログイン・Bridge の有無）と、表の読み方（機械と人の結果が違う行が見つけもの）を書く
- [ ] 前に書かれた人の結果・気づき・列幅・タブ名を引き継ぐ（`--out` に今のシートの xlsx を渡す既存の形。消さない）
- [ ] 機械と人の結果が違う行を数えて「はじめに」に出す（これが実機でしか出ない欠陥の候補・L-003）
- [ ] 作り手の試験：UI の行だけが載る・API の行は載らない・機械の結果が記録どおり・前の答えが残る
- [ ] PM が Google シート「確認」に取り込む手順（memory の sheet-edit-in-place・File → Import → Replace spreadsheet）を 07_tasks/handoff/README.md に写す（PM の手順は版に入れる）
- [ ] チケットの CI（act）が緑

## 前提と制約

分類: TOOL

- 対象は「動作テストが要る行」だけ（決める人の言葉）。口の試験・静的検査は載せない
- Google のシートへの取り込みは人（PM）が手でする（Drive の API で xlsx を上げると壊れる・memory）。このチケットは xlsx までを機械で作る
- 見込みは列に入れるときに、直近の取り込みの実測から引いて書く
