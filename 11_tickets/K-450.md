## 目的

項目の表の「確認項目」（終わったときに確かめること）を本物にする。行は **確かめること（文）とチェックの箱だけ**（D-150.39）。人も AI も足せる行で、種類（機械・AI・人）・判定の型・設定値・使わない（OFF）・抜けの点検は無い（D-150.39・D-150.45）。行為 A102。

- 正の絵は下絵 v2 の `/dev/mock/f4v2/f4v2-specs`（詳細のパネルで開いた形）・`f4v2-spec-add`（足す小窓）と、作る面の項目の表の中の「確認項目」。2026-11-22 に下絵へ足された 3 つもこの葉が持つ：`f4v2-spec-edit`（行の文をその場で直している・チェックの付いた行は直せない）・`f4v2-spec-add-error`（足す小窓・書かずに足した）・`f4v2-create-specs`（作る面の確認項目・チェックの箱は押せない形）。部品は K-431 が運ぶ `features/F4/doc/views.tsx` の `SpecsItem`・`detail-views.tsx` の `SpecAddDialog`（見た目だけ・書き換えない）。字・並び・ボタンは下絵が正：0 件の文「確認項目はまだありません。足すと、終わったときに機械と人が確かめます」・行＝チェックの箱＋確かめること＋「外す」・「＋ 確認項目を足す」・「AI の案を出す」（押せない形）
- **2 つの形で使う**：
  - **作る面**（まだチケットが無い）：行は画面の中だけに持ち、口を呼ばない。作るとき `specs`（文の並び・足した順・0〜50 件）で送る（K-437）。チェックの箱は押せない形（作る前に確かめた事は無い）。50 件に達したら足せない
  - **詳細のパネル**：閉じた形は「N 件 ・ 開く」だけ（N は getTicket の `spec_count`・K-560）。**開くとき 1 回だけ** `listTestSpecs` を読む（開くまで口を呼ばない＝詳細の口の数を増やさない）。開いたあとは閉じない。足す・チェックを付ける・外す・文を直す・行を外すは、`meta.can_edit` が true のときだけ。完了したチケットは `can_edit` が false で全部押せない形
- **文を直す入口**（下の「代表に聞くこと」の勧めで切った）：行の文の字を押すと、その場で入力に替わる。Enter で決める・Esc でやめる。**直せるのはチェックが付いていない間だけ**（D-150.55）。チェックが付いた行の文は押せない形（付いた後は外してから直す）
- **断り**：完了したチケット（409 E-SPEC-001）・先に変えられた（409 E-SPEC-020・画面は読み直す）・チェックが付いた行の文を直そうとした（409 E-SPEC-021）・出どころ `knowledge` の行の文を直す／外す（409 E-SPEC-022・押せない形で先に止め、古い画面で押したときだけ口が断る）・書けない人（403）・行やチケットが無い（404）・読めない・503・0 件・50 件の上限（作る面）。出す場所は下の「前提と制約」

- **作る面・詳細の前からのファイル（`features/F4/create-ticket/*`・`ticket-detail.css`）には触らない**（決め：K-442 が作る面を、K-571 が詳細を丸ごと作り直し、前からの画面の試験の持ち主もその 2 本。K-569 と同じ決め）。この葉は部品 `SpecsItem` を `features/F4/specs/` に作り、**動くことは開発用の置き場の頁 `/dev/f4-specs`（この葉の changes・実ブラウザの試験が開く）で確かめる**。K-442（作る面）は K-569 の `ItemsTable` の `slots.specs` に `<SpecsItem mode="create" …/>` を、K-571（詳細）はパネルの区画に `<SpecsItem mode="detail" …/>` を組む（両方ともこの葉に依存する）。作る面の古い箱 `SpecBox`・前の `features/F4/test-spec/` は K-431 が外す

- **口**：`listTestSpecs`（GET /api/v1/tickets/:id/test-specs・答え `{ data: SpecItem[], meta: { count, limit, can_edit } }`・K-434）・`createTestSpec`（POST 同じ道・体 `{ title }`・201 `{ data: SpecItem }`）・`updateTestSpec`（PATCH /api/v1/test_specs/:id・体 `{ version, checked }` か `{ version, title }`・200 `{ data: SpecItem }`・K-435）・`deleteTestSpec`（DELETE /api/v1/test_specs/:id・200）。`SpecItem = { id, title, checked, position, source, version }`（鍵 6：K-434 の答えに `version` が足される・まとめ役が K-434・K-435 に合わせる）。画面は行の `version` を覚えて直す口に送り、答えの行で更新する（答えの `version` が次の送る版）

- **断りの出し分け**（段 9 の D-148.30〜38 の分け方）：足す小窓の中は、422 を欄の下の赤い字・403・404・409 E-SPEC-001・503 を小窓の上の赤い箱（書いた中身は残る・小窓は開いたまま）。行の操作（チェック・直す・外す）の断りは 5 秒で消える小さな知らせ：409 E-SPEC-001（完了）と 403（書けない人・「この操作をする権限がありません。権限が変わったかもしれません。画面を読み直してください」）と 503（E-PAGE-003 の文）は行を変えず、409 E-SPEC-020（先に変えられた）・409 E-SPEC-021（チェックが付いた行の文）・409 E-SPEC-022（`knowledge` の行・口の答えの正本の文を出す）・404（行が先に外された・正本 E-PAGE-001 の文）は知らせたうえで**一覧を 1 回読み直して**最新の行を出す。直している文の入力は、020 では開いたまま残す（行はまだ直せる）・021・022 では閉じて文のボタンを押せない形で出す・404 では行ごと消える。409 E-SPEC-001 と 403 では入力を閉じ（直せない）、503 では開いたまま残す（もう一度決められる）。文は全部 `07_qa/test-specs/errors.json` の正本のまま（画面で作らない）
