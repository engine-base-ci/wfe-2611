## 目的

2026-11-14 に PM が確かめた事実：GitHub の main に入るたびに、Vercel の 2 つのプロジェクト（kaname-api・kaname-web）が commit status「Deployment was blocked」（failure）を返していた（`gh api repos/engine-base/Kaname/commits/<sha>/status`）。2 日分・約 30 本のチケットが 1 つも staging に配られていなかった。

訳は 2 つあった（PM が 2026-11-14 に確かめた）：

1. **名義**：コミットの名義（author）が、Vercel のチームに入っていない利用者（個人の GitHub の利用者）だった。チームに入っているのは組織の利用者だけ。11/2 頃までのコミットは組織の名義（メールの @ の後ろが engine-base.com）で、その後、作業フォルダの git の名義が個人の物に変わっていた
2. **上げる先の枝**：Vercel が本番として見ている枝は GitHub の `claude/modest-lamport-77ue02` で、取り込みは GitHub の `main` にだけ上げていた（`ticket-flow.yaml` の `remote_mainline: main`）。main はプレビュー扱いで設定が無く、組み立てが失敗していた

配りが止まっても CI は緑なので、だれも気づかなかった。

PM は 2026-11-14 に、このリポジトリの git の名義（local の user.name・user.email）を組織の物に替え（作業場所は設定を共有する）、K-201 の 2 本（組織の名義・`Co-Authored-By:` の行つき）を Vercel が見ている枝に上げた。口・画面とも配られた（Ready）。Vercel の「Ignored Build Step」も 2 つのプロジェクトに入れた（本番の環境の回だけ組み立てる。プレビューは飛ばす）。

**このチケットが止めるのは訳 1（名義）だけ**。訳 2（上げる先の枝）は別のチケット K-207。この検査が緑でも、訳 2 だけで配りは止まる。

このチケットは、名義がまた変わったときに、GitHub に出す前に機械で止める：本線との差分のコミットの author のメールが、決めたドメインで終わらなければ赤にする検査を、CI の static の組に足す。
