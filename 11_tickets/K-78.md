## 目的

staging の DB とファイルの置き場を用意する（infra/STAGING.md S1）。

## 完了の条件

- [ ] Supabase のプロジェクト `kaname-staging` が東京にある
- [ ] Session pooler の接続（migration 用）と Transaction pooler の接続（実行用）を控えた
- [ ] S3 の鍵を作った
- [ ] 値は Vercel の API のプロジェクト（K-80）に入れる準備ができた（値はここに書かない）

## 前提と制約

- 料金：Free で始める。顧客のデータを入れる前に Pro（月 25 USD 前後）
- Direct connection は IPv6 だけで Vercel から届かないので、全部 pooler を使う
- 鍵・パスワード・接続文字列の値は、チャット・ファイル・コミットに書かない。入れる先は Vercel の環境変数（Sensitive）か Infisical だけ（infra/STAGING.md §1）

## 実施事項

1. https://supabase.com でプロジェクトを作る（名前 `kaname-staging`・Region `Northeast Asia (Tokyo)`・Free）
2. Connect → **Session pooler**（:5432・ユーザー `postgres.<ref>`）を `DATABASE_ADMIN_URL` 用に控える
3. Connect → **Transaction pooler**（:6543）を、ユーザー名を `kaname_app.<ref>` にして `DATABASE_URL`、`kaname_auth.<ref>` にして `AUTH_DATABASE_URL` 用に控える（パスワードは K-80 で作る乱数）
4. Storage → Settings → S3 Connection → S3 access keys を作り、`STORAGE_ACCESS_KEY_ID`・`STORAGE_SECRET_ACCESS_KEY`・`STORAGE_ENDPOINT`（`https://<ref>.storage.supabase.co/storage/v1/s3`）・`STORAGE_REGION` を控える。`STORAGE_BUCKET=kaname-staging`・`STORAGE_FORCE_PATH_STYLE=true`
