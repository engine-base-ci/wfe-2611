## 目的

パスキーか、パスワード＋2 段階のコードで本人を確かめ直し、セッションに時刻を付ける（15 分効く）。いつも要る口・条件つきの口はこの時刻を見る（KN-51）。

## 完了の条件

- [x] パスワード（＋2 段階を使う人はコード）で確かめ直せ、セッションの step_up_at が付く
- [x] 間違えたら 401 で時刻は付かない。回数の上限（契約の 60 回／分／人）で止まる
- [x] 契約の入力の形がパスワード・コードになっている（StepUpInput。SessionsInput ではない）
- [ ] CI が緑（手元で確かめた。GitHub の結果は push 後に見る）

## 前提と制約

- 暗号の中身は Better Auth に任せる（D-128.91）

## 実施事項

- [x] 契約の入力（StepUpInput：password・code）。表の行ではない入力の形を 05_flow/screen_api.py の INPUTS に書けるようにした
- [x] hooks（apps/api/src/hooks/auth.ts）：Better Auth の verifyPassword、2 段階を使う人は verifyTOTP。結果は app.record_step_up（0083）で security_events に残し、通ったらセッションに時刻
- [ ] パスキーの確かめ直しは画面の土台（KN-5）と一緒に（ブラウザの WebAuthn が要る）
