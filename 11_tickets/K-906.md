## 目的

ゲスト（役割 requester）が先方の場所（/portal）で見る物を返す 3 つの読む口を作る（D-155.37・D-155.41）。**チケットはチケット。特別扱いしない。新しいのは「ゲストが見られるか」だけ**：見えるのは、自分のゲストのグループの依頼と、**見せる相手に自分のグループが選ばれたチケット**の題・本文・詳細・チャットと段の札 3 つ（作っている・確認中・完了）だけ。期限・担当・確認項目・決定ログ・分身の記録は返さない。確認してほしいもの（検収）は作らない（D-155.44）。

- `getPortalHome`（GET /portal）：ゲストのグループの名前・本人の表示・初めてか・グループの依頼の一覧・見せてもらったチケットの一覧
- `getPortalTicket`（GET /portal/tickets/:id）：見せてもらったチケット 1 件（題・段の札・本文・詳細・チャット）
- `listPortalNotices`（GET /portal/notices）：運営からの全部向けのお知らせ（障害・保守）

前からある 3 つの口の行（取引先の形・`to_review`・`due_on`・`artifacts`）を、芯の形に作り直す。画面は K-911（ホーム）・K-913（見せてもらったチケット）。依頼 1 件を読む口は K-907、チャットに書く口は K-882。

## 前提と制約

分類: PERM, LIST

- **見えるか見えないかは K-881 の `app.guest_sees_ticket(tid)` だけで決める**（見せる相手の行・消していない・下書きでない）。この葉は新しい見せ方を持たない。依頼から作ったチケットも同じ（特別な枝は無い・D-155.42）
- **ゲストでない人は 403**：`app.guest_ok()`（K-878）が false（役割 requester でない・グループに入っていない・止めた・抜けた・グループが消えた）なら、3 つの関数とも 42501 を返し、口は 403・FORBIDDEN に倒す（G-14：毎回その時の所属を見る）。社内の人（role member）は入口の 403・ログインしていなければ 401（K-878 が守る柵のまま）
- **読めるのは関数の口だけ**：関数は security definer。ゲストの文脈で `ticket_sections`・`notices`・`ticket_messages`・`client_request_messages` を直に読んでも 0 行（行の守りを足さない・K906-API-022）
- 返す字の絞り（二次の守りは画面・K-913）：チケットは `id・title・stage・body・detail・from_request` だけ。`assignee`・`due_on`・`priority`・確認項目（test_specs）・決定（ticket_decisions）・成果物・分身の記録は鍵も字も返さない。関数が欄を決めて組み立てる（行をそのまま返さない）
- 段の札：社内の段のキーを 3 つにまとめる。`done`→「完了」・`checking`・`awaiting_approval`→「確認中」・それ以外（`todo`・`doing`・`hold`・`running`・鍵の無い会社の自分の段）→「作っている」
- 本文は鍵 `body` の区画の `text`・詳細は鍵 `detail` の区画の `text`（区画が無ければ空の字）。**チケットの本文の区画の鍵 `detail` を「詳細」とする**（D-155.54 PM の決め。いまの DB に詳細を書く画面は無いので、無ければ空で返す。K-905・K-913 も同じ決めに合わせる）
- チャット：K-882 が作る関数 `app.portal_ticket_messages(チケット)` の答えをそのまま `messages` に入れる（ゲストに見える印 `ticket_messages.guest_visible` が true の post だけ・古い順・1 件ごと `{ id, side, name, at, text }` に、**依頼から来た書き込み（`from_request` が true）の行にだけ `from_request: true`** が付く＝K-882・まとめ役の決め 1。`side` は書いた人の役割が requester なら `they`・それ以外は `we`。変更・仕組みの書き込みと、見せない書き込みは出ない・別のグループのゲストの書き込みも出ない）。この葉は選び方を持たず、関数の答えを返すだけ
- `first_visit`：本人が先方の場所を初めて読んだとき true を返し、同じ取引で証跡 `portal.first_visit`（payload は空）を 1 行書く。2 回目からは false で何も書かない。書けなかったら 503・E-PAGE-003 で、証跡も残らない（次の読みでまた true）
- 依頼の札（`badge`）：チケットになる前は、いちばん新しいやり取り（K-892 の `client_request_messages`）が会社の側（`side = company`）なら「返事あり」・ゲストの側（やり取りが 1 件だけも）なら「受付済み」。チケットになった・断った依頼は「済み」
- お知らせ：公開済み（`state = published`）・消していない・全部向け（`target_tenant_id` も `target_plan_ids` も空）・`placements` に `banner` を含み・保守の終わり（`maintenance_to`）が過ぎていない物。新しい順・3 件まで。字は `id・title・body`（運営のメモや本文のほかの欄は返さない）
- 認証の要る答えは `Cache-Control: private, no-store`（K906-API-001・013）
- 関門の宣言（頭の欄 choke_points）は [C2]（`first_visit` の証跡を DB に書く。読む口なので外へは出さない）
