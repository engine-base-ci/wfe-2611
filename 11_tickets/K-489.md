## 目的

契約の口 `restoreTicket`（POST /api/v1/tickets/:id/restore・今は 501）を作る。消したチケットを `deleted_at` から 30 日以内（`restorable_until`）なら戻す（D-128.84・D-128.116・PM の決め P7）。完全に消す（30 日後）は作らない（時間で動く仕組みが無い）。30 日を過ぎた物は戻す口が断る（409）。

- **戻せる人**：消した本人（今の権限が変わっていても）と、そのグループのマネージャー・会社の管理者（`app.manages_scope`）。edit は要らない
- **一緒に戻る物**：cascade で一緒に消えた子・孫（親と同じ `deleted_at`・`deleted_by` の物）。別の時に消した子は戻さない
- **戻さない物**：子の付け替え（move・detach）・取り下げた承認・止めた AI の実行・取り消した渡し（戻した後に人がもう一度頼む）。添付・成果物・つながりは消していないのでそのまま見える
- 親が消えている子は、先に親を戻す（409）
- 消した直後の「元に戻す」（K-590）はこの口を呼ぶ。記録 › 消した の画面は F10

入口の行の確かめ（契約の perm.row）は、消したチケットが行の守りで見えないため必ず 404 になる。**この口だけ入口の行の確かめを外し**（`scripts/ci/row_rules.mjs` の除外・前の道の除外の表と同じ作り）、戻せる人と見える・見えないは DB の関数と口が持つ。答えは `{ data: { id, restored_count } }`。消す口は K-488、画面は K-590。

## 前提と制約

分類: CRUD

- 戻す順の決まり（DB の関数の中・先に当たった物で答える）：① 同じ会社に行が無い → 404 ② その人にグループが見えない（`visible_scopes`・消した本人でもない）→ 404（別の会社・見えないグループ・無い id と同じ答え。消した物が有ることも漏らさない）③ 消した本人でもグループのマネージャー・管理者でもない → 403・E-DEL-040 ④ 消えていない → 409・E-DEL-041 ⑤ `deleted_at + 30 日 < now()` → 409・E-DEL-042 ⑥ 親が消えている → 409・E-DEL-043 ⑦ 戻す
- 一緒に戻すのは「再帰で子孫をたどり、`deleted_at` が同じで `deleted_by` も同じ」物だけ（cascade は 1 つの取引で `now()` が同じ。K-488）。孫の親が消えていないか（途中が別の時に消えていないか）はたどる途中で切れる（別の時に消した子から先は戻さない）
- 戻したら `deleted_at`・`deleted_by` を空に、`updated_by` を戻した人に。番号・題名・親（付け替えていなければ元の親）・担当者・段は変えない。段が実行中のままの物は無い（K-488 が消すときに作業中に戻す）
- 入口：`scripts/ci/row_rules.mjs` に `OP_ROW_EXEMPT = { restoreTicket: "理由…" }` を足し、`rowOf` の頭で「その口は null（行を読まない）」にする。**既にある `ROW_EXEMPT`（道の頭で引く）と別の 2 つ目の表になるので、「道の頭で書けない口だけを `OP_ROW_EXEMPT` に置く」と `row_rules.mjs` の注に 1 行残す**（除外の表を継ぎ足さない・L-021。`authz.test.ts` の `EXEMPT_OPS` と口の名前が 1 対 1）。理由の文は「消したチケットは行の守りで読めず、入口で行を読むと必ず 404 になる。戻せる人と見える・見えないは DB の関数 app.ticket_restore と口が持つ（K-489）」。契約を作り直すと `restoreTicket` の `perm.row` は null になる。`apps/api/src/contract/authz.test.ts` の「行に結ぶ口で :id があるものは全部…持つ」は除外の表（EXEMPT）に口の名前の除外 `EXEMPT_OPS = ["restoreTicket"]` を足す（切る段で書き替えた・carry）
- 権限の言葉は PERMS のとおり `assignee` のまま（入口は社内の人であることだけ見る）。説明の文を「消した本人と、そのグループのマネージャー・管理者（D-128.84）」に直す
- 関門の宣言は [C2]。外には出ない。口の登録は葉ごとの hooks のファイル（K-326）：`ticket-restore.ts`。材料は `d.appPool` だけ。共通の小さな部品は K-487 の `shared.ts`（`RESTORE_DAYS`・`forbidden`・`notFound`・`down`）を使う（403 の文だけ E-DEL-040 の別の形にする）
- 体は空（strict）。知らない項目は入口が 422。完全に消す・復元の期限を伸ばすは作らない

## リスクと懸念

- 完全に消す（30 日後）が無いので、戻せる期限を過ぎた物は DB に残ったままで、口からは戻せず見えない。誰も触れない行が増える。時間で動く仕組みのチケット（後）で消す
- cascade で別のグループの子・孫まで戻る。戻す人はそのグループが見えなくてもよい（親と一緒に消えた物だから）。見えない物の中身（題名など）は答えに出さない。ただし `restored_count` は「見えないグループの子・孫が何枚戻ったか」の数だけを漏らす（数だけなので許容する・K-487 の下見の子・孫の数と同じ扱い）
