## 目的

グループを直す小窓（下絵 gr-edit：名前・マネージャー・色）と、グループの並びを替える小窓（下絵 gr-order：上へ・下へ）が呼ぶ口 `updateScope`（PATCH /api/v1/scopes/:id）を作る。**短い名前（番号の頭）・上のグループ・層は変えられない**（下絵「作ったあとは変えられません」・欄が無い）。グループは消せない（D-154.8）。

口の登録・断る番号（errors）は K-800 が持つ。入力と答えの形は K-800 の「契約」の節で決めた形で、この葉の口の分をこの葉が契約（.d）に書く。この葉は `scopes/update.ts` の空の形を本物にして `ready = true` にする。

**画面が使う答えの形**（K-806 が使う）：200 `{ data: ScopeUpdated }`。鍵は K-802 の ScopeCreated と同じ 10（id・name・ticket_prefix・color・parent_id・layer・position・managers・member_count・created_at）。画面は答えで 1 行を差し替え、並びを替えたときは並び全体を読み直す（getWorkspaceMembers）。

**グループの一覧 listScopes に足す**（画面 K-806 の並びを替える小窓・グループの小窓が読む）：listScopes は K-60 の口（`apps/api/src/features/F4/create-ticket/hooks.ts` の `listScopes`・表の行をそのまま返す）。**元の列は残し**（外枠の第 2 ナビ・チケットの作成が読んでいる）、1 件に ScopeUpdated と同じ 10 の鍵（id・name・ticket_prefix・color・parent_id・layer・position・managers・member_count・created_at）を足し、**上のグループが先・兄弟は position の順**で返す。足し方：この葉の migration に `app.scope_list_json(p_ids uuid[]) returns jsonb`（kaname_app に渡す・stable）を置き、listScopes の hook が今の行を取った後、見える id の並びで 1 回呼び、返った並び（depth・position・created_at・id の順）で `{ ...元の行, ...足す鍵 }` に組む。meta（limit・writable）・`layer_id` の絞り込み・見える範囲（行の守り）は今のまま。契約の 1 件の形は `05_flow/screen_api.d/K-804.py` に書く（K-60 の META と同じ道で足す鍵を宣言する形。作り手に足す鍵の宣言が無ければ作る段で確かめ、RESPONSES の配列の 1 件の型で足す）。

## 前提と制約

分類: CRUD, PERM, LIST

- **だれが書けるか**：K-802 と同じ（scopes の edit を持つ人・マネージャーは直せない・DB の関数も頭で見る・403・FORBIDDEN）
- **直せる欄は 4 つ**：name・color・position・manager_member_ids。**1 つは要る**（体が空は入口が 422）。短い名前・上のグループ・層・番号の次の値は欄が無く、送ると strict で 422
- **名前**：K-802 と同じ（整えた後 1〜100 文字・同じ上のグループの下に自分を除いて同名があれば 409・E-GRP-011・消した兄弟とは重なってよい）。名前を変えても短い名前・作ったチケットの番号は変わらない
- **色**：tone の鍵 6 つのどれか（teal・plum・indigo・amber・coral・sage・K-802 の `COLORS`・DB の check）
- **並び**（position）：同じ上のグループの兄弟（消していない）の中で位置を指す。範囲を超えた値は最後。動かした後、兄弟の position を (position, created_at, id) の順に 1 から振り直す（前からの 0 の行も直る）。**別の上のグループの兄弟は動かさない**。0 以下は入口が 422（欄 position）。「上へ・下へ」は隣の位置を送る・「最後に送る」は大きい値（D-154.8）
- **マネージャー**（manager_member_ids・0〜10 人）：指した人の集まりを **そのグループのマネージャー全員にする**。指した人は、そのグループの所属の行の役割を manager にする（行が無ければ兼務の行を足す・主の所属の人で行が無ければ主の行を足す）。外れた人（今 manager で指していない人）は役割を member に下げる（所属は残す）。空の配列で全員を member に下げる。**同じ人を別のグループのマネージャーにもできる**（兼務・D-154.15）。人の確かめは K-802 と同じ（`app.handover_member_state`：無い・別の会社・消した・抜けた・AI は 404・E-GRP-015、止めた・招待中は 409・E-GRP-016、閲覧のみは 409・E-GRP-017）。**1 人でもだめなら何も変えない**（1 取引）。役割の束の権限は引き金（0080）が付け替える
- **直す先が無い**（道の id が無い・別の会社・消した）→ 404・E-GRP-002（欄・details なし）
- **同時**（D-154.21）：`app.admin_lock()` で順に通す。同じ名前への同時の変更は 200 と 409・並びの同時の変更は連番が崩れない
- 入口の共通が先に効く：401・429・同意し直し 403・1MB 超 413・知らない欄 422・形の誤り 422（**欄 name・color・position・人の数・体が空は入口が VALIDATION_ERROR で先に断る**。E-GRP-001・004・005・008・009 は整えた後の値が外れた場合の後ろ盾）・NUL 422
- 関門の宣言は [C2]。メール・外のサービス・ファイル・AI は無い。**マネージャーにした人・下げた人への知らせは作らない**（決定ログに無い）
- 断る番号は控え帳どおり（404 は欄・details なし／409 は欄・details なし・detail は付ける／503・E-PAGE-003）
