## 前提と制約

- 今の staging の実際（2026-11-13・リポジトリの中だけで確かめた）
  - **コードにある**：作り方＝API の Build Command が `pnpm db:migrate && pnpm provision:bucket && node apps/api/build-vercel.mjs`（apps/api/vercel.json）。置き場の用意と非公開の確かめ＝infra/provision/bucket.ts（K-133）。API を Vercel の関数 1 本にする入口＝apps/api/src/vercel.ts。起動時の確かめ 5 つ（db:tables・storage:bucket・secrets:master-key・notify:resend・secrets:vault）。設定の名前の正本＝.env.example
  - **人の準備で済んでいる**：K-78（Supabase）・K-79（Infisical）・K-80（Vercel の API）・K-81（Resend）・K-82（Vercel の画面）は 2026-11-08 に完了（コミット bb1fdde9「/health と CORS を確かめた」）
  - **無い・分からない**：(1) staging の住所がリポジトリのどこにも無い（`git grep vercel.app` が 0 件）ので、今も立っているかを機械で確かめられない (2) 配る道すじは .github/workflows に無い（配る段は 0）。Vercel が GitHub の main を見て自分で配る形のはずだが、設定は Vercel の画面の中で、リポジトリからは見えない (3) K-133（置き場が公開なら Build を止める）が入った後の Build が通っているか分からない (4) CI から staging を指す設定が無い：.github/workflows/v3-gate.yml の e2e の組は `secrets.STAGING_BASE_URL` の 1 つだけを読み、has-ui の札の PR でしか起きず、流すのは前の画面の試験（`pnpm e2e:web`） (5) 健康診断の台本が無い：`python3 scripts/ci/pipeline-next.py check-staging` は selected-stack.json に欄があるかを見るだけで、staging には当てていない (6) K-78〜K-81 の途中でチャットに出た秘密がまだ取り替えられていない
  - **古くなった書き方**：前の完了の条件の「~/.config/act/kaname.secrets・.act-ci.env の ACT_STAGING=1」は前の CI（act）の形。今の CI は GitHub Actions を自分の Mac の上の使い捨ての Linux の VM で流す（ticket-flow.yaml の vm）。VM は組ごとに捨てるので、台にファイルを置く形は使えない。infra/STAGING.md の §0「いま無いもの」と infra/provision/README.md の「S3 Railway」も古い（K-200 で直す）
- 鍵・パスワード・接続の文字列の値は、チャット・ファイル・コミット・このチケットに書かない。入れる先は Vercel の環境変数（Sensitive）・Infisical・GitHub の Actions の secrets だけ（infra/STAGING.md §1）
- 本番の値を使わない。本番のプロジェクトには触らない
- GitHub の台（hosted runner）と有料の逃げ道は使わない（決定済み）
