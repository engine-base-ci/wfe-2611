## 目的

段 6 の 3 つの道具（K-736 の `spec_check`・K-738 の `guard_report`・K-775 の `draft_propose`）は API の側にだけ在り、**自分のAI（本人の Claude Code）にはまだ見えない**。Bridge の道具のサーバー（`kaname-tools.ts` の台本・MCP の「kaname」）に定義を足し、仕事の種類と会話の種類ごとの出し分け・断られたときの AI への文・進み具合の字を決める。契約の口・DB・道具の鍵の扱いは K-62 のまま。

- **チケットの仕事**は `ticket_read`・`spec_check`・`guard_report`（承認の後の実行も同じ。**試し打ちは `ticket_read` だけ**＝確認項目を変えない仕事）
- **作る画面の会話の仕事**（種類 `draft`）は `draft_propose` **だけ**
- **自分の AI の会話・チケットの会話・種類なし**は前の会話の道具のまま（3 つの道具は出さない。呼べない道具は見せない）
- **ログインの試し**は何も出さない（前のまま）
- 道具の入力は `spec_check`＝`spec_id`・`basis`／`guard_report`＝`spec_id`・`note`（任意）／`draft_propose`＝`title`・`body`・`checks`（どれも任意・どれか 1 つは要る＝API が見る・1 つの仕事で 3 回まで）
- **Claude を起こすときに、Claude の側へナレッジ・チケットを残させない**（代表の言葉 2026-11-22 23:00）：AI に読ませるのは制限しない（チケットの詳細・ナレッジは今までどおり読める）。ただし Claude Code の記憶（自動の記憶・CLAUDE.md・メモのファイル）に書き写して後で使い回す形を作らせない。記憶は Kaname の側だけが持ち、仕事ごとに渡す。Bridge の起こし方（引数と環境）に、自動の記憶を止める環境と、書き写す宛先を使わない道具として渡す設定を足す（下の前提と制約・実施事項）
- **PC は仕事の会話の種類を取る口の答えから知る**：`app.bridge_take_job` の答え（TS の `withExtras` が道具の鍵などを足す所）に `talk_kind` を 1 つ足す（会話の仕事は `conversations.talk_kind`・それ以外は null）。DB の関数は作り直さない。
