## 目的

2026-11-13 に段 1 の「全部の CI」（回 43418631870・本線 787b0fea）を流すと、unit-1 の組（と、分けた結果を合わせる unit の組）が赤になった。`apps/bridge/test/login-check.test.ts` と `login-check-2fa.test.ts` が読み込みで落ちる：「CI には Google Chrome が要る（Bridge のログインの確認は本人の Chrome で動く）」。

CI の台は K-173 から Mac の上の Linux（arm64）の使い捨ての VM で、元の像（K-175）に入っているのは Playwright の chromium だけ。Google Chrome は入っていない。CI の定義（v3-gate.yml）にも Chrome を入れる段は無い（GitHub の台には初めから入っていたので、要らなかった）。チケットの CI ではこの 2 本が範囲に入らないので、全部の回まで見えなかった。

このチケットですること：元の像を温める命令に Google Chrome（stable）を足す。試験と製品は変えない（本人の Chrome で動く、のまま）。あわせて「台の道具が要る試験」（道具の道を existsSync で見る試験）の一覧を置き、① 一覧に無い試験 ② 一覧にあるのに像に入れていない道具 ③ CI で道具が無いと黙って飛ぶ形の試験、を全部の回を待たずにチケットの CI の形の試験で止める。道を見ずに道具を使う試験と、台の種類（Mac だけ）で飛ぶ試験は、このチケットでは止めない（リスク・申し送り）。

## 前提と制約

分類: TOOL

- 製品のコードと 2 本の試験は変えない。Bridge は本人の Chrome で開く（`apps/bridge/src/login-check.ts` の `channel: "chrome"`）。CI で飛ばす・chromium に替える・実行ファイルの道を渡す、はどれもしない（K195-RC-002 が止める）
- CI の台は自分の Mac の VM だけ（決定済み）。GitHub の台に戻す案は出さない
- Chrome は像に入れる。組の中で回ごとに落とさない（139MB × unit の 6 組・K195-RC-006）
- 版は止めない（決めたこと）：像を作り直すたびに、その日の最新の stable が入る。本人の PC の Chrome も自分で上がっていくので、同じにする。部品の版の決まり（lockfile・21 日）は npm の部品の決まりで、台の道具は見ていない
- 入れ方は、同じ像を作る台本の docker と同じ形：公式の apt の置き場を signed-by つきで足し、apt に署名を見させる。その前に、鍵の指紋を行の中で照らす（指紋 `EB4C1BFD4F042F6DDDCCEC917721F63BD38B4796`＝Google Inc. (Linux Packages Signing Authority)。2026-11-14 に `curl -fsSL https://dl.google.com/linux/linux_signing_key.pub \| gpg --show-keys --with-colons` で確かめた）。落とした包み（.deb）を直に入れない（apt が署名を見ない）
- 入れた後に、置き場の list（`/etc/apt/sources.list.d/google-chrome*.list`。足した物と、包みが自分で足す物）を消す：組の中の `apt-get update`（web・e2e の組の `playwright install --with-deps`）が、回ごとに dl.google.com を見に行かないように
- **一覧に載せる物の決まり**：台の道具が要る試験＝試験のファイルで、道具の道（/opt・/usr・/Applications）を existsSync で見るもの。そういう試験は必ず process.env の CI を読み、CI で道具が無ければ飛ばさずに throw する（K195-RC-008）。CI をほかの用（やり直しの回数・時間切れ）で読むだけの試験は、一覧に載せない（数えない）。同じ決まりを一覧の `_doc` に書く
- G65 の並び（`05_flow/build_testplan.py`）の最後に、このチケットの試験を足す（K-193 の後ろ）

- arm64 の VM で、Playwright が `channel: "chrome"` の Google Chrome を headless で開けるかは、読んだ限りでは足す物は無いはずだが、動かしていない（確かめたことの 6）。取り込みの前に PM が使い捨ての VM で試す（完了の条件）。開けなければ「決める人に聞く」の 2
- 像を作り直すまでは、全部の回と、apps/bridge を触るチケットの CI は、今と同じ所で赤（取り込んだだけでは直らない）。温める命令を変えたのに像が古いことを、機械は見ない。赤の文は今と同じ「CI には Google Chrome が要る」
- Chrome の版は像を作った日の stable のまま止まり、像を作り直すと上がる（決めたこと）。本人の PC の版とずれることがある。版が上がった回に Bridge の試験が赤になったら、製品が新しい Chrome で動かないという本物の知らせ
- 像が約 460MB 大きくなる（包みの Installed-Size 458,984KB）。VM 3 台の写しの時間とディスクは PM が像の作り直しのときに見る

- `apt-get install` が、像に無い依存の部品を外から取る（温める行の `playwright install --with-deps` と同じ形）
- 包みは置き場の list を足し直す毎日の仕事（cron）も置く。組の VM は使い捨てなので効かないが、長く立てたままの VM では list が戻る
- **この検査で見つからない物**：道を見ずに道具を使う試験（命令を直に呼ぶ など）は、一覧にも RC-008 にも当たらず、全部の回で初めて赤になる。台の種類（Mac だけ）や環境の値で飛ぶ試験も見ない（K-197）
