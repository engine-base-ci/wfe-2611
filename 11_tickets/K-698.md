## 目的

AI が目次から要るページを**道具 `knowledge_open` で開いて読める**ようにする（API と DB の側）。新しい口は作らず、K-62 の契約の口 `callKanameTool`（POST /api/v1/bridge/jobs/:id/tools/:name）に道具を 1 つ足す。AI に道具を見せる側（Bridge の定義）は K-718。

- 道具の入力は `page_id`（ページの uuid）だけ。答えはページの題名・1 行の説明・場所・本文（全文・50,000 字まで）・版
- **その仕事で見える物だけ開ける**：範囲は K-697 の `app.kn_ai_visible_pages(任せた人, チケット)`。見えない・無い・消えた・下書き・別の会社・範囲の外は、**どれも同じ答え**（404・`{error, code}` だけ）。在るかどうかを漏らさない
- チケットの仕事にも会話の仕事にも出す。ログインの試しには出さない
- **開いた記録**を残す：`reference_logs`（`ref_type = 'page'`・`ref_id`＝ページ）。チケットの仕事は `ticket_id`・実行の記録つき／会話の仕事は `ticket_id` なし（`bridge_job_id` で結ぶ）。同じ仕事で同じページを 2 回開いても記録は 1 行
- **チケットの仕事だけ**、やり取りに 1 行（「AI が『請求書の送り方』（会社 › 経理）を開きました」）。同じ仕事で同じページを 2 回開いても行は 1 つ
- AI が開いた数は、K-677 の足元（`app.kn_page_ai_opened_30d`）と K-695（使われていないページ）が `reference_logs` から数える。この葉は数える関数を変えない（列と条件が同じ）

## 前提と制約

分類: AI, PERM

- 名前の決めは `07_functional/段10-F9/土台-knowledge.md` 6 章（案）と K-697 の md。**この葉が決めた名前**：DB `app.knowledge_open(p_job uuid, p_token_hash text, p_session uuid, p_page uuid)`（土台の案 `(p_member, p_page, p_ticket)` から変えた：`ticket_tool_read` と同じく**鍵のハッシュと受け取った PC を DB でも見る 2 層目**にするため）。TS は `apps/api/src/features/F9/knowledge/ai/open.ts`（`parseOpenInput`・`runKnowledgeOpen`・`openAnswer`・定数 `KNOWLEDGE_OPEN_TEXT_MAX = 50000`）
- **道具の口の足し方**（`apps/api/src/features/F5/delegate/tools.ts`）：`TICKET_TOOLS` に `knowledge_open` を足す（`["ticket_read", "knowledge_open"]`）。会話の仕事は `Object.keys(TOOLS)` に加えて `knowledge_open` を返す。`ALL_TOOLS` にも入れる。前の決まり（チケットの仕事に会話の道具は 403・会話の仕事に `ticket_read` は 403）は変えない。口の本体は `ticket_read` の分岐の隣に `knowledge_open` の分岐を足し、`rawBody` から `input` を読んで `parseOpenInput` → `runKnowledgeOpen` を呼ぶ
- **入力**（AI の出力なので緩く読む）：`input.page_id` が uuid（大文字も通し、小文字に直す・`auth/ids.ts` の `idOf`）。無い・文字でない・uuid でない → 422（`{error: "validation_failed", code: "VALIDATION_ERROR", details: [{field: "page_id", message}]}`）。知らない欄は捨てる
- **`app.knowledge_open(p_job, p_token_hash, p_session, p_page) returns jsonb`**（`security definer`・`set search_path = public, app, pg_temp`・`kaname_app` に渡す）。**1 つの取引の中で次の順**：
  1. 仕事を引く：`bridge_jobs` で `id = p_job`・`state_id in ('running','asking')`・`tool_token_hash = p_token_hash`・`taken_session_id = p_session`・仕事の持ち主が止められていない（`members.deleted_at`・`suspended_at` が空）。無ければ **null**（口は 404 の答えにする。鍵の確かめは口の前段〔`app.bridge_tool_job`〕が 403 で先に済ませているので、DB まで来て null になるのは「見つからない」と同じ扱い）
  2. チケット：仕事の種類が `ticket` なら `action_runs.ticket_id`（最新の 1 つ）。会話の仕事は null
  3. `p_page` が `app.kn_ai_visible_pages(仕事の持ち主, チケット)` に入っていなければ **null**
  4. `reference_logs` に 1 行：`tenant_id`・`ticket_id`（無ければ null）・`bridge_job_id`・`member_id`（仕事の持ち主）・`action_run_id`（あれば）・`ref_type = 'page'`・`ref_id`・`title`（その時の題名）・`seen_at = now()`・`created_by`（持ち主）。部分一意 `reference_logs_page_job_uq on (bridge_job_id, ref_id) where ref_type = 'page' and bridge_job_id is not null and deleted_at is null` で `on conflict do nothing`。入ったか（`opened_now`）を覚える
  5. 入ったとき、かつチケットの仕事のとき：`app.knowledge_ticket_line(チケット, 'knowledge_open', [{field: 'knowledge_open', from: null, to: <題名>, note: <場所>, page_id}], 'AI が『<題名>』（<場所>）を開きました')`
  6. 証跡：`app.agent_tool_audit(持ち主, 会社, 'tool.knowledge_open', 'knowledge_page', ページ, {job_id})`（ページの題名・本文を入れない。開くたびに 1 行・`ticket_read` と同じ）
  7. 答え：`{ ok: true, opened_now, page: { id, title, desc, place, body_text, truncated, version } }`（鍵ちょうど 7 つ。`body_text` は公開の最新の版の字。50,000 字（コードポイント）を超えたら切って `truncated: true`。`version` は `current_version`）
- **口の答え**（`openAnswer`）：DB が null → 404 `{ error: "not_found", code: "NOT_FOUND" }`（欄・details・detail を付けない）／ok → 201 `{ data: { result: <ok の答え> } }`。**DB の例外は 503 `E-PAGE-003`**（`unavailable`・何も残らない・ログに例外の種類だけ・題名・本文・id を出さない）
- **reference_logs の直し**（migration の中）：`ticket_id` の not null を外す・列 `member_id uuid references members(id)`・`bridge_job_id uuid references bridge_jobs(id)` を足す・check `reference_logs_owner_ck`（`ticket_id is not null or bridge_job_id is not null`）・上の部分一意と索引 `(tenant_id, ref_id)`・**引き金 `reference_logs_same_tenant` を新しい関数 `app.kn_open_same_tenant()` に付け替える**（`ticket_id` があればそのチケット、`member_id`・`bridge_job_id` があればそれぞれが同じ会社であること。前の `app.ticket_around_same_tenant` は触らない＝ほかの表が使う）。**前からの行・前からの入れ方（`ticket_id` だけ）は通る**。`revoke update, delete` は前のまま。行の守り（`reference_logs_ticket_read`・`_ticket_write`）は変えない（`ticket_id` が空の行は人の接続からは見えない。読むのは `security definer` の関数だけ）
- 外へ出ない：メールもお知らせも出さない。AI の外のサービスも呼ばない。**開いた記録とやり取りの行を書くのは AI の仕事の鍵が合ったときだけ**
- ログに題名・本文・道具の鍵・PC の印を出さない
