## 目的

K-999（段 13 の統合テスト）は、運営の入口がパスキーだけで外から作れる道が無い（D-156.22）ため、運営の筋（K999-STG-03・04）を BLOCKED（理由つき）で残した。K-1101 が staging の試験だけの運営の人とそのパスキーの鍵を Environment staging の秘密に置いたので、この葉が：

1. **秘密を読む口**：`site.ts` に鍵を返す関数 `opsPasskey()`（3 つの名前を `need` で読む・関数の中で読むので、秘密が無い回でも K-65・K-999 の試験は落ちない）。作り手 `05_flow/build_testplan.py` の統合テストの段（G15）の env に 3 つの名前を足し、`staging-e2e.yml` を作り直す（健康診断の段には渡さない）。伏せる台本（scrub.mjs）は `STAGING_` で始まる値を全部伏せるので直さない（K1102-FM-009 で確かめる）
2. **運営の 2 本**（`apps/e2e/staging/k1102-f12-ops.spec.ts`）：K1102-STG-01（運営が回す）・K1102-STG-02（配る・値段）。K-999 の K999-STG-03・04 の受け持ちは、この 2 本に移る（K-999 の md を書き直した）

ここで見るのは 2 つだけ：① 運営のパスキーで入ったセッションの印が、別の住所の運営の口に画面から通ること ② 運営の操作が、別のブラウザで入っている顧客の画面と口に本物の DB ごしに効くこと。中の分岐は単体と中間（K-996・K-997・K-998）が開発の環境で持つ。

- **「できた」を決める記録**：本体（K1102-STG-01・02）は、取り込みの後に main から起こす staging-e2e.yml の回の JUnit で決める（K-65 の PM の決め 1）。チケットの CI（枝）では本体の行を判定しない（judge-skip）
- **試験のための抜け道を作らない**：page.route を使わない・製品に試験用の分かれ道を足さない（運営の入口に外から作れる道を開けない＝D-156.22。パスキーはふつうの手順で付けた物を仮の認証器に入れ直すだけ）・固定の待ちを置かない・**DB は読みも書きもしない**（確かめは画面・同じブラウザからの口の読み直し `readAs`・Resend の記録だけ）
- **鍵の扱い**：`opsPasskey()` が返す 3 つ（PEM の秘密鍵・資格の id・利用者の印）は、道具 `ops-steps.ts` の `addOpsPasskey` だけが受け、CDP の `WebAuthn.addCredential` に 1 回ずつ渡す。画面に打たない・ページの中に渡さない・投げる文に入れない（K1102-FM-005）。署名の回数は回ごとに今の時刻の秒（前の回より必ず大きい）。rpId は `WEB`（site.ts）のホストの名前
- **秘密の名前**（K-1101）：`STAGING_OPS_PASSKEY_KEY`・`STAGING_OPS_PASSKEY_ID`・`STAGING_OPS_PASSKEY_USER`。`site.ts` は `export const opsPasskey = (): { key: string; id: string; user: string } => ({ key: need("STAGING_OPS_PASSKEY_KEY"), id: need("STAGING_OPS_PASSKEY_ID"), user: need("STAGING_OPS_PASSKEY_USER") })`（関数の中で読む）
- **作り手**：`05_flow/build_testplan.py` の `STAGING_NAMES` の扱いを分け、統合テストの段（G15・`pnpm e2e:staging`）の env にだけ 3 つを `${{ secrets.<名前> }}` で足す。健康診断（staging_health.py）の段には足さない。`python3 05_flow/build_testplan.py` で `staging-e2e.yml` を作り直す（手で直さない・K-204）
- **値段は決めない**：STG-02 は案の下書きと影響を読むまで。決める・差し戻すと staging の全部の会社の請求に効く。1 つのプランに開いた案は 1 つ（K-988）なので、理由が「統合テスト」で始まる下書きが残っていればそれを使う（回を重ねても案は 1 つ）
- **会社を止めない**：STG-01 は止める日を決める（既定の 7 日後・先に知らせる）→ すぐ再開する。止めた画面（K-1008）は通さない（止めると顧客が入れなくなる・単体の K-1012 が持つ）
- **回数の上限**：1 回の通しで登録 1 人・メール 1 通（確認のメール）。運営の返事は鈴に出す（D-156.28・メールは出さない）。1 本ずつ順に（設定 workers 1）
- **試験が作った物は staging に残す**（名前に「統合テスト」）：顧客の会社・問い合わせ（返事あり）・1 社へのお知らせ・中を見た記録・止める日と再開の記録・案の下書き
- 画面の名前（「運営のログイン」「パスキーで入る」「自分が持つ」「返す」「お知らせを送る」「題」「本文」「送る」「中を見る」「理由」「見る時間」「見るだけで開く」「パスキーで確かめる」「そのほかの操作」「止める」「再開する」「変える案を作る」）はモックと画面の葉の md の字。staging の最初の回で違えば、直すのは `_lib/ops-steps.ts`（試験の期待の字なら切る段へ戻す）
