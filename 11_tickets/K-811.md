## 目的

メンバーの一覧の行の役割の ▾（下絵 mb-role-menu・D-154.9）で役割を選ぶと動く口 `updateMemberRole`（PATCH /api/v1/members/:id/role）を作る。

- ▾ は **そのグループでの役割**（マネージャー・メンバー・閲覧のみ）を変える。同じ人が複数のグループに居れば、グループごとに別の役割を持てる（兼務・D-154.15）
- ▾ の「**管理者**」を選ぶと、会社全体の管理者にする（グループの印は要らない）。管理者を下げるときは、グループの役割を選ぶ（管理者でなくなる）
- **本人確認の取り直し**（D-154.18）：契約の `stepUp: "always"` で、入口が 15 分以内でなければ 403・STEP_UP_REQUIRED を返す。画面は今の取り直しの小窓（`features/F1/security/step-up.tsx`・パスキーは `passkey.ts` の `stepUpWithPasskey`）で取り直し、通ったら 1 回だけやり直す（K-363 と同じ形）
- **自分の役割は自分で変えられない**・**最後の管理者は下げられない**（D-154.19）

口の登録・断る番号（errors）は K-800 が持つ。入力と答えの形は K-800 の「契約」の節で決めた形で、この葉の口の分をこの葉が契約（.d）に書く。この葉は `members/role.ts` の空の形を本物にして `ready = true` にする。

**画面が使う答えの形**（K-818 が使う）：200 `{ data: MemberRoleChanged }`・鍵はちょうど 3：member_id・company_role（admin・manager・member・viewer・requester）・groups（`[{ id, name, code, primary, role }]`・K-810 の getMember の groups と同じ形）。画面は答えで行を差し替え、一覧を読み直す。

## 前提と制約

分類: PERM, CRUD

- **だれが呼べるか**：契約の PERMS のまま（members の edit・会社全体＝管理者の束と、個別に付けた人。**マネージャーは呼べない**・D-128.97）。入口が先に 403。DB の関数も頭で `app.admin_lock()` の後に `app.admin_can('members', 'edit')`（K-800 の決めの順・守りは入口と関数の 2 層）。**「members の edit を個別に付けた人」の行（K811-API-008・012）は DB の守りとして残す**：人ごとの「できること」を作らない（D-154.10）ので製品の画面からは個別に付けられない（試験は DB に直に入れた権限の行で確かめる）
- **入力**：`role_key`（必須・manager・member・viewer・admin の 4 つ）・`scope_id`（任意）。形の誤りは入口が 422（契約の VALUE_RANGES）。**知らない欄・role_id・tenant_id は 422**（strict）
- **相手**：`app.admin_target`（K-800）が null なら 404・E-MEM-002（無い・別の会社・外した・消した・AI。欄・details なし）。止めている人の役割も変えられる（会社の役割・グループの役割は書く。止めている間は役割の束の引き金 0080 が束の権限の行を作らず、戻すと作る・K811-API-016）
- **自分**：相手が呼んだ本人（`is_self`）なら、どの役割でも 409・E-MEM-003（欄・details なし）
- **admin を選ぶ**：相手の会社の役割（tenant_memberships.role）を admin にする（所属の行を持たない owner は元から管理者なので何も変えない）。scope_id は見ない（送られても無視する）。グループの所属の行は変えない。すでに管理者なら何もしない（200・証跡を増やさない）
- **manager・member・viewer を選ぶ**：scope_id のグループ（無ければ相手の主の所属）での役割にする。グループが同じ会社の消していない物でなければ 404・E-MEM-006。相手がそのグループに居ない（主の所属でも兼ねる所属でもない）なら 409・E-MEM-007。**主の所属に所属の行が無い人は、行を足して（is_primary true）役割を入れる**（管理者・会社を作った人の主の所属など）。行があれば役割だけ直す。同じ役割なら何もしない（200・証跡を増やさない）
- **管理者を下げる**（相手が今管理者で、選んだのが admin 以外）：相手が最後の管理者（`app.admin_is_last_admin`）なら 409・E-MEM-004。そうでなければ会社の役割を member にして、グループの役割を入れる（所属の行が無ければ主の所属に足す）。**止めた管理者は管理者に数えない**（K-800 の数え方）ので、残る 1 人が止めている間は最後の 1 人も下げられない
- **会社の役割（tenant_memberships.role）が変わるのは admin ⇔ それ以外のときだけ**。グループの役割だけを変えるときは、会社の役割は触らない（manager・member・viewer はグループごとの役割で決まる）
- **セッションが切れる**（G-14・D-125.140）：役割の束の引き金（0080 `tenant_memberships_bundles`・`scope_memberships_bundles`）が権限の行を作り直し、権限の引き金（0004 `permissions_revoke_sessions`）がその人の全セッションを切る。**口は別にセッションを切らない**（同じ取引の中で引き金が切る）。何も書かない回（同じ役割の選び直し）は切れない。画面の「相手は入り直しになる」の字は K-818
- **同時**（D-154.21）：`app.admin_lock()` で順に通す。2 人の管理者が同時に互いを下げても、片方だけが通り、管理者が 0 人にならない（2 本目は権限が無くなって 403 か最後の管理者で 409）
- **記録は追記だけ**（D-154.25）：`member.role_change`（payload は `{scope_id（admin のとき null）, from, to}`。役割の名前 admin・manager・member・viewer だけ・名前もメールも入れない）。何も変わらなかったときは書かない
- 入口の共通が先に効く：401・429・同意し直し 403・本人確認 403・道の id の形 422・NUL 422
- 断る番号は控え帳どおり（404 は欄・details なし／409 は欄・details なし／503・E-PAGE-003）

## リスクと懸念

- 役割の束の引き金は、所属の行・会社の役割の行のどの変更でも権限の行を作り直し、その人の全セッションを切る（0080・0004）。**同じ人の役割を「同じ値に」直す更新も引き金が走るので、口は同じ値なら書かない**（K811-API-010）。画面は 200 のあと、相手が次の操作で入り直しになることを示す
- 同時に互いを下げる試験（K811-API-013）は、2 本目が権限を失って 403 になるか最後の管理者で 409 になるか、どちらかの形になる（どちらも通ってよい）。0 人にならないことだけを確かめる

## 申し送り

- K-818：役割の ▾ は「マネージャー・メンバー・閲覧のみ・管理者」。管理者を選んだ行・管理者を下げる行は、本人確認の取り直しの小窓を通る（口が 403・STEP_UP_REQUIRED を返したら小窓を開き、通ったら 1 回だけやり直す）。自分の行の ▾ は押せない形（self）。最後の管理者の ▾ は 409・E-MEM-004 の字で断る（下絵 mb-role-last-admin）
