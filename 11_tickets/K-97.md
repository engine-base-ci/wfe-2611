## 目的

前の画面の試験 SCR-BRIDGE-SETUP-103 は、組み立てた Bridge（apps/bridge/dist/runner.js・apps/web/tests/_lib/agent-bridge.ts 23 行が読む）が無いと動かない。手元にも CI にも組み立てる段が無い（K-57・K-60 の取り込みの途中で見つけた。途中で見つけたものはその場で直さずチケットにする・D-128.147）。

## 完了の条件

- [ ] workflow に Bridge を組み立てる段があり、その試験の前に流れる
- [ ] SCR-BRIDGE-SETUP-103 が組み立てた Bridge で流れる
- [ ] workflow の全部（act）が緑

## 前提と制約

- 組み立ては本番の配布と同じ手順を使う：本番の配布の台本 `apps/bridge/scripts/release.mjs` は 43 行で `pnpm -s build`（apps/bridge の package.json の build ＝ `tsc -p tsconfig.json && node scripts/copy-renderer.mjs`）を流してから electron-builder で包む。試験に要るのは包む前の dist なので、CI はこの `pnpm -s build` までを同じ命令で流す（包む electron-builder は流さない・OS ごとの入れ物は試験に要らない）

## 実施事項

- [ ] 命令：`pnpm --filter @kaname/bridge build`（＝ release.mjs の 43 行と同じ build）。終わったら `test -f apps/bridge/dist/runner.js && test -f apps/bridge/dist/loop.js` で確かめる
- [ ] workflow の段：.github/workflows/v3-gate.yml は 05_flow/build_testplan.py の生成物なので、作り手に `web` の job（と、前の画面の試験を流す job）の「画面を立ち上げる」の前の段 `Bridge を組み立てる（本番の配布と同じ build・K-97）` を足して作り直す（手で直さない）
- [ ] 手元：`scripts/dev/up.sh`（開発の立ち上げ）に同じ命令を足す
