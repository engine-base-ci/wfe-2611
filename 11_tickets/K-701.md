## 目的

段 5 の K-566 は、完了の口 `completeTicket`（DB の関数 `app.ticket_complete`）を「確認項目の未チェックは数えて返すだけ・止めない」に直した（D-150.42）。段 10 の代表の決め 12 は、そこに**1 つだけ例外**を足す：**「必ず守る」から入った確認項目（出どころ `knowledge`）にチェックの無い行が在れば、完了にできない**。人が足した確認項目（出どころ `manual`）は、これまでどおり注意だけ。

- 止めるときは **409・新しい番号 E-KNW-240**。答えに**残りの行の一覧**（行の id・文・ページの id・題名）を返す（画面の小窓「まだ完了にできません」が並べる）
- **止めるのは今も必ず守るで生きているページの行だけ**（K-699 の決め）：必ず守るが外れた・ページが消えた・まだ公開していない・効く範囲から外れた行は、チェックが無くても止めない。判定は K-700 の `app.knowledge_guard_specs` の 1 か所
- **完了にする道は `app.ticket_complete` の 1 本だけ**（本線の migration を全部見て確かめた：完了の段へ動かす `ticket_stage_to(..., 'done', ...)` はここだけ。承認して完了も AI の仕事の終わりも、段は作業中に戻るだけ）。それでも道が増えたときの**最後の砦**として、チケットの段が完了へ変わる更新を DB の引き金でも止める（K701-API-014）。`updateTicket` が完了へ動かせないこと（K-387）は変えない
- **止めた記録は破られた数に数えない**（破られた数を数える出来事は K-700 の 3 つだけ）。止めるときは何も書かない
- 口は新しく作らない。`completeTicket` の断りに 1 つ足すだけ（口の持ち主は K-165 のままなので、頭の `apis:` は空・生成の試験 `post_tickets_id_complete.test.ts` は `tests:` に書かない＝段 5 の K-566 と同じ書き方。入力と成功の答えは K-566 のまま）
- 確認項目の行の答えに出どころのページ（`source_page`）を足すのは別の葉 K-726（画面 K-703 の小窓と印が読む）。この葉と K-726 は互いに要らない（K-726 は K-700 の `app.knowledge_guard_specs` だけを使い、この葉の関数は使わない）

### 画面が使う答えの形（K-703 の小窓「まだ完了にできません」が使う）

- 409 の体：`{ error: "conflict", code: "E-KNW-240", message, action, undo, support_code, detail: { left: [{ id, title, page_id, page_title }] } }`。画面の小窓の行は 文＝`title`・「ナレッジ：<`page_title`>」（押すと `page_id` のページが開く）。見出しの「チェックの付いていない物が N つ」の N は `left.length`。**人が足した確認項目の注意**（「完了は止めませんが、見直してください」）は、画面が `listTestSpecs` の未チェックの数と `left` の差から出す（この答えには入れない）
- 「確認項目に戻る」は確認項目の欄へ戻る。チェックが付けば（AI が付ける＝段 6・人が付ける＝K-435）もう 1 度押して完了にできる
