## 目的

決まり（ai-driven-process.md §8・2026-11-08）は「試験の結果の欄は CI の記録から機械で書く。結果の欄の PASS は CI の回の印が付いたものだけで、手で書いた PASS は検査で赤」。決める人の決定 D-129.51 は、検査を 07_qa/test-specs のどの仕様のファイルにも掛け、今ある印の無い PASS は「まだ流し直していない行」の台帳に載せ（台帳は減らすだけ）、結果の欄は取り込みの台本（pm_merge.sh）が CI の記録から書く、とした。D-129.50 で K-62 の前に入れる（仕組みが無いと K-62 の CI が G48 の「結果が空」で赤になり取り込めない）。ところが Kaname では次が残っている。

1. 試験の仕様の中に「PASS に書き換える」（手で結果を書く形）が 26 か所ある：`07_qa/test-specs/k/sign-up.md:7`・`terms.md:9`・`verify-email.md:8` の前書き（K-51〜K-53 の仕様）と、`07_qa/test-specs/errors.md` の 23 行（例：:14 E-AUTH-003-A の「CI の報告で緑になってから PASS に書き換える」）。K-62 の仕様（delegate.md:6）は精査 R1 の差し戻しで直した
2. 手で書いた PASS を赤にする検査（スキル ai-team-delivery の `scripts/gates/result_gate.py` の形）が、Kaname の `.github/workflows/v3-gate.yml` の段に無い（K-103 で decision_source_gate（G60）は入れたが result_gate は入れなかった・PM の入れ漏れ）
3. 結果の欄を CI の記録から書く台本が無い。CI はまっさらな写しで流すので、写しの中で書いた結果は残らない

このままだと、手で書いた PASS が CI を通り、流していない試験が「通った」に見える。
