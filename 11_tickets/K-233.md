## 確かめたこと（切る段・2026-11-16）

1. 解決は `packages/auth/src/resolver.ts` の createSessionResolver の 1 か所。呼ぶのは契約の口の入口（server.ts → app.ts の resolver → middleware/tenant.ts）・認証の部品の口の止め（app.ts の /api/auth/*）・前の道すじ（ext.ts の fresh・同じ要求の中は WeakMap で 1 回）
2. `app.session_check` は、生きていれば 1 行・閉じたら 0 行（理由を付けて閉じ、国と端末なら security_events）を返す（0083）。`app.session_step_up_at(text)`・`app.session_terms_pending(uuid)` は security definer で kaname_app が呼べる（0081・0088）。3 つを `select … from app.session_check($1,$2,$3,$4) c` の 1 本にまとめられる（session_check は from の中で 1 回だけ動く）
3. 入口の抜けた人の確かめ（op.ts の 2.6）は `c.get("memberLeft")` を呼ぶ。tenant.ts が `() => repo.memberLeft(ctx)`（withTenant の取引 1 つ＝4 本）を入れている
