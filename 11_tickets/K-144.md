## 目的

K-62 で契約の fuzz（G36・Schemathesis）の的を K-57・K-60 の口まで広げたら、前から食い違っていた所が 4 件見つかった（K-62 の 8 本の口はどれも緑）。どれも「契約の書き方」と「口の実際の振る舞い」がずれていて、fuzz が赤になる。K-62 の完了の条件は「広げた範囲で fuzz が緑」なので、これを先に直す（決める人の決定：起票して K-62 の前に入れる・2026-11-08 answer=c8bb89cac057）。

1. `GET /bridge/releases/{name}/file`（K-57）：配布物が無いとき 404 を返すが、契約に 404 が無い
2. `GET /ticket_kinds`（K-60）：`color` が null を返す（DB の列は null を許す）が、契約は文字（string）
3. `POST /bridge/pairing-codes`（K-57）：知らない項目を 422 で断るが、契約に `additionalProperties: false` が無い
4. `POST /me/ticket-drafts`（K-60）：`draft_id` が uuid でないと 422 で断るが、契約に `format: uuid` が無い

**4 件はどれも「類」の 1 件**（精査 R1 回 1・L-008）。fuzz が 1 本ずつしか赤にしなかったのは例の数（-n 30・seed 固定）のたまたまで、同じ形のずれが入力の形全部・ほかの uuid の欄・同じ口のほかの応答・ほかの答えの null にある。決める人の決定 D-129.42（ゼロトラスト：uuid の欄は契約に format: uuid を書いて入口で厳しく確かめる・入力の形は知らない項目を許さない・同じ形のずれは K-144 で全部そろえる）に従い、**類ごとに全部**このチケットでそろえる。

分類: CRUD, EXT, PERM

- 直す向き：**契約を実装に合わせる**。ただし uuid の欄だけは D-129.42 で**入口を厳しくする**（契約に format: uuid を書き、作り手の入口の形 z.uuid() が版と variant の桁まで確かめる）。前の口の正規表現（`/^[0-9a-f-]{36}$/i`）が通していた「36 個のハイフン」「版の桁が 0 の 36 字」は 422 になる（中の `$1::uuid` で 500 になる道を残さない）。PM の 08:50 の決め（口の振る舞いは変えない）は、08:57 にこの決定に合わせて直した（.ai-team/pm-decisions-2026-11-08.md）
