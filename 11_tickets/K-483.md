## 目的

チケットの詳細の「期限を変える」・ガントの期限を動かす小窓・カレンダーの日の小窓から呼ぶ、期限と開始日を変える口を作る。契約の口 `updateTicket`（PATCH /api/v1/tickets/:id）は、段 7 の K-387 が「段・実績・保留」の分だけ先に作り、ほかの欄は「まだ変えられません」（E-VAL-018）で断っている。K-387 の作りは **欄ごとの処理の表**（`TICKET_FIELD_GROUPS`）に欄の組を足せる形で、K-440（優先度・親）・K-564（会社の項目の値）・K-583（予定時間）が先に組を足す。この葉は **期限の組**（due_on・start_on・due_reason・expected_due_on・expected_start_on）を 1 つ、その後ろに足す。**期限・開始日の欄はこの葉だけが持つ**（K-440 の組からは外してある・まとめ役の決め 2026-11-21）。口そのもの（hooks のファイル・登録・契約の口）は K-387 の物で、この葉は新しい口を作らない（`apis` は空）。

- 期限を変えるときは理由が必須（D-125.33・D-150.4・D-151.11）。理由はやり取りの変更の 1 行に残る。期限は日付だけ（時刻は持たない・D-150.4）。開始日だけの直しは理由が要らない
- 期限を延ばす・縮める・なくす・初めて決める、どれも同じ口。承認待ちの間も変えられる（承認する人にお知らせが出る・絵の「期限を延ばすと承認する人にお知らせが出る」）
- 子の期限は親の期限より後にできず、親の期限は子の期限より前にできない（D-128.65・D-151.12）。開始日は期限より後にできない（DB の check もある）
- 担当者は変えない（D-151.13）。担当を替えるのは渡す口（F8・段 9）
- お知らせは受け箱の行だけ（メールは出さない・D-151.6）。種類 `ticket.due_changed`（札と行き先は K-461 の表が持つ）。本文はほかの組と同じ形（番号・リンク・変えた欄の名前。題名は鈴の答えの上に出る・P13）
- お知らせは受け箱の行だけ（メールは出さない・D-151.6）。種類 `ticket.due_changed`（札と行き先は K-461 の表が持つ）。本文は番号と題名だけ（P13）
- 詳細の答え（getTicket）に `can.due`（期限を変えられるか）を足す。画面 K-484 が「期限を変える」を押せるかを決める

### 契約に書く値域（screen_api.d/K-387.py の VALUE_RANGES・INPUT_RULES の `updateTicket`・contract_shape.d/K-387.py の VALUE_RANGES に同じ字で足す）

日付の欄 4 つ（`due_on`・`start_on`・`expected_due_on`・`expected_start_on`）は暦にある `YYYY-MM-DD` の字だけ（時刻つき・斜線・空の文字は契約の外）。理由は 200 文字まで・見える字を 1 つ以上。入口の normalize（NFKC と前後の空白）の後の値に口は掛けるので、契約の `maxLength` と pattern は「入口の後の字」の決まり。同じ辞書を 2 か所に置くと YAML の別名が出る（build_api の注）ので、理由の決まりは関数で作る。

```python
_Y = r"(?:000[1-9]|00[1-9][0-9]|0[1-9][0-9]{2}|[1-9][0-9]{3})"
_LEAP = r"(?:[0-9]{2}(?:0[48]|[2468][048]|[13579][26])|(?:0[48]|[2468][048]|[13579][26])00)"
_DATE = rf"^(?:{_Y}-(?:0[13578]|1[02])-(?:0[1-9]|[12][0-9]|3[01])|{_Y}-(?:0[469]|11)-(?:0[1-9]|[12][0-9]|30)|{_Y}-02-(?:0[1-9]|1[0-9]|2[0-8])|{_LEAP}-02-29)$"
def _date(): return {"pattern": _DATE}
def _reason(): return {"maxLength": 200, "pattern": r"[^\s\u0000-\u001f\u007f-\u009f]"}   # 制御文字と空白だけでない
VALUE_RANGES_ADD = {"due_on": _date(), "start_on": _date(), "expected_due_on": _date(), "expected_start_on": _date(), "due_reason": _reason()}   # updateTicket の VALUE_RANGES に足す
INPUT_RULES_ADD = {"allOf": [
    {"anyOf": [{"not": {"required": ["due_on"]}}, {"required": ["due_reason"], "properties": {"due_reason": {"type": "string"}}}]},   # 期限を送ったら（null＝なくすときも）理由が要る
    {"anyOf": [{"not": {"required": ["due_reason"]}}, {"required": ["due_on"]}]},                                                       # 理由だけは送れない（start_on だけに添えるのも）
    {"anyOf": [{"not": {"required": ["expected_due_on"]}}, {"required": ["due_on"]}]},                                                  # expected_due_on は due_on と一緒に
    {"anyOf": [{"not": {"required": ["expected_start_on"]}}, {"required": ["start_on"]}]},                                              # expected_start_on は start_on と一緒に
]}   # updateTicket の INPUT_RULES に足す
```

実際の断片には `VALUE_RANGES["updateTicket"]` の辞書の中に 5 欄をそのまま足し、`INPUT_RULES["updateTicket"]` に `allOf` を足す（上の `_ADD` の名前は説明用）。K-387 が INPUT_RULES に `allOf` を持っていればその並びに 2 つを足す。この表現で、暦に無い日・時刻つき・空の理由・制御文字だけの理由・201 文字以上・理由だけの要求（試験 005・006・008）は契約の外の入力になる。

### 契約に書けなかった物（PM の決め 2026-11-21 02:00 で 409 に当てはめた）

契約の言葉（pattern・enum・長さ・個数・欄の有無・oneOf）で書けない決まりは 422 にしない（控え帳 11-20 16:51）。この葉の 2 つは次のとおり。
