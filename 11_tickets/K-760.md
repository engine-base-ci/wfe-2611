## 目的

自分の AI の会話は、本人の PC の Claude Code の記録が正本で、Kaname の会話はその**写し**（D-112）。PC が文を写す口と、写し漏れを取り戻す先を教える口を契約の口にする（今はどちらも契約だけで 501）。前の道すじ `POST /api/auth-ext/bridge/entries`・`POST /api/auth-ext/bridge/mirror-targets`（agent.ts）の中身を移し、Bridge の呼び先も契約の道に替える。

- `mirrorConversationEntries`（POST /api/v1/bridge/jobs/:id/conversation-entries・体は `{ entries: [{ uuid, text, at? }] }`）：その仕事の**会話**に、自分の AI の文を記録と同じ id で写す。会話は**仕事から決める**（体に会話の id・仕事の id を持たない）。同じ id は二度入れない／同じ返答の続きは書き換える（D-115）／写す前からある同じ文には id を付けるだけ／「覚える」の印は吹き出しに出さない（D-105.1）。答え `{ inserted }`（入れた数）
- `listMirrorTargets`（GET /api/v1/bridge/mirror-targets・問い合わせは `limit` だけ）：直近 14 日の本人の会話と、そこで使った Claude Code の session を、**いちばん新しい仕事の id つき**で新しい順に返す（既定 50 件・上限 50）。PC は返った物のうち記録がある物を、その仕事の道すじで写す

- **migration は 1 本**（番号−600＝160 分 → 02:40 → `packages/db/migrations/20261125024000_talk_mirror.sql`）。列・表は足さない。①`app.talk_mirror_entries(p_session uuid, p_job uuid, p_entries jsonb) returns jsonb`：PC の印が生きていなければ null。仕事を `app.bridge_job_of(p_session, p_job)`（0092・その仕事を受け取った PC だけ。ほかの PC・人・会社・無い仕事は引けない）で引き、無ければ `{error:'not_found'}`。仕事に会話が無ければ `{error:'no_conversation'}`。会話が消えている・仕事の持ち主の会話でなければ `{error:'not_found'}`。あれば前から在る `app.bridge_entries(p_session, 仕事の会話, p_job, p_entries)`（0055）を呼んで `{inserted: 入れた数}`（**吹き出しの書き方は 1 か所のまま・作り直さない**）。仕事が動いているかは問わない（終わった後に取り戻す）②`app.talk_mirror_targets(p_session uuid, p_limit integer) returns jsonb`：生きていなければ null。直近 14 日・session あり・消していない仕事のうち、**その PC が受け取った仕事（`app.bridge_job_of(p_session, 仕事)` が引ける物＝写す口と同じ条件。受け取り前の古い行は同じ人のどの PC にも）**の、消していない**本人の**会話を、会話×session ごとに**いちばん新しい仕事**（`distinct on`）で 1 つ・新しい順に `p_limit` 件。`[{conversation_id, agent_session_id, job_id}]`。関数は `security definer`・`set search_path = public, app, pg_temp`・public から外し `kaname_app` に渡す
- **入力の形の確かめは口が自分でやる**（入口の zod は全部 optional）：`entries` が配列で 1〜500 件（無い・配列でない・0 件・501 件は 422・欄 `entries`）。1 件ごとの中身（`uuid` が `^[0-9a-f-]{8,64}$` でない・文が空・空白だけ）は**読み飛ばして入れない**（PC は記録の全部を送り直すので、形が悪い 1 件で全体を断らない。入れた数に数えない）。文は DB が 200000 字（コードポイントでなくコード単位の `left`）までで残す（PC の写し。人が書いた字でなく AI の返事なので切る。結果の上限 200000 と同じ）。**「覚える」の印**（`[[覚える: …]]`）は口が `takeRemember(text).text` で落としてから DB へ渡す（前の道すじと同じ・印の中身は記憶に入れない＝覚えるのは仕事の結末で 1 回だけ）
- **断る番号**（控え帳）：404＝受け取っていない・ほかの人の・無い仕事／消した会話（NOT_FOUND・欄・details を付けない）／409＝仕事に会話が無い（**E-TALK-030**）／422＝契約に書ける形の誤りだけ（entries の形・limit・知らない項目）／DB の失敗は 503・E-PAGE-003。PC の印が無い・外した PC は入口が 401
- **取り戻す先は続きを持たない**：契約の `cursor` は読まない（常に新しい 50 件まで・`meta` は `{ limit }` だけ）。`limit` は入口が 1〜50 に確かめる（契約の `LIST_DETAILS.limit_max`）
- **量の見積もり（G-16）**：1 回の写しは文 1 つ（関数 1 回・1 取引）・1 回に最大 500 件・1 件 200000 字（体の上限は入口の 1MB）。取り戻す先は 1 回の読みで最大 50 件。PC は返答の文ごとに 1 回送るので、契約の既定の上限（POST 60/分）に当たったら 429 を受けて今の送りを捨て、あとで `mirror()`（つないだとき・仕事の終わり）が記録から全部取り戻す（同じ id は二度入らないので取り戻しで足りる）
- **つなぎ直した PC・同じ人の別の PC には、前の PC が受け取った仕事は返らない**（返しても写す口が 404 にし、Bridge が毎回送り直して接続が切れた表示が続くため）。つなぎ直した後に前の PC の記録を取り戻すことはしない（新しい PC が受け取る仕事から写す）
- 関門の宣言は [C2]。外には出ない。お知らせ・証跡・AI は無い（会話の書き込みの知らせの合図は 0054 の引き金が前から出す）。材料は `d.appPool` だけ。送る量・uuid・上限の入口の共通の確かめ（K-144）と同意し直しの止め（K-53）はそのまま
