## 目的

管理者とグループのマネージャーが、「見直すページ」を開いて、**直したほうがよいページ**を 3 つの一覧（使われていない・食い違っている・よく破られる）で読み、そこから該当のページを開く・2 つのページを並べて見る・書き方を直せる画面を、口 K-695 につなぐ（行為 A93・代表の決め 4）。K-694 が置いた管理の入口の「見直すページ」（今は押せない形）を押せる形にする。

| 一覧 | 行の字（下絵のとおり） | 押す物 |
|---|---|---|
| 使われていないページ | 題名・場所・「AI が最後に開いた：2025/12/20」（開かれていなければ「1 度も無い」） | 「開く」→ そのページ |
| 食い違っているページ | 上のページ（棚の上の方）と下のページの題名と場所・食い違う所の 1 行（「支払期日：会社は…、営業は…と書いてあります」） | 「並べて見る」→ その行の下に 2 つの本文をその場で並べる（**下絵に無い・仮・代表に確認中**） |
| よく破られる決まり | 題名・場所・「7 回」・「いちばん多い：…（5 回）」 | 「書き方を直す」→ そのページを書いている画面で開く |

## 前提と制約

分類: LIST, PERM, XSS

- **代表に確認中・勧めで切る**（下の「代表に聞くこと」）。画面に出す字のうちモックに無い物は**仮**
- **入り方（K-694 が決めた物をそのまま使う）**：道は `/knowledge?view=admin&list=review`（`adminHref("review")`）。管理の一覧の登録 `admin-lists.ts` の `ADMIN_LISTS` に **この葉が 1 行足す**：`{ key: "review", View: ReviewAdmin }`（`AdminCtx = { tree, go(href), reload(what?), notify(text) }`）。登録が入ると `isListReady("review")` が真になり、K-694 の `inertLists` に載らない＝入口が押せる形になる。管理の入口の数は木の `admin_counts.review`（K-695 が 3 つの一覧の行の数の合計で返す）。上の帯の場所は「ナレッジ › 管理 › 見直すページ」
- **見られない人**：木の答えの `admin_counts` が null の人が直に道を開いたら、K-694 の `AdminMain` が `NoAccess`（E-PAGE-002・一手「戻る」）を出す（口は呼ばない）。見直すページの口が 403 のときも同じ「見られない」（`admin_counts` が外れた直後）
- **読む（`use-review.ts`・新）**：管理の一覧が開いたとき `getKnowledgeReview`（`GET /knowledge/review`）を **1 回**（`["k696","knowledge","review"]`・`retry: false`・`staleTime: Infinity`・窓に戻っても読み直さない・StrictMode でも 1 回・G-16）。口の答え `{ data: { unused, conflicts, broken } }` を `reviewRows(answer)`（画面の外の純粋な関数）で部品の `ReviewProps` にする：`unused[]`＝`{ id, title, place, lastOpened }`（`lastOpened`＝`lastOpenedText(last_opened_at)`＝日本時間の「AI が最後に開いた：yyyy/mm/dd」・null は「AI が最後に開いた：1 度も無い」）・`conflicts[]`＝`{ id, upper, upperPlace, lower, lowerPlace, point }`（`upper`＝`upper.title`・`upperPlace`＝`upper.place` ほか。行の id の組から上下のページの id を引く `pairs[id] = { upperId, lowerId }` も作る）・`broken[]`＝`{ id, title, place, count, how }`。**場所の字は口の `place` をそのまま出す**（画面で作らない）。画面は役の名前で出し分けず、口の答えで出し分ける
- **読む口の失敗**：403＝本文の場所に `NoAccess`・503・網の切れ＝`ErrorState`（`errorCodeOf`：503 → E-PAGE-003・それ以外 → E-PAGE-007）と一手「もう一度読む」（読み直す）。木・管理の入口はそのまま
- **空・50 件**：1 つの一覧が 0 件なら、その一覧の見出しの下に「使われていないページはありません」／「食い違っているページはありません」／「よく破られる決まりはありません」（`reviewEmptyText`・**仮**）。1 つの一覧がちょうど 50 件（`REVIEW_LIMIT`＝K-695 の上限）なら、見出しの下の説明の次に「多い順に 50 件まで出しています。」（`capNote`・**仮**）。49 件以下には出さない。見出しの数は返った行の数
- **「開く」**：`ctx.go(reviewPageHref(id))`＝`/knowledge/<id>`。そのページの口は K-682 の入れ物が読む（この葉は呼ばない）
- **「書き方を直す」**：`ctx.go(reviewPageHref(id, true))`＝`/knowledge/<id>?edit=1`。**K-682 の入れ物 `knowledge-page.tsx` が、ページの答えが読めた後 1 回だけ**、`startsEditing(search, acts に edit が在るか)`（`?edit=1` で、書ける人だけ真）が真なら `setEditing(true)`（K-683 の `WritingSlot` が書いている画面にする）にし、**そのあと道から `edit` を外す**（`router.replace(pathname)`）。書けない人（acts に `edit` が無い）・口が失敗した人には、読む形のまま開く（口 0 回・赤い箱を出さない）。再読み込みでは `edit` が無いので読む形に戻る（K-683 の K683-UI-022「直すだけ押して再読み込みは読む形」と同じ）。**書き込みの口は呼ばない**（保存は K-683 の自動で保存）
- **「並べて見る」（下絵に無い・仮）**：押すとその行の下に `role="region"`・`aria-label="2 つのページを並べて見る"` の領域が開き、**上のページと下のページの本文を左右に並べる**（幅 767 以下は上下）。各列は「題名・場所」の見出しと本文（`DocView`＝`@/features/F9/…` ではなく `@/features/F4/doc/editor` の読む部品・K-670。Tiptap・ProseMirror を直に読まない・境界 B10）。ページは `getKnowledgePage` で**開いたとき 2 ページ分を同時に**読む（`["k696","knowledge","page",<id>]`・`staleTime: Infinity`・同じ行を閉じて開き直しても、別の行が同じページを開いても読み直さない・開く・閉じる・開くを続けても各ページ 1 回）。ボタンは `aria-expanded`（閉じているとき false）・名前は部品のまま（`<上>と<下>を並べて見る`）で、もう一度押すと閉じる。1 つの列が読めない：404・403 は列に「見られません」（E-PAGE-002・どれかを知らせない）・503・網の切れはその列に ErrorState の文（E-PAGE-003・E-PAGE-007）と「もう一度読む」（その列だけ読み直す）。もう一方の列は読めていれば出す。下絵の kn-review は閉じた形なので、モックとの突き合わせ（K696-UI-001）は閉じた形で行う
- **部品に足す物（見た目と並びは変えない・任意の props だけ）**：`admin-views.tsx` の `ReviewView`（`handlers?: { open(id), fix(id), compare(id) }`・`openIds?`〔並べて開いている行〕・`panes?`〔行の id → 並べる領域の `ReactNode`〕・`limitNotes?`〔一覧ごとの注記〕）・`Block` に任意の `empty?`（空の字）と `note?`（注記）。`admin.css` に並べる領域の規則（`.k-f9-pair-open`・既存の余白・色の変数だけ。生の色・大きさを書かない＝design_gate D1〜D6・幅 767 以下は 1 列）を足す。渡さない呼び方（モック）は今の見た目のまま。動きの無い操作は押せない形（`aria-disabled`）。`knowledge.css` は変えない
- **読み上げ・キーボード**：「開く」「書き方を直す」は button（`aria-label` は部品のまま「<題名>を開く」「<題名>の書き方を直す」）・「並べて見る」は button（`aria-expanded`）・並べる領域は region・赤いお知らせは `role="alert"`。Enter で開閉・移動、焦点は押した所に残る（並べて見るを閉じたら「並べて見る」へ）
- 画面は題名・場所・点・破られ方・本文を字として描く（`dangerouslySetInnerHTML` を使わない）

## 代表に聞くこと

- **「並べて見る」の見た目**（下絵に無い・新しく出た）。実例：「請求書の送り方（会社）」と「見積書の出し方（営業）」が食い違っている。管理者の高本さんが「並べて見る」を押す。勧めは**その行の下に、上と下の本文を左右に並べてその場で開く**（もう一度押すと閉じる・幅が狭ければ上下）。違う答え（2 つのページへのリンクだけにする・小窓で並べる）が来たら、`ReviewAdmin` の並べる領域を替える
- **「書き方を直す」の行き先**（新しく出た）。実例：「メールの書き方」が 30 日に 7 回破られた。高本さんが「書き方を直す」を押す。勧めは**そのページを書いている画面でそのまま開く**（題名・本文が打てる形）。違う答え（読む形で開く）が来たら、`?edit=1` を付けるのをやめる（入れ物の 1 か所）
- **場所の字の頭**（下絵と口の食い違い）。実例：営業のページの場所が、下絵では「グループ：営業 › 見積もり」、口では「営業 › 見積もり」。勧めは**口の字のまま（頭を付けない）**。違う答えが来たら、口の `placeText` か下絵のどちらかを直す
