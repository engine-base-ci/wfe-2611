## 目的

「自分に関わるもの」の上の札（期限切れ 2・今日まで 3・自分が承認・AI が動いている）と、絞りの札（自分が担当 11・AI に任せている 5・自分が承認 2）の数を、**数だけの口を作らず**、一覧 `listTickets` の 1 回目の答えの `meta.counts` で返す（D-128.111・D-144.3：本当の値が無い数は出さない）。画面は K-478。

- 付く条件：**`view=mine`（既定）で、`cursor` が無いとき**だけ。`view=all`・次の分（cursor 付き）には付けない（meta は next_cursor だけのまま）
- 鍵はちょうど 5 つ（数は 0 以上の整数・完了のチケットは数えない・「渡されたもの」は数えず鍵も作らない・D-148.13／D-151.19）：
  - `overdue`：自分に関わるもので、期限が日本時間の今日より前（K-473 の `isFire`＝期限切れと同じ）
  - `today`：自分に関わるもので、期限が日本時間の今日
  - `assigned`：担当が自分（AI に任せているものも・期限なしも）
  - `ai`：担当が自分で AI に任せている（`delegated_to_clone`）
  - `approve`：自分が承認する（まだ決めていない・取り下げ・承認の行を消した・チケットを消したものは数えない）
- 数は **自分に関わるものの全体**で、`q`・`scope_id`・K-472 と K-473 の絞り込み・並び・limit・fields では変わらない（札は絞り込みの入口なので、絞ると数が変わっては押せなくなる）。見える範囲（行の守り・消したもの・他の人の下書き）の中だけを数える
- PM の「期限切れ・今日まで・自分が承認・AI が動いている」に、絞りの札の「自分が担当」（`assigned`）を足した（下絵 Main の「自分が担当 11」に要る。足さないと画面が数を出せない）

## 前提と制約

分類: LIST, PERM

- `ai`・`approve` の数と K-473 の欄 `delegated=true`・`approving=true` は **query.ts の `DELEGATED_SQL`・`APPROVING_SQL`（K-473 が置く）を使い、数だけ別に書かない**（K474-API-015 が絞った件数と突き合わせる）
- 「自分に関わるもの」の条件（担当者が自分か、自分が承認する決めていないもの）は、**一覧と数で 1 つの部品を共有する**（hooks.ts の中の SQL の断片 `MINE_SQL`。数だけ別に書かない・書くと一覧と数がずれる）。数える完了の除き方は K-472 の `done=false` と同じ `s.key is not distinct from 'done'`
- **文は 1 本のまま**（速さの台帳 `scripts/ci/perf_budget.json` の `GET /api/v1/tickets?limit=50` は max_statements 6・max_begins 1。この葉は台帳を緩めない）。数える select は、一覧の select の CTE に入れて 1 つの文で返す（`with page as (…), cnt as (select … count(*) filter …) select … from cnt left join (一覧の行) on true`。一覧が 0 件でも counts の行が 1 行返る形にし、行が無いときは data を空にして counts だけ取る）。mine の 1 回目だけ CTE `cnt` を足し、ほかの形では足さない（all・次の分は今の文と同じ）
- counts は答えの `meta.counts`（`{ overdue, today, assigned, ai, approve }`）。型は契約の META の dict の形（`{"type": "object", "properties": {…各 integer}}`）で、必須にしない（付かない答えがある）
- 日本時間の今日は K-92 の `todayJst()`（口が `Date.now()` から決める・試験が時刻を固定できる）。期限切れ・今日の判定は K-473 の `isFire`・`due_on = $2::date` と同じ定義
- 新しいエラーの番号は足さない。`E-LST-040〜049` の枠は使わない。この葉は新しい 4xx も契約に書けない 422 も作らない（counts は付くだけ）。続きの鍵が読めない 409・E-LST-001 は K-472 の物で、counts は鍵なしの 1 回目だけに付くので、その 409 の答えには counts が付かない（409 の本文は KanameError の形で `meta` を持たないため。K-472 の K472-API-016 は code・field・details を見る物で、counts の有無は見ない）
- 見える範囲・総数を返さない（D-144.3）・一覧の答えの 12 の鍵・並び・keyset は変えない。関門：C2（DB を読む）だけ。ログに題名と q を出さない
- 試験を書いた後は変えない（D-128.125）。実装の前に試験を流して赤を確かめない（D-128.143）
