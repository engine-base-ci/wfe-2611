## 目的

流れ F4「チケットを作って中身を決める」。K-60 で作ったチケットの下書き（ticket_drafts）は、作った本人にしか見えず配られない（D-125.57）。その人がワークスペースから抜けても（members.deleted_at が入っても）、下書きは消されずにずっと残る。本人はもう見られず、ほかの誰にも見えないのに、中身（書きかけの題名・目的など）が DB に溜まり続ける。K-60 のテスターが見つけた（2026-11-07）。途中で見つけたものはその場で直さずチケットにする（D-128.147）。

（K-140 からまとめた・2026-11-07）K-60 の下書きの扱いの残り 3 つ（K-60 のテスターのレビューで出た LOW・どれも下書きの写しの扱い）もこのチケットで直す。

1. **同意し直しの画面で 401 のとき写しを消していない**：`apps/web/features/F1/consent-terms/consent-terms.tsx` の 79 行で、getMe が 401 のとき `setToken(null)` だけしてログインへ送る。ほかのログイン切れ（lib/auth/session.tsx）とログアウト（同じファイルの 144 行）は `clearDraftCopies()` を通すのに、ここだけ通らない。共有の PC で、次の人に前の人の書きかけの写しが残る
2. **別のタブでチケットになった下書きへの保存を黙って捨てる**：新しいタブで続きとして下書きを出してチケットを作ったあと（source_draft_id で元の下書きを消す）、元のタブで書き続けた分の保存は、答えを捨てるので画面は「残せた」と思ったまま。書いた分が消えるのに利用者に言わない（失敗は何が起きたかと次にすることを言い、書きかけが消えないことを必ず言う・D-128.62）。捨てた答えに印を付け、「この下書きは別のタブでチケットになりました」と次にすることを出す
3. **この PC の写しが本人ごとに 1 つ**：写しの鍵が「ワークスペース × 本人」（draft.ts の COPY_KEY）なので、2 つのタブで別々の下書きを書くと、この PC の写しは最後に書いたほうだけになる。タブの id も鍵に入れる（書きかけはどの端末でも続きが書ける・D-128.138）

分類：JOB（時間で動く処理）・CRUD

## 完了の条件

- [ ] 抜けた人の下書きを、抜けてからどれだけの間とっておき、いつ消すかを決める人が決め、決定ログに入っている（**とっておく長さは決める人に聞く**。作る役が勝手に決めない）
- [ ] 決めた長さを過ぎた抜けた人の下書きを消す、時間で動く処理がある（何度流しても同じ結果・途中で止まっても次の回で続きから・ほかの人の下書きと抜けていない人の下書きは消さない・ほかの組織の下書きに触らない）
- [ ] 抜けた人が戻った（とっておく間に入り直した）ときの扱いが決まっていて、試験で受けている
- [ ] 消したことは件数だけ記録する（中身・メールを出さない）
- [ ] 同意し直しの画面の 401 で `clearDraftCopies()` を通す。ログインが切れる所・ログアウトする所を全文検索で洗い、写しを消さない所がほかに無い（同じ形を 1 つの関数にまとめる・L-008）（K-140 から）
- [ ] 別のタブでチケットになった下書きへの保存の答えを捨てず、画面に「この下書きは別のタブでチケットになりました」と、作ったチケットへの道（または新しく書き始める道）を出す（K-140 から）
- [ ] この PC の写しの鍵にタブの id を入れ、2 つのタブの写しが上書きし合わない。ログアウトとログイン切れでは今までどおり全部消える。古い鍵の形の写しの扱い（読む・消す）を決めて書く（K-140 から）
- [ ] 写しの 3 つとも、実ブラウザの試験の行で受ける（出したメッセージを実際に出す）（K-140 から）
- [ ] DB の書き込みは関門 C2 を通す。migration を足すなら取り込む順の次の空き番号で足し、Squawk を通す
- [ ] チケットの CI（act）が緑

## 前提と制約

- 依存：K-60（ticket_drafts の表と下書きの口が取り込まれてから。写しの扱いは apps/web/features/F4/create-ticket/draft.ts・create-ticket.tsx・lib/api/client の clearDraftCopies）
- 同意し直しの画面は F1（K-53）の物。直すのはこの 1 か所の写しの扱いだけで、同意の流れは変えない（K-140 から）
- 下書きの口（listMyTicketDrafts・saveMyTicketDraft）の形は変えない。変える要るなら切るときに書く（K-140 から）
- 時間で動く処理の置き場（段階 1 の配布先で動かす方法）は目録で今ある物を探し、無ければ選び方を実装の詳細に書く
- 止められた人（suspended_at）・会社ごと止めた・消したときに同じく消すかも、決める人に聞く項目として並べる
- 同じ形で抜けた人の物が残る表（ほかの本人だけの物）がほかにもあるかを全文検索で洗い、あれば別のチケットにする（L-008）
