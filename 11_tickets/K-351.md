## 目的

「自分の設定 › 預けたログイン情報」の画面（K-356）が開いたときに呼ぶ契約の口 `listCredentials`（GET /api/v1/credentials）を作る（今は 501）。
答えは、自分の個人の物と、自分のワークスペースの物を、名前の順に返す（名前で並ぶ・値は誰にも見せない・D-128.55・D-125.151）。答えに金庫の参照（vault_ref）と持ち主の id を出さない（K-250 の申し送り・D-128.57）。

あわせて、表 `credentials` に **名前・説明・層（ワークスペース／個人）** の列を足し（D-125.148・代表の答え ac0813ee7c21 ②「ワークスペースと個人」）、
行の守りを **個人の物は持ち主だけが書ける** 形に直す（D-128.57 ①）。今の守りは「持ち主（self_only_write）」と「credentials の edit の権限（permission_write）」の **または** なので、
権限のある人が他人の個人の物を書けてしまう。

預ける口は K-352、上書きと消すは K-353、画面は K-356。

## 前提と制約

分類: LIST

- 前の道すじ `/api/auth-ext/vault/credentials`（apps/api/src/auth/ext.ts の 599〜890 行）と前の画面はこの葉では消さない（消すのは K-358）。だから **名前と層を入れない insert（前の道すじの形）も通る** ように、名前は列の既定で埋め、層は既定で personal にする
- 扱う物は「秘密だけ」（代表の答え ac0813ee7c21 ①）。設定（秘密でない値）は後の段
- 層は「ワークスペース」と「個人」の 2 つだけ（同 ②）。グループの層は作らない
- ワークスペースの物を書けるのは credentials のワークスペース全体の edit を持つ人（既定は管理者の束・migration 0080 の role_bundle_defaults の admin）。キャンバス MeSecrets の「ワークスペース全体や層で共有するログイン情報は…管理者が預ける」（04_design/canvas_gen/me.py:99）と同じ
- 一覧は数が少ない（1 つのワークスペースで多くても数十）ので、cursor・limit は入口の共通の確かめ（形）だけで、口は全部を名前の順に返す（上限 500 行で切る・切ったらログに出す・K351-API-020）
- 関門の宣言（頭の欄 choke_points）は [C2, C8]。一覧の口は預かり先を呼ばないが、宣言は契約の口の関門と同じにする（関門の宣言の検査 KC4）
- 口の登録は葉ごとの hooks のファイル（K-326）。この葉は `apps/api/src/hooks/credentials-list.ts` を作り、K-352〜K-355 はそれぞれ自分の hooks のファイルを作る（同じファイルに足さない）。預かり先の関門 secrets は、この葉が材料 HookDeps に 1 欄足す（後の葉は registry.ts・server.ts・fuzz の的を触らない）。env は `d.config.env` を要求ごとに読む

### 範囲の地図（ci_scope.d/K-351.json）

土台 `credentials.harness.ts`（carry で運ぶ道具）は、葉の hooks のファイル `apps/api/src/hooks/credentials-*.ts` を readdirSync と動的 import で読む。パスを組み立てて読むので、import の地図（vitest の関わり）では hooks → 試験が辿れない。reads_ok だけだと、hooks や口のコードを変えても試験が選ばれず、範囲の道具が「試験の無いコード」で止まる（2 回目の精査の指摘）。だから data_links で名指しで結ぶ（形は scripts/ci/ci_scope.py の data_links ＝ paths と tests。前例は _base.json の F2 invitations「features と hooks → 試験」と K-364）。

  "apps/api/test/features/F3/credentials.harness.ts": "入っている葉の hooks のファイル apps/api/src/hooks/credentials-*.ts を readdirSync と動的 import で読む（まだ入っていない葉の物は無いので、在る物だけを差す）。読む物と使う試験は data_links で結ぶ・K-351"
