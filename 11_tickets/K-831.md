## 目的

管理者が、ワークスペースの設定を 1 画面で見て直せるようにする（行為 A75）。「誰ができるか」で可になった人（管理者とマネージャーにしたマネージャー・個別に付けた人）も開け、可の区画だけ押せる（D-154.83）。道 `/settings/company`（flow.json の画面 `company-settings`）。区画は 4 つ：「このワークスペース」（名前・ロゴ）・「プランと支払い」（段 13 が口につなぐ差し込み口）・「誰ができるか」（2 行の ▾）・「ワークスペースを消す」（小窓は K-832）。口は `getWorkspaceSettings`（K-827）を 1 回読み、名前は `updateWorkspace`（K-827）・ロゴは `uploadWorkspaceLogo`（K-828）・誰ができるかは `updateWorkspacePermissions`（K-829）。

この葉は**読む・名前・ロゴ・誰ができるか**まで。消す手続きの小窓と手続き中の帯は K-832、プランと支払いの中身は段 13 の K-962。それまで「消す手続き」と「プランを変える」「請求書」は押せない形（グレー・隠さない）。「取引先」の区画・取引先の見える人の既定・書き出しは作らない（D-154.22・D-154.4）。

## 前提と制約

分類: CRUD, PERM, FILE

- **口の答えの形は K-827 の「画面が使う答えの形」**：`getWorkspaceSettings` → `{ data: { workspace: { id, name, logo: { kind: "text"|"image", url } }, permissions: [{ key: "billing"|"delete_workspace", name, detail, value: "admin"|"admin_manager", options }], fixed_rules: [{ key, text }], deletion: { requested_at, delete_at, days_left, requested_by, preview: { tickets, members } }, access: { admin, billing, delete_workspace } } }`。名前の答えは `{ workspace }`・ロゴは 201 `{ logo }`・誰ができるかは 200 `{ permissions: [{ key, value }] }`（K-828・K-829）。違えば `f10-ops-kit.ts` の `settings()` だけを合わせる
- **外枠**：道は `app/(work)/settings/company/page.tsx`（PC をつないでいなくても開く）。`TicketShell`（screen `company-settings`・パンくず「ワークスペースの管理 › 設定」）・`WsHead`・`WsSub active="settings"`（K-420・K-710 の物）・`k-me-wrap` の中に `SettingsPage`（K-801 の部品）。**第 2 ナビの行き先は、この葉が `features/F10/invite/views.tsx` の `WS_ITEMS` の記録を `/audit`・設定を `/settings/company` に直す**（flow.json の道に合わせる・K-825 は記録の道を足すだけ）。直すのは href の 2 つだけで、並び・見た目・字は変えない。道が作られるまで押せない形・作られたら押せるリンク（K-818 の形）はそのままなので、この葉が入った時点で「記録」は /audit が無いので押せない形のまま、K-825 が /audit を足すと押せる（K831-UI-003 は両方で成り立つ形）
- **権限（D-154.83）**：開けるのは管理者と、「誰ができるか」で可になった人（口 K-827 が決める）。閲覧のみ（依頼する側）は会社の設定を持たない役なので `useMyRoles()` で入れ物が先に止め（口 0 回）、`NoAccess`（モック st-no-access と同じ作り・外枠の中の `section aria-label="設定"`・「この画面を見る権限がありません」）を出す。役を読み終えるまでは本文の場所に `Loading`（NoAccess を一瞬出さない・口も呼ばない）。ほかの会社の人（管理者・マネージャー・メンバー）は口を 1 回読み、口が 403（どちらも可でない・管理者でなくなった直後）なら同じ NoAccess（K831-UI-016・020・024）。兼務でグループのマネージャーなだけの人は可にならない（K-827 の判定・D-154.15）
- **可の区画だけ押せる（D-154.83）**：押せるかは口の答えの `access` で決める（役で決めない）。`access.admin` が false なら名前の欄は読むだけ（`readOnly`・保存しない）・ロゴの「変える」と「誰ができるか」の ▾ は押せない形（aria-disabled・口を呼ばない）。「消す手続き」は `access.delete_workspace` が false なら押せない形。「プランと支払い」は区画を出し、押せるかは `access.billing` を planRow を差す段 13 の K-962 に渡す（この葉の間は今の押せない 1 行）。隠さない（K831-UI-025）
- **名前**（保存のボタンは無い）：打つたびに誤りを出す（空・空白だけ「名前を入れてください」・101 字「名前は 100 文字までです。短くしてください」。`Array.from` で数える＝絵文字は 1 字・口 K-827 と同じ数え方）。**欄を離れたとき・Enter で保存**：前後の空白（全角を含む）を削り、今の名前と同じなら送らない・誤りがあれば送らない。`updateWorkspace { name }`。200 → 「✓ 保存しました ・ HH:mm」（日本時間）と「N ／ 100」・答えで名前を差し替える（読み直さない）。503・網の切れ → 欄の下「保存できませんでした。もう一度、入れ直してください」（入れた字は残す）。422（E-WS-001・002）→ 口の文を欄の下に。処理中の Enter は無視（二度押しで 1 回）
- **ロゴ**：「変える」でファイルを選ぶ（`input[type=file]`・`accept` は `image/png,image/jpeg,image/webp`・画面には出さない）。**2 MB（2×1024×1024 バイト）を超える物は口を呼ばず**赤い箱「ロゴは 2 MB までです。小さい画像を選んでください」（ちょうど 2 MB は送る）。送るのは `call("uploadWorkspaceLogo", { form })`（multipart の `file` 欄・下の「口の呼び手に form を足す」）。201 → 左のロゴを画像に（`img` の `src` は答えの url）・誤りを消す。413（E-WS-010）・422（E-WS-011）・502（E-WS-012）→ 口の文を赤い箱に。503・網の切れ → 正本の E-PAGE-003 の文。どの断りでも前のロゴのまま。選び直した後に同じファイルを選べるよう、送ったあと欄の値を空に戻す
- **誰ができるか**（2 行だけ・書き出しの行は作らない）：行の ▾ を押して選び直すと `updateWorkspacePermissions { <鍵>: <値> }`（**選んだ鍵だけ**）。今の値を選んだら送らない。値の字は「管理者」（admin）・「管理者とマネージャー」（admin_manager）。200 → 答えの値で差し替える（読み直さない）。**403 STEP_UP_REQUIRED** → `getMySecurity` を 1 回読んで `StepUp`（features/F1/security/step-up.tsx・パスキーだけの人はパスキー・D-154.3）を開く（理由「<行の名前>を変える前に、本人か確かめます」・**仮**）。通ったら同じ体で 1 回だけやり直す・やめたら何も送らない（K-363 と同じ形）。503・網の切れ → 区画の上に赤い箱（E-PAGE-003 の文）・値は前のまま。権限の 403 → 権限なしの画面に替える
- **口の呼び手に form を足す**（`apps/web/lib/api/call.ts`・この葉と K-839 が使う）：`CallArgs` に任意の `form?: FormData` を足す。`form` があるとき、体はその FormData・`content-type` は付けない（境の印は fetch が作る）・冪等キーと画面の印と答えの扱い（401・403・404・413・422・429）は今のまま。`form` が無い呼び方は 1 字も変えない（K831-UN-002）。前からの `api-call.test.ts` は変えない
- **プランと支払い**：入れ物 `settings-screen.tsx` が部品の `planRow?: ReactNode`（K-801 の部品が持つ・下の部品に足す物）を受け口として持ち、**渡さない間は部品の押せない 1 行**（`SettingCard title="プランと支払い"`・`labelledBy="ws-plan"`・「プランを変える」「請求書」が aria-disabled）。段 13 の K-962 は `settings-screen.tsx` の 1 行（`planRow={<PlanRow … />}`）を足すだけで、この葉の部品・入れ物の他の所は変えない。入れ物には `// K-962（段 13）がここに planRow を渡す` の印の 1 行を置く
- **消す手続き**：`settings-dialogs.tsx`：`export const SETTINGS_DIALOGS = { /* K-832 が delete を 2 字下げの キー: 部品, の形で 1 行足す */ }`・`openable(key)`。登録の無い間は「消す手続き」を aria-disabled・title「まだ使えません」にする（K831-UI-019 が登録の有無を字で読む：`^ {2}(delete)\s*:`）。手続き中の帯は K-832 が `deletingDaysLeft` を渡して足す（この葉は渡さない）
- **突き合わせの組（f10-ops-kit.ts の SET_PAIRS）**：「プランと支払い」の区画（`[aria-labelledby=ws-plan]`）は箱の位置（x・y）と見出しの字だけを比べ、中身（区画の中の `.k-set-row` を含む）は比べない（段 13 の K-962 の決め (a)：中身は段 13 の下絵が正。K-962 が planRow を差しても K831-UI-001 は赤にならず、K-962 が changes の外を直さない）
- スマホ（767 以下）は崩れず読めて押せる（D-154.13）。幅 320 でも横のはみ出し 0（100 字の名前・誤りの赤い箱・開いたメニューでも）
