## 目的

初めての人が、メール・名前・会社名（空でもよい）・パスワードを入れて「次へ」を押すと、**保留の申し込み**が作られ、確認のメールが 1 通届く。画面は「メールを確かめてください」に進む。

**登録が確定するのは、このチケットではない。** 確認のメールのリンクを押した時点で確定する（次のチケット「メールを確かめる」）。このチケットが作るのは、30 分で切れる保留の申し込みまで。

## 完了の条件

- 上の 2 つの表の「このチケット」のマスと、全部の分岐のテストが緑
- 前の道すじ `POST /api/auth-ext/sign-up` と前の画面が消えている
- 契約の口 `createSignup` が 501 でない
- 単体のテスト（下の表で「このチケット」が受け持つマスと、全部の分岐）が本物の DB と本物のブラウザの上で緑
- 中間テスト「登録 → メールの確認 → 規約」（K-54）のうち、このチケットの分が通る
- 手元の CI（dagci）が緑

## 前提と制約

分類: REG, MAIL, EXT

- 流れ F1 登録してログインできる（K-50）。歩く骨格の 1 本目（D-128.131）
- 依存：なし。次のチケット「メールを確かめる」（K-52）とは、下の表のマスで受け持ちを分ける
- テストはこのチケットを作る人がコードまで書き、実装する人は変えない（D-128.125）

### 決めた判断

- 会社名は空でもよい。空なら本人の名前で個人のテナントの申し込みになる（D-125.135）。**今の前の道すじは会社名を必須にしている（E-VAL-006）ので、決定に合わせて直す**
- 規約の同意は、キャンバスの絵のとおり登録の画面の中（「続けると利用規約とプライバシーに同意したことになる」）。同意した版と時刻は保留の申し込みに残し、確定のときに本人に移す
- 同じメールで確かめていない申し込みが既にあれば上書きし、前のリンクは使えなくする（D-088.3）。前のリンクの手がかりは消さずに残し、開かれたときに「前のリンク」と見分けられるようにする（K-52）
- 規約の画面の版は、K-53 の `getCurrentTerms` ができるまでは、今の版を直に読む
- ログイン中の人が登録の画面を開いたら、登録させずに今のアカウントの画面へ移す（別のアカウントを作りたいときは、ログアウトしてから）
- 照合の外のサービスが落ちているときは、登録を止めずに通し、セキュリティの記録に残して運営に知らせる（D-128.134）

| 保留中（期限内） | 確認のメールのリンク | どれでも | 確定する | メールを確かめる | — |

| 確定済み | 確認のメールのリンクをもう一度 | ログインしていない | 「登録は済んでいます。ログインへ」（D-088.9） | メールを確かめる | — |
| 確定済み | 確認のメールのリンクをもう一度 | ログイン中（同じ人） | 今のアカウントの画面へ | メールを確かめる | — |
| 確定済み | 確認のメールのリンクをもう一度 | 別のアカウントでログイン中 | 今のアカウントのまま。「別のアカウントの登録のリンクです」と出し、勝手に切り替えない | メールを確かめる | — |
| 保留中 | 確認のメールのリンクを別の端末・別のブラウザで | ログインしていない | 確定する（同じ端末でなくてよい） | メールを確かめる | — |

### テストの型の受け

| 型 | どこで受けるか |
|---|---|
| TP-REG-01 確定の時点 | 「何を実装するか」に書いた（確定はメールのリンク・次のチケット） |
| TP-REG-02 期限切れのリンク | 状態の表「保留中（期限切れ）× 確認のメールのリンク」（受け持ち：メールを確かめる） |
| TP-REG-03 確定後に同じリンク | 状態の表「確定済み × もう一度」（受け持ち：メールを確かめる） |
| TP-REG-04 送り直しで前のリンク | 状態の表「前のリンク」（受け持ち：メールを確かめる）・このチケットは上書きで前を使えなくする |
| TP-REG-05 別の端末・別のブラウザ | 状態の表「保留中 × 別の端末」（受け持ち：メールを確かめる） |
| TP-REG-06 ログイン中・別のアカウント | 状態の表「無し × ログイン中」（このチケット）・「確定済み × 別のアカウント」（メールを確かめる） |
| TP-REG-07 登録の有無を見せない | 守り「登録済みかを探られる」 |
| TP-REG-08 メールの正規化 | 入力「メールの大文字小文字・前後の空白・全角」 |
| TP-REG-09 漏れたパスワード | 入力「漏れたパスワード」・失敗「照合のサービスが落ちている」 |
| TP-REG-10 長さの境目 | 入力「パスワード 11 文字／12 文字」 |
| TP-REG-11 回数の上限 | 守り「1 分に 11 回」 |
| TP-REG-12 同時に 2 回・2 回押し | 操作の揺れ「2 回押し」「同じメールで同時に 2 回」 |
| TP-REG-13 規約の版と時刻 | 守り「規約の版」。同意し直しは「規約に同意する」のチケット |
| TP-REG-14 平文で残さない | 守り「DB の中」「ログ」 |
| TP-MAIL-01 送れなかったとき | 失敗「メールが送れない」 |
| TP-MAIL-02 二重に出ない | 操作の揺れ「2 回押し」（メールは 1 通） |
| TP-MAIL-03 本文に秘密を入れない | 守り：メールの本文にパスワードを入れない・リンクは期限つき（単体でメールの本文を見る） |
| TP-EXT-01 外が落ちた・遅い | 失敗「照合のサービスが落ちている」（通して記録・運営に知らせる） |
| TP-EXT-02 想定外の形 | 失敗：照合の答えの形が違う → 落ちている扱い（単体で答えを差し替え） |

要らない: TP-EXT-03 照合は問い合わせの答えを待つだけで、外から知らせが届く口ではないため
