## 目的

チケットのやり取りで話して決まったことを、その書き込みから決定ログに残せるようにし、決定を改める・取り消すをできるようにする（行為 A108・A107・用事 J20）。

- やり取りの書き込みの「決定にする」（下絵の書き込みの操作の行・`features/F6/thread/views.tsx` の Post の「決定にする」）から小窓「決定にする」（説明「書き込みを決定ログに残す。あとから根拠として引ける」・元の書き込みの箱）。決めたことの欄は書き込みの本文で始まり、人が直す（⑯ a：AI の案はグレー「AI の案は、自分の AI と話す画面ができてから使えます」・「本文と食い違う所…」の箱もグレー）
- 決定になった書き込みには「✓ 決定にした」（下絵どおり）
- 決定を改める：小窓「決定を改める」（説明「前の決定は消えず、「改められた」の印が付きます」・前の決定・新しい決定・改める理由）。古い方に「改められた」（D-125.63）
- 取り消す：確かめ「この決定を取り消しますか？」（取り消す理由が必須・「取り消した印と理由が残ります（消えません）」）。一覧では線を引いて下に（⑰ a）
- 同時にほかの人が改めていた：「この決定は、いま別の人が改めました。読み直してから、もう一度お試しください」（㉒）と「閉じて読み直す」。開いている間にほかの人が取り消していた（409 E-CONF-033）ときも同じ形で、字は E-CONF-033 の正本の文「この決定は、いま別の人が取り消しました。…」（K-391・仮）
- 取引先を持たないので「取引先のルールにする」の選び肢は無い（answer=4961f0280e9a）

正の絵はモック `/dev/mock/f6/<状態>`（本番と同じ部品 `features/F6/decisions/views.tsx`・K-382 が本線に入れる）の dec-from-message・dec-revise・dec-cancel・dec-conflict。見た目はモックの画面と本番の画面の写しを同じ幅（375・768・1440）で比べる（共通の道具 `apps/web/tests/k/stage2-match.ts` の matchMock・base は /dev/mock/f6）。
**書き込みの操作の置き場**：PM の頼みは「やり取りの行の「…」から」だったが、正の絵（下絵 OK の Post）は「…」の外の操作の行に「決定にする」を置いている（「…」の中は 直す・消す…）。正の絵に合わせた（報告に書いた）。

## 前提と制約

分類: CRUD, XSS

- 部品（views.tsx の DecisionDialog の from・ReviseDialog・CancelDecisionConfirm・DecisionLog の 改める／取り消す、thread/views.tsx の Post の「決定にする」「✓ 決定にした」）は K-382 が下絵のまま本線に入れる。この葉が足すのは押したときの関数・送っている間・欄の値を受ける口だけで、形・クラス・字は変えない
- 書き込みの行の「決定にする」は、K-382 が `features/F6/thread/from-message.tsx` に `FromMessageAction` を「まだ」の形で置き、**K-392 が受ける物を `{ ticket; item: TimelineItem; post: PostView }`（書き込みの 1 件と部品の値）に広げ、views の `DecideAct`（押せない形・決定の元なら「✓ 決定にした」）を返す形にする**。やり取りの一覧（K-392 の panel.tsx）が、それを部品 Post の置き場 `decideSlot` に置く（`decideSlot={<FromMessageAction ticket item post />}`）。書き込みの中身（名前・時刻・本文・種類・消したか・decided）は受けた item から読む（口を増やさない・問い合わせの器から引き直さない）。この葉は from-message.tsx の中身だけを作る（thread/panel.tsx・views.tsx・message-menu.tsx は触らない・受ける物の名前は K-392 の形のまま）
- 決定にできる・改める・取り消すのは書ける人だけ（⑧ a）。閲覧のみの人には「決定にする」「改める」「取り消す」を出さない（決定の一覧の口の meta.can_write・K-390。「✓ 決定にした」は読めるので出す）
- 決定にできる書き込みは、人の書き込み（kind post）で消していない物だけ。変更の 1 行・仕組みの 1 行・消した跡・AI の実行の 1 枚には「決定にする」が無い
- 「✓ 決定にした」はやり取りの口の答えの message.decided（K-383・K383-API-014）のとおりに出す（画面で決定の一覧と突き合わせない）。取り消した決定の元は decided false で「決定にする」に戻る（仮・K-383 に頼む）
- 改める理由は空でもよい（正の絵の欄に必須の印が無い）。新しい決定は必須（前後の空白だけなら空）。取り消す理由は必須（⑰ a）
- 決定にした・改めた・取り消した後は、決定の一覧とやり取りを同時に 1 回ずつ読み直す（やり取りに「〈名前〉 が決定を足した／改めた／取り消した」の 1 行が残る・⑲ は口の葉）
- 字は書いたとおり送り、画面では HTML を動かさない（TP-XSS-L01）。promoted_to は口に送らない
