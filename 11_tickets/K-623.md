## 目的

spec-sync の D0（分母）は、決定ログで `status: confirmed` かつ `reflect_in` を持つ決定が、全部 alignment_decisions に登録されているかを見る。2026-11-07 の記録の後に決定ログへ D-129〜D-148 が足されたが、地図に登録されていない（19 件：D-129〜D-136・D-138〜D-148）。D8 の「未判定 26 組」も、この 19 件の反映先に確かめ方が無いことから出る。これは **本当の食い違い（直す）**。

登録は `tier_d.py --register` が機械で書けるが、**そのまま使うと空回りする**（実測：19 件を足すと 28 件が赤に変わる）。理由は、生成される線が `file: 11_tickets`（フォルダ名だけ）・`file: 要件一覧`（節の名前）のように、実在しないファイルを指すため。決定ログの `reflect_in` は実ファイルの道（`11_tickets/tickets.json`・`11_tickets/K-156.md`・`03_architecture/共通の決まり.md`・`04_design/DESIGN-kaname.md` など）で書いてあるので、**線の file にはその道をそのまま使い、marker に決定の ID を置く**（実測：この形で書くと残る赤は下の 4 つだけ）：

| 残る赤 | 中身 | 判断 |
|---|---|---|
| AD-129 | reflect_in が `要件一覧`（節の名前）で、道ではない | **設定の抜け**：線の file を `01_hearing/要件一覧.md` にする（要件一覧は T7 が決定ログから機械生成するので、D-129 の印が在る） |
| AD-133 | 「全部」の語で『どこでも効く』と読まれ、画面の線が要る。だが D-133 は CI の範囲の決め（画面の決定ではない） | **正しい例外**：`not_applicable: <理由>`（K-156・K-160 の CI の決めで、画面に当たらない）を書く。画面の線を偽って足さない |
| AD-145 | 「全画面の決まり：キャンバスに在る物は機能がまだでも出し、使えない物はグレーにして押せない形にする」。画面の線が無い | **本当の食い違いではなく線の抜け**：`gate: python3 scripts/ci/k219_canvas_states_test.py`（キャンバスの区画に使える形と使えない形＝aria-disabled と不透明度 0.55 が在ることを見る・D-145.9。実測：4 秒で緑）を画面の線にする |
