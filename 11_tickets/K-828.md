## 前提と制約

分類: FILE, PERM

- 入口の権限は契約のまま管理者の束（ロゴは D-154.43 の「誰ができるか」の 2 つに入らない。D-154.83 で設定の画面を開けるマネージャーにも、ロゴの［変える］は押せない形で出る＝K-831）。受け取りの形は `multipart/form-data` の `file` 欄 1 つ（自分の設定の顔の写真 K-834 と同じ形）
- **契約の入口（op.ts）は今、体を受ける口の体を 1 MB までの字として読み JSON で読む**。このままでは 2 MB のロゴは入口で 413（PAYLOAD_TOO_LARGE）・multipart は 422（欄 body）・バイトが字に読み直されて壊れる。そこで**この葉が入口に multipart の道を足す**（K-834 の顔の写真も同じ道を使う・K-834 はこの葉に依存する）。口が hooks に `multipart: { maxFileBytes, tooLarge }` を持つと、入口は (0) で体を字でなくバイトのまま「maxFileBytes ＋ 余白 64 KB」まで読み（超えたら読むのをやめて hooks の tooLarge の答え＝この口は 413・E-WS-010）、content-type が multipart/form-data でなければ 422（欄 body）、頭を付けたまま FormData に読み（読めなければ 422・欄 body）、(4) の JSON の読み・NUL・契約の strict な形を飛ばして FormData を `HookArgs.form` で hooks に渡す。冪等（5）の比べは欄ごとの中身（ファイルは中身の sha256）で行う（境の印は送るたびに変わるので生のバイトで比べない）。multipart を持たない口は今のまま（1 MB の字・JSON・strict）
- **種類は中身の先頭の印（マジックバイト）で見る**：PNG（89 50 4E 47 0D 0A 1A 0A）・JPEG（FF D8 FF）・WebP（`RIFF` ＋ 4 バイト ＋ `WEBP`）だけ。content-type と名前は信じない。SVG・GIF・空のファイル・画像でない物は 422（E-WS-011）。見分ける関数は `apps/api/src/features/F10/image-kind.ts` に 1 つ置く（この葉が作り、K-834 が使う）
- **大きさは 2 MB（2×1024×1024 バイト）まで**。判定は**ファイルの大きさ**（`file.size`）で行う：ちょうどは通り、+1 は 413（E-WS-010・「ロゴは 2 MB までです」）。体全体の長さは境の印と頭の分だけファイルより長いので、体の先の確かめ（入口・巨大な体を読み切らない）は余白つき（2 MB ＋ 64 KB）にする。ファイルの大きさは種類より先に見る
- **置き場は関門 C4**（`objects.put`）：権限・サイズ・保持期間・記録は関門の中。置けなければ 502（E-WS-012）で `tenants.logo_ref` を変えない（前のロゴのまま）
- **順番**：置く → DB の取引（logo_ref を新しい ref に・前の ref を返す・記録 `workspace.logo_changed`）→ 前の実体を消す（後片付け）。DB が落ちたら置いた新しい実体を消して 503（E-PAGE-003）。前の実体を消せなくても 201 のまま（ログに 1 行 `[workspace-logo] 前のロゴを消せなかった`・宛ての値は出さない）
- **同時の置き換え**は会社ごとの錠 `app.admin_lock()`（K-800）で順に通す。残るのは後に通った方
- 外に出す期限つき URL は読む口（K-827）が作る。この口の答えも同じ作り（`{ logo: { kind: "image", url } }`）
