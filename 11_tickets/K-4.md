## 目的

チケットのまわりの表（テスト仕様・検査・決定・スレッド・参照の記録・つながり・渡す・保存した検索条件・CSV の取り込み）を作り、契約の API が読み書きできるようにする。行の守りで、元のチケットを読めない人には見せない。

## 完了の条件

- [x] migration（`packages/db/migrations/0072_ticket_around.sql`）で表と列ができ、まっさらな DB に全部入る（72/72）
- [x] 表ごとに RLS の決まり（`packages/db/policies/0072_ticket_around.sql`・gen_rls.py ← `05_flow/rls_policies.py`）がある
- [x] repository の表の一覧（`packages/db/src/repository.ts` の TABLES）に入っている
- [x] 場合表（access-matrix.json）にこの表の行があり、全部通る（全体で 1344 件 PASS・FAIL 0）
- [x] 渡された相手は、答えるまでグループの外でも読める（`app.ticket_involved`・D-128.115）
- [x] CSV の取り込みの下書きは、確定するまで取り込んだ人だけ（D-128.119）
- [ ] CI が緑のまま

## 前提と制約

- 表は ER 図 §16 と「足す列」が正。足すだけで、消す・名前を変える migration は作らない
- 全部の表に `tenant_id` と RLS。RLS を飛ばす鍵はサーバーで使わない（ZT3）
- 承認する人を「関わっている人」に入れるのは K-9（approvals.ticket_id ができてから）

## 実施事項

- [x] 表：`test_specs` `checks` `ticket_decisions` `ticket_messages` `reference_logs` `ticket_links` `ticket_handovers` `saved_views` `ticket_imports`
- [x] 列：`ticket_links` は 関連・派生元 の 2 つだけ（D-128.80）。ER 図に足した列：`checks.ticket_id`（行の守りのため）・`tickets.draft_import_id`・`ticket_imports.scope_id`・渡すの「取り下げた」
- [x] RLS の範囲：テスト仕様・検査・決定・スレッド・参照の記録は元のチケットに従う。検査の結果と参照の記録は追記だけ、決定は消さない（改めるだけ・D-125.63）。スレッドは読める人が本人として書き、直せるのは書いた本人だけ
- [x] つながりは両方のチケットを読める人だけ見える（見えないチケットがあることを、つながりから知らせない）
- [x] 渡すは チケットを読める人・渡した人・受ける人・渡す先のグループのマネージャー。断るには理由が要る
- [x] 保存した検索条件：自分のものと見えるグループに見せたもの。直す・消すのは作った人とグループのマネージャー（D-128.119）
- [x] 取り込みの記録：取り込んだ人と記録を見られる人（既定は管理者）。確定・やめるは取り込んだ人だけ
- [x] 種（seeds）：同じ表を 2 回指す表（つながりの元と先）には別の行を入れる。列どうしの決まり（書き込みは本文が要る）に当たったら文字の列も埋める
- [x] `zt_gate.py --lower-baseline` で記録を下げた（rls_missing 27 → 18）

## リスクと懸念

- 「マネージャー」は今、表ごとの権限の言葉（`has_permission(人, 'saved_views', グループ, 'edit')`）で見ている。グループごとの役割（兼務の表 scope_memberships）ができたら、そちらで見る（K-7）
- 取り込みの下書きも作るときに番号を取るので、やめた取り込みの分は番号が飛ぶ（番号は変えない決まり・D-128.115）
