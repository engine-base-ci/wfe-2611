## 目的

グループの小窓の「層 ▾」の中の「層を足す」と「層の名前と並びを直す」（D-154.7・下絵 gr-layer-add・gr-layers）が呼ぶ 2 つの口を作る。

- `createLayer`（POST /api/v1/layers）：層に名前を付けて足す（部門・チームなど・A117）。最大 8 段。足す位置を指せる
- `updateLayer`（PATCH /api/v1/layers/:id）：層の名前を直す・並びを替える（上へ・下へ・最後に送る）。**層は消せない**（D-154.8）
- `listLayers`（GET /api/v1/layers）：層の一覧（画面の「層 ▾」と層の名前と並びを直す小窓が読む・K-805・K-806）。**契約に無かったので足す**（この葉の `05_flow/screen_api.d/K-803.py` の SCREEN_API に `("GET", "/layers", "A117", "layers", "listLayers", ["scopes"])`・PERMS は read＝会社の人なら誰でも・QUERIES は空・LIST_DETAILS は並びを持たない旨）。口の登録はこの葉の新しい hooks のファイル `apps/api/src/hooks/f10-layers.ts`（K-800 の hooks のファイルは触らない・fuzz "same"）

口の登録・断る番号（errors）は K-800 が持つ。入力と答えの形は K-800 の「契約」の節で決めた形で、この葉の口の分をこの葉が契約（.d）に書く。この葉は `layers/create.ts`・`layers/update.ts` の空の形を本物にして `ready = true` にする。

**画面が使う答えの形**（K-805・K-806 が使う）：どちらも `{ data: LayerCreated | LayerUpdated }`（鍵はちょうど 6）。listLayers は 200 `{ data: [同じ 6 つの鍵の 1 件…], meta: { limit } }`（order_no の順・消した層を含まない・Cache-Control private, no-store）：id・key（`l_` ＋ 8 文字・画面に出さない）・label・order_no（1 から重ならない連番）・group_count（その層に入っている消していないグループの数）・created_at。画面は 200／201 の答えで 1 行を差し替え、並びを替えたときは層の一覧を持つ側（グループの小窓の層の一覧）が読み直す。

## 前提と制約

分類: CRUD, PERM, LIST

- **だれが書けるか**（D-125.116）：管理者と、layers の edit を会社全体に付けた人（入口が先に 403）。DB の関数も頭で `app.admin_can('layers', 'edit')`（書けなければ `{"error":"forbidden"}`・403・FORBIDDEN）。scopes の edit だけの人・マネージャーは直せない
- **層の名前**：入口が整えた後 1〜40 文字（ticket_kinds の名前と同じ長さ）。消していない層と重ならない（大文字小文字・全角半角は同じ・lower と NFKC 後で比べる）→ 409・E-GRP-019。消した層とは重なってよい。自分の名前を大文字にし直すのは通る（自分を除いて比べる）
- **上限**（D-154.8・G-16）：消していない層は 8 段まで（足す口だけ。超えれば 409・E-GRP-013）
- **並び**（order_no）：1 から重ならない連番。足すときに order_no を送ると、その位置に入り、それ以降の層が 1 つずつ下がる。大きすぎる値・送らない → 最後。直すときも同じ（指した位置に動き、間の層が 1 つずつずれる）。0 以下・小数・文字は入口が 422（欄 order_no）。key はサーバーが作り（`l_` ＋ `gen_random_uuid()` の先頭 8 文字）、送れない・変えられない
- **層の一覧**（listLayers）：会社の人なら誰でも読める（契約の perm は read・役を見ない）。同じ会社の消していない層を order_no の順に（`app.layer_list()`）。ページを持たない（層は 8 段まで）。別の会社の層は出ない
- **直す先が無い**（道の id が無い・別の会社・消した）→ 404・E-GRP-007（欄・details を付けない）
- **同時**（D-154.21）：足す・直すは `app.admin_lock()`（会社ごとの錠）で順に通す。同時の 2 本で最後の 1 枠・同じ名前・同じ order_no ができないように。一意の索引は置かない（前からの種が同じ会社に層を直に入れる）。並びの振り直し `app.layer_renumber` は同じ取引の中で呼ぶ
- 入口の共通が先に効く：401・429（60 回/分/人）・同意し直し 403・1MB 超 413・知らない欄 422（strict）・形の誤り 422（契約の VALUE_RANGES・INPUT_RULES。**欄 label・order_no・体が空は入口が VALIDATION_ERROR で先に断る**。E-GRP-004・006・008 は整えた後の値が口の確かめで外れた場合の後ろ盾）・NUL 422
- 関門の宣言は [C2]。メール・外のサービス・ファイル・AI は無い。層の守ること・やり方・承認の決まり（F9）は層の key で引くので、名前を直しても決まりは変わらない
- 断る番号は控え帳どおり：422＝形の誤り／404＝指した物が無い／409＝今の状態ではできない（field・details を付けない）／403／DB の失敗は 503・E-PAGE-003
