## 目的

外した人（K-816）が 30 日のあいだに招き直されて戻るとき、**グループごとの役割を「外す前の役割」と「招いた役割が許す上限」の低いほうにする**規則を、DB の関数 `app.restore_group_role` の 1 か所に置く（D-128.96・D-154.26・D-154.41）。戻す振る舞いそのもの（グループと役割だけ戻る・個人の物は戻らない・30 日の境・記録）は、**製品で実際に通る道の K-852**（参加の関数 `app.join_invitation` の戻し）が、この関数を使って受ける。

**引き金は作らない**（案 x・PM の決め・2026-11-27・.ticket-flow/out/K-817/F11-note.md）。前の形（受けたとき＝accepted_member_id が入ったときの引き金で、新しいアカウントの人に戻す）は、製品の道で届かない分岐だった（L-003 G-03・G-08）：

- 同じアカウントのまま戻る人は、受ける口（F2 の accept.ts）がログイン中なら参加の関数（K-852）へ行き、`app.accept_invitation` を呼ばない
- ログインせずに名前とパスワードで受ける人は、宛てのメールにもうアカウントがある（外した人のアカウントは K-849 では消えない）ので、`createInvitedUser` が exists を返し、口は 409・E-INV-006 で止まる
- 新しいアカウントは別の auth_user_id になるので、同じ auth_user_id で探す引き金は見つけない

製品のふるまい（外して 30 日以内に招き直すとグループと役割だけ戻る）は変えない。受け持ちが K-852 に移るだけ。

## 前提と制約

分類: INV

- **役割の上限**：`app.restore_group_role(p_old text, p_invited text) returns text`。戻すグループの役割＝「外す前のグループの役割 p_old」と「招いた役割 p_invited（招待の role_id）が許す上限」の低いほう。上限は admin・manager → manager／member → member／viewer・requester ほか → viewer。順は viewer < member < manager。p_old が null なら上限。**招いた人が選んだ役割を超える権限を、昔の役割で戻さない**（PM の決め・D-154.41）
- 会社の役割（tenant_memberships.role）はこの関数で決めない（招待の役割のまま・K-852 と受ける関数のとおり）
- 関数は immutable・`search_path` 固定。public と kaname_app には execute を渡さない（呼ぶのは K-852 の security definer の参加の関数の中だけ）
- **引き金と、引き金の関数 `app.member_restore_after_join` は作らない**。招待の表・受ける関数 `app.accept_invitation`・招く関数は変えない
- 戻す振る舞い（探し方・30 日は招いた時刻で見る・戻す行・兼務・在るグループだけ・個人の物と個別の権限は戻さない・記録 member_restored・全部か無しか）は K-852 の「実施事項」の 2 と、その行（K852 の試験）が受ける
