## 目的

K-898（届いた依頼の一覧・開いた依頼・届け先を変える・返事・断る）の後ろで、**チケットを作る**ところを口につなぐ。芯は「ゲストの依頼は依頼としてやり取りし、社内が**普通のチケット**にする。違いは依頼のやり取りがチケットのチャットの頭に残ることだけ」（D-155.42）。下絵（`/dev/mock/f11` の rq-create・rq-create-bad・rq-saving・rq-accepted・rq-accept-failed・tk-from-request）のとおりに：

- 「チケットを作る」の小窓：題・本文は依頼から入る・**担当と期限は社内が入れる（必須）**・グループ・「ゲストに見せる相手」は依頼を出したゲストのグループが最初から選ばれている（外せない）。口 `acceptClientRequest`。作ると帯「チケットを作りました（EG-131）」＋「チケットを開く」（K-898 では押せない形で出していたボタンを、この葉が押せる形にする・D-145.9）
- **担当とグループの選び肢**は前からの口：担当＝`listMembers`（GET /api/v1/members?limit=200・会社の人）・グループ＝`listScopes`（GET /api/v1/scopes・答えの meta.writable に入るグループだけを選べる）。段 4 の作る画面（`features/F4/create-ticket/ticket-shell.tsx` の `readScopes`・`tickets-page.tsx` の `listMembers`）と同じ読み方で、小窓を開いたときに 1 回ずつ
- 作った後の詳細（tk-from-request）：作ったチケットの詳細のチャットの頭に、**依頼のやり取りが残っている**（札「依頼のやり取り」・依頼の本文・区切り「ここからチケットのやり取り」）。区切りを引くのは K-905（`message.from_request` を使う・まとめ役の決め 1）。この葉はそこへ行ける（「チケットを開く」）ことと、開いたとき頭が出ることを見る

- 部品は K-871（`features/F11/requests/views.tsx`）・K-872（`dialogs.tsx` の `CreateTicketDialog`）が運び、K-898 が入れ物 `requests-page.tsx`・`use-request-acts.ts` を作った。**部品は値と動きを props で受けるだけ・口を呼ばない・useEffect を持たない**（K871-MK-004・K872-MK-002 が部品の中身を読む）。この葉は部品に足りない props（`onCreate`・`creating`・`createError`・`members`・`scopes`・`choicesState`）を足すだけで、口は入れ物 `requests-page.tsx`・`use-request-acts.ts`・新しい `use-create-choices.ts`（前からの口 2 本を読む）が呼ぶ
- 画面が呼ぶ口：`acceptClientRequest`（POST /api/v1/client_requests/:id/accept）＋前からの `listMembers`・`listScopes`
- **送る体（K-894 の確定）**：`{ title?, body?, assignee_member_id, due_on, scope_id, kind_id?, guest_group_ids? }`。担当は選び肢の member id・期限は日付（`YYYY-MM-DD`・小窓の欄は「12/26」の形で入れ、今日から見て次のその日付に直して送る。過ぎた日は口が 422 で断る）・グループは選び肢の scope id。題・本文は小窓で直していなければ送らない（口が依頼の題・本文を使う）。**見せる相手の追加（`guest_group_ids`）は送らない**：依頼を出したゲストのグループは口が必ず入れる（K894-API-004）。種別 `kind_id` は送らない（口が会社の初期の種別を使う）。答えは 201 `{ data: { ticket_id, number } }`
- 口の断りの出し方（画面は番号で `errorText` から文を引く・小窓は閉じず入力は残す）：409・E-GST-120（依頼がもう決まっている）＝「この依頼はもう決まっています」＋依頼を読み直す／404・E-GST-040（見せる相手のゲストのグループが消えた）＝「このゲストのグループは見つかりません」／409・E-GST-041（見せる相手が 20 を超える）＝「見せる相手は 20 までです」／404・E-GST-100（依頼が見えなくなった）＝一覧へ戻る文／422（担当が会社の人でない・止めた・抜けた＝欄 `assignee_member_id`・種別が無い・本文が不正）＝欄の下に「担当の人を選んでください」など／403（グループに書けない＝欄 `scope_id`）＝グループの欄の下に「グループを選んでください」／503＝「チケットを作れませんでした」＋「もう一度押してください。書いた内容は、この小窓に残っています。」
- 読めない形：担当・グループの選び肢が読めなければ（503）小窓は開き、その欄に「読めませんでした」と「もう一度」を出し、作るは口を呼ばない。グループが 1 つも書けない人（`writable` が空）には、グループの欄を押せない形で出し、作るは口を呼ばない（口も 403）
- **画面に「取引先」「クライアント」「先方の人」と出さない**（D-155.35・呼び名は「ゲスト」）
- 「担当・期限などはゲストに見えません」の字は下絵のまま小窓に出す（ゲストに見えるのは題・本文・詳細・チャットと段の札 3 つだけ・D-155.41）
- 作った後の詳細のチャット（tk-from-request）は段 7 の読み `GET /api/v1/tickets/:id/timeline` の `message.from_request`（K-882 が足す・true の行にだけ鍵がある）。区切りを引く部品は **K-905** が差し込む（まとめ役の決め 1・K-905 の depends に K-930 は無く、K-930 が K-905 の後）。この葉の試験は社内の読みの偽の答えに `from_request: true` を入れ、頭の札と区切りが出ることを見る
