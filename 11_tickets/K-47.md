## 目的

CI を GitHub と全く同じもの（.github/workflows の workflow）にし、GitHub を通さずに手元で act で流す（ずっと無料・D-128.147）。チケット 1 本ごとに workflow の全部を 1 回流し、緑なら取り込む。自作の実行器（dagci）はやめる。

## 完了の条件

- [x] act で .github/workflows/v3-gate.yml の全部の job が手元で流れ、緑になる（11 組すべて緑・15 分 24 秒・2026-11-05・取り込んだコミット 9840077 の木）
- [x] わざと壊したコード（型の誤り）で act が赤になる（G2 が error TS2322 で赤・act の終わり方 1）
- [x] コミットにチケットの番号（K-n）が無ければ赤になる検査を workflow に入れる（G55・scripts/ci/ticket_commit_gate.py・No Ticket, No Commit・D-128.147）
- [x] dagci の設定と検査をやめる（ci.yaml・scripts/ci/ci_stages.py・G52 を消した）
- [x] まだ作っていない API の試験で、試験用のサーバーを立ち上げない（D-128.148・gen_ears_tests.mjs。作っていない口 354 ファイルが約 880 秒 → 約 64 秒）
- [x] 決定のトレース（trace_gate）を workflow の検査にする（G54・それまで手で流していた）
- [x] DB の番号を組ごとに分ける（database 5432・unit-<i> 5432+i・spec 5439）。act は 1 台で組を同時に流し、割り当てた番号も渡さないので、同じ 5432 だと取り合いになった
- [x] 取り出しを全部の履歴にする（fetch-depth: 0・G55 がコミットを読むため）

## 前提と制約

- act は GitHub と同じ workflow の書き方を手元の Docker で流す道具（MIT）。同時に台を分けて流すのと、PR に緑と赤を出して止める仕組みは弱いので、流して確かめてから扱いを決める
- 外す job：task-gate（task/ の枝の PR だけ）・e2e（staging が要る・K-37）・auto-merge（GitHub の取り込みの道具）は、act でどう扱うかを流してから決める

## 実施事項

- [x] act（v0.2.89・出てから 21 日以上）を入れ、v3-gate.yml を流す
- [x] 流れない所を直す（DB の番号を組ごとに分ける・Chrome 入りの台の像・中継の証明書・部品の写し）
- [x] コミットのチケット番号の検査
- [x] dagci の設定を消す
- [x] この作業場所（クラウド）での act の起動の設定：GitHub の部品は普通の git で取った写しを使う（--local-repository）・中継の証明書を容れ物に渡す・pnpm の置き場を作業場所の外に・DB の像は Docker Hub の取りすぎの制限（429）のため mirror.gcr.io から取る。どれも workflow は変えない。Mac では要らない
