## 目的

届いた依頼（K-892）に社内がする 2 つ：

- **届け先のグループを変える**（`updateClientRequest`・PATCH /client_requests/:id・体 `{ route_id }`・200 `{ data: { route_name } }`）：届いた依頼ごとに、届け先を別の社内のグループに変える（D-155.43・ゲストのグループが持つ届け先はそのまま・この依頼だけ `routed_scope_id` を替える）。変えた後は新しい届け先の人に見える
- **返事を送って詳しく聞く**（`replyToClientRequest`・POST /client_requests/:id/reply・体 `{ body }`・201 `{ data: { state: "asking" } }`）：返事を依頼のやり取り（`client_request_messages`・`side = 'company'`）に入れ、依頼を「聞いている」にする。返事は人が押して送る（分身の下書きは直せる・D-155.10）。**出し手に受け箱の 1 件と、メール（リンクだけ・本文は載せない・D-128.103）**

## 前提と制約

分類: CRUD, PERM, MAIL

- 使う守り・関数は K-892 の物：見える `app.client_request_visible`・直せる `app.client_request_actable`・届け先にできるグループ `app.client_request_routes()`・出し手へのお知らせ `app.client_request_notify_author`。**更新・返事の書き込みも K-892 が足した方針（`client_requests_staff_guest_update`・`client_request_messages_staff_write`）を通る**
- 道の :id の依頼が見えない・無い・消した・別の会社・前の取引先の形なら 404・E-GST-100（K-892 の番号）。見えるが直せない人（読むだけ）は 403・FORBIDDEN。ゲストの文脈は入口で 403・ログインなしは 401
- **もう決まっている依頼**（`ticketed`・`declined`）は変えない・返事もできない：409・E-GST-110（欄・details なし）。状態が `new`・`asking` の依頼だけが対象
- **届け先を変える**：`route_id` は `app.client_request_routes()` に入る物だけ（無い・消した・別の会社・見ている人が edit できないグループは 404・E-GST-111・欄・details なし）。同じ届け先（今の届け先と同じ）を送ると 200 で何も変えず証跡も書かない（冪等）。変えたら証跡 `client_request.route_changed`（payload は `request_id`・`from`・`to` のグループの id だけ・名前は載せない）。変えた後に見えなくなる人（自分が新しい届け先を見られないとき）にも 200（以降は 404）。答えは新しい届け先の名前 `route_name`
- **返事**：本文は前後の空白を取った後が空なら 422（契約の `minLength: 1`・入口の normalize で字は NFKC）・体の欄は `body` だけ（知らない欄は 422）・字数の上限なし（D-130.1）。返事は `client_request_messages` に `side = 'company'`・`kind = 'message'`・書いた人はセッションの人。状態は `new` なら `asking`・`asking` のまま。続けて何度も返事できる
- **知らせ**：返事を 1 件書くごとに、出し手の受け箱へ `app.client_request_notify_author(依頼, 'client_request.replied', { ref: <書き込みの id> })` で 1 件（payload は `request_id`・`ref` だけ・本文・題は載せない）。出し手が居なければ何もしない（返事は書く）。**メール**（関門 C6・取引が終わった後）：宛先が分かるとき 1 通。件名「Kaname：依頼に返事が届きました」・本文は 1 行の案内と `<web の住所>/portal/requests/<依頼の id>` のリンクだけ（返事の本文・依頼の題・社内の人の名前は載せない）。送った結果は `app.client_request_mail_record` で受け箱に `channel_id = 'email'` の行として残す（送れた：`sent_at`・送れなかった：`failed_at`）。**メールが送れなくても返事は残り 201**（送れなかった行が残る・K893-API-016）
- 1 つの取引（`app.client_request_reply`）：返事の行・状態・受け箱の行・証跡 `client_request.replied`（payload は `request_id`・`message_id` だけ）。どれかが落ちたら全部戻る（503・E-PAGE-003・ログは例外の種類だけ）
- 二度押しは入口の冪等キーで 1 つ。キーの違う 2 本は 2 つの返事
- 関門の宣言は [C2, C6]（DB に書く・メール）
