## 目的

場合表（access-matrix.json）を新しい表と足した列に広げ、「範囲の外の行が取れない」を全部の表で確かめる。G33 と zt_gate の rls_missing を 0 にする。

## 完了の条件

- [x] `pnpm ci:access-matrix` が緑（1540/1540・未 migration の表 0）
- [x] `zt_gate.py` の rls_missing が 0 で、記録（zt_baseline.json）も 0 に下げた（open_read_child も 2 → 1）
- [x] 親に従う子の表を、親が見えない行で確かめる（K-3 の申し送り）
- [x] わざと守りを壊すと場合表が赤になる試験がある
- [ ] CI の G33 が緑

## 前提と制約

- 場合表は役 × 表 × 操作で作る（会社の人・取引先の人・運営〔許可あり／期限切れ〕・ログイン済み・追記だけ）
- 業務の表として作らない表（ログインの部品の側の passkeys・pending_signup、ER 図で「段階 1 は作らない」の embedding_models・search_embeddings）は、理由を持たせて場合表と ZT の検査から外す（黙って数えないのではない）

## 実施事項

- [x] 生成元（`05_flow/build_testplan.py`）：取引先の人の場合、全社向けの読みがある運営の表の場合、作らない表の外し方を足した。テスト計画の検査（tv_gate TV5）も同じ表を外す
- [x] 場合表の道具（`packages/db/src/matrix.ts`）：親に従う子の表（読む守りが app.ticket_visible・app.kpage_visible・app.client_visible を通る）は、「見えない層」の場合に親が見えない種の行で 0 行を確かめる（今までは「層を持たない表は会社全体が見える」として素通りしていた）
- [x] 種：取引先は「担当グループだけ」にする（担当グループの無い担当者から見えない＝子の表を確かめられる）
- [x] わざと壊す試験（`packages/db/test/matrix_breaks.test.ts`）：使い捨ての DB で ①チケットを誰でも読める ②チケットの本文を同じ会社なら読める ③取引先の人の柵を外す、をすると場合表が赤になる
- [x] 記録を下げた（rls_missing 1 → 0・open_read_child 2 → 1）
