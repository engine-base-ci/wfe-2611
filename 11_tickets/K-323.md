## 目的

チケットの CI の全体の時間は、ほぼ spec の組の長さで決まっている（.ticket-flow/research/ci-time.md：spec は最長経路で台の時間の 50%・1 回 10〜17 分）。spec の組の中は独立した検査の段の列で、2026-11-18 の緑の 3 回（44290743483・44270084957・44268144574）の段ごとの時間を測ると、重いのは 4 つだけだった。

| 段 | 3 回の時間（秒） | 中央値 |
|---|---|---|
| G56 取り込む順（ticket_order_gate） | 472・268・281 | 281 |
| G67 画面のクラス（class_gate） | 150・147・146 | 147 |
| G65 CI の形の試験 | 110・110・107 | 110 |
| G57 範囲の台本の試験 | 43・41・40 | 41 |
| G27 層の棚卸し | 10・49・9 | 10 |
| ほかの 21 段 | どれも 0〜6 | 合計 約 50 |
| 組の準備（checkout・部品・DB・分かれ目） | 約 35〜45 | 40 |

これを 3 つの組に分け、static の後で同時に流す。いちばん長い組は G56 の 1 組（準備込み 約 5〜8 分）になり、spec の組の待ちが 11〜18 分 → 5〜8 分、チケットの CI の全体が 13〜20 分 → 8〜10 分前後になる見込み（目標 10〜15 分）。

## 前提と制約

分類: TOOL

- v3-gate.yml は作り手 05_flow/build_testplan.py の生成物。作り手を直して作り直す（手で直さない）
- 流す検査を減らさない・変えない：段の名前・命令・if は前と同じ。組をまたいで同じ段を 2 回流さない
- 分けた組それぞれが、spec と同じ準備の段（checkout・pnpm install・Python・DB・本線との分かれ目 scope）を持ち、`steps.scope.outputs.*`（base・gates・full・db_range・py_tests）は自分の組の scope の段から同じ入力で出す（G61 の CI_LEDGER_BASE・G56 の CI_BASE も同じ値）。組をまたいで出力を受け渡さない
- 前からの試験が spec の組に置いていると決めている段（G27・G46・G57・G61・G62・G65・G68・G69・G71 ほか）は spec に残す。動かすのは G56（spec-2）と G67（spec-3）の 2 つだけ
- JUnit：チケットの Python の試験（spec-py.xml）と G65 の node の試験の記録は spec の組のまま（junit-spec）。spec-2・spec-3 は JUnit を書かないので記録を上げない（空の記録は赤の決まり・K172-CI-005）。まとめる組 junit・task-gate・auto-merge は spec の組を 3 つとも待つ
- 1 回の CI が同時に使う台は、static の後に spec の 3 組が並ぶ分だけ増える（web 無しの回で 2 → 3〜4）。台は 4 つ（MacBook 2・Mac mini 2）
- 同時に走る K-312 と同じファイルを触らない（K-312 は apps・packages・05_flow/screen_api.py など）。生成物（11_tickets/tickets.*・07_qa/test-plan/**）は取り込みでぶつかったら作り手で作り直す
- 試験を書いた後は変えない（D-128.125）
