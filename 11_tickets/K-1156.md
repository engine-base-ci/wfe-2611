## 目的

チケットの CI が赤で、担当が直してもう 1 回流すとき、今は前の回と同じ範囲（チケットの試験の全部＋本線から変えた物に関わる物の全部）をまた流している。

代表の決め（2026-11-24）：赤を直した回は、前の回で赤だった行と、前の回から変えたファイルに関わる行だけを流す。流れなかった緑の行は ticket-flow が前の回の記録を使う（スキル側は作った：ci.py の prev_red・carry_green・takes_rerun。入力 rerun＝前の回で赤だった行 ID を空白区切り・since＝前の回の版 40 桁）。段の全部の CI（scope=full）は全部流す。

Kaname の側で要る直し：CI の定義（v3-gate.yml）が入力 rerun・since を受けて範囲の台本に渡し、範囲の台本（ci_scope.py）がそれで絞る。ticket-flow の設定（ticket-flow.yaml の ci.inputs）に名前を書く（書かないと ci.py が渡さない）。

PM の決め（作り方）：
1. 絞るのは **rerun に行 ID が 1 つ以上あり、かつ since が 40 桁のコミットのとき** だけ（両方あるとき）。片方だけ・どちらも無いときは今までと全く同じ（絞らない＝前の回と同じ範囲で、結果は大きい側に安全）
2. 絞る回は 2 回決める：
   - **確かめ**（今までどおり base で）：base…先頭の差分・件名のチケットの番号（base..先頭）・affects と ci_wide の食い違い・中間と統合の試験・試験の無いコード・止める理由。どれかが赤なら絞らずにそのまま止める（今と同じ答え）
   - **選ぶ**（since で）：since と先頭の木の差分（`git diff since 先頭`・取り込んだ本線の分も入る）から、関わる試験・検査（unit の試験・DB の範囲・組・重い検査 gates・migration の lint・画面の組）を選ぶ。チケットの番号は確かめの答えを使い、since..先頭の件名では裁かない
3. チケットの試験（tests: と、このチケットでそろう中間・統合の試験）は、rerun の行 ID を中身に持つファイルだけにする。行 ID は `-` の形（K12-API-003）と `_` の形（test_K12_API_003）のどちらでも当てる。左が英数字の続き・右が数字の続き（K12-API-0031・test_K12_API_0031_x）には当てない。右に `_` と名前が続く形（test_K12_API_003_name）には当てる
4. 出力の base（G56・G61・G63・G67 などが比べる元）は本線の base のまま。since は出力に出さない
5. 入力の形が違うとき（since が 40 桁の 16 進でない・コミットでない・rerun を空白で分けた 1 つずつのどれかが行 ID の形 `[A-Za-z0-9]+(?:[-_][A-Za-z0-9]+)+` でない。本物の行 ID は K12-API-003・K9-M9-9・K107-J1 の形）は、絞らず全部にも倒さず止める（組を流さない・理由を出す）
6. rerun の行がチケットの試験のどのファイルにも無いときは、止めずに理由の行に出す（その行は流れない＝ticket-flow の判定で赤のまま）
7. scope=full のときは rerun・since があっても全部（今と同じ）
8. CI の定義は作り手 `05_flow/build_testplan.py` で直す（v3-gate.yml は生成物）。入力 rerun・since（type string・default ''）を足し、ci_scope.py を呼ぶ 4 か所（static の G0・spec・spec-2・spec-3 の分かれ目）全部に env `CI_RERUN_INPUT: ${{ inputs.rerun }}`・`CI_SINCE_INPUT: ${{ inputs.since }}` と引数 `--rerun "$CI_RERUN_INPUT" --since "$CI_SINCE_INPUT"` を足す（外から来る値は run の字に直に入れない）
