## 目的

ワークスペースと人の表（ワークスペースへの所属・グループへの所属と兼務・規約の版と同意・知らせの設定・PC の接続コード）を作る。兼務を見える範囲に入れる。

## 完了の条件

- [x] migration（`packages/db/migrations/0075_workspace_people.sql`）と RLS（`packages/db/policies/0075_workspace_people.sql`）
- [x] repository の TABLES に入っている・場合表が全部通る
- [x] 兼務（scope_memberships）を visible_scopes に入れた（KN-38 の申し送り）
- [ ] CI が緑のまま

## 前提と制約

- 表は ER 図 §16 と「足す列」が正。足すだけで、消す・名前を変える migration は作らない
- 全部の表に `tenant_id` と RLS。RLS を飛ばす鍵はサーバーで使わない（ZT3）
- 自分の表の読む守りに「その表を id で引く関数」を使わない（作った行がその場で見えず INSERT … RETURNING が弾かれる）

## 実施事項

- [x] 表：`tenant_memberships` `scope_memberships` `terms_versions` `terms_consents` `notification_settings` `bridge_pairing_codes`
- [x] 列：ワークスペースの役割（管理者・マネージャー・メンバー・閲覧のみ・依頼する側）・グループごとの役割と主の所属（1 つだけ）
- [x] RLS の範囲：所属は本人と管理者。グループへの所属は本人とそのグループが見える人、変えるのは管理者だけ（マネージャーの束に入れない・D-128.97）。規約の版はログイン済みなら読み、出すのは運営。同意は本人の追記だけ。知らせの設定と接続コードは本人だけ
- [x] 接続コードはハッシュだけ（32 文字以上・平文を入れさせない）・10 分まで・使った印は関門の関数だけが付ける
