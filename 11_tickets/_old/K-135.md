> **しまった：K-132 にまとめた（2026-11-07・API の試験の土台の送り元の IP は、回数の制限を全台共通に数える直しと一緒に直す。完了の条件・実施事項・分岐・試験の行は K-132 に移した。K-132 の depends_on から K-135 を外した）**

## 目的

API の試験の土台 `apps/api/test/features/fixture.ts` の `nextIp()` は、`203.0.113.1`〜`.250` の 250 個を順に配る。1 つのファイルで 250 回を超えて呼ぶと同じ IP がまた配られ、前の試験の数が残っている IP で回数の制限の試験（K57-API-038：引き取りを 1 分に 6 回で 429 など）が始まって赤になる。試験を足したり順を変えたりするだけで赤と緑が入れ替わる（試験の順に頼る）。K-57 の実装の役が見つけた。

## 完了の条件

- [ ] 試験ごとに決まった IP を持つ（試験の名前などから決まる・同じ試験はいつも同じ IP・別の試験とは重ならない）。配る順と試験の数に頼らない
- [ ] 回数の制限の試験（K57-API-038・K57-API-056 ほか、上限を数える試験）が、ほかの試験の数と混ざらない。順を入れ替えて流しても・1 本だけ流しても同じ結果
- [ ] 試験の中で IP を変える必要がある所（偽の IP の試験など）は、その試験の中で明示して決める
- [ ] チケットの CI（act）が緑

## 前提と制約

- 回数の制限を DB で全台共通にする K-132 はこのチケットに依存する（共通にすると、IP の重なりは別のファイルの試験とも混ざる）
- 画面の試験の側（K-122：ブラウザごとに x-forwarded-for を足して避けている）とは別の土台。K-122 と同じ考え方（試験ごとに決まった IP）にそろえるかを、切るときに書く
- 時間で隠さない（待ち・再試行で数が消えるのを待たない）

## 実施事項

- [ ] 作る役：nextIp を使う所と、回数の制限を数える試験を全文検索して一覧にする
- [ ] 作る役：分岐（1 本だけ・全部・順を逆・250 本を超える）と試験の行

## テスト仕様と確認の結果

| 確認項目 | 種類 | 判定のしかた | 結果 |
|---|---|---|---|
| 順を変えても回数の制限の試験が同じ結果 | ① 単体 | connect-pc.test.ts を順を逆にして流し、1 本だけでも流して緑 | |
| 試験ごとの IP が重ならない | ① 単体 | 全部の試験の IP を集め、重なりが無い | |
