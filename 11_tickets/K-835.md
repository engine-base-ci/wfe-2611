## 目的

自分の設定 › プロフィールの「メール［変える］」（下絵 me-email・me-email-error・me-email-sent・me-email-done）が使う 2 つの口。

- `requestEmailChange`（POST /api/v1/me/email-change）：新しいアドレスを受け取り、**新しいアドレスに確かめのメール**を送る。リンクを押すまでは今のメールのまま（本人確認の取り直しが要る・D-154.18）
- `verifyEmailChange`（POST /api/v1/me/email-change/verify）：メールのリンクの印を受け取り、ログインのメールを新しいアドレスにする。**古いアドレスにも「変わりました」と知らせる**

確かめのリンクは **24 時間・1 回だけ**（D-154.12）。「送り直す」は同じ宛てでもう一度頼む（新しいリンクが届き、前のリンクは使えなくなる）。**「やめる」の口は作らない**（契約に新しい口を足さない・待っている変更は 24 時間で切れ、新しい頼みが前の頼みを無効にする。下絵 me-email-sent の［やめる］は仮の字なので、画面の葉 K-840 が押せない形にするか外す）。

**画面が使う答えの形**（K-840 の正）：

```
requestEmailChange 201 { data: { pending_email: <そろえた宛て>, expires_at: ISO 8601 } }
verifyEmailChange  201 { data: { changed: true, email: <新しいメール> } }
```

確かめのリンクは `{webBaseUrl}/account/email-confirm?token=<印>`（画面の葉 K-840 が外枠の外の画面 `/account/email-confirm` を作る）。画面は 409 の番号で出し分ける：変わった（201）・期限切れ（E-ME-022）・もう使った（E-ME-023）・使えない（E-PAGE-006）。待っている宛ては K-833 の `getMe` の `member.email_pending`（この葉が `app.me_email_pending` を本物にする）。

## 前提と制約

分類: AUTH, MAIL, PERM

- **だれが呼べるか**：本人だけ（頼む口は契約の `stepUp: "always"`＝取り直しが直前 15 分の内でなければ入口が 403・STEP_UP_REQUIRED を返す。口の中では見直さない・D-125.139）。確かめる口はログイン中の本人（取り直しは要らない・契約のまま）。入口の共通（401・429・同意し直し 403・strict の形・NUL 422）が先に効く
- **宛ての決め方**：`normalizeEmail`（packages/auth/src/signup.ts・NFKC・空白を除く・小文字）でそろえてから比べる。形は契約の pattern（`scripts/ci/invite_patterns.py` の EMAIL と同じ字）で 422・E-ME-020（欄 email・画面の字は下絵の「メールの形が違います。「名前@会社.example」のように入れてください」）。長さは 254 字まで
- **断る場合**（どれもメールを送らず、待っている変更を作らない）：今のメールと同じ → 409・E-ME-026（「今のメールと同じです」＝仮）／ほかのアカウント（ほかの会社の人も含む・kaname_auth の利用者の email が同じ）が使っている → 409・E-ME-021（「このメールは、もう別のアカウントで使われています。別のメールを入れてください」＝下絵の字。**使われているかを本人に見せる**のは下絵の決め）／1 時間に 5 回目まで（その人の待っている変更の作った時刻で数える）・6 回目は 429・E-ME-024（「メールを送りすぎです。しばらくしてからやり直してください」＝仮）
- **待っている変更**：新しい表 `member_email_changes`（tenant_id・member_id・auth_user_id・new_email・token_hash（sha256・リンクの印そのものは持たない）・expires_at（作った時刻 + 24 時間）・used_at・revoked_at と共通の列）。頼むと、その人の前の待っている変更（使っていない・取り消していない）を取り消し（revoked_at）、新しい 1 つを作る＝待っているのは 1 人 1 つ
- **印**：`randomBytes(32)` の base64url。メールの本文にだけ在り、DB・ログ・答えには出さない
- **確かめる**：印を受けて、① 待っている変更が無い・取り消された・別のログインの人の物 → 409・E-PAGE-006（在るかを漏らさない）② 使った → 409・E-ME-023（「このリンクはもう使いました」）③ 期限（expires_at）が過ぎた → 409・E-ME-022（「リンクの期限が切れました」）④ 新しいアドレスがその間にほかの人に使われた → 409・E-ME-021 ⑤ 通れば、同じ取引で kaname_auth の利用者の email を新しいアドレスに・emailVerified を真に・待っている変更の used_at を入れる。**同じログインの全部のワークスペースでメールが新しくなる**（メールはログインの物）。ほかの端末のセッションは切らない（メールを変えただけでは G-14 の対象でない・PM の決め）。同時に同じ印で 2 回確かめても 1 回だけ通る（行を錠で取る）
- **記録**：安全の記録 `security_events`（kind `email_changed`・detail は新旧の宛てを入れず印の有無だけ）を、そのログインが入っている全部のワークスペースに 1 行ずつ残す。会社の記録（audit_events）には載せない（自分の設定・K-833 と同じ）
- **メール（関門 C6）**：新しいアドレスへ「確かめ」（リンクつき・24 時間・1 回だけと本文に書く）。変わったあと古いアドレスへ「メールが変わりました。心当たりが無ければ運営へ」（**リンクを入れない**・新しい宛ては伏せ字の一部だけ）。署名はサーバーの共通の送出が付ける。メールの文に秘密・パスワードを入れない
- 確かめのメールが送れなかった → 502・E-ME-025（「確かめのメールを送れませんでした。少し待ってやり直してください」＝仮）で、その待ちを取り消す（送れたと嘘をつかない）。古いアドレスへの知らせが送れなくても 201 のまま（ログ 1 行・宛てを出さない）
- DB の失敗は 503・E-PAGE-003（頼む口は何も残らず・確かめる口はメールを変えず印も使わない）
- 断る番号は控え帳どおり（422＝契約に書ける形の誤り／404 は欄・details を付けない／409 は欄・details を付けない／503）

### DB の表と関数（20261126003500_me_email_change.sql）

関数は `security definer`・`set search_path = public, app, pg_temp`・`revoke all … from public`・`grant execute … to kaname_app`。**表は app スキーマに置き、`revoke all on app.member_email_changes from public, kaname_app`**（K-383 の `app.ticket_thread_seen` と同じ形。アプリの接続は表を直に読み書きできず、読み書きは関数だけ。public の表でないので行の守り（RLS）と packages/db/policies の台帳は要らない）。監査列と更新時刻の引き金は表に付ける。

| もの | 形 |
|---|---|
| 表 `app.member_email_changes` | `id`・`tenant_id`（今の会社）・`member_id`・`auth_user_id text`・`new_email text`・`token_hash text unique`・`expires_at timestamptz`・`used_at`・`revoked_at`・共通の列（created_at・updated_at・created_by・updated_by・deleted_at）。会社の分けは関数が `app.tenant_id()`・`app.user_id()` で行う（表を直に触れる役が無い） |
| `app.me_email_change_request(p_new_email text, p_token_hash text) returns jsonb` | ① 自分の login の現在のメール（kaname_auth."user"）と比べて同じなら `{"error":"same"}` ② ほかの利用者（id が違う）の email が同じ（小文字比べ）なら `{"error":"taken"}` ③ その人の直近 1 時間の作った数が 5 以上なら `{"error":"too_many"}` ④ 前の待ちを revoked_at に ⑤ 新しい行を作る ⑥ `{"ok": true, "expires_at"}` |
| `app.me_email_change_revoke(p_token_hash text) returns void` | その人の待ちを revoked_at に（メールが送れなかった頼みの取り消し） |
| `app.me_email_change_verify(p_token_hash text) returns jsonb` | 行を `for update` で取る → invalid／used／expired／taken の順に確かめ → kaname_auth."user" の email・emailVerified・updatedAt を変え・used_at を入れ・`app.record_security_event_for_auth_user(…, 'email_changed', …)` → `{"ok": true, "old_email", "new_email"}` |
| `app.me_email_pending() returns text` | **K-833 の空の形を `create or replace` で本物に**：その人の待っている（使っていない・取り消していない・期限内の）新しいアドレスか null |

## 外に影響する手順

- 1. DB に書く（頼む口）：待っている変更（前のを取り消し・新しいを作る）を 1 つの取引で [残る]（メールが送れなかった頼みの待ちが残る。3 で取り消す）

- 3. 後片付け：送れなかった頼みを取り消す（revoked_at）。失敗してもその印は誰にも届いていないので害は無い（ログ 1 行）
- 4. DB に書く（確かめる口）：メール・emailVerified・使った印・安全の記録を 1 つの取引で（失敗したら何も残らない）
- 5. 古いアドレスへ「変わりました」のメール（関門 C6）：失敗しても 201（ログ 1 行）

## リスク

- 「使われているメールだと分かる」（E-ME-021）はアカウントの有無を本人確認のあとの人に見せる。下絵の決め（me-email-error）。頼みすぎの上限（1 時間に 5 回・口の上限 60/分も別に在る）で、同じ人が宛てを総当たりしにくくする
