## 目的

本線の先頭（69cb1f8b）で、CI の spec の組の G27「層の棚卸し」が赤。ほかのチケットが CI に出せない。

1. **赤を直す**：入口の箱の中の読み込み中を真ん中にそろえる直しで、入口の枠（`apps/web/features/F1/sign-up/frame.tsx`）に待ちの部品 `AuthLoading` を足し、`import { Loading } from "@/components/k"`（共通の部品の束）を入れた。束 → `components/k/states.tsx` → `./error-of` → `@/lib/api` → `fetch(`。規約の文面の画面（`features/F1/consent-terms/legal-page.tsx`）は入口の枠を使うので、「API を呼ばない画面」の台帳（`05_flow/screen_api.py` の STATIC_SCREENS の `legal`）の画面が口を呼ぶコードに届き、`scripts/ci/static_screens.py` の S4 が赤になった（G27 の中の fb_gate の FB3・FB8 が 5 層・api_gate の A3 が 2 層、計 7 層）。待ちの部品を別のファイルに移し、入口の枠を束も states も読まない形に戻す

- G27 がほぼ全部のチケットの回で流れる（チケットの md を読むので）。1 回 14 秒ほど増える回が出る
- gates の 27 の並びは置き場ごとの広い glob。G27 が読まない物（apps の試験・packages の文書など）を変えた回でも流れる（流れすぎの側で、すり抜けの側ではない）
- 地図に新しい置き場の層が足されたら、011 が赤になって並びの足し忘れを止める。命令が新しい置き場を読むように変わったとき（地図に層として載らない読み先）は、011・012 では止まらない（命令ごとの読み先は人が見る）

## 申し送り

- 重い検査の当たりの抜け（上の表の G36・G38・G47・G57・G62）を直すチケットを切る。直し方は 27 と同じ（その検査が読む物を当たりに入れ、読む物の一覧との突き合わせを試験に持つ）
- 命令ごとの読み先を機械で出す形（層の命令が開くファイルを記録する）は、流れすぎが問題になってから
