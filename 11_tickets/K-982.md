## 目的

運営が銀行の入金を見て、請求書に 1 件ずつ記録する口を作る（行為 A72・D-128.69・今は 501）。記録すると顧客の請求書の画面（K-958）も払われたになり、運営の記録と会社の記録に残る（D-128.108）。答えの形は K-1005 の `OpsInvoiceRow`（11 欄・入金の並び payments を含む・D-156.44）で、運営の請求の一覧（K-983）と同じ 1 行。

- **差は残す**（D-156.32）：合計が請求の額と同じときだけ払われた。足りない・多いはお支払い待ちのまま差を残し、2 回目の入金で足せる
- **取り消し**（D-156.32）：打ち間違いは「取り消す」で、取り消す入金の id を付けて負の同じ額の行を足す（元の行は消さない・記録に残る）
- **請求書の 1 行の作り方を 1 か所に置く**：`app.billing_invoice_row(p_invoice)`。一覧の口（K-983）も同じ関数で 1 行を作る

- **入金**：`payments`（`tenant_id`＝請求書の会社・`invoice_id`・`paid_on`・`amount`・`payer_name`・`method_id 'transfer'`・`recorded_by_ops_member_id`＝運営の人の `members.id`（`app.user_id()`）・`created_by`）。払われたかの決めの後に、請求書の `status_id` を `paid`（合計＝額）か `issued`（ほか）に書き直す（K-963 の気にかけるが読む）
- **取り消し**：`reverses_payment_id` を付けると、その入金を `for update` で取り、ⓐ その請求書の、消していない、正の額の入金でなければ 404（欄なし） ⓑ もう取り消した（同じ入金を指す打ち消しの行がある）・打ち消しの行そのものなら **409 E-BILL-004**（欄なし） ⓒ `amount` が元の額と違えば **409 E-BILL-005**（欄なし） ⓓ 負の額（`-amount`）の行を `reverses_payment_id` つきで足す。一意の索引で同じ入金の取り消しは 1 つだけ
- **状態の決め**（`app.invoice_state(p_amount numeric, p_paid numeric, p_due date) returns text`・stable）：`p_paid = p_amount` なら `paid`・`p_due < 日本の今日` なら `overdue`・ほか `unpaid`。K-958 の状態の決め（K-968 が `app.tenant_invoices` に分けた所）を、この関数を呼ぶ形に create or replace で寄せる（同じ決めを 2 つ持たない・答えは同じ＝K958-API-002・003 を同じ回に流す・D-156.46）
- **1 行の形**（`app.billing_invoice_row(p_invoice uuid) returns jsonb`・security definer・stable・**アプリに execute を渡さない**＝運営の関数の中から呼ぶだけ）：`id`・`workspace { id, name }`・`plan_name`（請求書の `plan_name`・前からの行で空なら契約のプランの名前・無ければ null）・`month`（`YYYY-MM`）・`amount_total`（整数）・`state`・`paid_total`（消していない入金の合計・負の行も足す）・`difference`（`amount_total − paid_total`）・`due_on`・`can_record_payment`（`state <> 'paid'`）・`payments`（その請求書の消していない入金のうち打ち消しの行でない物を `paid_on, created_at` の順に `{ id, paid_on, amount, payer_name, reversed }`。`reversed` はその入金を取り消した打ち消しの行が在るか。画面の［取り消す］が `reverses_payment_id` に渡す id・D-156.44）

- 鈴・メールは出さない（顧客は請求書の画面で分かる・D-125.130）
