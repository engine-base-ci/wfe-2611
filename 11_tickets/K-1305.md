## 目的

代表の決め（2026-11-26・PM 経由）「完璧に直しましょう」。段の全部の CI（scope=full）で毎回赤になる、プロジェクト側の元を 2 つ直す。

1. **全部の回で .py の試験が JUnit に載らない。** `scripts/ci/ci_scope.py` の全部の回は `_full_plan` で返り、`py_tests` が空のまま。spec の組の「チケットの Python の試験」の段は `junit/spec-py.xml` に `<testsuites />`（0 本）を書く（実測：段の回 45801811744・`CI_PY_TESTS: []`）。G65 の段では試験は流れるが JUnit に書かないので、.py の試験だけで確かめる葉（K-1304・K-1156）は段の CI で毎回「流れていない」になる
2. **G64 が CI の置き場に無い sha を見て赤。** G64 の `ticket_process_test.py`（K146-CI-008）は、着手前の K-63・K-64 の突き合わせの表（`01_hearing/聞くこと_K-146.md` の「ファイル:行@sha」）の sha が git に在るかを見る。K-64 の 87970598 は控えの枝 k64-make にしか無く、置き場 engine-base-ci/wfe-2611 の写しに k64-make が無かった（ci・ci2 の置き場には在る）。赤の文は「控えの枝を消した？」で、どの枝を置き場に上げればよいかを言わない

PM の決め（作り方）：
1. 全部の回でも、段の葉の `tests:` のうち `.py` を `py_tests` に出す。**段の葉は、取り込みの機械（ticket-flow の stageq）が段の全部の CI に渡す入力 `leaves`（空白区切りの番号）だけで決める。** 木の形（取り込みのコミットの件名・親）から推し量らない・2 本立てにしない（PM の決め 2026-11-26 テスター Q 回 1：推し量りは重ねた葉を見分けられず、形の分からないコミットで黙って葉が減る）。ほかの段の葉の .py は入れない（その葉の段の CI が流す）。全部の回で入力 `leaves` が無い・空・番号（K-<数字>）の形でない語がある・名指しした葉のチケットの md が無い → errors にして**全部の回を止める**（組を流さず終わりの番号 1）。名指しした葉の `tests:` が何にも当たらない → 止めずに理由（その葉の行だけが記録に無く照らしで赤）。葉を出すのに base は使わない。チケットの回（scope=ticket）は `leaves` を見ず今と同じ
2. CI の定義（作り手 `05_flow/build_testplan.py`・生成物 `v3-gate.yml`）の workflow_dispatch に入力 `leaves`（string・既定 ''）を足し、`ci_scope.py` を流す 4 つの段（static・spec・spec-2・spec-3）の env に `CI_LEAVES_INPUT: ${{ inputs.leaves }}`、run に `--leaves "$CI_LEAVES_INPUT"`。`ticket-flow.yaml` の `ci.inputs` に `leaves: leaves`（ci.py は入力の名前を ci.inputs で引く）。スキル側（stageq の full_ci が fields に leaves を渡す・ci-contract・setup.py check）は別の担当が直す
3. G64 は緩めない：着手前の間は sha とファイル:行の在りかまで見るのは今のまま。置き場が写しでも同じ中身を見る。直すのは「置き場に要る枝が分かる」こと：ページの「<K-番号> は枝 <枝> の <sha>」（控えの枝の宣言）を読む道具 `scripts/ci/prior_refs.py` を足し、無い sha の赤の文に枝の名前と上げ方を出す。着手前のチケットに宣言が無いのは赤。表の sha が宣言の sha と違い、取り出した木の履歴（HEAD の先祖・どの写しにも在る。K-64.md:48@38aee79b は本線の版）にも無いときは「宣言と違う」の赤（git に無くても、宣言の枝を上げても直らないので git push の文は出さない）。置き場の枝の先頭が手元に無いときは git fetch を案内する赤。確かめは `prior_refs.commit_problems` の 1 か所にし、K146-CI-008 はそれを呼ぶ
4. G65 の中で `k425_decision_log_test.py` が赤で止まり後ろの .py の試験が走らない形（`&&` でつなぐ）は替えない：決まり（ai-driven-process §9「検査の繋ぎは && で」）どおりで、1 の直しで葉の .py の行は G65 と別の段（G64・G65 より前・`!cancelled()`）で JUnit に載るので、G65 が途中で止まっても照らしの行は落ちない（K1305-CI-007 で見る）。k425 の赤そのもの（決定ログの answer が答えの記録に無い 5 件）は別の元で、この葉では直さない
