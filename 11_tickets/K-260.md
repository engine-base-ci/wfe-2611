## 目的

取り込んだ後にまとめて流した画面の CI（https://github.com/engine-base/Kaname/actions/runs/43919201388）で、作る画面の試験 K224-UI-028 が
`page.goto: net::ERR_ABORTED at http://127.0.0.1:3124/tickets?new=1`（CI の版の試験の 572 行＝(d) の前の openCreate）で落ちた。前に「作った後に詳細へ移るのを待ってから次へ」（toHaveURL）を足したが、まだ揺れる。原因を突き止め、期待を弱めず・決めた時間の待ちを足さずに直す。

## 原因（確かめたこと・2026-11-17）

1. 作ると、作る面は `window.location.assign("/tickets/<id>")` で詳細へ移る（`apps/web/features/F4/create-ticket/tickets-page.tsx`）。toHaveURL は、新しい文書に URL が移った時点で通る。このときまだ詳細の画面の JS は動き出していないことがある（CI の VM は遅い）
2. 詳細の画面（`ticket-detail.tsx` の DetailBody）は、動き出したときの最初の処理で鍵（localStorage の `kaname.token`）を見て、無ければ `window.location.replace("/login?next=…")` で移す
3. 試験は (d) の前に `localStorage.clear()` で鍵ごと消してから `openCreate`（goto）する。詳細の画面が動き出す前に消すと、動き出した詳細の画面が鍵の無いことを見てログインへ移し、その移りが走っている goto を取り消す → ERR_ABORTED
4. 使い捨ての試験（リポジトリには入れない・本番の形で組み立てた画面）で、詳細の画面の JS（`app/(work)/tickets/[id]/page-*.js`）を 1.5 秒・開き直しの文書の答えを 3 秒遅らせて（CI の VM が遅いときの形）今の形をなぞると、goto が 3 回とも CI と同じ `net::ERR_ABORTED` になった。詳細の見出しが出るのを待ってから消す形は 3 回とも 200 だった。遅らせなければ手元では詳細の画面が先に動き出すので揺れが出にくい（手元で緑・CI で赤になる訳）
5. 前の直し（toHaveURL）は「移る途中の goto」を防いだが、「移った後、画面が動き出す前に鍵を消す」は防いでいなかった

### 選ばなかった直し方

| 案 | 選ばない訳 |
|---|---|
| 決めた時間（例 1 秒）待ってから消す | 遅い VM では足りず、速い所では無駄。決めた時間の待ちは足さない |
| 鍵を残して写しだけ消す | 揺れは消えるが、詳細へ移り切る前に次へ進む形が残る（別の理由で詳細が移れば同じく揺れる）。移り切るのを待つ方が原因に当たる |
| goto を取り消されたらやり直す | 落ちる原因を隠すだけで、期待を弱めるのと同じ |
| 詳細の画面を直す | 鍵が無ければログインへ移すのは決まりどおり。試験の待ち方の誤り |
