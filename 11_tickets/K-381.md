## 目的

メニューの型（`components/k/menu.tsx`・K-369）・選ぶ欄（`select.tsx`）・外枠の自分のメニュー（`shell.tsx`）・自分の設定の第 2 ナビ（`me-sub.tsx`）の開いた箱は、Base UI の置き場（Positioner）が transform で重なりの層を作り、重なりの順（z-index）を持たない。だから画面の上に貼り付く物（詳細の本文の道具の帯 z-index 1・上の帯 20・スマホの右のパネル 30・下のタブ 40・メニューの引き出し 45）と重なると、**箱がその下に潜る**（段 7 の下絵で、頭の行の段の札のメニューが本文の道具の帯の下に潜った。下絵は F6 の CSS で `[role="presentation"]:has(> .k-prog-menu) { z-index: 2 }` を当てて避けていた）。

箱の置き場の 4 か所に共通のクラス `k-popup-layer` を付け、重なりの順を正本のトークン `--k-c-popup-layer-z`（正本の部品 `popup-layer` の `zIndex`）で 1 か所で決める。使う側が置き場を狙って避ける形はやめる（段 7 の下絵の避け方は K-382 が運ぶ時点で消してある）。

- 層の高さは **70**：今の画面の CSS の z-index のうち、小窓の後ろの幕（80）より下の物で一番高いのは前の外枠（`components/shell/shell.css`）の 50〜60 と AI の成果物の板（`components/ai/chat.css`）の 61。それより上・幕より下。小窓（81）の中で開く選ぶ欄は、Base UI の置き場が小窓の外（body）に出るので 70 では小窓の裏に回る（K-372 が直した不具合）。選ぶ欄の一覧だけ専用の層 popup-layer-field（82）で小窓の上に出す（K381-UI-005 で見る）
- あわせて、メニューの型の開くボタン `MenuTrigger` に `disabled?` を足す（段 7 の K-395 が、段を送っている間に段の札を押せなくするのに使う・まとめ役の決め）。押せない間は `aria-disabled="true"` を付け、押しても・Enter・Space・↓ でも箱を開かない。Base UI の Trigger に native の `disabled` は渡さない（渡すと焦点がボタンから落ち、送り終わったときに焦点が迷子になる）
- 効く所：段 4 の PC の行の「…」のメニュー（K-369 の `PcMoreMenu`・本物の画面につなぐのは K-363）と、段 4 で本線に入る・作っている葉の PC の行の部品（K-349・K-361・K-373）が使う選ぶ欄とメニュー、段 7 の段の札のメニュー（K-395）・書き込みの「…」（K-394）・書く欄の「状態 ▾」（K-396）、段 9 の箱。どれもこの型を使うので、使う側で避けなくてよくなる
