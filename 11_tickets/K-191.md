## 目的

並行で進めたチケットを本線に入れるとき、本線が先に進んでいても、本線の新しい変更とその枝の変更が同じファイルに重ならなければ、CI を流し直さずに入れる（2026-11-13・決める人 answer=86dae8f3cdc0「ぶつからなければ流し直さない」）。

進め方の道具（ticket-flow の取り込み）は、枝に本線を取り込んでから入れる形になった。取り込みでぶつかってよいのは設定 changes_ignore の物（作り手が作る生成物と、決める人の答えの記録）だけで、設定 `catch_up.union` に挙げた物は両方の行を残し、ほかは本線の版にして設定 `catch_up.regen` の命令で作り直す。作り直した後は CI を流さずに本線に入る。
Kaname にはこの 2 つの設定と作り直しの命令がまだ無いので、生成物（11_tickets/tickets.json など）がぶつかると今は止まる。

設定を入れると、changes_ignore の物は「ぶつかったら本線の版にして作り直す」物になる。だから changes_ignore と生成物の目録（scripts/ci/generated.json）は、作り手が実際に書くファイルとちょうど同じでなければならない。今は 2 つの向きでずれている（下の「洗い出し」）：

- 作り手が書くのに載っていない物（3 つ）：今日 2 回、ER 図に列を足すチケットが「changes: の外を変えた」で止まった
- 載っているのに、どの作り手も書かない手で持つ物（3 つ。glob に当たっている）：設定を入れた時点で、取り込みでぶつかると本線の版に黙って置き換わり、枝が足した分が消えたまま本線に入る

両方をこのチケットで直し、同じ形が次に出たら生成物の検査が赤にする（F5・F6）。

## 前提と制約

- 取り込みの動き（本線を枝に取り込む・ぶつかった物の扱い・コミット）は道具（ticket-flow）が持つ。このチケットはプロジェクトの側の設定・台本・目録・検査だけ
- 道具は `git merge --no-ff --no-commit` の後、ぶつかった changes_ignore の物を本線の版に書き（本線が消した物は消し）、`git add` をせずに、取り込み先の作業場所をいまのフォルダにして作り直しの命令を `bash -c` で呼ぶ。だから台本が流れるときの作業場所は、index に未解決の物があり（`git ls-files` は同じ道を段ごとに 2〜3 回出す）、版にあるのに作業場所に無いファイルがある。0 以外で終われば道具は取り込みをやめて元に戻し、出力（stdout の後に stderr をつないだ物）の最後の 300 字だけを出す
- 作り手の一覧は目録（scripts/ci/generated.json の generators）だけが持つ。台本は一覧を持たない。前からある持ち込みの台本（scripts/tickets/cut_take.py）の短い一覧（5 つ）はこのチケットでは変えない
- 目録と changes_ignore から外す手で持つ 3 つ（07_qa/test-plan/ears-elsewhere.json・07_qa/test-plan/result-ledger.json・packages/contracts/src/index.ts）は、これからは変えるチケットが changes: に書く物になる。取り込みでぶつかれば「ぶつかった」で止まり、実装の人が手で合わせてチケットの CI を流し直す。今走っている枝でこの 3 つを変えているチケットは K-165 だけで、changes: に書いてある（2026-11-13・t/ の枝 24 本を本線との差分で見た）
- 目録の outputs を読む前からある道具（scripts/ci/ci_scope.py・ticket_order_gate.py の generated_outputs）では、外した 3 つが「生成物」でなくなる。実装の人は scripts/ci/ci_scope_test.py・ci_lean_test.py・k178_flow_config_test.py を流して緑を見る（K178-CF-003 は、目録と changes_ignore を同じに替えれば緑のまま）

### 作り直しの台本

| 欄 | 中身 |
|---|---|
| 台本 | scripts/tickets/regen_all.py（引数なし）。目録の作り手を上から順に 1 回ずつ流すのを 1 周とし、周の中で 1 つも変わらなくなるまで周を重ねる。上限は 3 周 |
| なぜ周を重ねるか | 前の作り手が、後ろの作り手の生成物を読む（05_flow/build_testplan.py は 6 番目で、12 番目の scripts/tickets/build_index.py が作る 11_tickets/tickets.json を読む）。取り込みで tickets.json が本線の版になると、1 周ではテスト計画が古い一覧から作られたまま残る。目録の順には頼らない。要件一覧（trace_gate.py --index）を最後にもう 1 度流す特別扱いは持たない（目録にあり、周を重ねれば足りる） |
| 「変わった」の見方 | 周の前と後で、git が知っているファイル（版に入っている物と、無視していない新しい物）の中身を比べる。変わった・新しくできた・消えたが 1 つでもあれば「変わった」。作った日を刻む出力の「今日の刻みだけの違い」（下）は変わったに数えない |
| 終わり方 | ある周で 1 つも変わらなければ、そこで終わって 0（変わらない作業場所なら 1 周だけ）。3 周目でもまだ変わったら 0 以外で終わり、出力の最後の 1 行に、先に説明（「3 周」流しても変わる）、続けて 3 周目に変わったファイルの名前を先頭の 5 件までと総数（`40 件` の形）を出す（ファイルが多くても、説明が最後の 300 字から押し出されない）。0 で終わった状態は、もう 1 度流しても変わらない。前の結果を覚えて作り手を飛ばすことはしない |
| 流す場所 | 呼んだときのいまのフォルダが入っている git の作業場所の根（`git rev-parse --show-toplevel`）。目録もその根の scripts/ci/generated.json を読む。作り手はどれも根をいまのフォルダにして、シェルの 1 行として流す（run の中の `cd 05_flow && …` はその作り手にだけ効く）。台本のファイルがある場所では決めない。git の作業場所の外から呼ばれたら、何も流さずに 0 以外で終わる |
| 目録を読めない | 目録が無い・JSON でない・generators が無い・並びでない・空・run が無い（空の字を含む）項目が 1 つでもある → 目録の道（scripts/ci/generated.json）を出して 0 以外で終わる。作り手を 1 つも流さない（読めた所まで流さない） |
| 作り手が落ちた | 最初に落ちた所で止める（後ろの作り手も次の周も流さない）。作り手が出した文を出し、その後、出力のいちばん最後の 1 行に、落ちた作り手の name と run をもう一度出して 0 以外で終わる。作り手の文がどれだけ長くても、stdout の後に stderr をつないだ最後の 300 字に name と run が入る（道具が PM に見せるのはそこだけ）。本物の目録の name と run は合わせて 200 字に収まる |
| 作った日を刻む出力（dated） | 目録の作り手ごとの欄 `dated`：その作り手の outputs のうち、作り手が「作った日」を刻む物の並び（glob 可・outputs と同じ書き方）。無ければ、その作り手は作った日を刻まない。戻す・戻さないはファイルの道で決める（どれかの作り手の dated に当たる道が「作った日を刻む出力」）。dated が字の並びでない目録は「目録を読めない」と同じに止まる |
| 今日の刻みを戻す | 台本を始めたときの中身を覚えておき、終わるとき（落ちたとき・3 周で止まらなかったときも）に、作った日を刻む出力のうち「違いが今日の刻みだけ」の物を、始めたときのバイトに戻す。「今日の刻みだけ」とは：日付の形（生成物の検査 scripts/ci/generated_gate.py の DATE と同じ式。`2026-11-13` と `2026-11-13T01:02:03Z` の形）を伏せると同じ中身で、かつ、違っている日付の新しい側の年月日が、どれも台本を流した日（手元の日付か UTC の日付）であるもの |
| 戻さない物 | ① dated に当たらないファイルは、日付だけの違いでも、新しい側が今日でも戻さない（チケットの期限 due を今日に変えた後の 11_tickets/tickets.json・tickets.csv・README.md、決めた日が変わった 01_hearing/要件一覧.md は本物の変更で、作った日の刻みと見分けられない）② dated に当たるファイルでも、違っている日付の新しい側に今日でない日付が 1 つでもあれば戻さない。①② は「変わった」にも数える |
| 戻し方 | 同じフォルダの一時のファイルに書き切ってから置き換える（元のファイルの中に直に書かない。途中で落ちても中身が欠けない）。権限は元のファイルに合わせる。一時のファイルは残さない |
| 覚える量 | 始めたときのバイトを覚えるのは、dated に当たるファイルだけ（1 ファイル 5MB まで。超える物は戻す対象にせず、変わったかどうかだけを見る）。周ごとの「変わった」は、ファイルの中身の要約（sha256）で比べる（dated に当たる物だけはバイトで比べる）。git が知っている全部のファイルの中身をメモリに持たない |
| OS・git の失敗 | ファイルの読み書き・置き換えの失敗（権限が無いなど）と git の命令（`git ls-files`）の失敗でも、Python の例外の跡（Traceback）を出さずに 0 以外で終わり、出力の最後の 1 行に、何が失敗したか（ファイルの道か、落ちた git の命令）を出す。ファイルの一覧を読めなければ作り手を流さない。作り手が落ちた後に戻すのにも失敗したら、最後の 1 行に、落ちた作り手の name・run と、戻せなかったファイルの両方を出す（後の失敗が前の失敗を隠さない）。戻せなかったファイルは作り手が書いた中身のまま（欠けない） |
| 中身の違い | 日付の形を伏せても違う物は、新しい版のまま残す（作った日も新しいまま）。新しくできたファイルも残す。作り手が消したファイルは消えたまま（戻さない） |
| 取り込みの途中 | index に未解決の物がある作業場所・版にあるのに作業場所に無いファイルがある作業場所でも、落ちずに同じ動きをする（無いファイルは「無い」として覚え、作り手が作らなければ無いまま。同じ道を 2 度戻さない）。台本は `git add` もコミットもしない。台本の後の `git add -A` と `git commit` が通る |
| 読み方 | git が知っているファイルは `git ls-files -z` で読む（日本語と空白の名前を落とさない） |

## PM が決めたこと

作り方の決めで、製品のふるまいではない（2026-11-13・精査の指摘を受けて）。

## リスクと懸念

- F5・F6 は更新の時刻で「書いた」を見る。中身が同じなら書かない作り手は、F6 の理由つきの一覧（not_always_written）に載せないと赤になる（今は gen_built_routes.py の 1 つ）
- 作り直しは 1 周が手元 4 秒ほど（2026-11-13 の実測・作り手 16 個）。取り込みでは 2〜3 周で 8〜12 秒。node の作り手は node の組み込みだけを読むので node_modules は要らない。python の作り手は yaml が要る（PM の殻の python3 に入っている）。入っていない殻では作り手が落ち、取り込みは「作り直しの命令が落ちた」で止まる（黙って古い生成物を入れない）
- F5・F6 は更新の時刻（と大きさ）で「書いた」を見る。時刻の刻みが粗い台では、前の作り手が同じ刻みの内に書いたファイルを次の作り手が同じ大きさで書いても見えない（F5 の見逃し・F6 の誤り）。作り手 1 つは数十ミリ秒かかるので今は当たらない。当たったら、流す前の中身の要約と合わせて見る形に直す
- リポジトリの中のシンボリックリンクが dated に当たると、戻すときにリンクそのものがふつうのファイルに置き換わる（リンクの先には書かない）。今、dated に当たるリンクは無い
- 作り手が落ちた回（F2）は、書かれなかったファイルが F6 にも重なって出る（赤の理由は F2 を先に読む）
- result-ledger.json を CI が減らすチケットは、changes: にそれを書く（書かないと「changes: の外」で止まる）
- 日をまたいで流すと、前の周に刻んだ日付が「今日」でなくなり、戻らずに残ることがある（中身は正しい。生成物の検査は日付の違いを見ないので赤にはならない）
- 後ろの生成物を読む鎖が 2 段より深くなると、3 周で止まらずに取り込みが止まる（今の目録は 1 段。止まったら目録の順を直す）
- 持ち込みの台本（cut_take.py）は自分の短い一覧を持ったまま。作り手を足したときにそちらが古くなる形は残る
