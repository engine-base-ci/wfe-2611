## 目的

並行で進めたチケットを本線に入れるとき、本線が先に進んでいても、本線の新しい変更とその枝の変更が同じファイルに重ならなければ、CI を流し直さずに入れる（2026-11-13・決める人 answer=86dae8f3cdc0「ぶつからなければ流し直さない」）。

進め方の道具（ticket-flow の取り込み）は、枝に本線を取り込んでから入れる形になった。取り込みでぶつかってよいのは設定 changes_ignore の物（作り手が作る生成物と、決める人の答えの記録）だけで、設定 `catch_up.union` に挙げた物は両方の行を残し、ほかは本線の版にして設定 `catch_up.regen` の命令で作り直す。
Kaname にはこの 2 つの設定と作り直しの命令がまだ無いので、生成物（11_tickets/tickets.json など）がぶつかると今は止まる。

あわせて、今日 2 回止まった穴をふさぐ：作り手（05_flow/build_api.py）が作る 08_api/api-field-consumption.json が、設定 changes_ignore にも生成物の目録（scripts/ci/generated.json）にも載っておらず、ER 図に列を足すチケットが「changes: の外を変えた」で止まった。同じ形の物を機械で洗い出し（下の「洗い出し」）、同じ形が次に出たら検査が赤にする。

## 前提と制約

- 取り込みの動き（本線を枝に取り込む・ぶつかった物の扱い・コミット）は道具（ticket-flow）が持つ。このチケットはプロジェクトの側の設定・台本・目録だけ
- 道具は作り直しの命令を、取り込み先の作業場所をいまのフォルダにして `bash -c` で呼ぶ。0 以外で終われば取り込みをやめて元に戻し、出力の最後の 300 字を出す。だから台本は、落ちた作り手の名前と命令を出力の最後に出す
- 作り手の一覧は目録（scripts/ci/generated.json の generators）だけが持つ。台本は一覧を持たない。前からある持ち込みの台本（scripts/tickets/cut_take.py）の短い一覧（5 つ）はこのチケットでは変えない（持ち込みの後は一部の作り手で足りる。全部に替えるかは別に決める）
- 台本の先頭 3 行に、生成物の検査が拾う言い回し（scripts/ci/generated_gate.py の MARK）を書かない
- scripts/tickets/** と scripts/ci/** は CI の範囲の地図（scripts/ci/ci_scope.json の full.ci）にもう入っている。地図は変えない
- ticket-flow.yaml は道具の「changes: の外を変えていないか」の検査に数えられる（数えないのは changes_ignore・11_tickets/**・`.ticket-flow*/**` で、ticket-flow.yaml はどれにも当たらない）。だから changes: に書く

### 作り直しの台本

| 欄 | 中身 |
|---|---|
| 台本 | scripts/tickets/regen_all.py（引数なし）。目録の作り手を上から順に 1 回ずつ流し、全部が 0 で終わったら最後に `python3 scripts/ci/trace_gate.py --index`（要件一覧。後ろの作り手が作った物を読むので、もう 1 度最後に流す）を流す |
| 流す場所 | 呼んだときのいまのフォルダが入っている git の作業場所の根（`git rev-parse --show-toplevel`）。目録もその根の scripts/ci/generated.json を読む。作り手はどれも根をいまのフォルダにして、シェルの 1 行として流す（run の中の `cd 05_flow && …` はその作り手にだけ効く）。台本のファイルがある場所では決めない（別の作業場所の台本を道で呼んでも、呼んだ側の作業場所で流れる）。git の作業場所の外から呼ばれたら、何も流さずに 0 以外で終わる |
| 目録を読めない | 目録が無い・JSON でない・generators が無い・並びでない・空・run が無い（空の字を含む）項目が 1 つでもある → 目録の道（scripts/ci/generated.json）を出して 0 以外で終わる。作り手も最後の命令も 1 つも流さない（読めた所まで流さない） |
| 作り手が落ちた | 最初に落ちた所で止める（後ろの作り手と最後の命令は流さない）。その作り手の name と run、作り手が出した文の最後を出して 0 以外で終わる。最後の命令が落ちた・その台本が無いときも同じ（命令を出して 0 以外） |
| 日付だけの違い | 流す前の中身を覚えておき、終わったとき（落ちて止まったときも）に、git が知っているファイル（版に入っている物と、無視していない新しい物。`git ls-files -z` で読む）のうち、中身が変わったが日付を伏せると同じ物を、流す前のバイトに戻す。日付の見方は生成物の検査と同じ決まり（scripts/ci/generated_gate.py の DATE：`2026-11-13` と `2026-11-13T01:02:03Z` の形）。台本は `DATE` という名前でその決まりを持ち、検査のものと同じ式にする（試験が突き合わせる） |
| 中身の違い | 日付を伏せても違う物は、新しい版のまま残す（日付も新しいまま）。新しくできたファイルも残す |
| 終わり方 | 全部が 0 で終わったら 0。流した作り手の数を 1 行出す。2 回続けて流しても、1 回目の後から何も変わらない（前の結果を覚えて飛ばすことはしない。毎回全部流す） |

## 決める人の答え

- 本線が先に進んでいても、同じファイルを変えていなければ、チケットの CI を流し直さずに取り込む（「ぶつからなければ流し直さない」）。チケットの CI はそのチケットの範囲だけで、組み合わせは大分類の終わりの全部で見る（D-133.7）

## 切る段が決めたこと

作り方の決めで、製品のふるまいではない。

- 洗い出しで 3 つ見つかったので、3 つとも同じチケットで目録と changes_ignore に載せる
- 同じ形（作り手が目録の外に書く）を次に機械で止めるため、生成物の検査に F5 を足す。前からある突き合わせ（K178-CF-003・この試験の K191-RG-014）は「2 つの一覧が同じか」しか見ず、両方に無い物は緑のまま通していた（今日の穴はこれ）
- 作り手が落ちたら最初の 1 つで止める（後ろの作り手は前の生成物を読むので、続けても正しい物にならない）
- 根は呼んだ場所の git の作業場所で決め、git の外では止まる（台本のある場所へ倒さない＝別の作業場所を黙って書き換えない）
- 日付だけの違いを戻すのは、落ちて止まったときも同じ（手で流したときに差分を残さない）

## リスクと懸念

- F5 は更新の時刻で「書いた」を見る。中身が同じなら書かない作り手（scripts/ci/gen_built_routes.py）は、変わらない回には当たらない（変わる回は F1 が見る）
- 作り直しは作り手 16 個で手元 4 秒ほど（2026-11-13 の実測・依存が入っている作業場所）。node の作り手は依存（node_modules）が要る。取り込み先の作業場所に依存が無いと落ち、取り込みは「作り直しの命令が落ちた」で止まる（黙って古い生成物を入れない）
- 持ち込みの台本（cut_take.py）は自分の短い一覧を持ったまま。作り手を足したときにそちらが古くなる形は残る
