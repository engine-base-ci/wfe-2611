## 目的

招待の画面のうち、宛てのメールにアカウントがある人・ログイン中の人の 4 つの状態を本物にする（代表の答え answer=becc3d3aa526 ②③④・7fe1f09fdab4 ⑦）。

- アカウントがある（ログインしていない）：「ログインして参加する」→ /login?next=/invite/<token> → ログインの後この画面に戻り、「今のアカウントで参加する」1 つで入る
- ログイン中・同じメール：「今のアカウントで参加する」→ 招かれたワークスペースに切り替わって「/」へ
- ログイン中・別のメール宛て：「この招待は a@… 宛てです。いまは b@… でログインしています」→「ログアウトして開き直す」（今のアカウントでは参加させない）
- もう入っている：「〈ワークスペース〉にはもう入っています」→「開く」（参加の口は呼ばない）

## 前提と制約

分類: INV

- 依存：K-335（同じ入れ物 invite-page.tsx）・K-333（今のアカウントで参加の口）
- ログインの画面は今の /login（next は同じ出どころの道だけ・apps/web/lib/after-login.ts の sameOriginPath）。段 2 の K-316 が見た目を載せ替えても、欄（メール・パスワード）と送る form の submit は同じ役
- ログイン中の判定は下見の答えの signed_in だけで決める（画面で別に「誰か」を聞かない）。印が壊れて signed_in が null なら、ログインしていない形で出す（401 でログインの画面へ飛ばさない）
- 段 2 の「付けるまで進めない」：画面の試験の本人は試験の鍵で入り方をそろえてからログインする（K-321 の道具と同じ）

## 実施事項

| 何を | どこ・どう |
|---|---|
| アカウントがある | loginHref は `/login?next=${encodeURIComponent("/invite/" + token)}`。名前とパスワードの欄は出さない |
| 今のアカウントで参加 | 体なしで参加の口 → 201 は data.token を kaname.token に置き data.next（"/"）へ。409 E-INV-007 は member の状態・403 E-INV-005 は other の状態へ（K336-UI-009）。403 E-INV-005 のときは、出すログイン中のメールが下見の時の物と違う（開いた後に別のアカウントへ入り直した）ので、形は other のまま下見を読み直して中身（signed_in.email）だけ入れ替える（K336-UI-013） |
| 今のアカウントで参加の口のほかの断り | 新しく作って参加（K-335）と同じ道を通す（K336-UI-011）：410（E-INV-002・003・004）・404 → 下見と同じ画面／409 E-INV-006 → アカウントがある形／429 → 赤の知らせに正本 E-LIM-005 の文（口の秒）／403 E-AUTH-012 → 赤の知らせに口の文／網の切れ → 赤の知らせ。422 が返った（開いた後・押す前にログインが切れ、口がログインしていない人として受けた）ら、この形には欄が無いので下見を読み直して今の形を出す（K336-UI-010 ①） |
| 別のメール宛て | 下見の答えの email（宛て）と signed_in.email（ログイン中のメール・K-331 が答えに入れる）を出す。ログアウトの口（POST /api/v1/auth/sign-out・K-306）→ kaname.token と、この PC の書きかけの写し（K-60・lib/auth の signOut と同じ）を消す → 同じ招待の下見を読み直す（ログインしていない形・ページは読み込み直さない）。口が 401（もう切れていた）のときも通ったのと同じに扱う（K336-UI-010 ②） |
| 口の失敗 | 参加の口・ログアウトの口が 503・網の切れなら、K-335 が足した赤の知らせ notice に「いま Kaname の調子が悪くなっています。少し待ってから、もう一度押してください」を出し、ページは移らない。ログアウトの口の 429 は正本 E-LIM-005 の文。ログアウトが失敗したら印も書きかけの写しも消さない（知らせとボタンは K336-UI-008・印と写しが残ることは K336-UI-012） |
| 二度押し | 押した口の答えを待つ間、ボタンは待ちの形で押せない。口は 1 回だけ呼ぶ（K336-UI-014・K-335 の入れ物の決まりと同じ） |
| 部品の印 | K-335 が付けた押せない印（views の signedLocked）を外す。赤の知らせ notice を、ログイン中の 2 つの状態（signed・other）の押すボタンの上にも出す |
| もう入っている | 「開く」は "/"（そのワークスペースへ切り替える口はまだ無いので、今の場所の「/」。切り替えは左上・D-128.46） |
| 親 | 11_tickets/K-55.md の残り（このチケットの分）を外す。全部の葉が入ったら K-55 は完了。2026-11-19：本線の K-55 は screens・apis・tests がもう空（画面の行は K-335 が外した）で、この葉が外す行は残っていない（K-55.md は変えない） |

## 外に影響する手順

画面は口を呼ぶだけ。呼んだ口が失敗したときの画面：

- 1: 今のアカウントで参加の口を呼ぶ。失敗（503）したらページは移らず赤の知らせ（K336-UI-008）。429・網の切れも同じ（K336-UI-011）
- 2: ログアウトの口を呼ぶ。失敗（503・429・網の切れ）したらページは移らず、印は消さずに赤の知らせ（知らせとボタンは K336-UI-008・印が残ることは K336-UI-012）
