## 目的

決める人の決定 D-128.169（チケットごとの CI は機械で出した影響の範囲に絞る）は K-107 で仕組みが入ったのに、2026-11-09 の取り込み 2 回（K-144・K-143）はどちらも「範囲：全部」で流れ、1 回 23.5 分かかった（11 組を順に 1 つずつ・段の合計 20.1 分）。決める人「なんでそんなに CI が時間かかるの」「更新部分とか影響部分だけ流してそうなんだ本気で？？」。act の回の記録を実測して原因を 3 つに切り分けた。

1. **範囲の表の抜け**：`scripts/ci/ci_scope.json` に生成物（07_functional/*・08_api/*・07_qa/test-plan/*・11_tickets/tickets.json・01_hearing/要件一覧.md ほか `scripts/ci/generated.json` の outputs）と、その作り手（05_flow/*.py）が載っていない。載っていないファイルは unmapped として「全部」に倒れる。どのチケットも取り込みの前に生成物を作り直すので、実質どのチケットも全部になる（K-144 の回の理由：unmapped（05_flow/build_api.py・07_functional/features.json・08_api/api-decisions.json …））
2. **spec の G27（層の棚卸し）3.5 分**：`layer_audit.py --run` が 62 の検査をもう一度（static と二重に）回す。中に `pnpm -s type-check` 8 回・trace_gate 6 回など、static の段（G1・G2）や spec の他の段で既に流している検査の繰り返しが入っている
3. **spec の G46（部品の確かめ）2.6 分**：`stack_gate.py` の S6 が毎回 npm の registry に lockfile の全部（約 1,000 個）の出た日を聞きに行く。lockfile が変わっていない回でも同じ答えを取りに行く

## 前提と制約

分類: TOOL

- workflow（.github/workflows/v3-gate.yml）は GitHub と同じものを使う決まり（正本 §9）。直すのは検査の台本と決まりの表で、組の形（組の数と名前・段の形）は変えない。組の依存（needs）1 行・upload の条件 1 行は作り手（05_flow/build_testplan.py）で直し、生成物を作り直す
- 台の側（Docker の記憶と CPU・act の同時の数〔~/.actrc の --concurrent-jobs〕・action の手元の写し）は PM が ~/.actrc と Docker Desktop で直す（このチケットの外・ai-team-delivery の references/ci.md §3）。同時の数の実測は、~/.actrc を変えずに `act_ci.sh <sha> -- --concurrent-jobs N` で回ごとに渡して測る
- スキルの台本（act_ci.sh・pm_merge.sh）はこのチケットでは触らない。成果物の落ち方の手当てがスキル側に要るなら「判断をお願いしたいこと」に書く
- 見込みは列に入れるときに、直近の取り込みの実測から引いて書く

### 決まり（切る時点で出した 4 つの問いと、決める人の答え・D-133・2026-11-09 answer=cf9419dd10ab）

1. CI で記録が lockfile と合わないときは **赤（S7）**にし「手元で `python3 scripts/ci/stack_gate.py` を流して記録をコミットする」と出す。手元では赤にせず記録を書き直す（D-133.1）
2. hookTimeout は **11 秒**（CI の記録の全部のファイルの最大 3.6 秒 × 3 を切り上げ）を vitest.config.ts の 1 か所に。式と実測の数を注釈に（D-133.2。2026-11-09 answer=cf9419dd10ab で式と 6 秒、2026-11-10 answer=5185823099d3 で数を 11 秒に直した）
3. 「CI の設定に触った回は全部」の範囲に **scripts/ci/** を含め続ける**（D-133.3）
4. 台の側：PM が Docker の CPU を 4 → 6 にしてから、同時 2 で成果物が届くかを測る（D-133.4・PM の判断）
5. tickets.json の変化で web の組を流すのは、変わった・足した・消した行が画面を持つチケット（screens: か apps/web の tests: がある）のときだけ（D-133.5・2026-11-10 answer=a224738a2ce5・K107-CS-061 の当てはめを変える）。「普通のチケットの回が 3 分以内」は、この直しと同時 2 の実測の後に引き直す（PM の判断）
