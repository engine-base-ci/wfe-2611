## 目的

ログインの画面（`/login?next=…`）は、入った後の行き先 `next` を afterLogin に渡す。afterLogin は「/ で始まり // で始まらない」だけを見て、そのまま `router.push` に渡している。
`?next=/%5Cevil.com`（画面には `/\evil.com` として届く）や `?next=/%09/evil.com`（`/<タブ>/evil.com`）はこの見方を通り、ブラウザは `\` を `/` と読み、道のタブと改行を消すので、`//evil.com` ＝ https://evil.com/ へ移る（開いた転送）。
ログインの直後に偽のログインの画面へ送れるので、パスワードを抜く入口になる。代表の答え（answer=afc3b0f2fdb4）で割り込みにした。

## 完了の条件

- [ ] 下の 15 行（K259-LIB-001〜013・K259-UI-001〜002）が緑
- [ ] afterLogin は next を `new URL(next, location.origin)` で解き、出どころが同じときだけ 道＋問い合わせ＋# を返す。違えば既定の行き先 `/`
- [ ] 同意し直しの画面（consent-terms.tsx）は変えない（K-53 の画面の試験 K53-UI-012 は今のまま緑）
- [ ] チケットの CI が緑

## 実施事項

| 欄 | 中身 |
|---|---|
| 判定（apps/web/lib/after-login.ts） | `export function sameOriginPath(next: string \| null \| undefined, fallback: Route): Route` を置く。window が無ければ fallback。`new URL(next, window.location.origin)` で解き（例外なら fallback）、出どころが違えば fallback。道を符号から戻して（decodeURIComponent・例外なら fallback）、制御文字（\u0000-\u001f・\u007f）か `\` を含むか、`//` で始まれば fallback。それ以外は `pathname + search + hash` |
| ログイン（同じファイル） | `afterLogin(next)` は `sameOriginPath(next, "/")` を返す（既定の行き先は入口 `/`。今のまま） |
