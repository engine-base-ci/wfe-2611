## 目的

段 1 の画面のチケット（K-51〜K-65・K-161〜K-165）には、どの絵が正かも、絵と見比べることも書かれていなかった（調べの H4・H12）。決める人の決め（D-143.5・answer=4d3e8f714c5d）：画面を作る・変えるチケットは ①どのモックが正かを書く ②モックが無い画面は作る前にモックを起こして代表に見てもらう ③モックどおりかを機械で突き合わせてから完了にする。

このチケットは ① を機械で必須にし、③ の突き合わせの組（K-216 の 04_design/fidelity.json）と結ぶ検査 `scripts/ci/canvas_field_gate.py` を作る。

- 当てるチケット：取り込み済み（stage が確認中・完了）でなく、子を持たず、次のどれかに当たる ── 頭の screens が空でない／頭の area が「画面」／頭の changes に `apps/web/(app|features|components/k|styles)/` の道がある
- 当てたチケットは頭に `canvas: [<組の id>, …]`。組は fidelity.json に在り、組の owner がこのチケット。状態は組が持つ（組の id で状態まで決まる）
- 逆向き：fidelity.json の組の owner は 11_tickets に在り、取り込み済み（確認中・完了）でなければ canvas を持ち、その canvas に組の id が在る（持ち主なのに書き忘れた組が出る。台帳に載っていても、当たり方に当たらなくても赤。取り込み済みの持ち主は見ない）
- 全部の画面に効くチケット（トークン・土台の部品・速さ）は `canvas: [全部の組]`（入れた組を全部緑のまま保つ。ほかの id と混ぜない）
- 見た目を変えないチケット（画面の試験の土台だけを直す 等。頭の screens で当たる）は `canvas: []` と `canvas_none: <訳>`。changes に画面のコード（`apps/web/(app|features|components/k|styles)/`）があれば訳があっても使えない。組を書いた canvas と混ぜない
- 今ある当てはまるチケット 27 枚は台帳 `scripts/ci/canvas_field_ledger.json` に載せて通し、台帳は減らすだけ

精査の指摘で直した所：前は「着手前で screens が在る」だけに当て、絵の名前で照らしていた（tickets の画面には絵が 37 枚載るのでほぼ効かない・状態は照らさない・着手した後や screens を書かないチケットは素通り・完了の条件の字が在るかだけを見ていた）。組の id で結び、当てる範囲を広げた。入れずに残る組は K-238 が止める。
