## 目的

操作要素 1 つ＝1 行の実ブラウザの試験（行 ID を名前に持つ Playwright・G28）の型を作り、見本の画面で 1 回通す。新しい画面のチケットはこの型で書く。

## 完了の条件

- [x] 行 ID を名前に持つ Playwright の型がある（`apps/web/tests/_lib/row.ts`：row()・rowsOf()・missingRows()）
- [x] 見本の画面で通り、G28 の記録に入る（53 行すべてに実ブラウザの証拠。記録＝baseline なしで緑）
- [ ] CI が緑（手元で本番の形に組み立てて確かめた。GitHub の結果は push 後に見る）

## 前提と制約

- 前の画面は少しずつ直さず、新しく作ってから外す（D-128.78）。前の画面の G28（記録 143）はそのまま

## 実施事項

- [x] 試験の型：行 ID ＋テスト項目を試験の名前にし、押した後の画面を証拠として報告に添える。仕様に無い行の試験は書けない
- [x] 漏れの検査：画面の読み上げの木から操作要素（押せる・入れられるもの）を全部集め、仕様に行の無い要素を赤にする（KSC-00-001）。書いた最初の回に、数を持つリンク 4 つの名前の違いを見つけた
- [x] 見本の画面の仕様 `07_qa/test-specs/k/showcase.md`（53 行・操作要素 1 つ＝1 行）と試験 `apps/web/tests/k/showcase.spec.ts`
- [x] G28（op_gate.py）が新しいチケット（11_tickets・行のタスクの列が KN-…）を読めるようにした
- [x] 新しい画面の実ブラウザの試験を CI で回す：新しい段 **web**（**G48**）。staging も札も要らない：CI の中で本番の形に組み立てて（next build）立ち上げ、新しい画面の試験 84 本を流し、その報告で G28 を記録なしで通す
