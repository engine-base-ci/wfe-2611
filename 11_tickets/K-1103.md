## 目的

プランの人数の上限（flows.json の E4「上限を越えたら止まり、上のプランでは止まらない」・F12 → F3）を、招く所で効かせる。今は無料（3 人まで）の会社でも何人でも招けて、上限は「プランを下げられない」（K-961）にしか効いていない。

- **代表の答え 2026-11-23（D-156.51）**：ゲスト（先方の人）はプランの人数に数えない。数えるのは社内の人だけ。ゲストを招くときは人数の上限で止めない
- 止め方は**代表の答え 2026-11-23（D-156.58）**：招く小窓で止め、招待のメールは送らない。人数とプランを上げる行き先の字は画面の葉（下絵が無い・まとめ役に頼む）
- 数えて止めるのは関数 1 か所（`app.seat_check`）。招く口（K-419 の createInvitations・K-876 がゲストの欄を足した物）とリンクの口（K-421 の createInvitationLink）が、招待を書く同じ取引の頭で呼ぶ。口は断りの言葉を番号に替えるだけ。表の引き金にしない訳：試験の道具の `createInvitation`（`@kaname/auth`・本番の口は使わない）で招待を直に入れる前からの試験が多く、引き金だと無関係の試験が赤になる

## 前提と制約

分類: INV, PERM

- **数える物**：`app.tenant_seat_count(p_tenant)`（K-961 が作る 1 か所・社内の人・ゲストは数えない）＋その会社の招待で `accepted_member_id is null`・`revoked_at is null`・`deleted_at is null`・`expires_at > now()`・`role_id is distinct from 'requester'` の数（招待中の社内の招待）
- **上限**：いまのプラン（K-961 の `app.tenant_plan_id(p_tenant)`）の `plans.limits->>'members'`（整数）。プランの行・上限の値が無ければ止めない（上限なし）。下げる予定の間は今のプランの上限（K-961 の「効いている行」）
- **止める式**：今から作る社内の招待の数を N とし、人数＋招待中（ただし今回の宛てと同じ宛ての招待中は数えない＝K-419 は同じ宛ての招待中を取り消して作り直す）＋N が上限を超えるなら止める。何人かまとめて招くときは N 人分を 1 回で見る（全部か無しか・招待もメールも作らない。K-419 はメールを DB の後に送る）
- **ゲスト**：役割 `requester` の招待は数えず止めない（D-156.51）。口は role_key が requester のとき関数を呼ばない
- **同時に 2 本**：関数の頭でその会社の `tenants` の行を `for update` で取り、取引が終わるまで持つ（同じ取引で招待を書くので、後の方は前の招待を数える）
- **断る番号**（控え帳）：上限 → **409 E-PLAN-003**（新しい番号・field と details を付けない・字に差す値は detail `{ members, invited, member_limit }`・K-401 の形）。ほかの断り（権限・形・グループが無い・もう入っている人）は K-419・K-421 のまま。満員の会社で、もう入っている人を含めて招いた回は、席の確かめが先なので 409 E-PLAN-003 になる（どちらも何も作らない）
- 口：`create.ts` の `store()` の `withTenant` の中、`app.create_invitations` の前に、role が requester でなければ `select app.seat_check($1::int, $2::text[])`（そろえた宛ての数・そろえた宛ての並び）。`link.ts` も同じ取引の中、`app.create_invitation_link` の前に `select app.seat_check(1, '{}')`。断りの言葉 → 番号は 2 つの `refused` に「`code === 'P0001' && hint === 'E-PLAN-003'` → 409・`kanameError('E-PLAN-003')` に `detail`」（例外の detail「members,invited,limit」を `,` で分けて整数に）を足す。ほかの行は変えない
- 関門の宣言 choke_points は [C2]（招待を書く取引の中で止める）。お知らせ・記録は足さない（止めたら何も書かない）
- 参加（accept・join）は止めない：招く時に止めるので、上限の内で招いた人は入れる。下げた後に前の招待で入る筋は代表に聞く（下・追加）

### 関数（migration `20261128032300_seat_limit.sql`・K-1103 → 203 分＝03 時 23 分）

- `app.seat_check(p_adding integer, p_replacing text[] default '{}') returns void`（volatile・security definer・`search_path = public, app, pg_temp`・`revoke … from public`・`grant execute … to kaname_app`）：ⓐ 会社＝`app.tenant_id()`（引数で会社を受けない＝ほかの会社を数えられない）。`p_adding <= 0` なら何もしない ⓑ `perform 1 from tenants where id = <会社> for update` ⓒ 上限＝`(select (p.limits->>'members')::int from plans p where p.id = app.tenant_plan_id(<会社>))`。null なら何もしない ⓓ 人数＝`app.tenant_seat_count(<会社>)`・招待中＝その会社の招待で `accepted_member_id is null`・`revoked_at is null`・`deleted_at is null`・`expires_at > now()`・`role_id is distinct from 'requester'`・`email is null or lower(email) <> all(<p_replacing を小文字にした並び>)` の数 ⓔ 人数＋招待中＋p_adding ＞ 上限なら `raise exception using errcode = 'P0001', message = 'seat_limit', hint = 'E-PLAN-003', detail = 人数 || ',' || 招待中 || ',' || 上限`（数だけ・名前やメールを載せない）
