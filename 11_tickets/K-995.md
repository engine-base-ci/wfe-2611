## 目的

漏れたパスワードの照合のサービスが落ちている間も、登録は止めずに通す（D-128.134）。運営へのメールは落ち始めの 1 通だけで、あとは記録にためて運営の画面で回収する（D-128.146）。代表の答え 2026-11-23（D-156.35）：運営のワークスペースの一覧の上に帯「パスワードの照合が使えなかった登録が N 件あります」→ 一覧の小窓（日時・ワークスペース・人）と「確かめた」。確かめた後にまた落ちたら、また 1 通メール。

この葉はその口 2 本を作る（行為 A138・K-1000 が足す）：

- **一覧 listOpsPwned**（`GET /api/v1/ops/pwned`）：まだ確かめていない会社を 1 行ずつ（日時・ワークスペース・人・件数）
- **確かめた ackOpsPwned**（`POST /api/v1/ops/workspaces/:id/pwned/ack`）：その会社に確かめた印を書き、運営の記録に残す。確かめていない会社が 0 になったら運営の会社にも印を書き、照合が次に落ちたときにまた 1 通メールが出るようにする（0086 の `app.record_security_event_opening` は運営の会社の最後の印から数える）

2 本は契約に無い（範囲 3-B・K-1000 の申し送り）ので、この葉が契約に足し、親 K-72 の `apis:` に書く。

- **1 行は会社ごと**：security_events の `pwned_check_unavailable` が、その会社の最後の `pwned_check_acknowledged` より後にある会社（0086 と同じ見方・K-963 の getOpsShell の `pwned.unchecked` と同じ数え方）。数える会社は K-963 と同じ（運営の会社・作りかけ・消した会社を除く）。会社にこの出来事を書くのは登録の確定（K-1018）。登録の前の失敗は運営の会社に残る（0086・メールの判定だけに使う）ので、一覧には出さない
- **答えの形**（画面の葉 K-1019 の正本）：
  - listOpsPwned：`OpsPwnedRow[]`：`workspace`（`{ id, name }`）・`member`（`{ id, name }` か null：いちばん新しい出来事の member_id の members.display_name）・`last_at`（いちばん新しい出来事の occurred_at）・`count`（確かめた印より後の出来事の数）。並びは last_at の新しい順。件数は少ない（数社〜数十社）のでページを持たない（`LIST_DETAILS` は cursor・limit を受けない）
  - ackOpsPwned：体は空の `{}`（strict・ほかの欄は 422）・答え `{ acknowledged_at, remaining }`（remaining は確かめた後に残る会社の数＝外枠の pwned.unchecked と同じ）
- 答えに出来事の中身（detail の reason・メール）を入れない。人の名前だけ
- **入口**：2 本とも `ops:any`（運営の人なら誰でも。ワークスペースの一覧を見る人が帯を見る）。確かめたは `/ops/workspaces/:id` の下なので perm.scope は ops_tenant（K-1001 の作り手が道で決める）。運営の会社を指すと入口で 404
- **確かめるとき（1 つの取引）**：同じ会社の出来事の順と 0086 の落ち始めの判定がぶつからないよう、`pg_advisory_xact_lock(hashtext('security_event_opening:' || <会社> || ':pwned_check_unavailable'))` を取ってから見る
- 番号：確かめる物が無い（もう確かめた・出来事が無い）は **409 E-OPS-026**（欄なし・新しい番号・errors.d に足す）
- 操作の名前は `pwned.acknowledge`・対象 `security_events`・対象の id は書いた確かめた印の id・payload `{ target_label: <ワークスペースの名前> }`。1 社の記録の字は K-1011 の表の「照合が使えなかった登録を確かめた」（D-156.48）
- 断る番号（控え帳）：ログインなし 401・運営でない 403（入口）・道の id と体の形 422（入口・契約）・会社が無い・見えない 404（欄なし）・確かめる物が無い 409 E-OPS-026・DB の失敗 503 E-PAGE-003（K-947 の opsErrorReply）・上限 429

### 関数（migration `20261128013500_ops_pwned.sql`・K-995 → 95 分）

- `app.ops_pwned_list() returns jsonb`（security definer・stable）：ⓐ `app.ops_require('any')` ⓑ 数える会社ごとに、最後の確かめた印より後の `pwned_check_unavailable` を数え、1 つ以上なら 1 行 ⓒ `{"data": [...]}`（last_at の新しい順）
- `app.ops_pwned_ack(p_tenant uuid) returns jsonb`（security definer・volatile）：ⓐ `app.ops_require('any')`（値を `v_ops` に）ⓑ `app.ops_target(p_tenant)` ⓒ 上の advisory lock ⓓ 確かめる物が無ければ `{"error":"none"}`（口が 409 E-OPS-026）ⓔ `insert into security_events (tenant_id, kind_id, member_id, detail) values (p_tenant, 'pwned_check_acknowledged', null, jsonb_build_object('ops_member_id', app.user_id()))` ⓕ `app.record_ops_audit(p_tenant, 'pwned.acknowledge', 'security_events', <印の id>::text, null, jsonb_build_object('target_label', <名前>))` ⓖ 残りの会社の数を数え、0 なら運営の会社（`app.ops_tenant_id()`）にも `pwned_check_acknowledged` を 1 行（同じ advisory lock の鍵を運営の会社でも取る）ⓗ `{"acknowledged_at": …, "remaining": …}`
- どちらも `grant execute … to kaname_app`。索引は `security_events_tenant_time_idx`（0003）を使う
