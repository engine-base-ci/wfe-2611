## 目的

チケットの確認項目が 1 件も無いときに「AI に任せる」を押したら、任せる口を呼ぶ前に小窓を開き、**確認項目を足すか、使わない理由を書く**まで進ませない（D-150.45）。確認項目が無いと、終わったときに機械と人が確かめられないため。理由は承認のカードに「検査なし」と一緒に出る（D-125.56 の続き・出す所は K-565 が口の答えに足した `no_spec_reason`）。

- 正の絵は下絵 v2 の `/dev/mock/f4v2/f4v2-nospecs`（部品 `features/F4/doc/detail-views.tsx` の `NoSpecsDialog`）。題「AI に任せる」・対象の行・赤い注意「確認項目がありません」（足すか、使わない理由を書いてください。確認項目が無いと、終わったときに機械と人が確かめられません。）・必須の欄「確認項目を使わない理由」（例「定型の作業で、送ったメールを見れば確かめられる」）・足「やめる」（左寄せ）「確認項目を足す」「理由を書いて任せる」（理由が空の間は押せない・title「理由を書くか、確認項目を足してください」）。**字・並び・ボタンは下絵が正**
- 入口は**題の行の「AI に任せる」**（下絵 v2 のとおり・2026-11-22 のまとめ役の決め・X8）：K-571 が置いた差し込み口 `DelegateActSlot(props: ActsProps)`（`detail-entry-slots.tsx`）の先 `delegate/delegate-act-slot.tsx` の `DelegateActSlotFill`（K-571 が何も出さない形で先に置く）の本体を、この葉の `delegate/delegate-act.tsx` の `DelegateAct` に替える（`detail-entry-slots.tsx` は触らない）。**F5 の帯からは「AI に任せる」のボタンを外す**（任せる前の白い箱の見出しと要約・止まった赤い箱の題と理由・出し分けの条件・文は帯に残る）。止まった赤い箱の中の「AI に任せる」も外し、題の行のボタンが同じ条件（`can.delegate`・段・走っている実行が無い）で出る。「完了にする」が出ている間は outlined（K-62 の決め・`completeShown`＝`canCompleteNow`）。**ボタンと帯は同じ状態を見る**：流れの状態（押している間・429 の待ち・小窓の開閉・小窓の中の赤い知らせ）は `delegate/use-delegate.ts` の頁の中の store（チケット id ごと・`useSyncExternalStore`）に置き、題の行のボタンと帯が同じ物を読む（小窓を出すのは帯の側。ボタンは押す・押している間・待つ間の押せない形）。編集の間は題の行のボタンを引っ込める（K-447・本文の編集中の規則と同じ）
- **口は新しく作らない**（`apis: []`）。確認項目の数・前に残した理由は `getTicket`（K-560）の `spec_count`・`no_spec_reason`、任せる口は `delegateTicket`（K-565・入力に `no_spec_reason`）

## 前提と制約

分類: AI, PERM

- **任せるときの流れ**（`delegate-band.tsx` の `delegate`）：
  1. 帯の `ticket.specCount === 0`（数がちょうど 0）なら、任せる口を呼ばずに小窓を開く。1 件以上・`null`・無い（前の口の答え）なら、今までどおり空の体 `{}` で口を呼ぶ（口が最後の砦・K-565）
  2. 小窓の「理由を書いて任せる」→ 体 `{ no_spec_reason: <前後の空白を落とした理由> }` で口を呼ぶ。理由の欄は、`ticket.noSpecReason`（前に残した理由）があれば最初から入れる（口は前の理由を数えないので、毎回送る）。理由は 500 字まで（欄は 500 字で止め、`onChange` でも 500 字に切る）
  3. 口の答えが 409・E-CONF-020（画面は 1 件と思っていたが口は 0 件）なら、小窓を開き、詳細を読み直す（`onChanged`）。理由を書いて任せ直せる
- **理由が空の間は押せない**：前後の空白（半角・全角・タブ・改行）を落として空なら、「理由を書いて任せる」は `disabled`（title「理由を書くか、確認項目を足してください」）。口に空の理由を送らない（口の 422 は最後の砦）
- **「確認項目を足す」**：小窓を閉じ、確認項目を足す小窓を開く合図を出す。合図は `window` の `kaname:f4:open-spec-add`（`CustomEvent`・detail は `{ ticketId }`・定数 `OPEN_SPEC_ADD_EVENT` を `features/F5/delegate/spec-add-event.ts` が 1 か所で持つ）。聞くのは K-450（確認項目の欄が自分のチケットの合図だけで足す小窓を開く）。任せる口は呼ばない・足し終えたら人がもう一度「AI に任せる」を押す（自動では続けない・代表に聞くこと 1）。書きかけの理由は捨てる
- **「やめる」・Esc・頭の右上の ×**：小窓を閉じるだけ（口は呼ばない・焦点は「AI に任せる」へ戻る）。書きかけの理由は捨てる（開き直すと、残っていた理由か空）
- **失敗**：
  - 409・E-CONF-013（もう走っている）は小窓を閉じ、帯に正本の文と走っている実行を出す（今の帯と同じ）。409・E-CONF-014（任せられない段）は小窓を閉じ、帯に正本の文を出して詳細を読み直す（今の帯と同じ）
  - それ以外（503・409 E-CONN-001〔PC がつながっていない・「PC をつなぐ」のリンク〕・429・403・404 ほか）は、**小窓は開いたまま**、中の赤い箱に正本の文を出す（今の帯の知らせ `NoticeLine` と同じ文・同じリンク）。書いた理由は残り、押し直せる。429 は待つ秒数の間「理由を書いて任せる」を押せない形にする（今の帯の `waitUntil` と同じ）。401 は入り直し（共通の扱い）
  - 422 は出さない（理由の形は画面が先に止める。500 字の切りで超えない）。出てしまったら、ほかの失敗と同じ扱い（小窓の中の赤い箱）
  - 答えを待つ間は「理由を書いて任せる」を押せない形・小窓は閉じない（二度押しでも口は 1 回）
- **小窓の対象の行**は `ticket.target`（「番号 題名」）。詳細が帯に渡す（K-571）
- **帯の props の足し**（`BandTicket`）：`specCount?: number | null`・`noSpecReason?: string | null`・`target?: string`。詳細（`ticket-detail.tsx`・K-571 が作り直す）が `getTicket` の `spec_count`・`no_spec_reason` と「番号 題名」を渡す（K-571 の申し送り・まとめ役に頼むこと）。**この葉は詳細の本体に触らない**
- 前の形のチケット（本文の行が無い）：口は 0 件でも理由なしで任せられる（K-565・K-575 が本文に移すまで）が、画面は `spec_count` が 0 なら小窓を出す（口が理由を受けて捨てる・K-565）。K-575 の後は全部のチケットに効く
- 画面は役の名前で出し分けず、口の答え（`can.delegate`）で出し分ける。AI がつながっていないときの字は足さない
- **承認のカードに理由を出す**（2026-11-22 のまとめ役の決め）：承認待ちの詳細の確認の要約（`approvalSummary`「成果物は … に作成 ・ 確認 検査なし（まだ流していません）」・決められる人の帯＝`decide.tsx`／決められない人の帯＝`delegate-band.tsx` の `sub`）の後ろに「 ・ 確認項目を使わない理由：<理由>」を足す。理由は詳細の読み `getTicket` の `no_spec_reason`（K-560・`ticket.no_spec_reason` の答えの鍵）。無い・空なら足さない。`decide.tsx` の `approvalSummary(d, noSpecReason?)` に引数を足し、`band.tsx` が渡す（1 行・K-572 も同じファイルの別の行を直す）。承認の一覧 `/approvals` には出さない（口の答えに足さない・K-565 の `approval.no_spec_reason` は無い）。下絵に無い字なので、下の「代表に聞くこと」5 に書いた
- **本文の道具の決め（代表 2026-11-22・出来合いの部品の機能を絞らずに使う）は、この葉に当たらない**：この葉は本文の道具を作らない・使わない。本文の中身を読まない（確認項目の件数と使わない理由だけ）。下絵の部品（`features/F4/doc`）で使うのは任せる小窓と題の行のボタンだけ
