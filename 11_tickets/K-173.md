## 目的

K-172 で CI を自分の Mac の runner 4 台に移したら、1 台の Mac を全部の組で使い回すために、GitHub の台では起きない赤が続いた（置き場の取り合い・パスのずれ・残るプロセス）。
GitHub の台と同じく、組ごとにまっさらな Linux の機械を出して捨てる形にする（決める人 2026-11-12「無料でできる、かつ完璧に」）。
Mac の上で Tart の VM を組ごとに複製して起こし、GitHub の 1 回限りの登録（JIT）で runner を 1 組だけ動かし、終わったら VM ごと消す。試しで、services の DB に localhost で届く・置き場は /home/runner/work/Kaname/Kaname・VM の起動は約 10 秒・1 台の使うメモリは最大 1.8GB を確かめた。

## 完了の条件

- [ ] 全部の組（v3-gate.yml と release-gate.yml）が `runs-on: [self-hosted, linux-vm]`（Mac の runner には載らない）
- [ ] Python の部品を使う組は、ci_venv.sh の前に actions/setup-python で 3.14 を用意する（VM の Python は 3.12。GitHub の台と同じやり方）
- [ ] K-172 の試験 K172-CI-001（台の印）と K172-CI-003（setup-python を使わない）を新しい形に合わせる
- [ ] 試験 K173-CI-001〜002 が緑・チケットの CI が VM の台で緑

## 前提と制約

- 前提：VM の待ち受け（ticket-flow の vm_pool）が動いている（人の準備は済み。Tart は公式の 2.41.1・元の像は tf-golden）
- workflow の中の Mac の台への対応（DB を組の中で立てる・pid で止める・pnpm の置き場）は VM でもそのまま動くので、このチケットでは変えない
