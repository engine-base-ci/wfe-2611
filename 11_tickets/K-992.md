## 目的

代表の答え 2026-11-23（D-156.20）のひな形の置き場を作る：**ひな形は新しく入る会社が最初に使う既定の形**（種別（名前・色・本文のひな形）・状態・項目）。会社は後から自由に変えられ、運営が新しい版を出すと、会社が**手を付けていない所にだけ**「こう変わります」と知らせる（出すのは K-1010・会社の側は K-993）。新しく入る会社は最新の既定で始まる。

- **配るもの 3 つ**：運営の会社の `distributions` に `kind`（種別）・`state`（状態）・`field`（項目）の 3 行と、版 1 の中身（`distribution_versions.snapshot`）
- **手を付けていない印**：会社の種別・状態・項目の行に、どのひな形の物か（`template_key`）と、配ったときの中身の印（`template_hash`）を持つ。今の中身の印が配ったときと同じなら「手を付けていない」
- **新しく入る会社**：会社を作ったとき、3 つの最新の版の中身で種別・状態・項目を入れ、`tenant_distributions` に使い始めた版を残す
- **読む口 2 本**（ops:distribute）：一覧（下絵 oq-templates の 5 列）と 1 つ（中身と版の記録）

- **版 1 の中身**（migration の種。`distributions` には (tenant_id, key) の一意が無い（0014）ので `on conflict` は効かない。**`insert … select … where not exists`**（同じ運営の会社・同じ key の消していない行が無いときだけ・版の行も同じ distribution_id と version が無いときだけ）で足し、もう一度流しても行が増えない＝template_backfill の「もう一度呼んでも同じ」とそろえる）：種別＝今の既定の 4 つ（タスク `task`・課題 `issue`・QA `qa`・会議 `meeting`・名前・色・本文のひな形は 0071 と 20261122090100 の種の値・色は K-704 の初めの色）／状態＝0071 の 7 つ（key はそのまま・色は K-705 の `app.ticket_stage_first_color`）／項目＝空（会社が足す物）
- **列**：`ticket_kinds`・`ticket_stages`・`custom_fields` に `template_key text`・`template_hash text`（null は会社が自分で足した物）。`tenant_distributions` に `offered_version int`・`offered_at timestamptz`・`chosen text check (chosen in ('change','keep'))`・`chosen_at timestamptz`・`chosen_by uuid`（K-1010・K-993 が書く。この葉は置くだけ）。一意の索引 `tenant_distributions_uq on (tenant_id, distribution_id) where deleted_at is null`
- **中身の印**：`app.template_item_hash(p_part text, p_item jsonb) returns text`（immutable）＝部の中身の欄だけ（key を除く）を決まった順で並べた jsonb の `md5`。会社の行の今の中身から同じ形の jsonb を作る式 `app.template_item_of(p_part text, p_row_id uuid) returns jsonb` も 1 か所に（K-993 の手を付けたかの比べはこの 2 つ）
- **前からの会社**：migration で、全部の顧客の会社の既定の種別（`is_builtin` の名前で鍵を引く）・状態（key で引く）に `template_key` と、**版 1 の中身の印**を入れる（今の中身でなく版 1＝その会社がもう変えていれば「手を付けた」になる）。3 つの `tenant_distributions` を `version_in_use = 1` で入れる
- **新しく入る会社**：`tenants` の after insert の引き金 `tenants_ticket_zz_template`（名前の順で 0071 の `tenants_ticket_basics` と 20261122090100 の種まきの引き金の後に走る）が `app.template_seed(p_tenant)` を呼ぶ：3 つの部それぞれ、最新の版の中身の 1 つずつについて、同じ鍵の既定の行が在ればその行を中身の値に直し、無ければ足す（種別・状態は既定の行の名前・key で引く・項目は足す）。どの行にも `template_key` と中身の印。`tenant_distributions` を最新の版で入れる。運営の会社と作りかけの会社（`half_made_at`）には入れない
- **一覧**（listOpsTemplates・下絵 oq-templates）：3 行（種別・状態・項目の順）。1 行は `{ id, key, name, summary, version, using, took, last_released_at }`。`summary` は 種別＝「<名前を「・」で並べた字> の名前・色・本文のひな形」・状態＝「<名前を「・」で並べた字>」・項目＝空なら「チケットの欄の並び・必須。種別ごとに持つ」、在れば名前を「・」で並べた字（下絵 oq-templates の字の形）。`using` は `tenant_distributions` の生きている行の数。`took` は今の版を知らせた会社が在れば `{ changed, offered }`（`offered_version` = 今の版の数と、そのうち `chosen = 'change'` の数）・無ければ null
