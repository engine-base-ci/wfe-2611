## 目的

CI を GitHub Actions に移し、自分の Mac の self-hosted runner で流す（決める人 2026-11-12・answer=871f1796a76a・0702e79f90b8）。
手元の act では 1 本 15 分、GitHub の台では約 4 分だった（K-170 の実測）。台は Mac に、検査はチケットの範囲だけにして、さらに縮める。
ticket-flow（~/.claude/skills/ticket-flow）の CI の契約（references/ci-contract.md）に合わせる。

## 完了の条件

- [ ] 全部の組が `runs-on: [self-hosted, macOS]`
- [ ] DB は組の中で `docker run` で立て（空いている番号）、終わったら必ず消す（`services:` を使わない）
- [ ] `setup-python` を使わず、台の `python3` を使う
- [ ] 入口（workflow_dispatch）が scope・ticket・base を受ける
- [ ] 試験の結果を JUnit で出し、1 つの artifact「junit」にまとめる（落ちた組があってもまとめる）
- [ ] 重い検査（G27・G36・G38・G47・G56・G57・G62）は、scope=ticket のとき関係するファイルを変えたときだけ流す（scope=full は全部）
- [ ] 試験 K172-CI-001〜008 が緑・チケットの CI が緑
