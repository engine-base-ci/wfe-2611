## 目的

CI を GitHub Actions に移し、自分の Mac の self-hosted runner で流す（決める人 2026-11-12・answer=871f1796a76a・0702e79f90b8）。
手元の act では 1 本 15 分、GitHub の台では約 4 分だった（K-170 の実測）。台は Mac に、検査はチケットの範囲だけにして、さらに縮める。
ticket-flow（~/.claude/skills/ticket-flow）の CI の契約（references/ci-contract.md）に合わせる。

## 完了の条件

- [ ] 全部の組（v3-gate.yml と release-gate.yml）が `runs-on: [self-hosted, macOS]`
- [ ] DB は組の中で立てる：容れ物の名前に回と組の印・番号は空いているもの（決め打ちしない・直書きしない）・pg_isready で待ち時間切れは赤・終わったら必ず消す。DATABASE_URL は GITHUB_ENV だけで渡す（`services:` を使わない）
- [ ] Python の部品は台に置いた venv（scripts/ci/ci_venv.sh・回をまたいで使い回す）。組の中で `pip install` しない・`setup-python` を使わない
- [ ] 回の間の物は `$RUNNER_TEMP` に置く（`/tmp` を使わない）
- [ ] web の組は同時に 1 つだけ流し、立てた API と画面を必ず止める
- [ ] 入口が scope（ticket／full）・ticket・base（target は任意。空なら GitHub の既定の枝）を受ける。範囲の台本は scope=ticket を今の auto と同じに絞り、入力の ticket とコミットのチケットの番号が違えば止める
- [ ] 試験の結果を JUnit で出す（単体の組＝vitest の junit・web の組＝Playwright の junit・spec の組＝チケットの Python の試験を junit_unittest.py で）。組ごとに junit-<組>（記録が無ければ赤）を出し、最後の組が全部を待って artifact「junit」にまとめる（落ちた組があってもまとめる）
- [ ] 重い検査（static 以外の組の G27 層の棚卸し・G36・G38・G47・G56・G57・G62）は、scope=ticket のとき範囲の台本の出力 gates に入っているときだけ流す（scope=full は全部・前の段が赤でも流す）
- [ ] 試験 K172-CI-001〜012 が緑・チケットの CI が緑

## 前提と制約

- 前提：自分の Mac の self-hosted runner は登録済み（2026-11-12・engine-base のアカウントで登録・ラベル self-hosted・macOS・ARM64）。人の準備は済んでいるので依存のチケットは無い
- 重い検査の G27 は spec の組の「層の棚卸し」（static の組にも G27 の番号の別の段がある。番号の重複は直さず、組と名前で特定する）
