## 目的

画面と口が別の住所なので、画面が口を呼ぶたびにプリフライト（OPTIONS）の 1 往復が乗る（URL ごとに 10 分に 1 回・最初の読み込みではほぼ毎回）。同じ住所にまとめればプリフライトが無くなり、印をクッキーへ移す作り直し（後のチケット）の前提にもなる。代表の決め（answer=6e1493475229）は「今回入れる」。

ただし、間に画面の入口を挟むと、口が読む IP と国が中継した Vercel のものになるおそれがある。国の変化でセッションを閉じる見張り（K-20・0083_session_watch.sql）が、全員のセッションを閉じうる。調べ（.ticket-flow/perf-research.md の §3-3・(A) の A-2）の「正しい入れ方」で入れる：画面の入口が本当の値を秘密つきで写し、口の入口が秘密の合うときだけ置き換える。入れる前に staging で確かめ、赤なら入れない。

## 確かめたこと（切る段・2026-11-17）

- 調べの §3-1：外への rewrites で Vercel が受け手へ渡す頭は x-real-ip・x-forwarded-for・x-forwarded-host・x-forwarded-proto だけで、国（x-vercel-ip-country）は無い。受け手も Vercel のとき x-forwarded-for を何で上書きするかも公式に無い。だから「渡ってくる頭を信じる」形にしない
- 2026-04-06 以降に作ったプロジェクトは、外への rewrites の答えを受け手の Cache-Control に従って貯める。今の口の答えには Cache-Control が無い（`git grep -n "cache-control" -- apps/api/src` は 0 件）
- 画面の口の住所は apps/web/lib/env.ts の `NEXT_PUBLIC_API_BASE ?? "http://127.0.0.1:3001"`。空にすると今の CSP（security-headers.ts の `new URL(o.apiBase)`）が投げる → 空の住所を受ける直しが要る（K262-WEB-006）
- `@kaname/auth/device` は package.json の exports に無い。確かめの口（app.ts）と試験が countryOf・ipOf を読むので足す
- 契約に無い口の検査（scripts/ci/contract.mjs の endpoints）は apps/api/src/routes/*.ts の登録だけを見る。確かめの口は /health と同じく app.ts に置き、契約の外にする（本番は開かない）
