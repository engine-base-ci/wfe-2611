## 目的

手元の CI（act・GitHub と同じ workflow の全部）を、借り物ではない台（Mac か Intel・AMD の PC）で回せるようにする。

## 完了の条件

- [ ] 台を決めた（Mac なら Apple シリコンでも可）
- [ ] Docker（Mac は colima か Docker Desktop）を入れ、起動したら立ち上がる
- [ ] act を入れ、台ごとの設定（~/.actrc・ai-team-delivery references/ci.md §3：台の像・同時の数・pnpm の置き場・action の手元の写し）を書いた
- [ ] リポジトリで `act_ci.sh <本線の先頭>` が緑（workflow の全部）
- [ ] 統合テスト（K-65）の受け箱が台で動き、外（staging の API）から届く：`QA_MAILBOX_HOST=0.0.0.0`・鍵 `QA_MAILBOX_KEY`・URL を `STAGING_MAILBOX_URL` として ~/.config/act/kaname.secrets に（名前だけ・値はここに書かない）

## 前提と制約

- Mac は amd64 を Rosetta で動かす設定が要る（Linux 版 Chrome は amd64 だけ・ci.yaml の toolbox.platform）

## 実施事項

1. Mac：`brew install colima docker` → `colima start --vm-type vz --vz-rosetta`（ログインしたら起動する設定にする）。Docker Desktop なら設定の「Use Rosetta for x86/amd64 emulation」をオン
2. スキル ai-team-delivery を入れる
3. `brew install act flock`。台の像（GitHub の ubuntu-latest に Chrome を足したもの）を作り、~/.actrc を references/ci.md §3 のとおり書く（Docker の記憶 8GB 以上・同時の数 3）
4. リポジトリで `bash ~/.claude/skills/ai-team-delivery/scripts/ci/act_ci.sh <本線の先頭の sha>` が緑
5. 統合テストの受け箱（apps/web/tests/_lib/mailbox.ts の受け口）を台で常時動かす：`QA_MAILBOX_HOST=0.0.0.0`・鍵は `QA_MAILBOX_KEY`。staging の API から届く URL を `STAGING_MAILBOX_URL` として秘密のファイルに（K-80 の `RESEND_BASE_URL` と対）。dagci（自作の実行器）は 2026-11-09 に廃止（L-009）

## テスト仕様と確認の結果

- 確かめは `dagci smoke` が緑・`dagci run --all` が緑
