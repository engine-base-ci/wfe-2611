## 目的

ログインしていない人にも、Kaname の **いまの様子**（直っていない障害・いま中のメンテナンス）を返す契約の口 `GET /api/v1/auth/service-status`（getServiceStatus）を作る。ログインの画面の上の帯（K-317）と、困ったとき（/help・K-315）の「いまの稼働状況」が読む（D-128.110。D-128.110 の「メンテの予定も読める」は、代表の答え answer=88f98638a534 で「中のときだけ・予定は出さない」に改めた）。今は 501。

返すのは **運営が公開したものだけ**（どのワークスペースのことも出さない）。メンテナンスは **中のときだけ** 出し、予定は出さない（代表の答え answer=88f98638a534・帯も困ったときも同じ決まり）。契約の答えの型が曖昧（`components?: string[]` など）なので、この葉で決める：

```
{ data: { incidents: [{ state, title, started_at }], maintenance: { title, from, to } | null } }   // 型 PublicServiceStatus
```

### 決めた判断

- 障害は、運営が **公開したお知らせに結んだもの** だけを出す（題はそのお知らせの題・answer=8467d5780a91）。結んでいない障害（運営が調べ始めたばかり）は出さない
- メンテナンスは **いま中のものだけ**。予定（これから）も終わったものも出さない（answer=88f98638a534・帯も困ったときも同じ）。いま中が 2 つ以上なら早く終わるもの
- ワークスペース向け・プラン向けのお知らせは出さない（ログインの前は誰か分からない・どのワークスペースのことも出さない）
- 題・始まりの時刻・メンテナンスの始まりか終わりが空の行は出さない（答えの型の string を null で壊さない）
- お知らせの置き場（placements）は見ない（PM に確かめたいこと 1）
- 読めないときは 500・E-PAGE-003。画面はそれを見て帯を出さないだけで、ログインを止めない（K-317）

## 申し送り

- K-317 へ：帯は `incidents` の各件（障害）と、`maintenance` が null でないとき（メンテナンス中）に出す。`ongoing` の欄は無い（中のものだけが返る）。偽の答えとモック（login-status-both の予定のメンテナンス）は「中のメンテナンス」に直す（answer=88f98638a534）。読めない（500・通信の失敗）ときは帯を出さず、ログインは止めない。時刻の文は画面で作る

- 運営のお知らせ・障害を書くチケット（F12）へ：ログイン前に出るのは、全部向けに公開したお知らせ（題がある）と、それに結んだ障害（始まりの時刻がある）だけ。メンテナンスは始まりと終わりの両方を入れる
