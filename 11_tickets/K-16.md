## 目的

`has_permission` の穴（会社全体の確かめが、1 つのグループだけに付けた権限でも通る）を直す。役割（管理者・マネージャー・メンバー・閲覧のみ）を権限の束として、権限の行（permissions）に持つ。マネージャーはグループごとの役割（scope_memberships）で見る。

## 完了の条件

- [x] 会社全体の確かめ（グループ＝なし）は、会社全体に付けた権限だけで通る
- [x] 役割を付けると、その束の権限の行ができ、外すと消える。個別に足す・外すも同じ表
- [x] マネージャーの束（配る・承認する・記憶を確かめる）は、そのグループの中だけに効く
- [x] 場合表と DB の試験が全部通る（場合表 1542・DB の試験 160）
- [ ] CI が緑のまま

## 前提と制約

- 束の中身は決定どおり：管理者＝全部・マネージャー＝配る・承認する・記憶を確かめる（招く・役割を変える・外すは入れない・D-128.97）・メンバー＝自分のグループで書く・閲覧のみ＝見るだけ
- 束から作った行と、個別に足した行は見分ける（外すときに個別の行を消さない）

## 実施事項

- [x] migration（`packages/db/migrations/0080_permission_bundles.sql`）：has_permission を直した・役割の束の既定（role_bundle_defaults・製品のマスタ）と、束から権限の行を作る関数（app.apply_role_bundles）
- [x] tenant_memberships.role・scope_memberships.role を変えたら、その人の束の行を作り直す（trigger）。個別の行（bundle_role が空）は触らない
- [x] 束の行は会社の人が手で直せない（役割を変えて変える）
- [x] K-4・K-9 の「マネージャー」の判定（has_permission(人, 表, グループ, 'edit')）は、マネージャーの束の行でそのまま効く（追加の変更なし）
