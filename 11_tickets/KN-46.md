## 目的

migration には既にあるのに、repository の表の一覧に入っていないため契約の API から使えない表（`bridge_jobs` `bridge_job_events` `agent_usage_snapshots` `artifact_versions` `pending_signup`）と、パスキーの表を、契約から使えるようにする。

## 完了の条件

- [ ] repository の表の一覧に入り、起動時の存在確認（表が無ければ起動しない）が通る
- [ ] パスキーの表の置き場所（Better Auth の kaname_auth 側か public か）を決め、ER 図に書いた
- [ ] CI が緑のまま

## 前提と制約

- 表の中身は変えない（一覧に足すだけ）。PC の印（device）の口は /bridge/ の下だけ（ZT10）

## 実施事項

- [ ] `packages/db/src/repository.ts` の TABLES に足す
- [ ] パスキーの表の置き場所を決める（決定を足す）
- [ ] 足した表の RLS を見直す（本人だけ・PC の印は本人のセッションに結ぶ）

## テスト仕様と確認の結果

| 確認項目 | 種類 | 判定のしかた |
|---|---|---|
| 起動時の存在確認が通る | ① 機械 | `apps/api/test/vercel_entry.test.ts`・`apps/api/test/server.test.ts` |
| 本人以外の行が取れない | ① 機械 | `pnpm ci:access-matrix` |

## 成果物

- repository の表の一覧・（要るなら）ER 図とパスキーの決定

## 決定ログ

- 契約は第1フェーズの画面の API だけ（D-128.112）

## リスクと懸念

- パスキーの表を Better Auth と二重に持たない
