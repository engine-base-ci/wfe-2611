## 目的

K-896 が積んだ「案の仕事」（`kind = 'client_request_draft'`）を、Bridge が取って AI に 1 回だけ作らせ、結果を K-897 の口 `reportClientRequestDraft` へ返す（D-155.11・D-128.101）。この葉は Bridge の側だけを作る（Kaname の口・DB は K-896・K-897）：

- `loop.ts`：取った仕事の `kind` が `client_request_draft` なら、普通の会話の仕事の道（途中経過・書きかけの返事・会話の記録・結末の口 `finish`）に入らず、新しい `request-draft.ts` の `runRequestDraft` に渡す（`login_check` の分岐と同じ形）
- `request-draft.ts`：仕事の指示文（`prompt`・先方の字は乱数つきの囲みの中・K-896）をそのまま AI に渡して 1 回起こす。**道具は全部止める**（読む・書く・実行する・ブラウザ・Kaname の道具のどれも使わせない・許可を求められたら全部断る）。返事の本文から JSON（最初の `{` から最後の `}`）を取り出して決まった形に整え、成功なら `{ draft }`・AI が動かなかった・返事が空・JSON が取れない・形が違うなら `{ failed: "<理由>" }` を、契約の口 `POST /api/v1/bridge/jobs/:id/client-request-draft` に返す
- AI の出力は信用しない：決めた欄だけを残し、長さを切り、数を絞って**口が 422 にならない形**にしてから送る（口の側も確かめる・二重の守り）
- 仕事の結末はこの口が閉じる（K-897）。**会話用の `finish` は呼ばない**・会話の記録（`/bridge/entries`）・書きかけ・途中経過も送らない（案の仕事には会話が無い）

## 前提と制約

分類: AI, TOOL

- 仕事の形：取る口（`POST /api/v1/bridge/jobs/take`）の答えの `job` に `kind: "client_request_draft"` と `prompt`（K-896 の指示文）。`runner.ts` の `Job.kind` の型に `"client_request_draft"` を足す（K-896 は `bridge_take_job` を変えない・答えの `kind` は既に返っている）
- AI を起こす入口は既存の `runClaude`（`runner.ts`）をそのまま使う（新しい子プロセスの起こし方・新しい SDK を足さない・関門 C5）。起こす仕事は `{ ...job, tools: [], allowed_tools: [], browser: "off", conversation_id: null }`。`ask`（許可・問い合わせ）は常に `{ allow: false, note: "この仕事では道具を使わず、文だけで答えてください" }`（会話の無い仕事の既存の答えと同じ文）
- 取り出し：返事の本文の最初の `{` から最後の `}` までを JSON として読む（前後の「答え:」「```json」の飾りは捨てる）。読めない・オブジェクトでない・`ticket.title` が空は失敗
- 整え：`draft = { ticket: { title(≤200)・kind?(≤40)・owner?(≤80)・due?(YYYY-MM-DD の字だけ)・cost?(≤40)・route_name?(≤80) }, reply(≤10000・無ければ空)・questions(字の並びだけ・空と 300 字超は切って・5 個まで)・route?: { name(≤80), reason(≤200) } }`。知らない欄・文字でない値は捨てる。切るときは字数で切る（途中で切れてもよい・壊れた文字を作らない）
- 失敗の理由（口は 1〜400 字）：AI が動かなかった（`stopped`／`cancelled`）は「分身が動きませんでした」・返事が空は「分身の返事がありませんでした」・JSON が取れない・形が違うは「案の形になりませんでした」。AI の返事の本文・先方の字は理由に入れない
- 返す口の失敗：5xx・届かないときは同じ冪等キー（`draft-<job id>`）で送り直す（回数・間は `finish` と同じ）。401・403・410 は鍵が切れた（`gone` の道）・404・422 は送り直さない（仕事がもう終わっている／形が違う）
- 同時に 1 件ずつ（今の輪と同じ）。AI の起こしに失敗しても輪は止めず、次の仕事を取る
- 関門 C5：子プロセスの起こしは既存の `runClaude` だけを通る。この葉は `child_process`・`fetch` の生の呼び出しを足さない（`loop.ts` の既存の `post`・`call` を使う）
