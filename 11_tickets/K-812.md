## 目的

メンバーの 1 人の画面（K-819）の「グループを移す」「＋ 兼ねるグループを足す」と、兼ねるグループの「外す」（下絵 md-move・md-also）が呼ぶ口 `updateMemberGroups`（PATCH /api/v1/members/:id/groups）を作る。

- **移す**（primary_scope_id）：主の所属を別のグループにする。**主は 1 つ**（前の主のグループからは外れる。前のグループにも残したいときは同じ体の add_scope_ids に入れる）
- **兼ねる**（add_scope_ids）：別のグループにも入れる（兼務・D-125.115）。役割は role_key（既定 member）。違う層のマネージャーを兼ねる・別の部署に作業員として入る、どちらも通る（D-154.15）
- **外す**（remove_scope_ids）：兼ねているグループから外す。主の所属は外せない（移してから）

見えるものが変わるので、**本人確認の取り直し**を要る（契約の `stepUp: "always"`・D-154.18）。画面は今の取り直しの小窓（`features/F1/security/step-up.tsx`・パスキーは `passkey.ts` の `stepUpWithPasskey`）で取り直し、通ったら 1 回だけやり直す（K-363 と同じ形）。**自分のグループは自分では変えられない**（D-154.19）。

口の登録・断る番号（errors）は K-800 が持つ。入力と答えの形は K-800 の「契約」の節で決めた形で、この葉の口の分をこの葉が契約（.d）に書く。この葉は `members/groups.ts` の空の形を本物にして `ready = true` にする。

**画面が使う答えの形**（K-820 が使う）：200 `{ data: MemberGroupsChanged }`・鍵はちょうど 3：member_id・company_role・groups（`[{ id, name, code, primary, role }]`・主が先・K-810 の getMember の groups と同じ形）。画面は答えで「グループと役割」の区画を差し替える。

## 前提と制約

分類: PERM, CRUD

- **だれが呼べるか**：契約の PERMS のまま（members の edit・会社全体＝管理者の束と個別に付けた人。マネージャーは呼べない・D-128.97）。入口が先に 403。DB の関数も頭で `app.admin_lock()` の後に `app.admin_can('members', 'edit')`（K-800 の決めの順・守りは入口と関数の 2 層）。**「members の edit を個別に付けた人」の行（K812-API-011）は DB の守りとして残す**：人ごとの「できること」を作らない（D-154.10）ので製品の画面からは個別に付けられない（試験は DB に直に入れた権限の行で確かめる）
- **入力**：`primary_scope_id`・`add_scope_ids`（0〜20）・`remove_scope_ids`（0〜20）・`role_key`（manager・member・viewer・既定 member）。**1 つは要る**（体が空は入口が 422）。形の誤り・知らない欄（scope_id・tenant_id）は入口が 422
- **相手**：K-811 と同じ（`app.admin_target` が null なら 404・E-MEM-002・止めている人は変えられる＝所属は変わり、止めている間は役割の束の引き金 0080 が束の権限の行を作らず、戻すと作る・K812-API-015）。**自分**は 409・E-MEM-003
- **グループ**：体に出てくる全部のグループ id（primary・add・remove）が、同じ会社の消していないグループでなければ 404・E-MEM-006。**1 つでも無ければ何も変えない**（全部か無しか）
- **順番**：① 外す（remove）② 移す（primary）③ 足す（add）。外す → 足すの順なので、同じ id が remove と add の両方にあれば「外してから足し直す」（役割が role_key に入れ替わる）。同じ id が primary と add にあれば、primary が先に決まり add は何もしない
- **外す**：兼務の所属の行（is_primary false）を deleted_at で外す。そのグループに居なければ 409・E-MEM-007。主の所属を外す（移さずに）なら 409・E-MEM-008（欄・details なし）
- **移す**：members.scope_id を新しい主にする。前の主の所属の行は、add_scope_ids に前の主が入っていなければ **外す**（deleted_at）・入っていれば兼務（is_primary false・役割はそのまま）にする。新しい主のグループにすでに兼務の行があれば、その行を主（is_primary true）にして **役割は保つ**。無ければ role_key（既定 member）で行を足す（is_primary true）。主の行はいつもちょうど 1 つ（部分一意の索引 `scope_memberships_primary_uq`・0075）。今の主を指したら何もしない
- **足す**：その人がそのグループに居れば何もしない。無ければ兼務の行（is_primary false・役割は role_key）を足す。**外した行がある（deleted_at が入っている）なら新しく足さず、その行を生き返らせる**（deleted_at を空にして役割を入れる・同じ人・同じグループの行を重ねない）
- **変わらない指定**（今の主を主に・居るグループを足す）は何も書かず 200・証跡を書かない・セッションを切らない
- **セッションが切れる**（G-14・D-125.140）：役割の束の引き金（0080 `scope_memberships_bundles`）が権限の行を作り直し、権限の引き金（0004 `permissions_revoke_sessions`）がその人の全セッションを切る。口は別に切らない（同じ取引の中で引き金が切る・K-811 と同じ）。何も書かない回は切れない
- **同時**（D-154.21）：`app.admin_lock()` で順に通す。同じ人の主を 2 人が同時に別のグループへ移しても、後の 1 本が前の確定を待ち、主の行は 1 つのまま・members.scope_id と主の行が同じグループ
- **記録は追記だけ**（D-154.25）：`member.groups_change`（payload は `{from_primary, to_primary, added（足したグループの id の並び）, removed（外したグループの id の並び）}`・id だけ）。何も変わらなかったときは書かない
- **グループの人数・上限は見ない**（1 人が入れるグループの数に上限を置かない。体の配列が 20 まで）
- 入口の共通が先に効く：401・429・同意し直し 403・本人確認 403・道の id の形 422・NUL 422
- 断る番号は控え帳どおり（404 は欄・details なし／409 は欄・details なし／503・E-PAGE-003）
