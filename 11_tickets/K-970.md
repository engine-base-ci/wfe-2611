## 目的

請求が払われない・規約に反するときに、運営が 1 社を止め、払われた・直ったら再開できるようにする（行為 A127・D-125.126・D-128.68）。止めても会社のデータと実行待ちは消さない。

- **代表の答え 2026-11-23（D-156.23）**：止める日までの間は、その会社の管理者にお知らせと画面の上の帯（管理者だけ）。止めた後は、その会社の人には止められた画面（K-1008）。実行中は区切りまで進めて止め、実行待ちは残す（入口と PC は K-1012）。ワークスペースに「止めた日・止める予定の日・理由」の印を足す（人ごとの一時停止とは別）
- **stopWorkspace**（ops:stop・step_up always）：先に知らせて日を決める（`mode scheduled`・既定は画面が 7 日後を出す）／すぐ（`mode now`・規約に反する `violation`・危ない `danger` のときだけ）
- **resumeWorkspace**（ops:stop・step_up always）：止める予定を取り消す・止めた会社を戻す（印を全部空にする）
- 止める日・止めた帯は稼働状況の口（K-955 の getServiceStatusForMember）の `bands` に kind `stop` で入れる（D-156.10）

- **組み合わせの決まりは契約に書く（422）**：`05_flow/screen_api.d/K-970.py` の INPUT_RULES に、`mode now` なら `reason_key` は violation・danger だけで `stop_on` を付けない／`mode scheduled` なら `stop_on` が要る（K-385 が E-VAL-027 を INPUT_RULES に移したのと同じ形・UNEXPRESSIBLE_422 は使わない）
- **止める日**：`stop_on` は明日（日本の暦）以降。今日・昔は **409 E-OPS-006**（欄なし・読むときの日で決まるので契約に書けない）。上の限りは置かない
- **二重**：止める予定がある・もう止めている会社に日を決め直すと **409 E-OPS-003**（欄なし・日を変えるときは再開で取り消してから）。予定がある会社を `mode now` で止めるのは通す（急ぐことになったとき）。止めた会社をもう一度止めると 409 E-OPS-003
- **再開**：止める予定も止めた印も無い会社は **409 E-OPS-004**（欄なし）。再開は 5 列を全部 null に（stop_on・stopped_at・stop_reason_key・stop_noticed_at・stop_notice）
- **印の列**：K-963 が足した 4 列（`stopped_at`・`stop_on`・`stop_reason_key`・`stop_noticed_at`）に、この葉が `stop_notice text`（管理者へのお知らせの本文・2000 字まで・check）を足す。日を決めて止める＝`stop_on`・`stop_reason_key`・`stop_noticed_at now()`・`stop_notice`（`stopped_at` は null のまま）。すぐ止める＝`stopped_at now()`・`stop_on` 今日・`stop_reason_key`・`stop_notice`
- **止めているかの決め（1 か所）**：`app.tenant_stopped(p_tenant) returns boolean` ＝ `stopped_at is not null or stop_on <= 今日（日本）`。止める日が来たら、何もしなくても止まる（時間で動く仕組みは使わない・D-156.33 と同じ考え）。K-1012 の入口と帯が使う
- **管理者へのお知らせ**（日を決めて止めたとき・D-156.23）：その会社の管理者全員（`tenant_memberships` の role admin・status active・消していない・members も消していない）に `notifications`（`channel_id 'inapp'`・`event_kind_id 'workspace.stop_scheduled'`・payload `{ stop_on, reason_key }`＝本文の字を入れない・`created_by` は運営の人）を 1 行ずつ。すぐ止めるときは出さない（止められた画面で分かる）。再開でも出さない（帯が消えて使える）。運営のお知らせ（notices）ではない（D-156.28 の鈴に出さない物は運営のお知らせ）
- **お知らせの種類の表**（段 8 の K-461 の `apps/api/src/features/F7/notifications/kinds.ts`）に 1 行足す：`workspace.stop_scheduled`（札 `setting`・チケットに結ばない・行き先なし＝押せない行・帯で分かる）。足さないと K461-API-016 が赤・鈴に出ない
- **鈴の文はこの葉で足さない**（D-156.73・D-156.41 を改めた・PM 2026-11-23）：文の表 `notice-text.ts`（段 8 の K-467）は画面のコードなので、workspace.stop_scheduled の文 「ワークスペースを止める日が決まりました。日付は画面の上の帯で確かめられます」 の行と試験は押した先の画面の葉 K-1008 が持つ。この葉は種類の表 `kinds.ts` の 1 行だけ
- **帯**（K-955 の `app.member_stop_band()` を create or replace・K-1004 の bands の 1 つ）：止めている（`app.tenant_stopped`）なら、その会社の人全員に `{ kind: "stop", notice_id: null, title: <理由の字>, state: <stop_notice か null>, note: null, ref: null, from: <stopped_at か、無ければ stop_on の 0 時（日本）>, to: null, closable: false, more: 0 }`（`note`・`ref` は K-1004 の bands の欄・D-156.45。止める帯では null）。止める予定（止めていないで stop_on が今日より後＝明日以降）なら**管理者にだけ**同じ形（from は stop_on の 0 時）。ほかは null。運営の人が中を見ているとき（role ops）は管理者と同じに見せる
- 記録（D-128.108）：日を決める `workspace.stop_scheduled`・すぐ `workspace.stop`・再開 `workspace.resume`。どれも `app.record_ops_audit(<会社>, <操作>, 'tenants', <会社>::text, null, {target_label: <会社名>, reason: <理由の字>（再開は無し）, note: <note か null>})`。操作の字は K-1011 の表（止める日を決めた／止めた／再開した）
- 断る番号（控え帳）：ログインなし 401・運営でない・stop を持たない 403（入口・契約の ops:stop）・本人確認が無い・15 分より前 403 STEP_UP_REQUIRED（入口）・形と組み合わせ 422（入口・契約）・会社が無い・見えない 404（欄なし）・止める日が今日以前 409 E-OPS-006・二重 409 E-OPS-003・止めていない会社の再開 409 E-OPS-004・DB の失敗 503 E-PAGE-003（何も残さない）・上限 429。ログは `[ops] stop の DB が失敗した（<SQLSTATE>）` だけ（本文の字を出さない）
