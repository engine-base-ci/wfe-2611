## 目的

運営の人の画面（K-986・下絵 op-team-edit・op-team-remove）の「変える」「外す」の口を作る（行為 A134・今は 501）。運営の場所に入れる人を減らしたら、その場で入れなくなる（D-128.70）。

- **updateOpsMemberCaps**（ops:ops_people・本人確認の取り直し）：`caps` を丸ごと置き換える。答えは K-985 の 8 欄
- **removeOpsMember**（ops:ops_people・本人確認の取り直し）：外す。パスキーを消し・使っていないリンクを使えなくし・セッションを閉じ・その人が担当の問い合わせの担当を空にする（受信箱に取り残さない・K-974 の申し送り）。もう一度入れるには K-985 で足し直す（D-156.22）
- **守り**（代表の答え 2026-11-23・D-156.34）：自分のできることは変えられない・自分は外せない。「運営の人」「値段を決める」を持つ最後の 1 人は外せない・その印を外せない

## 前提と制約

分類: CRUD, PERM

- **生成の試験は作る段の最初に作る**：契約の断片を足して作り手で生成の試験を作り、**実装より先に 1 つのコミットにする**。先の葉の契約を前提にした前からの試験は carry に入れない
- **入力の形（契約に書く＝422）**：変える＝`caps`（K-985 と同じ 9 つの字・1〜9 個・重ならない・必須）だけ・ほかの欄は 422。外す＝体なし（`{}` か無し）。道の `:id` は uuid（members.id・K-985 の `member_id`）
- **対象**：運営の会社の members で、生きている ops_members を持つ人だけ（外した人・顧客の会社の人・無い id は **404**・欄なし）
- **自分**（`:id = app.user_id()`）：変えるも外すも **409 E-OPS-017**（欄なし・「自分のできることは変えられません」）
- **最後の 1 人**（ops_people は呼ぶ人が必ず持ち、自分は変えられないので口からは 0 にならない。関数は 2 つとも同じ式で守る＝口の試験は plan_decide で見る）：変えた後・外した後に、生きている運営の人のうち `ops_people` を持つ人、`plan_decide` を持つ人のどちらかが 0 になるなら **409 E-OPS-018**（欄なし・detail `{ cap: "ops_people" | "plan_decide" }`・画面の字に使う）。数えるときは、その印を持つ生きている ops_members の行をすべて `for update` で取ってから数える（同時に 2 人を外して 0 になるのを止める）。K-985 の `app.ops_member_row` の `locked_caps` と同じ式を使う（1 か所）
- **変えたものが同じ**：caps が今と同じ（並びは問わない）なら何もしない（200・記録も書かない）
- **外す**（1 つの取引）：ⓐ `ops_members.revoked_at = now()` ⓑ `kaname_auth.passkey` の `"userId"` = その人の `auth_user_id` の行を消す（下絵 op-team-remove「登録していたパスキーも使えなくなります」）ⓒ その人の使っていないリンク（`ops_setup_links`）を `used_at = now()` ⓓ その人の生きている `sessions` を `revoked_at = now()`（解決は K-944 のとおり外した時点から解かない＝ここは 2 層目）ⓔ `inquiries` で `assignee_ops_member_id = その人` の行の担当を空に（どの会社の問い合わせでも・数を記録の payload に）ⓕ 記録
- **記録**（K-947 の検査）：変える `app.record_ops_audit(app.ops_tenant_id(), 'ops_member.caps', 'ops_members', <ops_members.id>::text, null, {target_label: <名前>, before: [...], after: [...]})`・外す `'ops_member.remove'`（`{target_label, released_inquiries: N}`）。これまでの操作の記録は消さない（下絵「これまでの操作の記録は残ります」）
- 断る番号（控え帳・D-156.12・D-156.17）：ログインなし 401・運営でない・ops_people を持たない 403（入口）・取り直しが無い 403 STEP_UP_REQUIRED・形 422・無い 404（欄なし）・409 E-OPS-017／018・DB の失敗 503 E-PAGE-003（何も変えない）・上限 429
