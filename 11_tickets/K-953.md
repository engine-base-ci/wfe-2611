## 前提と制約

分類: CRUD, FILE, XSS

- **代表の答え 2026-11-23（D-156.25・D-156.26）**：何について は 使い方／うまく動かない／お金・プラン／ほか の 4 つ。添付は 1 つ 10MB・5 つまで・画像と PDF と zip。画面の写しは自動では撮らない（ファイルとして付ける）。書けるのは R1〜R3（先方の権限の人は入口が 403・口の葉 K-949）。送った問い合わせは書いた本人だけが見る
- **道**：`app/(work)/inquiry/page.tsx`（`searchParams` の `from` を待って渡す）。`built-routes.ts` を作り手で作り直す（生成物）→ K-956 のホームの「問い合わせる」が `/inquiry` への押せるボタンになる
- **入れ物（`ask-screen.tsx`）**：K-956 の `HelpScreen` の上に `AskDialog`（開いた形）。焦点は「何について」。やめる・Esc は口を呼ばず `router.replace("/notices")`
- **入力の確かめ（`ask-shape.ts`・純粋）**：`askProblems({ title, body })`：前後の空白（全角・タブ・改行）を落として空なら「題を書いてください」「内容を書いてください」（下絵の字）・題 101 字以上「題は 100 字までです」・内容 4001 字以上「内容は 4000 字までです」（仮・契約の 1〜100・1〜4000 と同じ・字は文字で数える）。JS が先に働く（`<form noValidate>`・ブラウザ標準の確かめに奪われない・G-01）。口を呼ばない
- **付けるファイル（`fileProblem(file, count)`）**：種類は `image/png`・`image/jpeg`・`image/gif`・`image/webp`・`application/pdf`・`application/zip` だけ（ほかと空の種類は「この種類は付けられません（画像・PDF・zip）」仮）・10MB（10485760 バイト）を超えるか 6 つ目は「大きすぎて付けられません（1 つ 10MB まで・5 つまで）」（下絵の字）・0 バイトは「中身が空のファイルは付けられません」（仮）。理由があるファイルは口を呼ばず、行に理由を出す（送る体に入れない）
- **上げる流れ**（K-948 の uploadInquiryAttachment の形・K-950 の決め：体は口を通さず置き場へ直に送る）：① `call("uploadInquiryAttachment", { body: { name, content_type, size } })` → `{ id, upload_url, done_url, expires_at }` ② `fetch(upload_url, { method: "PUT", body: file, headers: { "content-type": file.type } })`（上げる先は関門 C4 が大きさと種類を入れて署名した置き場の URL。口＝Vercel の関数の体の上限 4.5MB と 1MB の守りの入口を通らない） ③ 2xx なら `fetch(done_url, { method: "POST" })`（体なし・上げ終わり。口が置き場の物の頭と大きさを照らす） ④ 200 なら行を「付いた」にして id を持つ。③ が 415 E-INQ-003 なら行に「この種類は付けられません（画像・PDF・zip）」、413 E-INQ-004 なら「大きすぎて付けられません（1 つ 10MB まで・5 つまで）」、①②③ のほかの失敗は「付けられませんでした。もう一度付けてください」（仮）で id を持たない。上げている間（①〜③）は「送る」を押せない（付け終わるまで待つ）
- **いま見ている画面の情報（`askContext`）**：「いま見ている画面の情報を付ける」が入っているときだけ体に `context` を入れる：`path`（`from` が `/` で始まり `//` で始まらない同じ場所の道ならそれ、ほかは今の道）・`at`（ISO）・`browser`（UA から「Chrome 130」の形・読めなければ UA の頭 60 字）・`pc`（外枠の PC の印の答え〔鍵 `["k138-shell","devices"]`〕が分かるときだけ真偽）。**チケットの中身や会話は付けない**（D-128.71）
- **送る（`use-ask.ts` の `useCreateInquiry`）**：体 `{ topic, title, body, attachment_ids?, context? }`（何について の字 → `usage`・`trouble`・`billing`・`other`・付いたファイルが無ければ `attachment_ids` を送らない）。成功：小窓を閉じ `/notices?sent=1` へ移り、ホームに Callout「運営に届きました」（下絵の字）・鍵 `["k956","inquiries"]` を invalidate（別 GET で画面と答えを合わせる）。**二度押し**：答えを待つ間「送る」を押せない（口は 1 回）
- **口が断る番号**：503 → E-PAGE-003・網の切れ → E-PAGE-007・404（付けたファイルが見えない・使えない＝口の葉 K-949 の断り）→ E-PAGE-001 の字を小窓の上の赤い箱（`NoticeBox`・role=alert・`data-code`）に出す。**小窓は閉じず中身は残り、押し直せる**。409（K-949 の E-INQ の断り）も同じ赤い箱に正本 errors.json の字（K-949 が足す番号・作る段で合わせる）
- **部品に足す物（見た目と並びは変えない・任意の props だけ）**：`views.tsx` の `AskDialog`（`onKind`・`onTitle`・`onBody`・`onWithScreen`・`onPickFiles`・`onSend`・`onCancel`・`sending`・`notice`〔赤い箱〕）・`AskFile`（`error?`＝行の理由の字・`pending?`）。値を渡すと欄は書ける形（`readOnly` を外す）。「＋ ファイル・画面の写し」は `onPickFiles` があれば隠した `<input type="file" multiple accept="image/png,image/jpeg,image/gif,image/webp,application/pdf,application/zip">` を開くボタン（無ければ今の押せない形）。`HelpHome` の `sent` は K-956 の入れ物が `?sent=1` で渡す（`help-screen.tsx` に 1 行）
- 画面の字は下絵が正。下絵に無い字は仮（上の「仮」）
