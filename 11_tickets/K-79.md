## 目的

顧客の ID・パスワードなどを預ける先を用意する（infra/STAGING.md S1b）。無いと staging の API は起動時の確認（secrets:vault）で止まる。

## 完了の条件

- [ ] Infisical の口座と Project `kaname`（環境 staging・prod）がある
- [ ] Machine Identity `kaname-api-staging`（Universal Auth）を作り、Project の staging を読み書きできる役割にした
- [ ] 値（Client ID・Client Secret・Project ID・地域）を K-80 で Vercel に入れる準備ができた

## 前提と制約

- 無料枠で始める（identity 5・毎分 120 回）。8 割で info@ に知らせが届く
- 組織全体の権限は付けない
- 鍵・パスワード・接続文字列の値は、チャット・ファイル・コミットに書かない。入れる先は Vercel の環境変数（Sensitive）か Infisical だけ（infra/STAGING.md §1）

## 実施事項

1. https://app.infisical.com で口座を作る。地域（US／EU）を控える → `INFISICAL_SITE_URL`
2. Project `kaname` を作る。環境は `staging` と `prod` だけ使う → `INFISICAL_PROJECT_ID`・`INFISICAL_ENVIRONMENT=staging`
3. Organization → Access Control → Identities → Machine Identity `kaname-api-staging`（Universal Auth）→ `INFISICAL_CLIENT_ID`・`INFISICAL_CLIENT_SECRET`
4. その Identity を Project に足し、staging の Secrets を読み書きできる役割にする
