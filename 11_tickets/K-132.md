## 目的

契約の入口（apps/api/src/contract/op.ts）の回数の制限は、どの口も同じ形で数えている。

- 数える鍵：役が user の口はログインした人、それ以外は `ipOf`（`x-forwarded-for` の先頭 → `x-real-ip` → `unknown`）。`x-forwarded-for` の先頭は送り手が自由に書けるので、毎回変えれば上限をすり抜けられる
- 数える場所：`memoryLimiters()`（apps/api/src/contract/memory.ts・@kaname/actions の RateLimiter）で、台（プロセス）ごとのメモリ。配布先（Vercel の関数）は台が増えたり入れ替わったりするので、台の数だけ上限が増え、入れ替わるたびに数が 0 に戻る

接続コードの引き取り（1 分 5 回・IP ごと・public の口）や登録など、回数の制限を守りに使っている口が全部、本番では効かない。K-57 のテスターが見つけた。**決める人の判断（2026-11-07）：最初の公開（本番）の前に必ず直す。** そのため本番の一式を作るチケット（K-83）の depends_on にこのチケットを入れた。

信頼できる IP の読み方そのもの（右から数えた段の IP を使う共通の部品）は K-118 が作る。このチケットはその部品を使って、数を DB で全台共通にし、全部の口をそれに載せる。

（K-135 からまとめた・2026-11-07）API の試験の土台 `apps/api/test/features/fixture.ts` の `nextIp()` は、`203.0.113.1`〜`.250` の 250 個を順に配る。1 つのファイルで 250 回を超えて呼ぶと同じ IP がまた配られ、前の試験の数が残っている IP で回数の制限の試験（K57-API-038：引き取りを 1 分に 6 回で 429 など）が始まって赤になる。試験を足したり順を変えたりするだけで赤と緑が入れ替わる（試験の順に頼る）。K-57 の実装の役が見つけた。数を全台共通にすると、IP の重なりは別のファイルの試験とも混ざるので、送り元の IP の扱いは回数の制限の直しと一緒にこのチケットで直す。

## 完了の条件

- [ ] 回数の制限の鍵の IP は K-118 の部品だけから取る。op.ts の `ipOf` と、口ごとの前処理で IP を読む所（apps/api/src/features/F1/consent-terms/index.ts の `ipOf` ほか）を全文検索して、全部その部品に寄せる（L-008）
- [ ] 回数を DB の 1 か所で数える（台が 2 つあっても上限は 1 つ・台が入れ替わっても数が残る）。接続は関門 C2 を通す。表や関数を足すなら migration を取り込む順の次の空き番号で足し、ER 図に無い表は決める人に決めてもらってから
- [ ] DB に数えられないとき（接続が尽きた・時間切れ）は、通さず止める側（503）に倒す（fail-closed）。止めたことはログに理由の種類だけ出す（IP・メール・トークンを出さない）
- [ ] 全部の口が同じ形で数える（口ごとに別の数え方を作らない）。上限の値は今の契約の値のまま
- [ ] 試験：先頭に偽の IP を毎回変えて足しても、上限を超えたら 429。台を 2 つ立てて交互に送っても、合わせて上限で 429
- [ ] 配布物の試験 K57-API-055〜057（apps/api/test/features/F3/connect-pc.test.ts）は同じ IP から 1 分に約 127 回呼ぶ。IP ごとの上限を足すときは、056（1 分に 121 回で 429 を見る試験）を別の IP にして、ほかの試験の数と混ぜない（K-57 テスターの注意）
- [ ] 試験の土台の送り元の IP（K-135 から）：試験ごとに決まった IP を持つ（試験の名前などから決まる・同じ試験はいつも同じ IP・別の試験とは重ならない）。配る順と試験の数に頼らない
- [ ] 回数の制限の試験（K57-API-038・K57-API-056 ほか、上限を数える試験）が、ほかの試験の数と混ざらない。順を入れ替えて流しても・1 本だけ流しても同じ結果（K-135 から）
- [ ] 試験の中で IP を変える必要がある所（偽の IP の試験など）は、その試験の中で明示して決める（K-135 から）
- [ ] 画面の試験（K-122）と中間テスト（K-54）が緑のまま
- [ ] チケットの CI（act）が緑

## 前提と制約

- 依存：K-118（信頼できる IP の部品）。K-135（試験の土台が試験ごとに決まった IP を持つ）に依存していたのは外し、その中身をこのチケットにまとめた。土台の直しを先に入れてから、数を全台共通にする（順に頼る IP のままでは、全台共通にした数で試験どうしがぶつかる）
- 試験の土台（apps/api/test/features/fixture.ts）は画面の試験の側（K-122：ブラウザごとに x-forwarded-for を足して避けている）とは別の土台。K-122 と同じ考え方（試験ごとに決まった IP）にそろえるかを、切るときに書く（K-135 から）
- 時間で隠さない（待ち・再試行で数が消えるのを待たない）（K-135 から）
- 本番の一式（K-83）はこのチケットに依存する（最初の公開の前に必ず・決める人の判断 2026-11-07）。この判断はまだ決定ログに 1 行で書かれていない（PM が足す）
- 有限資源の枯渇（G-16）：数えるたびに DB に 1 回行く。1 要求あたりの接続の使い方（プールの接続を使う・専用の接続を使わない）と、上限に当たったときの挙動を実装の詳細に書く
- memory.ts の既定（メモリ）は、単体の試験の差し込み口として残してよい。本番と staging の組み立て（apps/api/src/server.ts）は DB の形だけを使う
- 外向きの送信の回数の制限（server.ts の `new RateLimiter(OUTBOUND_PER_MINUTE)`・関門 C1）も台ごとのメモリ。同じ形で直すかは、切るときに決めて書く
