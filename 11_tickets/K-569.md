## 前提と制約

分類: CRUD, PERM

- **作る面・詳細の前からのファイル（`features/F4/create-ticket/*`・`ticket-detail.css`）には触らない**（決め：K-442 が作る面を、K-571 が詳細を丸ごと作り直し、前からの画面の試験 k224〜k226 の持ち主もその 2 本。この葉が 1〜2 行ずつでも差し込むと同じファイルを 2 本の葉が触る）。この葉は **表の部品**（`ItemsTable`・`CustomRows`）と**読む・保存する道具**を `features/F4/items/` に作り、**動くことは開発用の置き場の頁 `/dev/f4-items`（この葉の changes・実ブラウザの試験が開く）で確かめる**。K-442・K-571 はこの部品を作る面・詳細に組む（両方ともこの葉に依存する）
- **開発用の頁 `/dev/f4-items`**（クエリ `mode=create|detail`・`kind=<uuid>`・`ticket=<uuid>`・`slot=due`）：`mode=create` は種別の口の答え（`kind` の `fields`）を読んで、項目の表（`ItemsTable`）と「作る」ボタンと、押した結果の値を字で出す `output`（名前「送る値」・`{"fields":{…}}` の JSON）を出す。「作る」は送る前の確かめ（`checkFields`・高の理由も含む）を通し、通れば `output` に出す。`mode=detail` は `GET /api/v1/tickets/:ticket` の `fields` を読んで `ItemsTable`（詳細の形）を出し、直した値は 1 項目ずつ `PATCH /api/v1/tickets/:ticket` で送る。`slot=due` のときだけ期限の差し込み口にボタン（名前「期限」）を渡す（差し込み口が使えることの確かめ）。頁は本物の部品と本物の読む・保存する道具を使う
- **口**：読む `listTicketKinds`（GET /api/v1/ticket_kinds・K-560。各種別の `fields` が会社の項目のマスタ・鍵 7 は K-563 の `TicketField`）。`listTicketFields`（K-563）は作る面・詳細とも呼ばない（マスタを直す画面は段 10）。詳細の値の読みは getTicket の `fields`（鍵 8：id・name・field_type・required・description・options・position・value・K-560）。直す `updateTicket`（PATCH /api/v1/tickets/:id・体 `{ fields: { "<項目の id>": 値 } }`・K-564）。作る口 createTicket の `fields`（K-437）は、この葉は送らない（作る面を組む K-442 が `toPayload` の結果を送る）
- **値の形**（K-564・K-437 と同じ）：短い文字・長い文章＝文字（前後の空白は画面で落とす）／数＝数（0 も値）／日付＝`YYYY-MM-DD`／1 つ選ぶ＝選択肢の id／複数選ぶ＝選択肢の id の並び／チェック＝真偽。空にするのは null（空の文字・空白だけ・空の並びも空）。**必須のチェックは、付いていないと必須を満たさない**（false は空と同じ・D-150.51）
- **送る前の確かめ（画面）**：必須の会社の項目が空なら、項目ごとに欄の下に赤い字（型で言い方が違う：文字は「〈名前〉を書いてください」・数は「〈名前〉を入れてください」・日付・選ぶ・複数選ぶは「〈名前〉を選んでください」・チェックは「〈名前〉にチェックを付けてください」。下絵の「支払期日を選んでください」「PJコードを選んでください」と同じ言い方）。最初の誤りの欄にキーボードの場所を移す。数の欄に数でない字が入っていたら「〈名前〉は数で入れてください」。口が最後の砦（画面の確かめを通らない値は口が 409・E-FLD-00x で断る）
- **種別を変えると**、その種別で出す項目に入れ替わる（種別の口の答えに全種別の分の `fields` が入っているので、口は呼ばない）。入れた値は項目の id ごとに画面の中に残り、戻すと戻る。**新しい種別で出ない項目の値は送らない**（`toPayload` は今出ている項目の分だけ作る）。種別の口が読めなかった（503 ほか）ときは会社の項目の行の場所に「会社の項目を読めませんでした」と「読み直す」（種別の口を 1 回読み直す）を出し、用意してある項目はそのまま使える
- **詳細で直す動き**（下の「代表に聞くこと」の勧めで切った）：値の字を押すと、その行がその場で表と同じ入力に替わる。決める（文字・数・日付は Enter か入力から外れる・選ぶは選んだとき・複数選ぶは「決める」・チェックは押したとき）と、その 1 項目だけを `fields: { <id>: 値 }` で更新の口に送る。Esc で何も送らずにやめる。**1 回に 1 項目**（K-564 の断りは欄なしなので、どの項目の断りかを画面が 1 項目ずつ送って決める）。送っている間は入力を押せない形（二度押しで口は 1 回）。完了したチケットでも直せる（K-564・口が断るのは 403 だけ）
- **断りの出し分け**（段 9 の D-148.30〜38 の分け方）：409 の E-FLD-001（その種別に出ない）・002（選択肢に無い）・003（型に合わない）・004（必須が空）と 404 の E-PAGE-001（項目が消された）は、その行の欄の下の赤い字に正本の文（`07_qa/test-specs/errors.json`）をそのまま出し、入力は開いたまま残る（もう一度直せる）。404 のときだけ getTicket の読み直しを 1 回する。403 と 503 は 5 秒で消える小さな知らせ（403 は「この操作をする権限がありません。権限が変わったかもしれません。画面を読み直してください」・503 は E-PAGE-003 の文）。403 は元の値に戻し、503 は入力を残す（もう一度押せば通る）。画面は役の名前で出し分けず、口の答えで出し分ける
