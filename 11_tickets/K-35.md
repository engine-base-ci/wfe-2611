## 目的

CI の G36（契約 fuzz）を、まだ無い印（gate_pending）から本物の検査にする。作った口を本物の DB の上で、契約から作った入力と契約の外の入力で叩き、サーバーが落ちない・答えの形と状態コードが契約どおりであることを毎回確かめる。

## 完了の条件

- [x] `pnpm ci:schemathesis` が Schemathesis（MIT）で作った口を全部回し、緑
- [x] 契約の表の行の答えの形が、本物の DB の列（型・null を許すか）と合う。合わなくなったら CI が赤になる
- [x] 一覧の問い合わせ（limit・cursor・sort・scope_id）と id の形が契約に書いてあり、入口の確かめと合う
- [x] 契約の外のメソッドは 405
- [ ] CI が緑（GitHub の結果は push 後に見る）

## 前提と制約

- まだ作っていない口（入口が 501 で止める口）は fuzz で回さない。501 で止まり何も書かないことは生成の試験（`apps/api/test/generated`）が見る。口を作るほど fuzz の範囲が自動で広がる
- 認証そのものは packages/auth の試験が持つ。fuzz の的は偽のセッション（Bearer boss）

## 実施事項

- [x] `scripts/ci/fuzz.sh`：DB の列の書き出しの確かめ → 的を立てる（`apps/api/test/fuzz/server.ts`・本物のサーバーと同じ hooks）→ 作った口を回す（例 30 個ずつ・種を固定）
- [x] `pnpm db:columns`：本物の DB の列を `08_api/db-columns.json` に書き出す。`05_flow/build_api.py` は表の行の答えの形をこれで作る（ER の名前の規則と migration がずれた列も DB のとおり。例：conversations.incognito は真偽、null を許す列は nullable）
- [x] 64 ビットの整数と小数（お金）は文字列で返る（丸めない）。日付（date）は文字列のまま返す（Date にすると時刻の帯で前の日に化けていた）
- [x] 一覧：空の値（?limit=）は指定なしと同じ。sort は表の列だけ。scope_id はその表にあるときだけ。続きの印（cursor）は何件目からの数
- [x] id の形・一覧の問い合わせの 422 を契約に書いた
- [x] 契約の外のメソッド（TRACE など）は 405 と Allow
