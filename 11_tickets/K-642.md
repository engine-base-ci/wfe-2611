## 目的

丸い選択（ラジオボタン）と四角い選択（チェックボックス）が、横の字とずれている（印が字の行より上に出る）と代表から何度も指摘された（2026-11-22）。共通の部品が無く、画面ごとに `<label><input type="radio" /> 字</label>` を手で組み、CSS も所ごとに `align-items: center`・`flex-start`・何も無い（字の並びの基準線に印の下を置く）とばらばらなので、1 か所を直しても別の画面で同じずれが出る。

- **部品を 1 つにする**：`apps/web/components/k/choice.tsx` に `Checkbox`・`Radio`・`RadioGroup`。label がネイティブの input を包み（読み上げ・キーボード・押す的はブラウザのまま）、印を「字の 1 行目の高さの箱」の縦の真ん中に置く。字が 2 行以上でも印は 1 行目にそろい、2 行の真ん中に寄らない。大きさ（印 13px・左右の余白はキャンバスの印と同じ左 4px・右 3px）と間（本文 8px・小窓 6px）は正本のトークン。左右の余白は字の大きさ（sm・md・lg）に関わらず全部同じにし、同じ並びの印の左端を 1 つにそろえる（2026-11-22 PM の実寸の確かめ：sm・lg だけ余白 0 にしていたので、同じ並びで印の左端が行ごとに 4px ずれて見えた）。小窓の行の幅と折り返し・見た目の突き合わせの小窓の高さとボタンの位置が変わらないことを実寸で確かめる。左端と印と字の間のずれも測る関数が測る（並び＝同じ親の兄弟の行で行の左端が 1px 以内の組。間は同じ字の大きさの行どうし）
- **本線の使い所を全部この部品に替える**（13 ファイル 18 か所・下の検索）。画面の .tsx にネイティブの丸・四角を直に書くのは部品だけにし、例外は理由つきの 2 つ（見た目の切り替えの札・外のサイトの偽物）
- **ずれを機械で止める**：印の縦の真ん中と、つながる字の 1 行目の縦の真ん中のずれを実ブラウザで測り、1px を超えたら赤。測る関数は `apps/web/tests/_lib/choice-align.mjs` の 1 か所で、試験も切る段の下絵の頁の作り手も同じ物を import する。試験は 3 つの所を測る：部品の見本の頁・開発用の置き場 `/dev/mock/<流れ>/` の全部の状態（流れのフォルダはファイルから拾う）・本番の画面のうち見た目の突き合わせに入れた組（`04_design/fidelity.json` の enrolled を、突き合わせと同じ道具 FIDELITY_STATES で整える。同意・完了と差し戻しと承認の小窓・承認の一覧・チケットの一覧と作る面など、所ごとの CSS が残る文脈）。どれもファイルから拾うので、後からモックや組が入っても自動で測る。画面の .tsx にネイティブの丸・四角を直に書いたら（属性の字・type: の形・字でない type の input・外の部品の丸・四角の import）ファイルの検査が赤にする
- 前の画面の測る仕組み（06_mockup の治具 make_state_rig.py の G13・アイコンの中心）は前のモック用で、今の apps/web の画面を見ない。その続きではなく、apps/web の試験の段（実 Chrome）に置く

## 前提と制約

分類: TOOL

- **部品の形**（実装の役が作る・名前と属性は試験が見る）：
  - `Checkbox(props)`・`Radio(props)`：props は input の属性（checked・defaultChecked・disabled・onChange・name・value・aria-*・data-* など。type は部品が決める）に、`children`（字・無ければ aria-label だけの印＝表の行の頭など）・`description`（1 行目の下に小さく出す説明・任意）・`size`（`sm`＝小窓の中 12px・行の高さ 1.6・間 6px ／ `md`＝本文 13px・1.6・間 8px（既定）／ `lg`＝14px・1.6・間 8px）・`className`（label に足す）。data-* と aria-* と role は input に渡す
  - 描く形：`<label className="k-choice …" data-size=… data-disabled?>` の中に、印の箱 `<span className="k-choice-box">`（高さ＝字の大きさ × 行の高さ・中の印を縦の真ん中に）と `<input className="k-choice-input" type=…>`、字 `<span className="k-choice-text">`（children）と説明 `<span className="k-choice-desc">`。字が無いときは label を描かず `<input className="k-choice-input" …>` だけ（aria-label が要る）
  - `RadioGroup({ legend, hideLegend?, name, value?, defaultValue?, onValueChange?, disabled?, size?, className?, children, ...fieldset の残りの属性 })`：`<fieldset className="k-choice-group …">` と `<legend>`（hideLegend なら sr-only）。残りの属性（data-*・aria-*・title など）は fieldset に渡す。中の Radio は組の name・選ばれた値・押せない・大きさを受ける（Radio に value を書く。Radio が自分で name・checked を持てばそちらが勝つ）。値が変わると onValueChange(value)
  - 押せない形：label に `data-disabled`・指の形 not-allowed、印の不透明度は正本の input-disabled（`--k-c-input-disabled-opacity`・今の小窓と同じ）。title は input に渡す（字の無い印の吹き出しのため）
  - キーボードと読み上げ：ネイティブの input のまま（Tab で焦点・Space で四角を切り替え・丸の組は ↑↓ で選び押せない物は飛ばす・名前は label の字）。焦点の輪は今の `.k-root :focus-visible`
- **縦のそろえ方**：印の箱の高さを `calc(<字の大きさのトークン> * <行の高さのトークン>)`（大きさごと。pc-row-parts.css が先にしていた形。生の `1lh` は D8 が止めるので書かない）にし、箱の中で印を縦の真ん中に置く。label は 2 列の格子（印の列・字の列）で上にそろえる。所ごとの CSS で label の字の大きさ・行の高さを変えない（変えると箱の高さとずれる。大きさは size で選ぶ）。Chrome は字の上と下の高さを整数に丸め、半分の行間を整数に切り捨てるので、13px・1.6 の字では印と字の真ん中が 0.89px ずれる（上限 1px の内）。この丸めは Blink が台によらず同じにする（Linux の Skia でも字の上と下を整数に丸める）ので CI の Linux でも同じ数の見込み。PM の最初の CI の回で 1px を超えたら、試験を緩めず部品の置き方を直す（例：印の箱を字の箱の高さに合わせる）
- **正本に足す値**（ticket-flow の切る段 5）：`04_design/DESIGN-kaname.md` の components の dialog-check（333 行）の前に `choice`（typography `{typography.body}`・lineHeight 1.6・gap `{spacing.sm}`）と `choice-box`（width "13px"・height "13px"・margin "0 3px 0 4px"＝キャンバスの印のブラウザの既定の余白）。作り手 `04_design/gen_tokens.py` は鍵を全部知っている（typography・lineHeight・gap・width・height・margin）ので作り手は直さない。小窓の大きさ sm は今の dialog-check のトークン（12px・1.6・6px）を読む（値を足さない）。lg は書体の段 body-md（14px・1.6）を読む
