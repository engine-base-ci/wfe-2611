## 目的

段 1 の 4 画面（チケット・詳細・承認待ち・PC をつなぐ）が、どの CSS にも定義の無いクラスを使っていた（k-page・k-page-head・k-row・k-section・k-list・k-link・k-pre・k-steps・k-code・k-check）。tailwind の土台の決まりで見出しが本文と同じ 13px・400 に戻り、余白も区切りも 0 になった。作る画面は外枠の右のパネルの決まり（`.k-panel`）を本文の箱に流用し、1024 以上は内側にスクロールする箱、1023 以下は画面に被さる引き出しになった。どの検査もこれを見ていなかった（調べの H2・H3・L-008：同じ形を 4 画面に同時に作った）。

このチケットは、その 2 つと、新しい層（features・components/k）に CSS の外の見た目（tailwind の字・`[` を含む任意の値・style 属性・変数で渡す名前）を書くことを、機械で赤にする検査 `scripts/ci/class_gate.py` を作る（精査の指摘：k で始まらない名前や生の値なら通ってしまう）。今ある赤を全部いま直すと本線が赤になるので、今の赤は台帳 `scripts/ci/class_ledger.json` に持ち主のチケットつきで載せて通し、台帳は減らすだけにする（増えたら赤・直したのに残れば赤・本線との分かれ目より行が増えたら赤）。直すのは持ち主のチケット（下の「台帳の最初の行」）。

## 前提と制約

分類: TOOL

- どの層でも、新しい部品の名前（頭が `k` と数字の後に `-`：`k-`・`k62-`・`k63-`）が CSS に在るかを見る
- 新しい層（`apps/web/features/**`・`apps/web/components/k/**`）では、className の字は全部「CSS に在る k の名前」か `sr-only`（画面の読み上げだけの決まり・許す一覧はこの 1 つ）でなければ foreign。`style={…}` は style。前の世代の層（components/ai など・D-128.78 で外す側）と app/ の下は foreign・style を見ない
- 「確かめられない書き方」（className={変数}・`cn(変数, …)`）を赤にするのは新しい層だけ。受け取った className をそのまま渡す（`className={className}`・`cn(className, …)`）は呼んだ側で確かめるので出さない
- 外枠の決まり＝`components/k/shell.css` に在って、部品の CSS（`components/k/` の shell.css 以外の .css）に無い k の名前（k.css にも在る `k-tabs` などは外枠専用ではない）。使ってよいのは `apps/web/components/k/` の中だけ。`components/k/` の外の .css が外枠の名前を定義していたら、その定義も shell で赤（別の CSS に書いて抜けさせない・レビューの指摘 2）
- 新しい層の className={…} は値になる位置（三項の 2 つの枝・`??` と `||` の両側・`&&` の右・`${}` の中・cn の引数・オブジェクトの鍵）を辿り、字・受け取った className・空（undefined・null・false）のどれでもなければ unresolved（読めない書き方は赤に倒す・レビューの指摘 1）。`&&` の左と三項の条件は見ない。名前にくっついた `${}` は built だけ。オブジェクトの鍵は字として判定し、計算した鍵 `[x]` は unresolved
- CSS の定義はセレクタの部分（`{` より前）だけを数える。`:not(…)` の中・文字の中・値の中は数えない（レビューの指摘 3）
- 定義に数える .css は、apps/web の .ts・.tsx の `import "…css"`（`./`・`../`・`@/` を辿る）か、読み込まれた .css の `@import` で辿れる物だけ。どこにも読み込まれていない .css の定義は数えない（新しい .css を作って import を忘れても緑になる道を塞ぐ・精査の指摘）。外枠の名前を外の .css が定義する赤は、読み込まれていなくても出す
- 台帳は減らすだけ（K-143 の結果の台帳と同じ形・D-129.51）。比べる版は本線との分かれ目（G0 の出力 base）。手元で比べずに流すときは `--no-base` を明示する（黙って比べずに緑にしない）
- 試験を書いた後は変えない（D-128.125）

## リスクと懸念

- 文字を拾う形（文の解析ではない）なので、className の外で名前を組み立てて変数で渡す書き方は、新しい層なら unresolved で出る。前の世代の層では拾わない
- 台帳の組は (名前, ファイル) なので、ファイルの名前を変えると台帳の行が古くなり赤になる（変える側のチケットが台帳も直す）
- 台帳の鍵は (種類, 名前, ファイル) なので、台帳に在るファイルで同じ名前の使い所を増やしても通る（レビューの指摘 4）。直す側のチケット（K-217・K-224・K-230・K-231・K-138）は、そのファイルの同じ名前を全部消してから台帳の行を消す
- 読み込みの辿りは import の字（`import "…css"`・`@import`）だけを見る。動的な読み込みや、外の部品（node_modules）の CSS の中の名前は数えない
