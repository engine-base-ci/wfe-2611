## 目的

ゲスト（役割 requester）が先方の場所から**依頼を出し**、自分のゲストのグループの**依頼とそのやり取りを読む**ための 2 つの口を作る（D-155.37・D-155.42）。依頼は「チケットになる前の話」で、ゲストのグループの全員に見える（誰が出しても同じグループの人が読める）。社内は届け先の社内のグループ（ゲストのグループが持つ・D-155.40）に知らせを受け、K-892〜K-895 の口で返事・受ける・断るをする。受けるとふつうのチケットになり（K-894）、依頼のやり取りはチケットのチャットの頭に残る。

- `createPortalRequest`（POST /portal/requests）：本文・いつまでに（任意）・添付（0〜5）を受けて依頼を作り（最初の本文は依頼の行の `body`・やり取りの表には 2 つ目以降が入る・K-892）、添付を依頼に付け替え、届け先の人に受け箱とメールで知らせる
- `getPortalRequest`（GET /portal/requests/:id）：自分のグループの依頼 1 件とやり取り（依頼の本文のあと、種類が message の行だけ）

返事を書く口は K-908、添付を足す口は K-909、書く間に分身が聞く口は K-910、分身の案の仕事は K-896。画面は K-912。

## 前提と制約

分類: PERM, LIST, MAIL

- **ゲストだけが使える**：`app.guest_ok()`（K-878）が false の人は 403・FORBIDDEN（抜けた・止めた・グループから外された・グループが消えた＝G-14・毎回その時の所属を見る）。社内の人（role member）は入口の 403・ログインなしは 401。**見るだけのゲストは作らない**（D-155.50）ので、読めるゲストは必ず出せる・書ける
- 依頼は**ゲストのグループの物**：`client_requests.guest_group_id` が自分のグループ・`client_id` は空・`state` は `new`・`created_by` は本人（K-878 が列を足す）。同じグループの別のゲストが出した依頼も読める。別のグループ・別の会社・消した依頼・無い id は 404・NOT_FOUND（欄・details なし・題を答えに出さない）
- 本文は 1〜10000 字（前後の空白を取って空なら 422）・NUL を含まない。題 `title` は本文の最初の空でない行（前後の空白を取って 60 字まで）。いつまで `due_on` は null か日付（日本の今日以降）・今日より前は 422（欄 `due_on`）。添付は 0〜5・知らない欄は 422（`group_id` や `state` を送らせない）
- **添付（K-909 の下書き）を依頼に付ける**：`attachment_ids` は、本人が足した下書き（`attachments.owner_type = 'portal_draft'`・`owner_id`＝本人の member id・`created_by`＝本人・`scanned_at` が空でない・消していない）だけ。1 つでも違えば（別の人の物・無い・もう依頼に付いた・消した・検査前）404・E-GST-160 で何も作らない（全部か無しか・欄なし）。付いたら `owner_type = 'client_request'`・`owner_id`＝依頼に替える（付いた先は `attachments` の持ち主の列だけ・やり取りの表に列は足さない）
- **二重に出す**：同じ人が同じ本文・同じ期限を 60 秒以内にもう一度出したら、新しい依頼を作らず前の依頼の id を 201 で返す（依頼もやり取りも知らせも増えない）。画面の二度押しと再送の保険
- **知らせ（D-155.25・D-155.33）**：届け先＝その依頼を置いたゲストのグループの `request_scope_id` のグループの人（`scope_memberships` の消していない行で、`tenant_memberships.status = 'active'` かつ役割が requester でない人）。**1 人 1 件**の受け箱の行（`notifications`・channel `inapp`・種類 `client_request.created`・payload は `request_id` と `url`＝`/requests/<id>` だけ・ゲストの書いた字・添付の名前を載せない・dedupe_key `client_request.created:<依頼>:<member>`）。届け先に人がいなければ会社の管理者（役割 admin）へ。メールは**リンクだけ**（件名「新しい依頼が届きました」・本文に依頼へのリンクだけ。ゲストの書いた字を載せない）。受け箱の行は DB の関数の中で書き、メールは書いた後に口が送る（関門 C6）。**メールが送れなくても依頼は残る**（受け箱の行が残る・201）。出した本人（ゲスト）には送らない
- 添付の大きさ・種類・検査（ファイルの型 TP-FILE）は K-909（置く口）が持つ。この葉は検査済みの下書きの付け替えだけ（K907-API-005・006）
- 依頼を出したときに分身の案の仕事（bridge_jobs）は積まない（K-896 が決める・D-155.11）
- 読む：`state` は new・asking→`open`・ticketed→`accepted`・declined→`declined`。`declined_reason` は断った依頼だけ。`can_write` は open のときだけ true（K-908 が書くとき同じ決めで断る）。やり取りは、1 件目が依頼の本文（`id`＝依頼の id・`side` they・`name`＝出した人の表示名・`at`＝依頼の時刻・`text`＝`client_requests.body`）、続いて `client_request_messages` の種類 `message` の行だけを古い順（ファイルを付けた記録（種類 `attachment`）など別の種類は返さない）・`side` は guest→`they`・company→`we`・`name` は書いた人の表示名
- 書いた字は**そのまま返す**（HTML の字・スクリプトの字も置き換えずに返す。文字として出すのは画面の受け持ち・K-912・ZT8）
- 関門の宣言（頭の欄 choke_points）は [C2, C6]（DB に書く・受け箱の行とメールを出す）
