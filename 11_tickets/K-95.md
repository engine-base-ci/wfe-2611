## 目的

画面の試験の土台（apps/web/tests/_lib/api.ts の claimBridge・signupViaApi の後の API 呼び出し）が、画面のログインの鍵で node から API を呼ぶ。node の fetch は Playwright の Chromium と user-agent が違うので、セッションの見張り（D-128.120：端末＝ブラウザの種類や OS が変わったら切る）が端末が変わったと見て画面のログインを切り、ログインの画面に戻される。前の「PC をつなぐ」画面の試験 9 本がこれで赤（070 を除く）（K-57・K-60 の取り込みの途中で見つけた。途中で見つけたものはその場で直さずチケットにする・D-128.147）。

## 完了の条件

- [ ] 下の 9 本の試験が緑
- [ ] セッションの見張りそのものは変えていない（守りを弱めない）
- [ ] workflow の全部（act）が緑

## 前提と制約

- 依存：K-57（前の画面が /setup/bridge/legacy にあり、試験がそこを開く形になってから）・K-129（土台の UA の直し。同じ原因の直しは K-129 で 1 回だけ入れる・2026-11-07 PM の判断）
- 赤になる 9 本（hold/k57-k60 の取り込みの回で、ログインの画面に戻されて `[data-state="ok"]`・`[data-connected]` が見つからない）：`apps/web/tests/screens/qa-b-bridge-setup.spec.ts` の SCR-BRIDGE-SETUP-062・SCR-BRIDGE-SETUP-090／091／092・SCR-BRIDGE-SETUP-100・SCR-BRIDGE-SETUP-097／098／099・SCR-BRIDGE-SETUP-101／102・SCR-BRIDGE-SETUP-104・SCR-BRIDGE-SETUP-107・SCR-BRIDGE-SETUP-108・SCR-BRIDGE-SETUP-109（試験の数で 9 本。060・096 は K-96、103 は K-97 の原因。070「この端末を外す」は K-91 が前の画面から消して新しい画面の remove-pc.spec.ts に書き直すので、ここでは数えない）
- セッションの見張りは変えない（D-128.120）
