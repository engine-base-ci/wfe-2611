## 目的

画面の試験の土台（apps/web/tests/_lib/api.ts の claimBridge・signupViaApi の後の API 呼び出し）が、画面のログインの鍵で node から API を呼ぶ。node の fetch は Playwright の Chromium と user-agent が違うので、セッションの見張り（D-128.120：端末＝ブラウザの種類や OS が変わったら切る）が端末が変わったと見て画面のログインを切り、ログインの画面に戻される。前の「PC をつなぐ」画面の試験 10 本がこれで赤（K-57・K-60 の取り込みの途中で見つけた。途中で見つけたものはその場で直さずチケットにする・D-128.147）。

## 完了の条件

- [ ] 下の 10 本の試験が緑
- [ ] セッションの見張りそのものは変えていない（守りを弱めない）
- [ ] workflow の全部（act）が緑

## 前提と制約

- 依存：K-57（前の画面が /setup/bridge/legacy にあり、試験がそこを開く形になってから）
- 赤になる 10 本（hold/k57-k60 の取り込みの回で、ログインの画面に戻されて `[data-state="ok"]`・`[data-connected]` が見つからない）：`apps/web/tests/screens/qa-b-bridge-setup.spec.ts` の SCR-BRIDGE-SETUP-062・SCR-BRIDGE-SETUP-090／091／092・SCR-BRIDGE-SETUP-100・SCR-BRIDGE-SETUP-097／098／099・SCR-BRIDGE-SETUP-101／102・SCR-BRIDGE-SETUP-104・SCR-BRIDGE-SETUP-070・SCR-BRIDGE-SETUP-107・SCR-BRIDGE-SETUP-108・SCR-BRIDGE-SETUP-109（試験の数で 10 本。060・096 は K-96、103 は K-97 の原因）
- セッションの見張りは変えない（D-128.120）

## 実施事項

- [ ] **直し方は 1 つに決める：試験の土台の node からの呼び出しを、画面のブラウザと同じ端末として送る。** `apps/web/playwright.config.ts` の `use.userAgent` に決まった UA（`TEST_UA`・Chromium の UA）を置き、`apps/web/tests/_lib/api.ts` の `api()`・`admin` 以外の口を呼ぶ道具（claimBridge・bridgeBeat・setupStep の前提作りを含む）がどれも `user-agent: TEST_UA` を付けて送る。国の頭（x-vercel-ip-country）も付けない（両方とも同じ）。別のログインを作る案（前提は別のセッションで作る）は、試験の中で人を 2 回ログインさせて遅くなるので採らない
- [ ] 上の 10 本を流して緑を見る。わざと UA を外して赤に戻ることも見る

## テスト仕様と確認の結果

| 確認項目 | 種類 | 判定のしかた | 結果 |
|---|---|---|---|
| 前提を作った後も画面のログインが切れない | ② 結合 | 上の 10 本を流す | |
| 土台の UA を外すと同じ赤に戻る（直した所が原因だった） | ② 結合 | TEST_UA を外して 1 本流す | |
