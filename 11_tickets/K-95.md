## 目的

画面の試験の土台（apps/web/tests/_lib/api.ts の claimBridge・signupViaApi の後の API 呼び出し）が、画面のログインの鍵で node から API を呼ぶ。node の fetch は Playwright の Chromium と user-agent が違うので、セッションの見張り（D-128.120：端末＝ブラウザの種類や OS が変わったら切る）が端末が変わったと見て画面のログインを切り、ログインの画面に戻される。前の「PC をつなぐ」画面の試験 9 本がこれで赤（070 を除く）（K-57・K-60 の取り込みの途中で見つけた。途中で見つけたものはその場で直さずチケットにする・D-128.147）。

（K-129 からまとめた・2026-11-07）同じ原因の詳しい筋：`signupViaApi` で作った人のログインの印（token）を、試験はまず node から使う（`claimBridge`・`startAgentBridge`（apps/web/tests/_lib/agent-bridge.ts）・`api()` に token を渡す呼び出し）。確定の口は端末の印を持たずにセッションを作り、セッションの端末は最初に使われたときに決まる（D-128.137）。そのため端末は node の fetch の user-agent になり、そのあとブラウザで画面を開くと切られる。これで `apps/web/tests/screens/bridge-loop.spec.ts` と `apps/web/tests/screens/qa-a2-chat-errors.spec.ts` の多くも通らない（K-57 で変えていない BRG-03-004 も赤）。K-57 の作業中に見つけた、前からある物。

- [ ] 下の 9 本の試験が緑
- [ ] bridge-loop.spec.ts と qa-a2-chat-errors.spec.ts のうち、この原因で赤だった試験が、ログインの画面に戻されずに進む（ほかの原因で赤のものは、その原因を名指しして別のチケットにする）（K-129 から）
- [ ] わざと土台の user-agent を外すと、同じ赤（ログインの画面に戻される）に戻る
- [ ] セッションの見張りそのもの（packages/auth/src/resolver.ts・app.session_check）は変えていない（守りを弱めない）
