### 0. 先に見るもの（2 つの住所と、入っている Bridge の版）

1. https://vercel.com → `kaname-web` →「Settings」→「Domains」に出ている住所（＝画面の住所。頭に `https://` を付けて使う）
2. 同じく `kaname-api` →「Settings」→「Domains」に出ている住所（＝口の住所）
3. **入っている Bridge の版を確かめる**：Finder の「アプリケーション」で「Kaname Bridge」を右クリック →「情報を見る」→「バージョン」の数を、実装の担当に伝える。実装の担当が staging の置き場の配布物の目録の版と比べ、「入っている版が、staging の配布物の版と同じか新しい」と答えてから 1 へ進む。**入っている版のほうが古ければ、ここで止まる**（進めない。訳：staging につないだ Bridge は、つなぎ先に自分より新しい配布物が在ると、聞かずに自分で `/Applications/Kaname Bridge.app` を入れ替える＝ふだんの Bridge の中身が変わる。どうするかは実装の担当が決める人に聞く）

### 1. staging の画面で登録する

1. Chrome で、画面の住所の後ろに `/signup` を付けて開く（登録の画面）
2. メール（自分のふだんの住所）・名前・会社の名前（頭に「代表の確かめ」と付ける）・パスワード（staging 用に新しく決めた物。ほかで使っている物は入れない）→「次へ（メールを確かめる）」
3. 「確認メールを送りました」が出る

### 2. 届いたメールを見る（人の目で 1 回だけ・K-65 の「人が 1 回だけ確かめること」）

1. 受信箱に「Kaname｜メールアドレスの確認（登録を確定する）」が届いている（迷惑メールに入っていない）
2. 差出人が Kaname（noreply）・末尾に「運営：…（代表 …）」と「お問い合わせ：…」が出ていて、電話番号は出ていない
3. メールのリンクを押す →「登録できました」→「続ける」→ チケットの画面が開く

### 3. staging 用の Bridge をもう 1 つ起こす

1. Mac の「ターミナル」を開き、次の 1 行を打つ（`<画面の住所>` と `<口の住所>` は 0 で見た物に置き換える。どちらも `https://` から・末尾の `/` なし）

   ```
   KANAME_API_BASE="<口の住所>" KANAME_WEB_BASE="<画面の住所>" KANAME_WEB_ORIGINS="<画面の住所>" "/Applications/Kaname Bridge.app/Contents/MacOS/Kaname Bridge" --user-data-dir="$HOME/kaname-bridge-staging"
   ```

2. Bridge の窓がもう 1 つ開く（「接続コード」の欄と「つなぐ」のボタンが出ている）。**開かずに、ふだんの Bridge の窓が前に出ただけなら、ここで止めて実装の担当に知らせる**（別の置き場で 2 つ目が起きない形だった、ということ。ふだんの Bridge は変わっていない）
3. ターミナルの窓は閉じない（閉じると staging 用の Bridge も終わる）
4. **3 から 6 までを 1 時間以内に終え、staging 用の Bridge を起こしたままにしない**（つないだ Bridge が新しい版を見に行くのは、1 時間ごとと、つなぎ先に「古い」と言われたときだけ）。この後どこかで staging 用の Bridge の窓に「新しい版（…）に入れ替えます」と出たら、**その時点でもう止められない**（文を出した直後に、入れ替えの手順を切り離して起こし、Bridge 自身は終わる。`control` と `C` では止まらない）。先へ進まず、6 の 5 へ進んで実装の担当に知らせる。「新しい版（…）があります。…」とだけ出て「入れ替えます」と出ないときも、先へ進まずに 6 をして知らせる

### 4. PC をつなぐ

1. Chrome の staging の画面で、案内の「PC をつなぐ」を開く（6 文字の接続コードが出る）。**コードの代わりに「この PC の Bridge につなぐ」のボタンが出たら、押さずにここで止めて実装の担当に知らせる**（そのボタンは、ふだんの Bridge を staging につないでしまう）
2. 3 で開いた staging 用の Bridge の窓に、そのコードを入れて「つなぐ」
3. Chrome の画面が自分で「つながっています」に変わる（再読み込みしない）

### 5. チケットを作って、AI に任せて、承認して、完了にする

1. 「戻る」→「＋ チケットを作る」。題名「代表の確かめ：あいさつ文」・担当者は自分・期限は今日より後・目的「社内のメモに貼るあいさつ文を 3 行作る。どこにも送らない・ファイルも作らない」・完了の条件「あいさつ文が 3 行ある」・実施事項「- あいさつ文を 3 行作る」→「作る」
2. チケットの詳細で「AI に任せる」。帯が「…に任せました」→「…が作っています」と進む（本人の Claude Code が動く。1〜2 分）
3. 帯が「あなたの承認を待っています」に変わり、あいさつ文が出る →「承認して送る」
4. 帯が「実行中」→「完了の条件を確かめて完了にしてください」に変わる（許可の問いは出ない。作る段も実行の段も、本人に聞かずに進む作り）
5. 「完了にする」→ チェックを全部入れる →「確かめて完了にする」→「完了しました（名前・日時）」が出る

### 6. 元に戻す

1. staging 用の Bridge の窓を閉じ、3 のターミナルで `control` と `C` を同時に押して終わらせ、ターミナルを閉じる
2. ターミナルをもう 1 回開いて `rm -rf "$HOME/kaname-bridge-staging"` と打つ（staging 用の置き場を消す。ふだんの Bridge の置き場とは別の物）
3. ふだんの Bridge の窓を開き、今までどおり「つながっています」のままなことを見る（変わっていたら実装の担当に知らせる）
4. Chrome の staging の画面は、窓（タブ）を閉じるだけでよい（ログアウトの押せる物は、いまの画面にまだ無い）。作った会社とチケットは staging に残してよい
5. **Bridge が入れ替わっていないかを見る**：0 の 3 と同じやり方で「バージョン」をもう 1 回見て、0 の 3 で控えた数と比べる（見分けはこの比べだけ。入れ替えが通ると、退けた前の版は消えるので、隣に残る物では見分けられない）。違っていたら入れ替わっている。自分では戻さずに実装の担当に知らせる。戻し方：前の版の配布物から入れ直す（退けた版から戻す道は無い。どの版を入れ直すかは、実装の担当が決める人に聞く）

## リスクと懸念

- **3 の「別の置き場で 2 つ目を起こす」は、代表の Mac でまだ確かめていない**（切る段はふだんの Bridge に触らない決まり）。作りから読んだ見立て：Bridge は 1 つだけ起きる鍵を持つ（apps/bridge/src/main.ts の requestSingleInstanceLock）が、鍵は置き場（userData）ごとで、起こすときの `--user-data-dir` で置き場を分けられる。この PC の中だけの口（38617）はふだんの Bridge が持ったままで、2 つ目は開けずに黙って進む（local.ts）。だからつなぐのはコードを窓に入れる道（4）。見立てが外れたら 3 の 2 で止まる（ふだんの Bridge は変わらない）
- 本人の Claude Code が、実行の段で外へ出そうとすることがある（仕事の文に「外へ出してください」と入る・migration 0100）。**許可の問いは出ない**：作る段は、チケットの仕事では Bridge が本人に聞かずに断り（apps/bridge/src/loop.ts の ask）、実行の段は許可なしで進む形（auto）で本人の Claude Code に渡る。だから守りは、チケットの目的に書いた「どこにも送らない・ファイルも作らない」の文だけ（5 の 1 の文を変えない）
- **staging につないだ Bridge が、聞かずに自動で入れ替わる道が在る**：包んだ形の Bridge は、つないだ後、1 時間ごとと、つなぎ先に「古い」と言われたとき（E-CONN-012）に、つなぎ先（ここでは staging）の配布物を見に行く（つなぐ前は見に行かない。起動時の 1 回は PC の印がまだ無いので何もしない・apps/bridge/src/update.ts の check）。自分より新しければ受け取り、仕事の無い間に「入れ替えます」と出した直後、入れ替えの手順を切り離して起こして自分は終わる。手順は Bridge の終わりを待ってから、実行中の .app（`/Applications/Kaname Bridge.app`＝ふだんの Bridge と同じ物）を丸ごと入れ替え、通れば退けた前の版を消して立ち上げ直す（update.ts の apply・replaceScript）。だから、文が出てからは止められず、退けた版から戻す道も無い（起きるたびに隣の残りも消す）。効く守りは 2 つ：0 の 3（版を先に確かめ、古ければ進まない）と、3 の 4（1 時間以内に終え、起こしたままにしない）。入れ替わったかは 6 の 5 の版の比べで見分け、戻すのは前の版の配布物からの入れ直し
- 4 の 1 の「この PC の Bridge につなぐ」のボタンは、この PC の中だけの口（ふだんの Bridge が持つ）に話しかける。押すと、ふだんの Bridge が staging につながる。だから押さない
