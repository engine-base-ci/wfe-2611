## 目的

詳細と作る面の「項目の表」に、会社が足した項目を、用意してある項目と同じ表に同じ形で並べる（D-150.36・D-150.37）。この葉は **表と読む口と、分類の軸からの移し**まで（マスタを作る・直す口と画面は段 10・値を書く口は K-564・K-437）。

- **表 3 つ**（新設）：`custom_fields`（会社の項目：名前・型・必須・説明・選択肢・並び）・`custom_field_kinds`（どの種別で出すか。行が無ければ全部の種別）・`ticket_field_values`（チケットごとの値）
- **読む口** `listTicketFields`（GET /api/v1/ticket-fields?kind_id=<uuid>）：その種別で出す項目を並びの順に、必須・説明・型・選択肢つきで返す。読めるのはワークスペースのメンバー（読むだけの人も、チケットが見えない人も。マスタを読む口なので `listTicketKinds` と同じ線）
- **分類の軸の移し**（D-150.46）：`class_axes`（作り付けでない物）を「1 つ選ぶ」の項目に、`class_values` を選択肢に、`ticket_class_values` を `ticket_field_values` に移す。3 つの表は**凍結**（消さない・コードが読まない）。作り付けの軸 `priority`（優先度）は移さない（優先度は `tickets.priority` の列）。`handover_rules.axis_id`（段 9 の渡すの決まり）は触らない
- **`listClassAxes`（GET /class_axes）は外す**。道・契約・生成の試験・目録の行をなくす

値の形（K-564・K-437 が書き、K-569 が読む。この葉の表の約束）：`ticket_field_values.value` は jsonb で null でない。型ごとに 短い文字・長い文章＝文字／数＝数／日付＝`YYYY-MM-DD` の文字／1 つ選ぶ＝選択肢の id の文字／複数選ぶ＝選択肢の id の文字の配列／チェック＝真偽。**値の形と必須・選択肢に在るかの確かめは書く口（K-564・K-437）が持つ**。この葉の表は null だけ断る。

## 前提と制約

分類: CRUD, LIST, PERM

- **口は 1 本・新しい専用の答え**。入力は問い合わせ `kind_id`（uuid・任意）だけ。cursor・limit は入口の共通の形の確かめだけで、全部を返す。並べ替え・絞り込みは `kind_id` 以外受けない
- **断る番号**（控え帳：422＝契約に書ける形の誤りだけ／404＝無い・見えない／409＝今の状態ではできない）：`kind_id` が uuid の形でない → 番号なしの **422・VALIDATION_ERROR**（欄 `kind_id`・入口の共通の確かめ。K144-API-530）／種別が無い・消された・別の会社 → **404**（体は `{ error, code }` だけで `field`・`details`・`detail` を付けない）／ログインなし 401。この口は 403・409 を返さない
- **種別の絞り込み**：`kind_id` があれば、その種別の行（`custom_field_kinds`・消していない）がある項目と、種別の行が 1 つも無い項目（全部の種別に出る）を返す。`kind_id` が無ければ消していない項目を全部返す
- **並び**：`position` の昇順・同じなら作った順（`created_at`）・`id`。消した項目（`deleted_at`）は出さない。選択肢は `options` の中の `position` の順
- **答えの形** `TicketField = { id, name, field_type, required, description, options, position }`（鍵ちょうど 7）。`options` は選ぶ型（select・multi_select）だけ `[{ id, name, position }]`、ほかの型は `[]`。`description` は文か null。会社の id・作った人・時刻は出さない
- **型は 7 つ**：`short_text`・`long_text`・`number`・`date`・`select`・`multi_select`・`check`（D-150.37）
- **項目の数に上限は置かない**（D-130.1。前の軸は 5 まで・今回は決まっていない）。選択肢の数にも置かない。名前は空白（全角・タブを含む）を除いて 1〜40 字（同じ会社の消していない物で一意）。説明は空白だけでなければ長さの上限なし
- **移しは migration の中で 1 回・DB の関数 `app.custom_fields_move_axes` が持つ**（何度流しても増えない。試験が同じ関数を直に呼ぶ）。項目の id は軸の id・選択肢の id は値の id・値（select）は選択肢の id の文字 — だから**段 9 の `handover_rules.axis_id` は項目の id としてそのまま読み替えられる**（付け替えは要らない）
- **移す物と移さない物**：作り付けでなく消していない軸だけ／消した値は選択肢にしない／値の行は、消していない行で値が消していない物だけ（消したチケットの値も写す）。同じ軸に 2 つ付いていた物（古い表は 1 つに絞っていなかった）は、最初に付けた 1 つだけ写す（1 つ選ぶは 1 つ）。種別の行は作らない（全部の種別に出る）。必須にはしない
- **凍結の印**：`03_architecture/db-catalog.json` の `class_axes` を `skeleton` から `frozen` に（理由「会社が足す項目に移した（K-563・D-150.46）。コードは使わない」）。`class_values`・`ticket_class_values` は前から `frozen`。新しい 3 つの表は `skeleton`（読む口が使う）で、理由を書く。凍結の表を `apps/*/src` が使い始めると CI（flow_db_gate の FD3）が赤にするので、`routes/class_axes.ts` と `hooks` の参照をこの葉で消す
- **行の守り**（`05_flow/rls_policies.py` → `gen_rls.py`）：`custom_fields`・`custom_field_kinds` は `workspace_master`（メンバーは読む・直せるのは `custom_fields` の edit を持つ人）／`ticket_field_values` は `child_of_ticket`（元のチケットを読める人が読み、書ける人が書く）。権限の資源名 `custom_fields` を `target_kinds` に足し、管理者の束に入れる（`app.refresh_role_bundle_defaults()` と全員の `app.apply_role_bundles` を migration の最後で呼ぶ・0080 の決まり）
- 外へ出ない：メールも知らせも出さない。AI も PC も呼ばない
- ログに項目の名前・説明を出さない（会社の id と例外の種類だけ）
