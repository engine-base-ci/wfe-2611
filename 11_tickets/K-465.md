## 目的

外枠（左のメニュー・上の帯・PC の表示）が、今は 4 本の口（`me`・`listScopes`・`listApprovalQueue`・`listMyDevices`）を別々に読んでいる（`ticket-shell.tsx`）。1 画面で口を増やさず 1 本にまとめる（D-128.111・PM の決め P8）ために、契約の口 `getShell`（GET /api/v1/shell）を作る（今は 501）。この葉は **口だけ（apps/api だけ）**。外枠をこの口につなぎ替える画面は K-466。

答え `Shell` の鍵はちょうど 9 個（契約の 7 個に `member` と `saved_views` を足す。`member` は今の `me` の口が答えていた自分の名前と役を外枠が別の口なしで読めるように、`saved_views` は左のメニューの保存した条件の並びを口を増やさず出すため・K-479）：

| 鍵 | 中身 |
|---|---|
| `member` | `{ id, name, role_id }`（自分。`me` の口が返していた分） |
| `workspace` | `{ id, name }`（今の会社。名前は前後の空白を取る。空なら null） |
| `approvals_waiting` | 整数。`app.approval_queue_count()` の答えそのまま（段 9 の K-405 が渡しを足して直しても、同じ関数を使い続ける） |
| `notifications_unread` | 整数。K-461 の一覧に出る未読の数（一覧と同じ文 `UNREAD_COUNT_SQL`） |
| `groups` | `[{ id, name, ticket_prefix, writable, open_count }]`。自分に見えるグループ（作った順）。`open_count`＝そのグループとその下のグループの、完了でない・消していない・自分に見えるチケットの数。**星付き・並べ替えの欄は作らない**（P9・口も表も契約に無い） |
| `pc` | `{ connected, count }`。アカウント全体の PC：つながっている物があるか・外していない台数 |
| `setup_left` | 整数。はじめにやることの残り（K-250 の数え方・使えない物・飛ばした物・済みの物・箱を閉じた後は数えない） |
| `banner` | `{ incidents, maintenance }`。`app.public_service_status()`（0105・K-307）の答えそのまま（直っていない障害と今中のメンテナンス。運営の本文・メモは出ない） |
| `saved_views` | `SavedView[]`。保存した検索条件（自分の物と、見えるグループの全員向けの物。名前の順・消した物は出ない・500 行まで）。**K-475 の `listSavedViews` と同じ読み方・同じ 13 個の鍵**（`id`・`name`・`share`・`scope_id`・`filters`・`columns`・`density`・`member_id`・`member_name`・`mine`・`can_edit`・`created_at`・`updated_at`）。**契約では任意の鍵**（`saved_views?: array`。外枠の答えの 8 鍵だけを返す古い画面・試験の答えも読めるように。口は毎回この鍵を付ける） |

## 前提と制約

分類: PERM

- **1 つの取引・文は 4 つ**（本人・会社・承認待ち・PC・帯・はじめにやること／グループと件数／未読の数／保存した条件）。どれかが失敗したら全体が 503・E-PAGE-003（部分の答えは返さない）。外枠は今は「失敗した部分を出さないだけ」だが、1 本にまとめたので、失敗は 1 つの失敗として画面（K-466）が扱う
- 承認待ちの数は `app.approval_queue_count()` をそのまま呼ぶ（新しく数え直さない）。未読の数は K-461 の `UNREAD_COUNT_SQL`（一覧と数がずれない・メールの印の行・知らない種類・見えないチケットの行は数えない）
- グループは行の守り（scopes・tickets の RLS）の上で読むので、見えないグループは出ず、件数にも漏れない。件数は「そのグループの下のグループ」も含める（一覧でそのグループを選んだときの件数と同じ・K-92 の `scope_id` と同じ数え方）。完了の段（key が done）・消したチケット・他人の下書きは数えない。`writable` は tickets の edit を持つか（今の `listScopes` の `meta.writable` と同じ判定）
- PC は `app.bridge_devices(自分)`（アカウント全体・外した PC と消した PC は出ない）の `state` が live の物があれば connected。`count` は外していない台数（まだ一度もつながっていない waiting も 1 台に数える）
- はじめにやることの残りは、K-250 の数え方を使い回す：`apps/api/src/features/F4/setup-tasks/hooks.ts` の `STATE_COLS`（本人の状態の列）・`StateRow`・`toItems` を export し、`setupLeft(state)`（箱を閉じていれば 0・そうでなければ「使える・済みでない・飛ばしていない」項目の数）を足す。口の答え（listSetupTasks）は変えない
- 本人の行が無い（今の会社のメンバーでない）ときは 403 FORBIDDEN（K-250 と同じ）。取引先の人・運営の人は 403（契約の auth が member・取引先の外枠は F11・P11）
- 契約の `Shell` に鍵を 2 つ足す（`member`・任意の `saved_views`）。契約の説明（PERMS の getShell）の「星を付けたグループの件数」は外す（星は作らない・P9）。契約の変更は `05_flow/screen_api.py` 本体の前からある行（RESPONSES の getShell と PERMS の getShell）を直す（段 8 でこの行を持つ葉はこの葉だけ）
- 口の登録は葉ごとの hooks のファイル（K-326）。この葉は `apps/api/src/hooks/shell.ts`
