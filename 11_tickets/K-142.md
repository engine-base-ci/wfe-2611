## 目的

操作の実証の検査 G48（`scripts/ci/op_gate.py`・v3-gate.yml の G48 の段）は、結果が空の行を「未実施」で赤にする（O2）。ところが見るのは、実ブラウザで確かめる観点の集合（`DEFAULT_VIEWS`：操作・状態・主アクション・到達性 など、または op-gate.json の evidence_views）に入る行だけで、分岐の 8 観点のうち「守り」「失敗」「操作の揺れ」の行は、結果が空でも赤にならない。K-60 では、この観点の行が 8 行、結果が空のまま検査を通った。書いた行を流したかどうかを見ていないのと同じ（書いていない＝漏れ・ai-driven-process.md §4）。K-60 の実装の役が見つけた（2026-11-07）。途中で見つけたものはその場で直さずチケットにする（D-128.147）。

## 完了の条件

- [ ] 仕様の全部の観点の行で、結果が空なら赤（未実施）にする。BLOCKED は理由が無ければ赤（今の O2 と同じ）
- [ ] 実ブラウザの証拠（行 ID の Playwright の試験が passed）を求める観点と、API の層の証拠（本物の DB の vitest の報告）でよい観点を分けて決め、op-gate.json に書く（「守り」「失敗」の行の多くは口の試験で受ける）
- [ ] 今の仕様（07_qa/test-specs/k）でこの直しを当てたときに赤になる行を一覧にし、どのチケットの行かを書く（直すのはそれぞれのチケット・このチケットでは結果を書き込まない）
- [ ] 検査の自己試験で、観点「守り」「失敗」「操作の揺れ」の行の結果を空にすると赤になる
- [ ] チケットの CI（act）が緑

## 前提と制約

- 検査は作った時点で CI に並べる（D-095）。今の G48 の段の中で直す
- 結果の欄を検査が書き換えない（流した人が書いた記録を消さない）
- この直しで今ある取り込み済みのチケットの行が赤になるなら、その行の持ち主のチケットに直しを書き、取り込みを止めるかどうかは決める人に聞く（D-128.147 ②）

## 実施事項

- [ ] 作る役：仕様の行の観点の種類を全部数え、どの観点がどの証拠で受けるかの表を作る
- [ ] 作る役：分岐（結果が空・PASS で証拠なし・BLOCKED で理由なし・N/A・観点の名前の表記ゆらぎ）と検査の自己試験の行
