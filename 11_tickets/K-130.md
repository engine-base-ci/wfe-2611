## 目的

流れ F3「使い始めの準備」の行為「PC をつなぐ」（A09）の画面 bridge-setup。K-57 で作った新しい画面（apps/web/app/(wizard)/setup/bridge/page.tsx → apps/web/features/F3/connect-pc/）には、Bridge の自己診断で「Bridge が新しい」が ✗（fix=update）のときの表示（「つながっていますが、Bridge が古いので仕事を渡せません」）と、入れ直す受け取り口（`[data-bridge-reinstall]` の macOS 版・Windows 版）が無い。前の画面（/setup/bridge/legacy）にはある。

会話の帯の「Bridge が古い」（E-CONN-012）の一手「PC の状態を見る」は /setup/bridge（新しい画面）へ行くので、行った先に入れ直す道が無い。試験 E-CONN-012-C・SCR-BRIDGE-SETUP-105／106（apps/web/tests/screens/qa-a2-chat-errors.spec.ts）は、いまは前の画面を開き直して確かめている。

根拠の決定：
- D-090：Bridge の自己診断は Kaname に送って画面に出す。つながっただけでは仕事は流れないことを画面に書く（古い Bridge には仕事を渡さない）
- D-109：Bridge が自分で入れ替えられないときは、入れ替えず「新しい版があります。入れ直してください」と受け取り口を案内する
- D-128.150：前の画面の 3 つの機能（Claude Code を入れる K-89・ブラウザを選ぶ K-90・端末を外す K-91）は F3 のチケットにしたが、この「Bridge が古い」の表示はどのチケットにも入っていなかった

K-57 の作業中に見つけた、前からある物（途中で見つけたものはその場で直さずチケットにする・D-128.147）。

## 完了の条件

- [ ] 新しい画面が、つながった PC の自己診断で「Bridge が新しい」が ✗ のとき、理由（古いので仕事を渡せない・書いたことは溜めておき入れ直した後に順に片づける）と、入れ直す受け取り口（macOS 版・Windows 版）を出す。新しい Bridge なら出さない
- [ ] E-CONN-012-C・SCR-BRIDGE-SETUP-105／106 が、前の画面を開き直さずに、帯の一手から行った新しい画面の上で緑

- [ ] チケットの CI（act）が緑
