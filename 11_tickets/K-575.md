## 目的

段 5 で本文が「自由な 1 枚の文書」になった（D-150.35・D-150.50）ので、**今ある（前の形の）チケットの区画の中身を 1 枚の本文に移す**（D-150.58：区画の順に「見出し＋中身」を 1 枚にまとめる・実施事項のチェックは本文のチェックの箱になる・前の版は残す）。これで本線・staging にあるチケットが、新しい詳細（本文を読む形）・AI に任せる（本文から中身を組む）・完了の数え方（本文のチェックの箱）で読める。

- 内側の関数 `app.ticket_body_move(p_tenant uuid) returns jsonb` を作り、migration の最後に全部の会社へ呼ぶ。**何回流しても同じ結果**（もう本文の行があるチケットは触らない）。答え `{moved: 移したチケットの数, skipped: 上限を超えて移せなかったチケットの数}`
- **チケットごとに**、区画（`ticket_sections`・鍵が `body` と `artifacts` でない・消していない）を `position`・鍵の順に並べ、中身が空白だけの区画は飛ばし、残りを次の形の 1 枚の本文（文書の木 `doc` と、それから作る `text`）にする。**全部の区画が空のチケットには本文の行を作らない**
  - **見出し**：区画ごとに 1 つ（level 2）。名前は 自由欄（鍵が `free` か `free_` で始まる区画）は区画の本文の `label`・ほかは そのチケットの種別の `kind_sections.label`・どちらも無ければ鍵のまま
  - **中身**：区画の `content_type`（`kind_sections` の物・無ければ text）で作る。`checklist`＝各行を「チェックの箱」（行頭が「- [x] 」「- [X] 」なら済み・「- 」か何も無ければ未チェック。箱の字は印と行頭の「- 」を除いた字）／`bullets`＝箇条書き（行頭の「- 」を除く）／それ以外（text・table）＝行ごとに段落。行は前後の空白を落とし、空の行は飛ばす
  - **text**：`docToText` と同じ規則（K-561 の K561-DOC-001：見出しと段落は 1 行・箇条書きは「- 」・チェックの箱は「[x] 」「[ ] 」・節どうしは改行でつなぐ）。**DB が text を作るのはこの移しだけ**（口は K-437・K-432 が `docToText` で作る）。**K-561 の決め（SQL に doc → text を書かない・L-002）の、この葉だけの例外**：移しは区画を SQL でしか読めず、1 回の migration で口を通らないので、口の `docToText` を呼べない。だから SQL が doc と text を同じ規則で組む。SQL が作る text は `docToText` の規則に合う形（見出し・段落・箇条書き・チェックの箱だけ）に限る。2 つの実装がずれないよう、試験が移した全部の行で `docToText(doc) = text` を突き合わせる（K575-DB-014）。**ずれたら正は K-561 の `docToText`**（SQL 側を直す）
- **書く物**：本文の行（`ticket_sections`・鍵 `body`・位置 0・版 1・`{doc, text}`・`created_by`／`updated_by` はチケットを作った人）と、版の行（`ticket_section_versions` の版 1・同じ中身・`edited_by`＝その区画のうち最後に直した人〔`updated_at` の新しい方〕・`edited_by_clone` false・`restored_from` 空）。**元の区画の行は消さず `deleted_at` を入れる**（版の行・中身は触らない）。`tickets` の列（`updated_at` も）は変えない。やり取りの更新の行・証跡・お知らせは書かない（機械の移しで、利用者の操作ではない）
- **移さない物**：鍵 `artifacts`（AI に任せた結果の置き場。K-560 の「結果の場所」が読む）・鍵 `body`。**決定ログ・申し送り・テスト仕様の区画（鍵 `decisions`・`handoff`・`tests`）は移す**（中身を失わないため。下の「代表に聞くこと」1）
- 消したチケット・完了したチケットも移す（戻したとき・読み返すときに読めるように）。別の会社には触れない（会社ごとに呼ぶ）
- **本文が 1MB を超えて移せないチケット**（`app.ticket_body_valid` が通らない）は、**区画のまま残して `skipped` に数える**（本文の行を作らず、元の区画も触らない）。次の葉（案 K-578）が区画を読む道を消す前に 0 件であることを確かめる

## 前提と制約

分類: CRUD

- 関門は C2（DB に書く）。口は作らない（`apis: []`）。関数は誰にも execute を渡さない（`revoke all from public`・`kaname_app` にも渡さない・migration と管理者の接続だけが呼ぶ・K-563 の `app.custom_fields_move_axes` と同じ置き方）。`security definer`・`search_path` に `pg_temp`
- **本文の行の形の守り `ticket_sections_body_ok`（K-561）と、行の唯一性 `unique (ticket_id, section_key)` に当たる**：すでに鍵 `body` の行があるチケットは（生きていても消していても）触らない。そうでなければ同じ鍵の行を足せない
- 空白は `btrim` の明示の文字クラス（全角の空白・タブ・改行を含む `E' \t\r\n　'`）で落とす（K-563 の項目の名前と同じ落とし方）。改行は `\r\n` を `\n` にそろえてから分ける
- 見出しの level は 2（K-561 の `validateDoc` が通る level は 2・3）。節の数に上限は無い（つなぎで決まった。`app.ticket_body_valid` の上限は大きさ 1,048,576 バイトだけ）。大きさの上限に当たったチケットは区画のまま残す（上の「skipped」）
- チェックの印の定義は K-438 の `uncheckDoc`（本文の木の `taskItem` の `attrs.checked`）と同じ物を使う（済み＝真偽の `true`）
- 移した本文の text は、画面（K-571）が出す素の文字と K-565（AI に渡す中身）・K-566（未チェックの数）が読む物と同じ形になる。K-566 の数え方は文書の木の `taskItem` の `attrs.checked` が `true` でない数なので、移した箱が数えられる
- ログ・証跡に本文を出さない（移しは 1 つの SQL の中で終わり、ログに何も出さない）
- 外のサービス・メール・PC は呼ばない。PC をつなぐ前でも流れる

## 依存の理由

- K-561: 要る — 本文の行の置き場（鍵 `body`・`{doc, text}`・形の守り）と `app.ticket_body_valid`・文書の木の型。移し先がこれ
- K-437: 要る — 作る口が区画を送らなくなる（口は必ず `body` で作る）。これが入る前は新しいチケットが区画を持つので、移した後に区画のチケットが増える
- K-438: 要る — 複製が本文の行の在るチケットの本文だけを写す（区画は読まない）。移しの後は全部のチケットが本文の行を持ち、複製の「本文の行が無い元」の道が消える。`uncheckDoc` の「箱の印」の定義を使う
- K-560: 要る — 読む口が本文（`body`）と結果の場所（`artifacts`）を新しい形で返す。これが入る前に移すと、前の画面が区画を読んで空に見える
- K-565: 要る — AI に任せる関数が本文の行の在るチケットの本文から中身を組む（確認項目 0 件の止め方も本文の行の在るチケットだけに効く）。移した後は全部のチケットに効く
- K-566: 要る — 完了の数え方が本文のチェックの箱（本文の行が在るとき）。移した後は実施事項の区画でなく本文の箱で数える
- K-442・K-571・K-572: 要る — 作る面・詳細・完了の小窓が区画を読まなくなる画面の葉。区画の行は `deleted_at` で消えるので、画面が古い鍵（`sections`）を読んだままだと空に見える。画面が古い鍵を読まなくなってから移す
