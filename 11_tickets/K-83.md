## 目的

顧客に触らせる前に、本番の DB・置き場・資格情報の預け先・API・画面を staging と同じ手順で作る。本番はスモークだけ（D-128.144）。

## 完了の条件

- [ ] Supabase の本番プロジェクト（Pro）
- [ ] Infisical の prod 環境と本番用の Machine Identity
- [ ] staging の Machine Identity（`kaname-api-staging`）を Staging だけに絞る。2026-11-08 の K-79 では、Infisical の無料の枠で役割を環境ごとに絞れず（自分の役割・Folder Access は有料）、決める人の判断で Member のまま進めた（Production にはまだ秘密が無い）。本番の秘密を入れる前に、有料の枠で Folder Access を使うか、プロジェクトを環境ごとに分けて、staging の鍵が本番に届かない形にする
- [ ] Vercel の本番の環境変数（Pro）
- [ ] 本番のスモークが緑
- [ ] 運営の最初の 1 人を本番でも作った：K-1002 の実施事項 1〜5（命令 ops:first を 1 回流し、届いたメールのリンクでパスキーを付けて運営の場所に入れる）を本番で流した。顧客に触らせる前に（D-156.22）
