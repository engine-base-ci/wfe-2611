## 目的

画面の試験の土台 `signupViaApi`（apps/web/tests/_lib/api.ts）で作った人のログインの印（token）を、試験はまず node から使う（`claimBridge`・`startAgentBridge`（apps/web/tests/_lib/agent-bridge.ts）・`api()` に token を渡す呼び出し）。確定の口は端末の印を持たずにセッションを作り、セッションの端末は最初に使われたときに決まる（D-128.137）。そのため端末は node の fetch の user-agent になり、そのあとブラウザ（Playwright の Chromium）で画面を開くと、セッションの見張り（D-128.120：端末＝ブラウザの種類や OS が変わったら切る）が「端末が変わった」と見て切り、ログインの画面に戻される。

これで `apps/web/tests/screens/bridge-loop.spec.ts` と `apps/web/tests/screens/qa-a2-chat-errors.spec.ts` の多くが通らない（K-57 で変えていない BRG-03-004 も赤）。K-57 の作業中に見つけた、前からある物（途中で見つけたものはその場で直さずチケットにする・D-128.147）。

## 完了の条件

- [ ] 土台が node から呼ぶときも、ブラウザと同じ端末の印（user-agent）で送る。土台の中で token を使う呼び出しがどれも同じ 1 つの決まった値を使う
- [ ] bridge-loop.spec.ts と qa-a2-chat-errors.spec.ts のうち、この原因で赤だった試験が、ログインの画面に戻されずに進む（ほかの原因で赤のものは、その原因を名指しして別のチケットにする）
- [ ] わざと土台の user-agent を外すと、同じ赤（ログインの画面に戻される）に戻る
- [ ] セッションの見張り（packages/auth/src/resolver.ts・app.session_check）は変えていない（守りを弱めない）
- [ ] チケットの CI（act）が緑

## 前提と制約

- **K-95 と同じ原因・同じ直し方。直しはこのチケットで 1 回だけ入れる**（2026-11-07 PM の判断・L-008：2 つのチケットで同じ所を別々に直さない）。直し＝playwright.config.ts の `use.userAgent` に決まった UA `TEST_UA`（ブラウザと同じ）を置き、apps/web/tests/_lib/api.ts ほか土台の node からの呼び出し（`api()`・`admin` 以外の口を呼ぶ道具：claimBridge・bridgeBeat・startAgentBridge などの前提作りを含む）も同じ UA で送る。別のログインを作る案（前提は別のセッションで作る）は、試験の中で人を 2 回ログインさせて遅くなるので採らない（K-95 から移した）。K-95 は depends_on にこのチケットを持ち、この直しの上で前の画面（/setup/bridge/legacy）の試験 qa-b-bridge-setup.spec.ts の 9 本を通すだけにする
- K-95 は K-57 に依存する（前の画面が /setup/bridge/legacy に移ってから）。このチケットは前の画面に頼らないので、依存は置かず先に進める
- **K-128 との重なり**：K-128 は登録の画面を通って人を作る道具 newcomer.ts（K-58）に、K-54 の試験の中の登録の手順を寄せる。newcomer.ts はブラウザでログインするので、この問題は起きない。このチケットは API で人を作る signupViaApi の側で、直す所は重ならない（どちらもどちらに依存しない）。signupViaApi を newcomer.ts に置き換える案は、試験 1 本ごとに画面の登録を通して遅くなるので採らない
- 国の頭（x-vercel-ip-country）は土台もブラウザも付けない（両方とも同じ）
- bridge-loop.spec.ts・qa-a2-chat-errors.spec.ts は、いまどのチケットの tests: にも属していない。試験の持ち主は切るときに決める（G53）
