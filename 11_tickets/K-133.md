## 目的

Bridge の配布物は置き場（Supabase の S3 互換）に置く。入れ物（インストーラーの本体）は非公開にし、受け取りは置き場の仕組みの期限つき署名 URL で渡す（D-128.153・D-128.160）。K-57 のテスターが「目録 kaname-bridge.json だけ公開・入れ物は非公開の範囲が、プロビジョニングのコードで作られていない（手で設定すると staging と本番で食い違い、作り直すと消える・G-11）」と見つけた。

切る段で調べて、作り方を変えた（PM の判断 2026-11-10）：
- 目録を読むのは API だけ（apps/api/src/auth/bridge-release.ts の readManifest・releaseState）。Bridge 本体は置き場を直に読まない（git grep で確かめた・下の search）
- 置き場は公開・非公開をバケット単位で決める（1 つのファイルだけ公開は素直に作れない）
- だから **目録も入れ物と同じく署名 URL で読み、置き場の中身は全部非公開にする**。公開の範囲を作る必要が無くなる。provision は「作る（冪等）」に加えて「非公開であることを確かめ、公開なら止める」をする

## 完了の条件

- [ ] API は目録を、関門 C4 の署名（signExternal と同じ置き場の仕組み・期限 60 秒）で読む。署名を作れない置き場（置き場の外の URL）だけ署名なしで読む（K133-API-001〜005）
- [ ] `pnpm provision:bucket` が冪等に置き場を作り、署名なしの読みが断られること（非公開）を確かめて出力に出す。公開なら失敗で止まる（exit 1）（K133-CI-001〜005）
- [ ] 本番と同じコードで staging に作る（D-097・Build Command の `pnpm db:migrate && pnpm provision:bucket`）。手で置き場の画面から設定しない
- [ ] 前からの K-57 の試験（connect-pc・bridge_release）が緑のまま
- [ ] チケットの CI が緑（取り込みの CI で見る）

## 前提と制約

- 依存：K-78（staging の Supabase と置き場の接続）。staging をそろえる K-37 はこのチケットに依存する
- 置き場は関門 C4（packages/storage）を通す。生の S3 の呼び出しを関門の外に書かない。provision の確かめの署名なしの読みは、置き場の公開の読みの口に当てる確かめで、関門の中（packages/storage/src/s3.ts）に置く
- 鍵の値はチャット・ファイル・コミットに書かない（infra/STAGING.md §1）
- 確かめの先：Supabase の S3 の口（…/storage/v1/s3）なら公開の読みの口（…/storage/v1/object/public/<バケット>/<鍵>）。ほかの S3 互換（MinIO・試験の偽の S3）は <口>/<バケット>/<鍵>

## 実施事項

1. `packages/storage/src/s3.ts` に足す：
   - `bucketPublicUrl(endpoint, bucket, key): string`（上の確かめの先の形）
   - `checkBucketPrivate(endpoint, bucket, fetchImpl = fetch): Promise<"private" | "public">`：鍵は `kaname-bridge.json`。署名なしの GET が 400・401・403 なら private、200・404 なら public（404 は「在る無しを答える」＝公開の読みが通っている）。届かなければ例外のまま投げる
   - `packages/storage/src/index.ts` から出す
2. `infra/provision/bucket.ts`：ensureBucket の後に checkBucketPrivate。出力に `[provision bucket] <バケット> @ <口>: <created|exists>・private` を出す。public なら「置き場が公開になっています。置き場の画面でバケットを非公開に戻す」を出して exit 1
3. `apps/api/src/auth/bridge-release.ts`：readManifest と releaseState の設定に `sign?: (name: string, ttlSeconds: number) => Promise<string | null>` を足す。base の目録は `sign(MANIFEST, 60)` の URL で読む。null のときだけ `${base}/${MANIFEST}` を署名なしで読む（今の形）。1 分の覚え・unreachable と none の分け方は変えない
4. `apps/api/src/features/F3/connect-pc/hooks.ts` の releaseState の呼び出し 2 か所（:174・:198）に、`d.objects.signExternal(ctx, d.release.base, name, ttl)` の url を返す sign を渡す（denied・failed は null）
5. `apps/api/test/fake-s3.ts` の先頭の注（「目録だけは署名なしで読める」）を「public を付けた物だけ署名なしで読める（K-133 からは目録も署名つき）」に直す（試験の土台の注だけ・振る舞いは変えない）
6. `infra/STAGING.md` の置き場の手順に「バケットは非公開のまま（公開にしない）。provision が確かめて、公開なら止まる」を 1 行足す

```search

  cmd: git grep -n -F 'fetch(`${base}/${MANIFEST}`' -- apps/api/src

- name: 目録を読む口（定義 2・hooks.ts の呼び出し 2＝sign を渡す所）

```
