## 目的

Bridge の配布物は置き場（Supabase の S3 互換）に置く。入れ物（インストーラーの本体）は非公開にし、受け取りは置き場の仕組みの期限つき署名 URL で渡す（D-128.153・D-128.160）。K-57 のテスターが「目録 kaname-bridge.json だけ公開・入れ物は非公開の範囲が、プロビジョニングのコードで作られていない（手で設定すると staging と本番で食い違い、作り直すと消える・G-11）」と見つけた。

切る段で調べて、作り方を変えた（PM の判断 2026-11-10・精査 R 回 1 が一次資料で確かめた）：
- 目録を読むのは API だけ（apps/api/src/auth/bridge-release.ts の releaseState）。Bridge 本体は置き場を直に読まない
- Supabase の公開・非公開はバケット単位。S3 の口は ACL を受けない（1 つのファイルだけ公開は作れない）
- だから **目録も入れ物と同じく署名 URL で読み、置き場の中身は全部非公開にする**。公開の範囲を作らない
- provision は、作る（冪等）に加えて、置き場が非公開であることを**在る物で**確かめ（Supabase の公開の読みの口は、非公開のバケットでも公開のバケットで物が無いときでも 400 を返すので、物が無いと見分けられない）、公開なら止める。配布物の頭（BRIDGE_RELEASE_BASE）が作って確かめた置き場の下にあることも確かめる（別のバケットを指すと作られず確かめられない・G-11 の元の見つけもの）

## 完了の条件

- [ ] API は目録を関門 C4 の署名（signExternal・期限 60 秒・証跡は残さない）で読む。署名つきの読みが断られた（403 など）・署名を作るのが例外になったときは「読み込めませんでした」（unreachable・E-PAGE-007）で、覚えない。署名の口がその頭に署名を作れない（置き場の外の URL・開発）ときだけ、今までどおり署名なしで読む（K133-API-001〜010）
- [ ] `pnpm provision:bucket` が冪等に置き場を作り、在る物で非公開を確かめて「<バケット> @ <口>: <created|exists>・private」を出す。公開・確かめられない・配布物の頭が置き場の下に無い、はどれも exit 1（K133-CI-001〜009）
- [ ] 本番と同じコードで staging に作る（D-097・Build Command の `pnpm db:migrate && pnpm provision:bucket`）。手で置き場の画面から設定しない
- [ ] 前からの K-57・K-144 の試験（connect-pc・bridge_release・k144-contract）が緑のまま
- [ ] チケットの CI が緑（取り込みの CI で見る）

## 前提と制約

- 依存：K-78（staging の Supabase と置き場の接続）。staging をそろえる K-37 はこのチケットに依存する
- 置き場は関門 C4（packages/storage）を通す。生の S3 の呼び出しを関門の外に書かない。provision の確かめ（物を置く・署名つきで読む・公開の口を叩く・消す）は関門の中（packages/storage/src/s3.ts）に置く

- 公開の口：Supabase の S3 の口（…/storage/v1/s3）なら …/storage/v1/object/public/<バケット>/<鍵>。ほかの S3 互換（MinIO・試験の偽の S3）は <口>/<バケット>/<鍵>

## 実施事項

1. `packages/storage/src/s3.ts` に足し、`packages/storage/src/index.ts` から出す：
   - `bucketPublicUrl(endpoint, bucket, key): string`（上の公開の口の形）
   - `checkBucketPrivate({ client, presigner, endpoint, bucket, fetchImpl = fetch }): Promise<"private" | "public">`：確かめ用の物 `.kaname-private-probe-<乱数の uuid>` を PutObject で置く（鍵に乱数：同じ置き場で Preview と本番の provision が同時に流れても、互いの確かめを壊さない） → `presigner.presignGet(<口>/<バケット>/<物>, 60)` を fetch して 200 でなければ例外（「非公開を確かめられない」）→ 公開の口を頭なしで fetch し、200 なら public・それ以外は private → 最後に必ず DeleteObject で物を消す（finally）。届かなければ例外のまま
   - `provisionBucket({ client, presigner, endpoint, bucket, releaseBase, fetchImpl, log }): Promise<0 | 1>`：ensureBucket → releaseBase が空でなく `<口>/<バケット>/` の下（末尾の / まで比べる：`kaname-staging2/…` は下でない）でなければ「BRIDGE_RELEASE_BASE が置き場（<口>/<バケット>）の下にありません」を出して 1 → checkBucketPrivate が public なら「置き場が公開になっています。置き場の画面でバケットを非公開に戻す」を出して 1、例外なら理由を出して 1 → `[provision bucket] <バケット> @ <口>: <created|exists>・private` を出して 0
2. `infra/provision/bucket.ts`：provisionBucket を呼び、返した番号で終わる（s3Client・s3Presigner・config の storage と bridgeReleaseBase を渡す）
3. `packages/storage/src/index.ts` の signExternal に、5 つ目の引数 `opts: { audit?: boolean } = {}` を足す。`audit: false` なら証跡（object.sign_external）を書かない（決める人 answer=005e60e70a71・目録は運営の中身で利用者の操作ではない）。入れ物を渡すときは今までどおり書く
4. `apps/api/src/auth/bridge-release.ts` の releaseState の設定に `sign?: (name: string, ttlSeconds: number) => Promise<string | null>` を足す：
   - sign が URL を返す → その URL で読む。2xx は目録として読む（壊れていれば none）・404 は none・それ以外（400・401・403・5xx）は unreachable で覚えない
   - sign が null（その頭に署名を作れない）→ 今までどおり `${base}/${MANIFEST}` を署名なしで読む（5xx は unreachable・ほかの 4xx は none）
   - sign が例外 → unreachable で覚えない
   - 1 分の覚えは ok と none だけ（今と同じ）
5. `apps/api/src/features/F3/connect-pc/hooks.ts` の releaseState の呼び出し 2 か所（:174・:198）に sign を渡す：`signExternal(ctx, d.release.base, name, ttl, { audit: false })` の done は URL、failed（署名の口がその頭に作れない）は null、denied は例外
6. `03_architecture/choke-points.json` の bridge-release.ts の例外 2 か所（C1・C4）と `03_architecture/choke-point-exceptions.md` の X-006・X-007 の理由と compensating_control を書き直す：「置き場の目録は関門 C4 の signExternal が作った署名 URL で読む。署名を作れない頭（開発・置き場の外）だけ署名なしで読む」
7. `infra/STAGING.md` の置き場の手順に足す：バケットは非公開のまま（公開にしない・provision が確かめて公開なら止まる）。`BRIDGE_RELEASE_BASE=<STORAGE_ENDPOINT>/<STORAGE_BUCKET>/<頭>`（S3 の口の下・path-style。provision が置き場の下かを確かめる）
