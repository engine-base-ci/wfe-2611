## 目的

Bridge の配布物は置き場に置く。目録 `kaname-bridge.json` は誰でも読めてよい（公開）が、入れ物（インストーラーの本体）は非公開にし、受け取りは置き場の仕組みの期限つき署名 URL で渡す（D-128.153・D-128.160）。いまのプロビジョニング（infra/provision/bucket.ts・`pnpm provision:bucket`）は置き場を作るだけで、この公開の範囲を作っていない。手で置き場の画面から設定すると、staging と本番で食い違い、作り直したときに消える（外部リソースの実在・G-11）。K-57 のテスターが見つけた。

## 完了の条件

- [ ] `pnpm provision:bucket` が、置き場を作るのと同じく冪等に、目録 `kaname-bridge.json` だけを公開にし、入れ物を非公開にする（ほかの物は非公開のまま）
- [ ] 本番と同じコードで staging に作る（D-097・API の Build Command の `pnpm db:migrate && pnpm provision:bucket`）。手で置き場の画面から設定しない
- [ ] 確かめ：staging で、目録は署名なしで読める・入れ物は署名なしで読めない（403）・署名 URL では期限の間だけ読める
- [ ] 起動時確認（storage:bucket）か provision の出力に、公開の範囲が合っていることが出る
- [ ] チケットの CI（act）が緑

## 前提と制約

- 依存：K-78（staging の Supabase と置き場の接続）。staging をそろえるチケット K-37 はこのチケットに依存する
- 置き場は関門 C4（packages/storage の ObjectStore）を通す。生の S3 の呼び出しを関門の外に書かない
- 鍵の値はチャット・ファイル・コミットに書かない（infra/STAGING.md §1）
- 手元の置き場の試験の役（apps/api/test/fake-s3.ts）でも、公開の範囲の分岐を受けられるかを切るときに決める

## 実施事項

- [ ] 作る役：置き場（Supabase の S3 互換）で、1 つのファイルだけ公開にする方法（バケットの方針・公開のバケットを分ける など）を調べて決め、実装の詳細に書く
- [ ] 作る役：分岐（初めて作る・2 回目・既に公開になっている入れ物を非公開に戻す・目録がまだ無い）と試験の行
- [ ] 実装：infra/provision/bucket.ts と packages/storage の ensureBucket を直し、staging で流して確かめを記録する
