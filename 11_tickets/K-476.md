## 目的

保存した検索条件（K-475）を直す・消す口を作る。契約の口 `updateSavedView`（PATCH /api/v1/saved_views/:id）と `deleteSavedView`（DELETE /api/v1/saved_views/:id）は今 501。契約の権限の文は「作った本人」だが、決定 D-128.119 は「グループに見せた条件は、使うだけ・直す消すは作った人とそのグループのマネージャー」なので、文を決定に合わせて直す（契約の側が誤り）。

- 直せる人・消せる人：作った人と、見せているグループのマネージャー（グループの全員向けの物だけ。自分だけの物は作った人だけ）。入口の行の確かめ（`scripts/ci/row_rules.mjs` の saved_views：作った人か `app.manages_scope(scope_id)`・前からある）と、行の守りの update（`has_permission(…, 'saved_views', scope_id, 'edit')`）の 2 層
- 見せる相手（share・scope_id）を変えられるのは作った人だけ。マネージャーは名前・条件・列・詰め方だけ直せる（見せる相手を勝手に変えられない）
- 消すのは「消した印」（`deleted_at`）を付けるだけ（行は残す・証跡を残す）。消した条件の名前は、同じ人がまた使える
- DB の 2 層目：今の行の守りの update は、直す人が `member_id`（作った人）や `tenant_id` を書き換えられ（マネージャーが自分の物にできる）、作った人が見えないグループへ見せ直せる（insert にはある見えるグループの確かめが update に無い）。引き金 `app.saved_views_guard` で止める

## 前提と制約

分類: CRUD, PERM

- 素の読み書きでは足りない（K-475 の前提と同じ訳）。直すに加えて、① 共通の更新は見せる相手・作った人を区別せずに書く ② 名前の重なり・形の確かめが無い ③ 消した後の一覧・数・名前の扱いをそろえる、がある。hooks で作る
- 入力 `SavedViewUpdateInput`：name・share・scope_id・filters・columns・density（全部任意・strict）。送った欄だけ変える。空の体は 422（欄 body「変える欄がありません」）。知らない欄（member_id・tenant_id・created_by・deleted_at など）は入口の strict な形が 422 にする
- 確かめは K-475 と同じ関数を使う（`features/F7/saved-views/input.ts`）：名前（E-VWS-001・002・008）・share と density の言葉・`share` を group にするときは `scope_id` を一緒に送る（E-VWS-003）・filters と columns の形と大きさ（E-VWS-007）。同じ名前（E-VWS-005）は「作った人の消していない別の条件」と比べる（直す人がマネージャーでも、比べる相手は作った人の物）。自分の名前の大文字小文字だけを変えるのは重ならない
- 見せる相手：`share` か `scope_id` が今と違う値で送られたとき、作った人でなければ 403 E-VWS-020（文「見せる相手を変えられるのは、作った人だけです」）。今と同じ値を添えただけなら変えないので通す。作った人が `scope_id` を変えるとき（share が group になるときも）、そのグループが同じ会社・消していない・`visible_scopes(作った人)` に入らなければ 404 E-VWS-004（K-475 と同じ）
- `share` は送らずに `scope_id` を null にして、結果が「group で scope_id が無い」になるなら 409 E-VWS-021（文「グループの全員に見せている条件から、見せるグループは外せません。先に「自分だけ」に変えてください」）。今の状態で決まる断りなので 422 でなく 409（控え帳 16:51）
- 何も変わらない直し（今と同じ値）は 200 で、更新も証跡も書かない（`updated_at` を動かさない）
- 見えない・無い・消した物は 404（存在を教えない）。**code は 2 つ**：入口の行の確かめ（op.ts）が先に返す 404 の code は `NOT_FOUND`、口の中で消した物を外したときだけ E-PAGE-001。試験（K476-API-009）は状態コードだけを見て、code の字は固定しない。入口の行の確かめは 404（見えない）・403（見えるが作った人でもマネージャーでもない）を先に返す。口の中でも同じ確かめを持つ（2 重）。行の確かめは通るが行の守りの update が断る人（マネージャーの役割はあるが saved_views の edit が無い人）は 403（口の更新が 0 行になり、見えるなら 403・見えないなら 404）
- **口の中の読み方**：まず plain な select（見える・消していない）で読む。`for update` は付けない（行の守りの select に加えて update の守りも当てられ、edit の無い人の行が「無い」に見えてしまう）。書くのは `update … where id = $1 and deleted_at is null returning` 1 文で、0 行なら「見える（消していない）か」をもう一度 plain な select で読み、見えれば 403・見えなければ 404
- 同時の 2 回：改名は、作った人ごとの助言ロック（K-475 の保存と同じ鍵 `saved_views:<作った人の id>`）を取ってから名前の重なりを数える。消すの同時の 2 回は、`update … where deleted_at is null` の 0 行を 404 にする（片方だけ 200・証跡は 1 つ）
- 証跡（関門 C2・同じ取引）：直すは `saved_views.update`（payload は `{fields: [直した欄の名前…]}`・順は name・share・scope_id・filters・columns・density・値は入れない）、消すは `saved_views.delete`（payload は `{}`）
- お知らせは出さない（受け箱もメールも）。消す・直すで見える人にお知らせは行かない（D-151.9）
- 守りの引き金（DB の 2 層目・migration）：`app.saved_views_guard()` を `before update on saved_views` に付ける。① `member_id`・`tenant_id` が変わるなら例外「保存した条件の作った人と会社は変えられません」② `share` か `scope_id` が変わるとき、`app.user_id()` が元の作った人でなければ例外「見せる相手を変えられるのは作った人だけです」③ **`share` か `scope_id` が変わるときだけ**、変わった後が share group で `scope_id` が `visible_scopes(app.user_id())` に入らなければ例外「見えないグループには見せられません」（名前・詰め方・列・条件だけの更新には掛けない。席を移した作った人が前のグループに見せた物の名前を直す K476-API-029 や、マネージャーの名前・詰め方の直し K476-API-020 が通るため。口の中の `scope_id` の確かめも「変わるとき」だけで同じ）。例外の errcode は 42501。名前・条件・列・詰め方・消した印の更新は通す。管理の接続（app.user_id() が空）の更新で `share`・`scope_id` が動かないなら通る（試験の種・後片付け）
- ログに名前と条件を出さない
- 書く所で DB が落ちたら 500（K-475 と同じ・1 つの取引なので何も残らない）

### 契約に書く値域（screen_api.d/K-476.py の VALUE_RANGES・INPUT_RULES・contract_shape.d/K-476.py の VALUE_RANGES）

値域（名前の長さと字・share と density の enum・filters の構造の上限・columns の個数と長さ）は **K-475 の `screen_api.d/K-475.py` と同じ字**（`_VISIBLE`・`_NAME`・`_key`・`_leaf`・`_FILTERS` の定義ごと自分の断片に写す。別の断片は読めない・同じ辞書を 2 か所に置くと別名が出るので `_key()`・`_leaf()` は関数のまま）。直すだけの違いは、`name` を必須にしない（K-475 の REQUIRED_INPUTS は書かない）ことと、INPUT_RULES が 2 つあること。

```python
VALUE_RANGES = {"updateSavedView": {"name": {…}, "share": {…}, "density": {…}, "filters": _FILTERS, "columns": {…}}}   # 5 欄の中身は K-475 と同じ
INPUT_RULES = {"updateSavedView": {"allOf": [
    {"anyOf": [{"required": [k]} for k in ("name", "share", "scope_id", "filters", "columns", "density")]},   # 空の体は送れない（欄が 1 つは要る）
    {"anyOf": [
        {"not": {"required": ["share"]}},
        {"properties": {"share": {"enum": ["self"]}}},
        {"required": ["scope_id"], "properties": {"scope_id": {"type": "string"}}},
    ]},   # share を group にするなら scope_id（null でない）が要る
]}}
```

この表現で、空の体・名前の空と制御文字・share と density の言葉の外・group で scope_id が無い・null・filters と columns の形と大きさは、契約の外の入力になる（試験 011・013・015）。「グループに見せたまま scope_id だけ null」（E-VWS-021）は今の行の状態で決まるので契約の形でなく 409。
