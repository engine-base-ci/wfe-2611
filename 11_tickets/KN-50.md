## 目的

spec-sync の横断監査の 4 段（D 振る舞い波及・F 下流分解・G 基盤依存の境界・H 関門）を、走らせられない（blocked）から、実際に走って緑にする。今はスキルの版がプロジェクトの書き方に追いついていない。

## 完了の条件

- [x] D・F・G・H が blocked でなく走る。**G・H は pass**。D・F は走るようになったが、地図（spec-dependencies.yaml）の古い所で赤 → **KN-121** に切った（スキルの読み違いではない）
- [ ] 直したスキルが組織のスキルに入り、次のセッションでも同じ版が使われる → 差分を用意した（`.qa/spec-sync/KN-50/spec-sync-orchestrator.patch`）。**組織のスキルへの反映は高本さん**。それまではリポジトリの版（scripts/spec-sync/）を使う（2026-11-04 高本さん：リポジトリに置き、組織へも）

## 前提と制約

- プロジェクト側をスキルの古い読み方に合わせて書き換えない（例外台帳・地図はプロジェクトの検査 G25 などが読む形のまま）→ 守った。直したのはスキルの側だけ

## 実施事項

- [x] tier_d.py：alignment_decisions の trace の file が .html（しまったモック）のとき、画面の導出物（flow.json）を読む
- [x] spec-validator.py（F）：downstream_coverage の command の形を読む（id_source が無いときは command を走らせ、終わりのコードで判定）
- [x] tier_g.py：dependency_boundaries.checks の command を走らせ、終わりのコードで判定する
- [x] tier_h.py：例外台帳の backtick で囲んだフォルダ（`packages/auth/` など）を越境の許しとして読む。★あわせて、表の行は迂回箇所の欄と期限の欄だけを読むようにした（理由の欄の経緯の日付「2026-10-03」を期限と読み、期限切れと誤って赤にしていた）。`ファイル#定数` はファイル全体を許さない
- [x] 直した版を scripts/spec-sync/ に置き、地図に載せた（G・H は層の棚卸し G27 から毎回回る）
