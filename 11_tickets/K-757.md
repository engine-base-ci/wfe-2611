## 目的

段 6 の束 G「自分の AI と話す」の土台。会話の**置き場**（3 つの種類を 1 つの表で分ける）と、会話を**読む** 3 つの口を、前の道すじ（`/api/auth-ext/agent/*`・`apps/api/src/auth/agent.ts`・`ext.ts`）から契約の口（`/api/v1/conversations…`）へ移す。言う・止める（K-758）・流す（K-759）・チケットの中で話す（K-763）・作る画面の会話（K-774〜K-776）は、ここで決める置き場と答えの形（ConversationView・MessageView）をそのまま使う。

1. **置き場**：`conversations` に種類 `talk_kind`（`clone`＝自分の AI との会話・`ticket`＝チケットの右のパネルの会話・`draft`＝チケットを作る画面の会話）と `ticket_id` を足す。前から在る会話は全部 `clone`（列の既定値）。`ticket` は人 × チケットで 1 つだけ（一意の索引）。
2. **前の道すじの守り**：前の道すじの関数が「いま開いている会話」「会話の一覧」「新しい会話で閉じる」を選ぶとき、`ticket`・`draft` の会話を拾わないように 4 つの DB の関数（`app.agent_state`・`app.agent_open_conversation`・`app.agent_conversations`・`app.agent_close_conversation`）を作り直す（種類が `clone` の物だけ）。
3. **読む口 3 つ**（画面が使う答えの形はこの葉が決める）：
   - `listConversations`（GET /conversations）：自分の `clone` の会話の一覧。新しい順・続きの鍵つき。**探す（q）・星（starred）は作らない**（D-153.16）ので契約の問い合わせから外す
   - `getConversation`（GET /conversations/:id）：1 つの会話の今（ConversationView）。自分の会話なら種類を問わず読める
   - `listConversationMessages`（GET /conversations/:id/messages）：会話の行の続き（上へ戻って古い分を読む）

## 画面が使う答えの形（画面の葉 K-762・K-764・K-767・K-777 が読む正本）

```
ConversationView = {
  conversation: { id, title, talk_kind: "clone"|"ticket"|"draft", ticket_id: uuid|null, updated_at },
  messages: MessageView[],      // 古い順・新しい 50 件（これより前は listConversationMessages）
  has_more: boolean,            // messages より前に行が在るか
  running_job_id: uuid|null,    // 待っている・動いている・答えを待っている仕事
  work: null | { job_id, state: "running"|"asking" /* 待っているだけの仕事では work は null・running_job_id だけ出る */, status: string|null, partial: string|null,
                 elapsed_ms: number, stopping: boolean, last_at: string },   // status＝作業中の 1 行・partial＝書きながらの返事
  stopped: null | { job_id, reason }                                          // 止まった理由
}
MessageView = { id, who: "me"|"ai"|"stopped"|"note", text, at, job_id: uuid|null,
               passed: ("title"|"body"|"checks")[],        // 人の言葉の上の「…を AI に渡しました」の印（作る画面の会話だけ・他は []）
               proposal: null | { title?, body?, checks?[] },   // AI の案のカード（who は "ai"・text は ""）
               took: null }                                // 「見たもの：…」の 1 行。段 6 では書く道が無いので常に null
ConversationRow = { id, title /* 無ければ「新しい会話」 */, updated_at, last_text: string|null /* 最新の人か AI の行の先頭 60 字 */ }
```

- `who: "note"` は 1 行の知らせ（「高本が AI を止めました」「このチケットを作りました（EG-129）。作る時の会話はここに続きます」）。`who: "stopped"` は止まった印。前の道すじの `memo`（記憶）・`quote`・`attachments`・`send_state`・`memory_id` は新しい形に出さない（段 10・D-153.16）
- 行の `passed` と `proposal` は `messages.options`（jsonb）の `passed`・`proposal` から読む（書くのは K-774・K-775）。AI の案の行は `messages.kind = 'proposal'`（本文は空・`who` は `ai`）
- 未読の数は出さない（既読にする口が契約に無く、下絵にも未読の表示が無い＝話すの芯だけ・D-153.16）。`last_read_at` の列は前から在るが、この葉は読まない
- 一覧の続きの鍵 `cursor` は文字（`base64url(<updated_at>|<id>)`）。行の続きの鍵は `base64url(<created_at>|<id>)`（「これより古い」。最後は null）。どちらも K-754 と同じ `KEY_CURSOR_OPS` の書き方

## 前提と制約

分類: LIST, PERM

- **会話は本人だけが読む**（管理者・運営も見ない）。他人の会話・無い会話・別の会社の会話は、行の守り（`conversations` は持ち主だけ・0084）で入口が先に 404 `{error:"not_found", code:"NOT_FOUND"}`（鍵は code と error だけ・欄も details も無い）を返す。口に来るのは消した会話などで、**口の 404 も入口と同じ形**（`features/F5/delegate/bridge.ts` の `notFound` と同じ）にして、4 つの 404 の本文が同じになるようにする。`OP_RULES` に行は足さない（入口が持ち主だけを通すので不要）。DB の関数も持ち主を見る（2 層）
- **DB の関数はどれも security definer・`set search_path = public, app, pg_temp`・`revoke all … from public`・`grant execute … to kaname_app`**。持ち主は `p_member`（口が `ctx.userId` を渡す）。口は `d.appPool` を使い、`withTenant` は使わない（前の道すじの `agent_*` と同じ形・会社は関数の中で `members` から引く）
- 入力の形は口が自分で確かめる（入口の zod は値域を読まない）：`limit`（一覧は 1〜100・既定 30／行は 1〜200・既定 50・整数だけ）・`cursor`（作り手の鍵の形だけ）が外れたら 422・欄 `limit`／`cursor`。契約に無い問い合わせ（`q`・`starred`・`before` ほか）は 422・欄名つき。値の形は `05_flow/screen_api.d/K-757.py` の `QUERY_RANGES`（K-468 の仕組み）に書く
- 断る番号（控え帳）：422＝契約に書ける形の誤りだけ／404＝指した物が無い・見えない（`NOT_FOUND`・鍵は code と error だけ）／DB の失敗は 503・E-PAGE-003／`_id` で終わる道の値は uuid（形違いは入口が 422）。E-TALK の番号はこの葉では足さない（読むだけで 409 が無い）
- 作り直す 4 つの関数は**今の版を写して、「開いている会話」を選ぶ所に `talk_kind = 'clone'` を足すだけ**（0051 の `app.agent_state`・0042 の `app.agent_open_conversation`・0061 の `app.agent_conversations`・0033 の `app.agent_close_conversation`）。会話の指定（`p_conv`）がある呼び方は種類を問わない（`agent_state(member, 会話)` は今までどおり自分の会話ならどれでも返す＝ConversationView が使う）。答えの鍵は変えない（前の画面が読み続ける。前の画面と前の道すじは K-765 が消す）
