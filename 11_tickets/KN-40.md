## 目的

ナレッジの表（ページ・版・つながり）を作り、契約の API が読み書きできるようにする。置き場が見えない人・下書きを知らされない人には見せない。

## 完了の条件

- [x] migration（`packages/db/migrations/0073_knowledge.sql`）と RLS（`packages/db/policies/0073_knowledge.sql`）
- [x] repository の TABLES に入っている・場合表が全部通る
- [x] 置き場（ワークスペース全体・層・グループ・自分）ごとに見える。自分の置き場は持ち主だけ
- [x] 下書きは持ち主とその置き場で書ける人だけ（下書きは知らせない）
- [ ] CI が緑のまま

## 前提と制約

- 表は ER 図 §16 と「足す列」が正。足すだけで、消す・名前を変える migration は作らない
- 全部の表に `tenant_id` と RLS。RLS を飛ばす鍵はサーバーで使わない（ZT3）
- 自分の表の読む守りに「その表を id で引く関数」を使わない（作った行がその場で見えず INSERT … RETURNING が弾かれる）

## 実施事項

- [x] 表：`knowledge_pages` `knowledge_page_versions` `knowledge_links`
- [x] 列：自分の置き場（is_personal）・状態（下書き・公開・しまった）・確かめの期限（30 日・90 日・半年・期限なし）・しまった日と移し先・版の種類（下書き・直す案・公開）・直す案の出どころ・入れたか・入れない理由
- [x] RLS の範囲：公開した版はページを読める人。下書きと直す案は書ける人だけ。直す案は読める人が出せる（チケットの完了から）。版は消さない。つながりは元のページに従う
- [x] ZT の記録を下げた（rls_missing 18 → 10）
