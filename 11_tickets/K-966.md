分類: CRUD, PERM

- **生成の試験は作る段の最初に作る**：契約の断片（`05_flow/screen_api.d/K-966.py`・`scripts/ci/contract_shape.d/K-966.py`）を足して作り手で生成の試験を作り、**実装より先に 1 つのコミットにする**。先の葉の契約を前提にした前からの試験は carry に入れない
- 答えの形は K-1006 の「画面が使う答えの形」。:id は会社（K-1001 の ops_tenant）。関数は K-947 の型：頭で `app.ops_require(<できること>)`、次に `app.ops_target(p_tenant)`（運営の会社・無い・作りかけ・消した → P0002 → 404・欄なし）
- 読むだけなので運営の記録は書かない（D-128.108 は書く操作だけ）
- **数の決まりは K-963 と同じ**（`app.workspace_facts` を使い、同じ数え方を 2 つ書かない）：プラン・状態・人数・PC がつながる人（90 秒の内）。K-963 の精査 1 回目の直しで、プランは `app.tenant_plan_id`（効いている行＝下げる予定の会社は今のプラン・K-961）、人数は `app.tenant_seat_count`（社内の人だけ・ゲストを数えない・D-156.51・K-961）を呼ぶ形にそろう。この葉は workspace_facts を読むだけなので、その決めをそのまま受ける（この葉で数え方を書かない）
- **今月の実行**：`{ count }`（今月の action_runs の数）。上限に対する割合（quota_ratio）は返さない：実行の回数はプランで分けず、上限で止める仕組みも作らない（D-156.63・D-156.72）。下絵 op-ws の「枠の 64%」は外した
- **止まった実行**：`{ count_7d, prev_week }`＝action_runs の `status_id = 'stopped'` の、直近 7 日と、その前の 7 日（7〜14 日前）の数
- **ファイル**：`{ bytes }`＝attachments の `deleted_at is null` の size の合計。上限（limit_bytes）は返さない：ファイルの量はプランで分けない（D-156.63・files_bytes を置く葉は無い）
- **最近のこと**（recent）：次の 4 つの出来事の新しい順に 5 件まで。`{ at, label, detail }` の 3 欄（detail は下絵の 2 行目の字・無ければ null・D-156.47）。字は下の型だけ（問い合わせの内容・チケット・会話は入れない）
  - 問い合わせ（inquiries の作った時刻）：`問い合わせ「<題>」が届いた`・detail `<問い合わせた人の名前>`（担当がいれば ` ・ 担当 <担当の名前>` を足す）
  - 請求書（invoices の issued_at）：`<月> 月分の請求書を出した ¥<金額>`（金額は 3 桁ごとのコンマ）・detail `期限 <MM/DD>`
  - 入金（payments の作った時刻）：`<月> 月分の入金を記録した`・detail は振込名義（payer_name・無ければ null）
  - メンバー（tenant_memberships の joined_at）：`メンバーが 1 人増えた（<その時点の人数> 人）`・detail は null
- **止まった理由の種類は返さない**（D-156.47）：実行の行に止まった訳の種類の列が無く、訳の字（`error_summary`）は中身なので運営に出さない（D-156.3）。下絵 op-ws の「止まった理由（種類と数）」の区画は下絵から外す（止まった実行の数は 4 つの数の 1 つで出る）
- **状態**：K-963 の `app.workspace_facts` の決め（止めている＝`stopped_at is not null or stop_on <= 日本の今日`・D-156.49）をそのまま使う
- **止める印**（stop）：K-963 が足した 4 列。`stop_on` か `stopped_at` があれば `{ reason_key, stop_on（YYYY-MM-DD）, stopped_at, noticed_at（stop_noticed_at） }`、どちらも無ければ null（D-156.23）
- **人数**（members）：`{ count }`＝会社の生きているメンバーの数。一覧の行の `members.count` と同じ 1 か所 `app.tenant_seat_count`（K-961 の数え方：その会社の `members` の kind human・`deleted_at is null` のうち、ゲスト〔役割 requester の所属〕でない人。AI 社員・自分の AI・ゲストは数えない・D-156.51。所属の status は見ない＝K-961 の決め）を呼ぶ（この葉で数え方を書かない・workspace_facts の数を使ってよい）。上限は持たない。運営の 1 社の頭と小窓の対象「<会社> ・ N 人」（K-971・K-972）がこの数を使う（それまでは PC の数を人数として出していた・PM の決め 2026-11-25・レビュー Q81）
- **済んでいない問い合わせ**（inquiries）：`{ open }`＝その会社の inquiries の `deleted_at is null`・`state <> 'done'`（open・waiting・later）の数。受信箱の数（K-963）と同じ「済み」の決め。数だけで題・中身は返さない（D-156.3）。inquiry を持たない運営の人にも数は返す（数と種類だけ・1 社は ops:any）。運営の 1 社の画面のタブ「問い合わせ N」（下絵 op-ws・K-971）が、問い合わせのタブを開く前から出すため（PM の決め 2026-11-25・案 A・K-971 の作り手の報告）
- **中を見る**（peek）：support_access_grants の、その会社・自分の ops_members の行・`closed_at is null`・`expires_at > now()` のうち新しい 1 つの `{ id, expires_at, reason }`。ほかの運営の人の許可は見せない（0078 の「開いた本人の柵」と同じ）
  - `reason`＝その許可の `support_access_grants.reason` をそのまま（openPeek が 1〜200 字で入れた字・切らない・前後を詰めない・作り直さない）。新しい許可は理由が必ず入る（0078 の reason_ck）。前からの null の行は作れないので試験しない（実装は null をそのまま返す）。運営の 1 社の画面の見ている間の帯「理由：問い合わせ「…」」（下絵 op-peek-open・K-972）が開き直した後も理由を出すため（PM の決め 2026-11-25・下絵から外さない）
  - 理由はその許可を開いた運営の人の答えにだけ入る（ほかの運営の人は peek が null）。会社の人はこの口を呼べない（403・K966-API-014）。止める・再開の答え（K-970）も同じ関数の 14 欄なので同じ形になる
- **メンバー**：tenant_memberships の `status <> 'left'`・`deleted_at is null` の人。並びは役割（admin → manager → member → viewer → requester）→ 名前。欄：`member_id`・`name`（members.display_name）・`email`（kaname_auth の user・無ければ null）・`role_label`（管理者・マネージャー・メンバー・閲覧のみ・ゲスト。role requester の字は段 12 にそろえて「ゲスト」・「依頼する側」の字は画面から消した＝D-155.35・K-877）・`last_seen_at`（kind web の sessions の最後・無ければ null）・`pc`（connected＝生きている知らせ 90 秒の内／paired＝bridge のセッションはあるが切れている／never＝無い／none＝閲覧のみ・ゲスト）・`login_methods`（`app.login_methods`（0113）から passkey・password・two_factor の並び）・`verified`（emailVerified・認証の人が無ければ false）
- 断る番号（控え帳）：ログインなし 401・運営でない 403・メンバーで inquiry を持たない 403（入口）・道の id の形 422（入口）・会社が無い・見えない 404（欄なし）・DB の失敗 503 E-PAGE-003・上限 429
