## 前提と制約

分類: LIST, PERM

- **代表の答え 2026-11-23（D-156.21）**：配るものはタブ 3 つ（プラン（版・案・決める）／ひな形／操作）。値段の流れは D-128.72（案を作る人と決める人を分ける・自分の案は決められない（決められる人が 1 人だけの間は例外）・理由は必須・記録は消せない）
- **生成の試験は作る段の最初に作る**：契約の断片と本体の直し（下）を書いて作り手で生成の試験を作り、**実装より先に 1 つのコミットにする**。先の葉の契約を前提にした前からの試験は carry に入れない（carry は土台だけ）
- **本体の直し**（`05_flow/screen_api.py`・操作 ID で探す）：PERMS の `listOpsPlans`・`listPlanProposals`・`listPlanHistory` を `("ops:any", "値段の案か値段を決めるを持つ運営の人（関数の中で見る）", False)` に（入口は 1 つの印しか書けず、値段を決めるだけの人が読めなくなるため）。QUERIES の `"listPlanHistory": ["plan_id"]` を `["plan_key"]` に（`_id` は uuid の決まり・プランは名前で絞る）
- **関数の中で見る**：`perform app.ops_require('any')` の次に、呼んだ人の caps に `plan_propose` か `plan_decide` が無ければ `raise … errcode = 'insufficient_privilege'`（42501 → 403）
- **プランの中身の行**（migration の種・`on conflict` のように、`limits->'facts'` が無いときだけ足す＝運営が直した値を上書きしない）：無料 `[{使えるもの, チケット・承認・ナレッジ}]`・チーム `[{使えるもの, ＋ ゲストを招く}]`・ビジネス `[{使えるもの, ＋ ゲストのグループ}]`（代表の答え 2026-11-23・D-156.63：分身の実行の回数とファイルの量はプランで分けないので中身の行から外す。下絵 oq-plans の「分身の実行」「ファイル」の行は下絵の側で外した（済み）。「＋ ゲストを招く」「＋ ゲストのグループ」は下絵の字）。答えの `facts` は先頭に「人数 <N> 人まで」を足した 2 行
- **版 1 の行**：`plan_versions` に、プランごとに版 `current_version`（無ければ 1）の行が無ければ、今の値段・人数・中身の写しで 1 行（`released_at` は plans の created_at）。`plans.current_version` が null なら 1
- **案の列**：`ops_plan_proposals.submitted_at timestamptz`（回した時刻・K-988 が書く）を足す
- **使っている会社の数**（places）：顧客のワークスペース（`tenants` の `deleted_at is null`・`half_made_at is null`・`id <> app.ops_tenant_id()`）のうち `app.tenant_plan_id(T)`（K-954）がそのプランの物の数（止めている会社も数える）
- **待っている案**（proposal）：そのプランの `state in ('draft','waiting')` の新しい 1 つ。`{ id, state, to_version, price_monthly, proposer_name }`・無ければ null
- **案の押せる印**：`can_edit` ＝ 呼んだ人が作った人で state が draft か returned。`can_decide` ＝ state が waiting で、呼んだ人が plan_decide を持ち、作った人でない（または plan_decide を持つ生きている運営の人が呼んだ人 1 人だけ＝D-128.72 の例外・0076 の引き金と同じ式）
- **一覧の並びと絞り込み**：案は `created_at` の新しい順・`state`（draft・waiting・decided・returned）で絞る。記録は ops_audit_events の `target_type = 'ops_plan_proposals'` で `action like 'plan.%'` の新しい順・`plan_key` で絞る。どちらも 100 件まで（101 を渡し、101 行目は捨てる・K-954 と同じ）。問い合わせの値の形は段 8 の K-468 の `QUERY_RANGES`
- 断る番号（控え帳・D-156.12・D-156.17）：ログインなし 401・運営でない 403（入口）・値段の印を持たない 403（関数）・問い合わせの値の形 422（入口・契約）・DB の失敗 503 E-PAGE-003・上限 429。答えは `Cache-Control: private, no-store`
