## 目的

**チケットはチケット。新しいのは「ゲストが見られるか」だけ**（D-155.41）。社内で作ったチケットは既定でゲストに見えない。この葉は、チケットの詳細の右のパネルに「ゲストに見せる」の区画を足し、見せる相手（ゲストのグループ・複数選べる・1 人ずつは選ばない）を選ぶ・やめる画面を口（K-881）につなぐ：

- 区画（`section[aria-label="ゲストに見せる"]`）：見せていなければ「社内だけ（ゲストには見えません）」と「ゲストに見せる」。見せていれば「見せている相手」（ゲストのグループの名前）・見えるものと見せないものの説明・「相手を選ぶ」「見せるのをやめる」
- 見せる相手を選ぶ小窓（ゲストのグループの箱・1 つずつの概要・見える物と見えない物の説明が小窓の中に）・見せるのをやめる確かめ（ゲストの画面から消える・チケットは残る）
- ゲストに見えるのは題・本文・詳細・チャットと段の札 3 つ（作っている・確認中・完了）だけ。担当・期限など社内の欄・確認項目・決定ログ・分身の記録は見えない（説明の字は下絵のまま）
- 詳細の分類の欄の「取引先」の行と、作る画面の振り分けの「取引先」の欄（押せない欄）を外す（取引先を持たない・D-155.35）

見せた後にゲストの受け箱に 1 件入る・見えるかの判定は口（K-881・K-878）。ゲストが見る画面は K-913。

## 前提と制約

分類: PERM, LIST

- **口の名前・答えは K-881 の確定**（K881-API-001・003）：`listTicketGuestShares`（GET /tickets/:id/guest-shares・答え `{ data: { shared: [{ guest_group_id, name, summary }], choices: [{ id, name, summary }], can_change: boolean } }`）・`updateTicketGuestShares`（PATCH 同じ住所・入力 `{ add?, remove? }`）。`can_change` は見ている人が変えられるか（書ける人のとき true・読むだけの人は false で `choices` は空）で、画面は役の名前で出し分けず口の答えで決める。`summary` は口が組む「山田 花子 様・鈴木 健太 様 ほか（3 人・招待中 1）」（ゲストも招待中も 0 のグループは「まだゲストはいません」）。まとめ役の決め 2026-11-23：`can_change`・`summary` の持ち主は K-881
- 読むのは詳細を開いたときに 1 回（詳細と並べる・直列の段を足さない）。付け外しの後に 1 回だけ読み直す（口の答えの写しを区画に出さず、再取得を出す・G-02）
- 付け外しの体は、小窓で新しく選んだ物を `add`・外した物を `remove`。変わっていなければ口を呼ばない。「見せるのをやめる」は今見せている全部を `remove`（1 つなら確かめの題にその名前、複数なら「N つのゲストのグループに見せるのをやめますか」・下絵に無い形・まとめ役に知らせる）
- 見せたことのお知らせ（ゲストの受け箱 1 件・メールなし・D-155.45）は**口の側**。K-881 の md は「知らせは送らない（仮置き）」で、D-155.45 と合わない（まとめ役に知らせる）。画面は知らせの有無に触れない
- **チャットの頭の印は、この葉が作る**（まとめ役の決め 1・2 の反映・段 7 の `features/F6/thread/panel.tsx`・`to-items.ts` に足す）：(a) 見せているチケット（`shared` が空でない）のやり取りの頭に札「ゲストに見えるやり取り」（区画と同じ問い合わせ `["guest-shares", id]` を使い、口を増やさない）。**見せた後に書いた書き込みはゲストに見え、見せる前の書き込みは見えない**（K-882・勧め：PM から代表に確かめる）ので、札の説明は下絵のまま。(b) 依頼から作ったチケット：社内の読みの答えの書き込みの `message.from_request`（`true` の行にだけ鍵が付く・K-882）が頭の連続した行に札「依頼のやり取り」、その最後の書き込みの下に区切り「ここからチケットのやり取り」。足し方：`to-items.ts` の `MessageView` に任意の `from_request?: true` を足し、`panel.tsx` の `renderPost` の外側に差し込み口（`GuestThreadMarks`・`features/F11/share/thread-marks.tsx`）を 1 つ足す（今の描き方は変えない・ゲストの印が無いチケットでは何も出ない）。K-930（作った後の詳細）・K-913（ゲストの画面）は同じ区切りの規則を使う
- 詳細のパネルは段 4 の `features/F4/create-ticket/detail-panel.tsx`。区画は**属性のタブの中**（`attrs` の「分類」の後・「本文の目次」の前）に直に足す（K-380 の差し込み口は「担当者」「予定」「実績」「帯」「タブ」の物で、区画の口は無い。新しい口は作らず、この葉が `detail-panel.tsx` に 1 行足す。K-380・段 7 の葉の入った後なので同じファイルの衝突は依存で順に並ぶ）
- 区画の部品は K-871 が運ぶ `features/F11/share/views.tsx` の `SharePanel`・`ShareDialog`・`UnshareConfirm`（見た目だけ・口を呼ばない）。この葉は `summary` と `can_change` を部品が受ける形に最小限だけ直す（`GUEST_GROUPS` の見本の定数は部品から外し、値は props で受ける）
- 作る画面の振り分けの「取引先」の欄（`create-ticket.tsx` の `OFF_AFTER_START`）と詳細の「取引先」の行は外す。キャンバスの絵（Create・TicketDetail）にも「取引先」の行があり、突き合わせの試験（K226-UI-028・K224 のキャンバス比べ）は絵と同じ並びを見る。**K-925 が絵の字を先に直す**（依存・K-925 の changes に TicketDetail・Create の絵が入っていることを確かめる）
- 画面に「取引先」の字を出さない（K905-UI-002）・新しい migration・DB は無い
- 区画の字の「ゲストに見せる」小窓の中の説明（見える物と見えない物）は下絵のまま。ゲストに期限・担当は見せない（D-155.41）
