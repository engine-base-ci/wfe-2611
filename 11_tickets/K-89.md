## 目的

PC をつないだ人が「PC をつなぐ」画面を開いたとき、その PC の Bridge の自己診断が「Claude Code が無い」「入っているが本体が落ちてきていない」「ログインしていない」のどれかなら、**足りないものとその直し方だけ**が出る。「Claude Code を入れる」（壊れているときは「Claude Code を取り直す」）を 1 回押すと、**Bridge が本人の PC で入れる作業を代わりに走らせ**、終わると「ログインする」が出る。押すと Claude Code がブラウザでログインの入口を開き、本人が 1 回承認して、出たコードを画面に貼って「決定」を押すとログインが済む（D-091）。人はターミナルを触らない。

**ログインが確定するのは、Bridge が `claude auth status` に聞いて「入れている」と返った時点**（コードを渡しただけでは合格にしない）。その後の生きている知らせ（K-57 の sendHeartbeat）で自己診断の行が「できる」に変わり、画面の区画が消える。**本人の資格情報（パスワード・コード・トークン）は Bridge も Kaname も AI も見ない・持たない**（D-017・D-092 ①）。コードは Bridge が Claude Code の標準入力にそのまま渡すだけで、Kaname のサーバーには届かない。

前の「PC をつなぐ」画面（/setup/bridge/legacy・D-128.164）にある実装を使う（D-128.150）。新しい契約の口は作らない（自己診断は K-57 の口が運ぶ）。

### 決めた判断

- 入れ方の順は D-091 のとおり（①動くなら何もしない ②取り直しだけ ③npm ④npm が無ければ理由で止める）。勝手に別のもの（Node.js など）を入れない
- ログインは本人がブラウザで承認する。Bridge は入口を開くところまで（D-091.3）。ターミナルは開かない（前の openClaudeLogin は使わない）
- コードを渡しただけで「できた」と言わない。`claude auth status` が入れていると答えるまで待つ（最長 2 分・login.ts の WAIT_LOGIN_MS）
- 押せるのはこの PC で開いた画面と Bridge の窓だけ。ほかの端末の画面は理由と「Bridge が入っている PC でこの画面を開いてください」だけを出す
- 入っていてログイン済みなら区画を出さない（済んだ手順を見せ続けない）
- 「入れる」「ログインする」はこの PC の中だけの口の上で動くので、Kaname のサーバーに新しい口は要らない。サーバーが知るのは自己診断の結果だけ
- 自己診断は PC ごと・アカウントの PC として、どのワークスペースの画面からも同じに見える（D-128.156）
