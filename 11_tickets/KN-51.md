## 目的

API ごとの「誰が呼べるか」（08_api の permission）を契約に載せ、入口（op.ts）で会社の段の言葉（admin の能力・運営のできること ops:〜）と本人確認の取り直し（15 分）を確かめる。

## 完了の条件

- [x] 契約（@kaname/contracts の ENDPOINTS）に perm（言葉・能力）と stepUp が出る
- [x] admin の口は、その能力（招く・書き出す・プランと支払い・ワークスペースを消す・表ごとの edit）を持つ人だけ
- [x] ops:〜 の口は、そのできること（caps）を持つ運営の人だけ
- [x] 本人確認が要る口は、直前 15 分以内の取り直しが無ければ 403（STEP_UP_REQUIRED）
- [x] zt_gate の step_up_missing が 0
- [x] CI が緑のまま（手元で G2・G3 の該当分・lint を確かめた。GitHub の結果は push 後に見る）

## 前提と制約

- 能力の当て方は機械で決める（表の名前＋読む／書く、招く・書き出す・お金・消すは決まった能力）。決まりから外れる口は理由を付けて表に書く
- 本人確認の取り直しの時刻はセッション（sessions）に持つ

## 実施事項

- [x] contract.mjs：perm と stepUp を出す（permOf）
- [x] op.ts：会社の段の確かめと本人確認（apps/api/src/contract/permissions.ts の CHECKS・stepUpFresh）
- [x] sessions に step_up_at を足す（0081）。付ける関数 app.mark_step_up は作った。本人確認の口（POST /auth/step-up）で呼ぶのは KN-4（ログインまわりの口と一緒に作る）
