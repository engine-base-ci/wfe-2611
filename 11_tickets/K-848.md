## 前提と制約

分類: CRUD, PERM, INV

- 入力は K-800 の契約：`{ transfer_to_member_id?: uuid, transfers?: [{ ticket_id: uuid, to_member_id: uuid }]（〜500） }`。**全部同じ人**は transfer_to_member_id、**1 件ずつ**は transfers（両方を指す・形の誤りは入口が 422）。答え `{ data: { member_id, tickets_moved, handovers_cancelled, restorable_until } }`（鍵はちょうど 4・K-800 の契約）
- 入口の権限は管理者の束（members の edit）か個別に付けた人（D-128.97）・本人確認 always（契約の step_up・15 分以内なら省く・口は 403 STEP_UP_REQUIRED）。マネージャー・メンバー・閲覧のみ・止めた人は 403
- **E-MEM-005 の字**：K-800 の errors の字を「自分は止めることも外すこともできません。抜けるのは自分の設定からです」に直した（外す小窓で「止められません」だけが出ないように）
- **関数の頭の順**（K-800 の約束）：`app.admin_lock()`（会社ごとの錠・D-154.21）→ `app.admin_can('members','edit')` → `app.admin_target(p)`（null → member_gone 404・E-MEM-002）→ 自分（`is_self`）→ self_stop 409・E-MEM-005 → `app.admin_is_last_admin(p)` → last_admin 409・E-MEM-004 → 引き継ぎ先の確かめ → 書く。**自分の番号が最後の管理者より先**
- **引き継ぎ先の確かめ**：外す人の担当＝assignee が外す人で完了も削除もしていないチケット（**下書きも含む**：下書きの担当も引き継がないと外した人に残る。下見 K-815・1 人の画面 K-810 の数え方と同じ・まとめ役の決め）。担当があるのに引き継ぎ先が無い・transfers が担当の全部でない（足りない・多い・同じチケットが 2 回）・下見の後で担当が変わった → 409・E-MEM-020（欄・details なし）。引き継ぎ先が別の会社・在らない・外した・招待中（`admin_target` が null）→ 404・E-MEM-021（欄・details なし）。止めた人・外す本人 → 409・E-MEM-022（detail `{ 名前, 訳 }`）。閲覧のみ・依頼する側 → 409・E-MEM-023（detail `{ 名前 }`）。**1 件でも誤りがあれば全部断る**
- 担当 0 件なら引き継ぎ先は要らない（付けても居る人なら受ける）
- **渡し中の取り消し**：外す人が渡した側（グループ宛て・申し出も）か受ける側の待っている渡しを、**この葉の DB の関数の中で**取り消す（段 9 の葉は直さない）：K-406 の `app.handover_withdraw` は呼んだ人が渡した本人でないと 403 で使えないので、K-406 の自動の取り消し（`app.handover_autowithdraw`）と同じ形で、待っている渡しの `state` を withdrawn・`decided_at` を now() にし、相手（渡した側が外す人なら受ける人・受ける側が外す人なら渡した人・グループ宛てはそのグループのマネージャー）の受け箱に `handover.withdrawn` の行（inapp・メールなし・payload に handover_id・番号・題名・cause `member_removed`・dedupe_key `handover_withdrawn:<渡しの id>`）を 1 行ずつ。決まった渡し（accepted・declined・withdrawn）は触らない。渡しの表を F10 が書く例外はこの 1 か所だけ（外す人が絡む待っている渡しの取り消し・PM の決め。段 9 の `handover_withdraw` の形は変えない）
- **承認は今の担当者が受け持つ**（D-150.21）ので、担当を移すだけで承認する人は引き継ぎ先に替わる（approvals は書かない）
- 付け替えたチケットは `delegated_to_clone` を false に戻す（外す人の分身は止まる。新しい担当者が自分の分身に任せ直す・PM の決め）
- 引き継ぎ先への受け箱：人ごとに 1 行（種類 `member.tickets_received`・channel inapp・メールなし・payload `{ from_member_id, from_name, count, numbers }`・dedupe_key は外す人の id と引き継ぎ先の id）。外した本人には出さない
- 証跡 `member.remove`（`app.record_audit('member.remove','members',p,'C2',payload)`・target_type は束 C のほかの葉と同じ 'members'。1 人の画面の記録 K-810 の recent_events と記録の葉 K-823 が target で引く）：payload は `{ tickets_moved, handovers_cancelled, heirs: [id…] }` だけ（メール・名前・理由は書かない）。追記だけ（D-154.25）
- すぐ消える物・セッションと PC・外した印は `app.member_erase(p, 呼んだ人)`（K-849）。件数の答えは口に返さない（画面は下見で見せた）
- **外した 30 日の戻りの元は K-849 が残す**（K-817 が読む）。DB の失敗は 503・E-PAGE-003（ログに言葉だけ）
