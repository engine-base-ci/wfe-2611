## 前提と制約

分類: CRUD, PERM

- **完了の流れ**（`use-complete.ts`・押すたびに最初から）：
  1. 「完了にする」を押す → `listTestSpecs` を **1 回**読む（押している間は押せない形）。読めなければ（503・404 ほか）小窓も完了もなく、帯に赤い知らせ（口の文・正本）を出す。404 は詳細も読み直す（完了の口は呼ばない）。もう一度押せる
  2. 数える：本文の未チェック（`uncheckedTasks(body.doc)`）と確認項目の未チェック（`checked` が false の行の文）
  3. どちらも 0 → **小窓なしで**完了の口を呼ぶ（体は `{ conditions_confirmed: true }`）。1 つでもあれば小窓を開く
  4. 小窓：「戻って付ける」は小窓を閉じるだけ（口は呼ばない・焦点は「完了にする」へ戻る・付けるのは本文と確認項目の側）／「このまま完了にする」は完了の口を呼ぶ。小窓の ×・Esc は「戻って付ける」と同じ
- **完了の口**（K-566）：`POST /api/v1/tickets/:id/complete` ← `{ conditions_confirmed: true }`（頭 Idempotency-Key は共通の呼び方のまま）。`todo_checked`・`todo_version` は**送らない**（契約には任意で残る・K-575 が外す）。**`conditions_confirmed` は画面が常に `true` を送る**（下絵の小窓に確かめのチェックが無く、「完了にする」「このまま完了にする」を押したこと自体が確かめ。代表に聞くこと 1）。201 で小窓を閉じて詳細を読み直す（帯が「完了しました（高本・11/08 15:20）」に替わる）。答えの `unchecked`（`{ body, specs }`）は画面で使わない（口の数と画面の数が同じ定義であることを試験が突き合わせる）
- **数え方**（口の `app.ticket_body_unchecked` と同じ定義・K-566）：文書の木 `doc`（K-561・`@kaname/contracts` の `Doc`）を根から `content` の並びだけ辿り（入れ子も）、`type` が `taskItem` で `attrs.checked` が真偽の `true` でない節を未チェックと数える（`attrs` が無い・文字の `"true"`・null も未チェック。段落の字の「[ ]」は数えない・`content` が並びでない節は 0）。行の文は、その箱の**直下の段落**の字をつないだ物（入れ子の箱の字は含めず、入れ子の箱は別の行として数える・hardBreak は空白 1 つ）。順は文書の出てくる順。`uncheckedTasks(doc: unknown): string[]` を `unchecked.ts` に純粋な関数で置く（`doc` が無い・形が違うなら空の並び＝前の形の口の答え）
- **`spec_unchecked`（詳細の答え・K-560）を使わず、押したときに `listTestSpecs` を読む訳**（意図）：詳細を開いた後に別の人が確認項目のチェックを付け外ししても、押した時点の数で小窓を出すため。口が 1 本増えるのは押したときだけ（詳細を開くときの口は 6 本のまま）
- **小窓の中身**（下絵）：未チェックの本文が n 個 → 注意「本文に、チェックのないやることが n つ残っています」（Callout・warn・本文「完了にしても止めません。このままでよいかを決めてください。」）と、その下に `ul.k-f4d-unchecked` の `li`「☐ 文」を n 行。確認項目の未チェックが m 個 → 注意「確認項目にチェックの付いていない物が m つあります」（Callout・warn）の中に「☐ 文」を m 行。どちらか 0 なら、その注意は出さない（確認項目だけ未チェックのときは「完了にしても止めません…」の文は出ない・下絵にその形の絵が無い→代表に聞くこと 2）。小窓の頭の下の対象の行は「番号 題名」（`targetLine`）
- **失敗**（小窓の中・外）：
  - 422 E-VAL-024（終わっていない子）は、小窓の中の赤い箱（`role=alert`）に口の文と、子の番号・題名（`details[].field = children` で id があれば、そのチケットへのリンク。id の無い行は文字だけ）を出し、小窓は閉じない。**小窓なしの完了で 422 E-VAL-024 になったときは、未チェックの注意を出さずに同じ小窓を開き**（赤い箱だけ）、押し直せる（足は「戻って付ける」「このまま完了にする」のまま・代表に聞くこと 3）
  - 422 E-VAL-023（確かめ印）は、画面が常に true を送るので起きない（出さない）
  - それ以外（409 の承認待ち・実行中 E-CONF-016・もう完了 E-CONF-018・404・503・403 ほか）は、小窓を閉じて帯に赤い知らせ（正本の文・今の `failed` と同じ）を出し、詳細を読み直す。401 は入り直し（共通の扱い）
  - 完了の口の答えを待つ間は、「このまま完了にする」と「戻って付ける」を押せない形（二度押しでも口は 1 回・小窓は閉じない）
- **帯の案内**：完了できるときの案内文 `MSG.completeHint` と「完了にする」は今のまま。**案内の下の要約「実施事項は全部終わりました」（実施事項の区画を読んでいた）は外す**（区画が無くなる。代表に聞くこと 4）。`band.tsx` の `BandTicket` から `sections` を外し、`body?: { doc?: unknown } | null` を足す（無い答えは本文の未チェック 0）
- **区画の読みを外す**：`band.tsx` の `sectionOf`（実施事項・完了の条件の区画を読む）と `Section`・`complete-model.ts` の `todoItems`・`checkedNumbers`・`TodoItem`・`complete-dialog.tsx` の項目ごとのチェック・確かめのチェック・`E-VAL-022`・`todo_checked`・`todo_version` を全部外す。`complete-model.ts` は `Completed`・`jstStamp`・`completedLine`・`Problem` だけが残る
- 見た目：`complete-dialog.tsx` は `@/features/F4/doc/doc.css`（K-431 が運ぶ）を import して `k-f4d-unchecked` を使う（F5 の css に同じ規則を複製しない）。値は正本のトークンだけ・生の色・大きさを書かない。画面は役の名前で出し分けず、口の答え（`can.complete`）で出し分ける
- **この葉は詳細の本体（`features/F4/create-ticket/ticket-detail.tsx`）に触らない**：帯には詳細が答えの全体（`d`）を渡している。getTicket が `body` を持つ（K-560）ので、型を広げるだけで渡る
- **本文の道具の決め（代表 2026-11-22・出来合いの部品の機能を絞らずに使う）は、この葉に当たらない**：この葉は本文の道具を作らない・使わない。本文については、チェックの箱（`taskItem` の `checked`）の未チェックを数えるだけで、後の葉が足す節と印は数え方に関わらない。下絵の部品（`features/F4/doc`）で使うのは完了の小窓と題の行のボタンだけ
