## 目的

問い合わせに答えるとき、運営が 1 社の中を見るだけで開けるようにする（行為 A64・D-125.128・D-128.68）。規約で先に許可をもらっているので顧客に聞かずに開くが、理由は必須・1 時間まで・開く前に本人確認を取り直す。見たことは運営の記録と会社の記録の両方に残す（D-128.108）。

- **openPeek**（ops:peek・step_up always）：許可の行 `support_access_grants` を作る
- **closePeek**（ops:peek・開いた本人）：閉じる。期限が来たら何もしなくても効かなくなる（`app.ops_grant_ok` が期限を見る・時間で動く仕組みは作らない）
- **見ている間の帯**（D-156.10・D-128.68）：稼働状況の口（K-955 の getServiceStatusForMember）の `bands` に kind `peek` を入れる。**2 つの側がある**
  - 運営の側：見ている運営の人が `x-tenant-id` でその会社の顧客の画面を開いたとき（K-1008 の uh-peek の帯）。`notice_id` に**許可の id**（＝closePeek の道の `:id`）
  - 顧客の側：その会社の人の画面（「運営が中を見ています」）。`notice_id` は null

- **見るだけ**：運営が会社の人の書く口を呼ぶのは、許可があっても 403（K-1001 の入口・K1001-API-009）。この葉は読む許可を作るだけ
- **帯の形**（K-1004 の bands の 1 つ・K-955 の `app.member_peek_band()` を create or replace）：
  - 運営の側（`app.role() = 'ops'`・`app.tenant_id()` がその会社・自分の効いている許可がある）：`{ kind: "peek", notice_id: <許可の id>, title: <会社名>, state: <理由>, note: null, ref: null, from: <許可の created_at>, to: <expires_at>, closable: false, more: 0 }`（`note`・`ref` は K-1004 の bands の欄・D-156.45。中を見る帯では null）

  - **閉じる口に渡す id の欄は `notice_id`**（帯の欄の並びは K-1004 で決まっていて欄を足さない。kind が peek で notice_id が null でないときだけ、それは許可の id）
