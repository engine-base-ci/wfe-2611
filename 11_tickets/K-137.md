## 目的

決定のトレースの検査 `scripts/ci/trace_gate.py` は、決定ログの節の「### 決めたこと」の表の各行を「文」として読み、文の番号を**表の上から何行目か**で決めている（`_clauses` の `len(rows) + 1`）。行の先頭の欄には `D-128.62` のように ID を書いているのに、その ID は番号に使っていない。

そのため、別々の作業で足した決定の行が、取り込みの順で表の中の位置を入れ替えると、同じ ID の行が別の番号として数えられ、導出物の `source` や要件一覧の「文 n/n」が別の決定を指してしまう。いまは取り込むたびに人が番号を振り直している（2026-11-07 に 2 回）。人が振り直しを覚えている形は飛ばされる（L-004）。PM が見つけた（2026-11-07）。途中で見つけたものはその場で直さずチケットにする（D-128.147）。

## 完了の条件

- [ ] 文の番号を、行に書いた ID（`D-128.62` の `.62`）から取る。ID の欄が無い表（古い節）は、今までどおり位置で数える形を残すか、ID を書くよう決めて全部の節を直すかを、切るときに決めて書く
- [ ] 行に書いた ID と表の位置が食い違う・同じ ID の行が 2 つある・節の番号と行の ID の頭が違う（`D-128` の節に `D-127.3` の行）ときは赤になる
- [ ] 行の順を入れ替えただけでは、要件一覧（trace_gate.py --index）と検査の結果が 1 字も変わらない
- [ ] 同じ形の検査（決定ログの表を位置で読む所）がほかにもあるかを全文検索で洗い、あれば同じ形にそろえるか、別のチケットにする（L-008）
- [ ] チケットの CI（act）が緑

## 前提と制約

- 決定は導出物から逆引きできなければ未反映と同じ（decision-traceability.md）。番号の付け方を変えても、今ある `source` の参照が全部同じ決定を指したまま残ること（変える前と後で、参照先の決定の文が同じかを機械で比べる）
- 要件一覧（01_hearing/要件一覧.md）は作り手が作る物。手で直さない
- 決定ログの中身（文）は変えない。新しい決定も足さない

## 実施事項

- [ ] 作る役：`_clauses` と、文の番号を使う所（T1〜T12・--index・clauses_out・clauses_noobj・amends）を一覧にする
- [ ] 作る役：分岐（ID あり・ID なし・ID と位置がずれる・同じ ID が 2 つ・別の節の ID・行を入れ替える）と試験の行

## テスト仕様と確認の結果

| 確認項目 | 種類 | 判定のしかた | 結果 |
|---|---|---|---|

| 今ある参照が同じ決定を指す | ① 単体 | 直す前と後で、全部の source が指す決定の文の題名を比べて同じ | |
