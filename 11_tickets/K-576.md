- 口：`restoreTicketItems`（POST /api/v1/tickets/:id/item-changes/restore）。入力は `from`（戻す先の点＝K-433 の `points` の `n`）と `to`（今見ている点）の 2 欄だけ（strict）。`from` から `to` までの正味の変わり（K-433 の `diff`）を、`from` の形に戻す
- **戻せる項目は D-150.52 の 5 つ**：開始日・期限・優先度・予定時間・会社が足した項目。**状態・担当者・親は戻さず**、答えに「戻せなかった項目と訳」を返す。**予定時間を直す組は K-583**（段 5 の `updateTicket` の組 `ticketEstimate`・`app.ticket_estimate_set`・変更の行の `field` は `estimate_minutes`・`raw_from`・`raw_to` は分の整数か null）なので、この口は予定時間を戻せる項目として戻す（K-433 の `restorable` は予定時間を true にした。2026-11-22 に K-583 を足して D-150.52 のとおりにした）
- **戻せる物だけ戻し、戻せなかった物を答えに返す**（1 つの取引）。1 項目が今の決まりに合わなくても、ほかの項目は戻る。戻せなかった訳は固定の文（下の表）
- 戻す先は**各組の関数を呼んで通す**（決まりを 2 つ持たない・L-002）：期限と開始日＝段 8 の K-483 の `app.ticket_due_set`（理由が必須・今日より前は E-VAL-012・開始が期限より後は E-VAL-028・親子の期限 E-DUE-005／006）／優先度＝K-440 の `app.ticket_sort_set`（高に戻すなら理由が要る）／予定時間＝K-583 の `app.ticket_estimate_set`（0〜100000 の分か null）／会社の項目＝K-564 の `app.ticket_fields_set`（型・選択肢・必須）。各組の関数が自分の**変更の行・担当者へのお知らせ・証跡**を書く

- **戻し方（組ごと・順に）**：①期限と開始日（どちらかが diff に在れば 1 回。体は `{due_on?, start_on?, due_reason: "点 N の形に戻した"}`・`expected_*` は送らない）②優先度（体 `{priority, priority_reason?}`）③予定時間（体 `{estimate_minutes}`・`raw_from` が null なら空に戻す）④会社の項目（まず全部を 1 回の `app.ticket_fields_set` で。断られたら**項目ごとに 1 つずつ**試し、断られた項目だけ戻せなかったとする）。①で断られたら、期限・開始日を**別々に**試し直す。各組の関数の答えが `changed: false`（すでにその値）の項目は、戻した扱いにも戻せなかった扱いにもしない。**組の関数は断るとき何も書かない**（K-483・K-440・K-564 の決め）ので、試し直しで二重に書かない。**書く所で DB が例外を出したら取引ごと戻す**（503・E-PAGE-003・何も残らない）
- **戻せなかった訳**（固定の文・画面は答えの文をそのまま出す。下の「代表に聞くこと」2）：期限が今日より前＝「期限は今日より前の日には戻せません」・開始日が期限より後＝「開始日が期限より後になるので戻せません」・親の期限より後＝「親の期限より後になるので戻せません」・子の期限より前＝「子の期限より前になるので戻せません」・高の理由が無い＝「優先度を高に戻す理由が残っていないので戻せません」・選択肢が無い／その種別に出ない／型が合わない＝「選択肢が無くなったので戻せません」（型・種別の分も同じ文）・必須の項目を空に戻す＝「必須の項目は空に戻せません」・消した項目＝「この項目は消されたので戻せません」・予定時間が範囲外＝「予定時間は戻せません」（`raw_from` が 0〜100000 の整数でない行だけ・通常は起きない）・状態・担当者・親は K-433 の `why`

- **断る番号**（控え帳 2026-11-20 16:51・20:50・21 日 01:15）：形の誤り（`from`・`to` が無い・整数でない・1 未満・知らない欄）は 422（欄つき・契約に書ける形だけ）／404＝無い点・無い・見えない・消した・別の会社（入口の `NOT_FOUND` か E-PAGE-001・欄なし）／409＝E-ITM-001（完了）・E-ITM-002（先に変えられた）・E-ITM-003（戻す物が無い）。404・409 の体は `{error, code, message, action, undo, support_code}` だけで `field`・`details`・`detail` を付けない。番号の枠は新しい頭 `E-ITM-`（001〜019・本枝と `c/段*` の errors に `E-ITM-` は 1 つも無い）。**判定の順は上の「断る順」のとおり**

## 依存の理由

- K-433: 要る — 点の番号と正味の変わり（`app.ticket_item_changes`）・戻せる印・`bodyReply`・hooks の置き方・試験の土台 `ticket-body.harness.ts` を使う。この葉は点の数え方も正味の出し方も持たない（K-433 の関数を呼ぶ）
- K-564: 要る — 会社の項目を戻す `app.ticket_fields_set`。変更の行の生の値 `raw_from`・`raw_to` を K-564 が足し（つなぎで決まった）、K-433 の `diff` がそれを通す
- K-574: 依存にしない — 「項目を戻しました」のまとめの行（`changes` の `field: "item_restore"`・`from`・`to`・`note`）の画面の文（「項目を版 N の形に戻しました」・N は `from`）は K-574 の文の表の既定の規則（K574-UN-008）が持つ。この葉は口と DB だけなので文の規則は書かず、**まとめの行の `changes` の形を契約の言葉（鍵 `field`・`from`・`to`・`note`・`from` は点の番号の字）で K-574 の `ChangeEntry` と合わせる**だけにした（形は言葉で合うので、画面の葉の取り込みを待たない）。K-579 も文の規則を足さない
- K-440: 要る — 優先度を戻す `app.ticket_sort_set`。同じ op の ears の断片を足し合わせる道具の直しも K-440 が運ぶ（この葉は自分の断片 `K-576.json` に足す）
- K-583: 要る — 予定時間を戻す `app.ticket_estimate_set`（0〜100000 の分か null）。変更の行の `field` は `estimate_minutes`・生の値 `raw_from`・`raw_to` は分の整数か null。同じ `updateTicket` の組を足す葉で、この葉はそれが本線に入ってから始める（K-433 の `diff` の `restorable` を true にした訳）
- K-483: 要る — 期限と開始日を戻す `app.ticket_due_set`（理由が必須・今日より前・開始が期限より後・親子の期限）。段 8 の葉で、この葉はそれが本線に入ってから始める。**K-483 に足してもらう物は無い**（変更の行の日付は生の値の字・`due_reason` は決まった文で通る）。ただし関数の答えの error の言葉（`past`・`order_state`・`over_parent`・`under_child`・`done`）を読むので、言葉を変えるなら知らせてもらう（段 8 への頼み）
