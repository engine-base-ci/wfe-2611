## 目的

作る面の区画（目的・完了の条件・実施事項…）が、項目名と textarea の縦の羅列になっている。キャンバス（Create の本文の箱）では、区画は見出しつきの文書（h2 16px・下に線・「必須」の印・ひな形の補足は見出しの中）として並ぶ（調べの C4）。

## 完了の条件

- [ ] 下の 13 行（K225-UI-001〜013）が緑
- [ ] 頭の canvas の組 tickets-new-sections（Create）を enrolled にし、キャンバスとの突き合わせ（K225-UI-012・G70）が組の幅で緑
- [ ] 幅 320・375・768・1024・1440 の横溢れが 0（K225-UI-009）。押した結果（作る口が呼ばれない・下書きに残る）まで実ブラウザで見る
- [ ] チケットの CI が緑

## 前提と制約

分類: UI

- 先に要るチケット：K-224（本文の箱 `section[aria-label="本文"]` を置く器）・K-217（区画の見出しの土台 .k-section h2）・K-218（入力欄・項目名の値）・K-216・K-238（突き合わせ）
- 区画の並びと必須は種別のマスタ（kind_sections）のまま。必須の確かめ（E-VAL-013）・下書きに残す・作る口は K-60 のまま
- 欄は今の TextArea のまま（文字で書く）。太字・表・チェックリストなど 14 個の道具の帯は出すが押せない（D-145.8）。グレーは正本の使えない状態の部品（button-disabled・不透明度 0.55・正本に在る）
- 区画の見出しの余白は絵ごとに違う（作る画面 20／22・6、詳細 28・8）。PM の決め「正本に部品を 2 つ持つ（名前を分ける）」により、このチケットが正本に section-heading（詳細・K-217 の .k-section h2 の値）と section-heading-form（作る画面）を足す（K-218 の後・依存）
- 値は全部 --k-* のトークン（生の色・大きさを書かない）
- 試験を書いた後は変えない（D-128.125）

## 確かめたこと（切る段・2026-11-16）

キャンバス Create の本文の箱：`section[aria-label="本文"]`（白・1px #DDE2E9・角丸 8・overflow hidden）。上に道具の帯（太字・斜体・見出し・箇条書き・番号つき・チェックリスト・表・画像・引用・コード・注意の枠・#・@・リンク と「種別「タスク」のひな形 ・ 「/」で部品」）。中の文書は padding 8px 28px 24px・max-width 900。h2 は 16px・margin 20px 0 6px（最初）／22px 0 6px（2 つめから）・padding-bottom 6px・下に 1px #DDE2E9。必須は h2 の中の b「必須」（#B91C1C・12px）。補足は h2 の中の span（11px・#4A5563・太さ 400）。

K-217 の区画の見出しの土台（`.k-section h2`）は詳細の画面（TicketDetail）の値（margin 28px 0 8px）。作る画面の区画は Create の値（20／22px 0 6px）。正本に部品を 2 つ持ち、`.k-section h2` は section-heading、`.k-create-doc h2` は section-heading-form のトークンを読む。

突き合わせの組 tickets-new-sections（K-216）の本文の箱の画面の側は `.k-panel form`（K-224 で器が替わると当たらない）。
