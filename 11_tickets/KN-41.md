## 目的

取引先の表。契約の API がこの表を読み書きできるようにし、行の守りで範囲の外を見せない。

## 完了の条件

- [ ] migration（packages/db/migrations）で表と列ができる
- [ ] 表ごとに RLS の決まり（packages/db/policies）がある
- [ ] repository の表の一覧（packages/db/src/repository.ts の TABLES）に入っている
- [ ] 場合表（access-matrix.json）にこの表の行があり、全部通る
- [ ] CI が緑のまま

## 前提と制約

- 表は ER 図 §16 と「足す列」が正。足すだけで、消す・名前を変える migration は作らない
- 全部の表に `tenant_id` と RLS。RLS を飛ばす鍵はサーバーで使わない（ZT3）
- 範囲（グループ・本人・担当・承認する人・取引先の人・運営の 1 時間の許可）は RLS の条件と API の権限の両方で見る（ZT4・D-073）
- `tickets.client_id` に外部キーを付け、取引先の人（client）は見せると決めたチケット（client_share）だけ読める決まりを足す（D-128.100・KN-38 の申し送り）

## 実施事項

- [ ] 表：`clients` `client_groups` `client_contacts` `client_requests` `acceptances`
- [ ] 列：`clients.email_domain`・`client_requests.questions`・`acceptances.reminded_at`
- [ ] RLS の範囲：社内：取引先の見える人（全員／担当グループだけ）。取引先の人：自分の取引先の中だけ・見せると決めた項目だけ
- [ ] 種（seeds）に見本の行を足す（試験と画面の見本用）
- [ ] `zt_gate.py --lower-baseline` で記録を下げる

## テスト仕様と確認の結果

| 確認項目 | 種類 | 判定のしかた |
|---|---|---|
| migration が新しい DB に全部入る | ① 機械 | `pnpm ci:migration-integration` |
| 表の RLS が有効 | ① 機械 | `pnpm ci:rls-enabled` |
| 範囲の外の行が取れない（場合表の全行） | ① 機械 | `pnpm ci:access-matrix`（この表の行を access-matrix.json に足す） |
| 会社をまたいで読めない | ① 機械 | 別の会社の文脈で SELECT して 0 行（わざと壊す試験） |
