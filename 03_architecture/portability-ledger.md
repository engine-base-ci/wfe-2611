## 意図的に使わないと決めたベンダー固有機能（越境を発生させないため）

| 機能 | 使わない理由 | 代替 |
|---|---|---|
| Supabase Auth | RLS が `auth.uid()` に固定され、**DB 層まで移行不能になる** | Better Auth（自前 Postgres 上） |
| Supabase Realtime | 移行時に作り直しになる | SSE ＋ ポーリング |
| Supabase Edge Functions | 移行時に作り直しになる | Hono の API 層 |
| Supabase 固有拡張（pgsodium / supabase_vault / pg_graphql） | `pg_dump` で詰まる | 標準拡張のみ（pgvector / pg_trgm） |
| Supabase Storage クライアント | S3 互換 API を使えば越境しない | AWS SDK（S3 互換エンドポイント） |
| Vercel 画像最適化 | 自前ホストで動かない | sharp を同梱 |
| Vercel on-demand ISR | 複数インスタンスで共有ストレージが要る | 使わない |

## 差し替えを実行するときの手順

1. 本台帳の全エントリの代替手段を確認する（現在 0 件）
2. `dependency-boundaries.json` の `allowed_paths` の中だけを差し替える（業務ロジックは触らない）
3. CI の import 境界検査・関門検査が緑であることを確認する
4. 移行後に台帳を空に戻す
