# Kaname 影響マップ ── 決定ごとに何がどこまで波及するか

作成 2026-09-07 / 目的：**一点だけ見て判断しない**ため。決定が触る層を全部並べる。

## 0. 最重要：実行経路は 2 つとも Must。実装は減らない

| | Bridge 経路 | **サーバー経路** |
|---|---|---|
| 誰が使うか | 既定の顧客（サブスク持ち） | ① Bridge を入れられない顧客<br>② BYOK（顧客の API キー）<br>③ 運営マネージド<br>④ 常時稼働が要る顧客 |
| Must か | **Must** | **Must**（4 つの場面で必須） |
| エージェントループ | Claude Code が持つ | **自前で作る** |
| ツール（bash・file・web・MCP） | Claude Code が持つ | **自前で作る** |
| 承認機構 | Claude Code の permission | **自前で作る** |
| サンドボックス | 不要（作業フォルダ制限のみ） | **必須**（Microsandbox / Firecracker） |
| ストリーミング | Bridge が中継 | **自前で作る** |
| LLM 費用の計測・請求 | 不要（顧客のサブスク） | **必須** |
| 実装量 | 小 | **大（本体）** |

**結論：サーバー経路の実装が本体で、Bridge 経路はその上に乗る薄い層。**
「Bridge があるから軽い」は誤り。**両方作る。**

## 2. 決定ごとの波及の中身

### A. 実行経路 2 つ

| 層 | 何が起きるか |
|---|---|
| API | 経路を 1 関数で決める（Atelier の `llm_route` 相当）。経路ごとに別 API を作らない |
| 実行基盤 | **サーバー経路のエージェントループを自前で作る**。ツール定義・並列実行・中断・再開 |
| ホスティング | 長時間実行が要る → **Vercel の関数上限（300 秒）では不足**。Railway / Fly.io / ECS が要る |
| Bridge | ジョブの取得・実行・結果返却。承認要求の中継 |
| セキュリティ | サーバーで顧客のコードが動く → **実行層までテナント分離**（サンドボックスをテナント単位で） |
| 課金 | サーバー経路は LLM 費用が発生 → **トークン計測・上限・請求**が必要 |
| コスト | サンドボックス基盤 ＋ 長時間実行ホスティングで **月 +2〜5 万** |
| 段階 | Bridge 経路を段階 1、サーバー経路を段階 2 に置く（両方 Must だが順序をつける） |
| 画面 | **能力表**が要る。経路によって「できること」が違うのをグレーアウトで示す |

### B. API 分離（アプリ対応）

| 層 | 何が起きるか |
|---|---|
| フロント | Next.js は「API を叩く画面」に徹する。Server Actions に業務ロジックを置かない |
| API | **独立した API 層を作る**（Hono 等）。OpenAPI で契約を持つ |
| 認証 | **トークンベース**にする（Cookie 前提にしない）。アプリからも使える |
| Bridge | Bridge も同じ API を叩く。Web・アプリ・Bridge の 3 クライアントが同じ契約を使う |
| コスト | API を別ホスティングに置くと **月 +5,000〜2 万** |
| 段階 | 今やらないと段階 5 で数週間の手戻り |

### C. 認証を Better Auth に

| 層 | 何が起きるか |
|---|---|
| API | 認証ミドルウェアを自前で持つ。セッション検証・組織スコープ |
| DB | ユーザー・セッション・組織テーブルを自前スキーマで持つ |
| **DB（RLS）** | **`current_setting('app.tenant_id')` で書ける** → クラウド非依存になる |
| Bridge | Bridge のトークン発行・失効を自前で設計 |
| セキュリティ | 退会・停止・権限変更で**発行済みトークンを即失効**させる仕組みが要る（Atelier GAP-245） |
| 段階 | 段階 0（土台）で作る。後から入れ替えは不可能に近い |

### D. RLS で auth.uid() を使わない

| 層 | 何が起きるか |
|---|---|
| API | 全リクエストで `SET app.tenant_id` / `app.user_id` を発行する共通処理 |
| DB | 全テーブルの RLS を `current_setting()` ベースで書く |
| セキュリティ | **設定漏れがあると全テナントが見える**。CI で全テーブルの RLS を機械検査する |
| 段階 | 段階 0。1 つでも例外を作ると原則が崩れる |

### E. 動的台帳

| 層 | 何が起きるか |
|---|---|
| フロント | **1 つの画面が定義を読んで描く**。react-jsonschema-form ＋ TanStack Table |
| API | 定義の CRUD ＋ 動的クエリ生成。**任意のクエリを許すと SQL インジェクション**になるので制約が要る |
| DB | JSONB ＋ 型付きカラムの混在。**インデックス戦略が難しい** |
| 実行基盤 | AI が台帳定義を読んで書き込む |
| 課金 | 台帳の数・行数が制限の対象になる |
| 段階 | **段階 1 の最難関**。ここが動かないと何も動かない |

### F. 複数 LLM プロバイダ

| 層 | 何が起きるか |
|---|---|
| API | プロバイダ抽象層（litellm 相当）。**能力表**を持つ |
| 実行基盤 | プロバイダごとにツール定義の形式が違う → 変換層 |
| Bridge | Claude Code / Codex / Gemini CLI の 3 種を起動できる |
| 画面 | 能力が無い機能は**グレーアウトして理由を出す**（黙って動かないのを禁止） |
| 課金 | プロバイダごとに単価が違う → 計測を分ける |
| コスト | 実装コストが増える。運用コストは顧客負担なので上がらない |

### G. 資格情報 vault

| 層 | 何が起きるか |
|---|---|
| API | 資格情報の登録・参照 API。**参照は ID だけを返し、実体は返さない** |
| DB | 暗号化して保存。テナントごとに鍵を分ける（エンベロープ暗号化） |
| 実行基盤 | 実行器だけが復号できる。**AI には一切渡さない** |
| Bridge | Bridge が復号してブラウザに注入。**Bridge のログに出さない** |
| セキュリティ | 退会・権限変更で即失効。漏洩時の影響範囲を証跡から特定できる |
| コスト | Infisical セルフホスト（月 +3,000〜） or AWS KMS（従量） |

### H. 長時間実行

| 層 | 何が起きるか |
|---|---|
| API | 実行を非同期で受け、状態を返す。同期実行にしない |
| DB | ジョブテーブル ＋ 状態遷移 ＋ 再開ポイント |
| 実行基盤 | **Hatchet / Temporal / DBOS** のいずれか。プロセスが落ちても再開できる |
| ホスティング | **Vercel では不足**。Railway / Fly.io / ECS |
| 画面 | 進捗の逐次表示（SSE）。中断・再開の操作 |
| コスト | 常時起動のワーカーが要る → **月 +1〜3 万** |

### I. マルチデバイス

| 層 | 何が起きるか |
|---|---|
| フロント | 320 / 375 / 768 / 1024 / 1440 で機能同等。**横スクロールを数値で測る** |
| API | 同じ API を全デバイスが叩く（B と同じ） |
| 認証 | デバイスごとのセッション管理 |
| 画面 | **承認と会話はスマホで完結**できないと意味がない |

### J. 覚えた操作

| 層 | 何が起きるか |
|---|---|
| API | 手順の保存・取得・更新 |
| DB | 手順を「意味の並び」で保存。バージョン管理 |
| 実行基盤 | 再生エンジン（Stagehand の observe/act キャッシュ相当）＋ 自己修復 |
| Bridge | ここで実行される（既定） |
| 課金 | **習得済みは LLM 費用 0 円**。学習中と自己修復だけ課金対象 |
| コスト | **運用コストを劇的に下げる中核**。ここが動くかで原価が変わる |
| 段階 | 段階 1。これが無いと「毎回高い」になる |

### K. スコープ 4 層

| 層 | 何が起きるか |
|---|---|
| フロント | 使わない層は画面に出さない（一人社長には部署が見えない） |
| API | 全リソースで「どの層のものか」を判定して返す |
| DB | 層を表す列 ＋ 優先順位の解決ロジック |
| 認証 | 権限が層ごとに違う |
| セキュリティ | **層をまたいだ参照を絶対に許さない**。CI で検査 |
| 課金 | プランによって使える層が変わる |

### L. 証跡

| 層 | 何が起きるか |
|---|---|
| API | 全変更を記録。**追記専用**（更新・削除させない） |
| DB | 追記専用テーブル ＋ 保持期間 ＋ パーティション |
| Bridge | Bridge の全操作も記録してサーバーへ送る |
| セキュリティ | 顧客が自分でエクスポートできる。**運営も改竄できない** |
| コスト | ログの保存量が増える → 月 +3,000〜1 万 |

### M. 会話（D-057・D-062・D-066）

| 層 | 何が起きるか |
|---|---|
| フロント | 会話モード（専用画面）と右パネル（作業画面）が **同じ会話を購読**。部品は 1 組（選択肢・承認カード・受領・引用・停止・失敗）を assistant-ui の上に自前で載せる（自前実装リスト L1〜L8） |
| API | AG-UI のイベント列（text / tool_call / state / interrupt）を SSE で流す。承認の割り込みは **関門の承認要求**と同じ実体 |
| DB | `conversations` に 領域／対象／分岐元、`messages` に kind／選択肢／自信／引用／取り消し先 |
| 実行基盤 | 生成中の段階（読んでいる／配っている／確認している）と **停止**を、Bridge・サーバー両経路で同じイベントに揃える |
| Bridge | PC が閉じている＝送れない。会話側は「起きたら続き」に落とす（失敗の種類ごとの回復） |
| 段階 | 段階 1（会話は段階 1 の Must）。右パネルのトグル・3 層の絞り込みも段階 1 |

### N. 目標の層・依存・かけたもの（D-058・D-061・D-063）

| 層 | 何が起きるか |
|---|---|
| フロント | 目標の木は **ログイン中の個人まで** 落ちる。層ごとの可視範囲（上をどこまで／下をどこまで）。横の引き取り。「かけたもの」列を目標・施策に |
| API | 足す／渡す／担当を変える／改訂する／無くす を **1 つの依存規則**で処理し、行き先のないタスクをゼロにする（無くしたら「行き先のない」一覧に落とす） |
| DB | `goals` の層と可視範囲、`tasks.goal_id` null 可（行き先なしの検出）、`task_handovers`、`measures` の予算・実コスト、`ledger_records.goal_id / measure_id` |
| 認証 | 可視範囲は RLS の述語に入る（層ごとの「見せる範囲」） |
| 段階 | 個人の層と依存規則は段階 1。部署層の配分は段階 3 |

### O. タスクの一日の型と見え方（D-068）

| 層 | 何が起きるか |
|---|---|
| フロント | 今日＝朝の計画（候補にチェック → 確定。見込み合計 vs 使える時間）と夕方の持ち越し。タスクの行は 状態・次の一手・目標への寄与・担当（人／AI社員）・見込み／実時間・期限。見え方はリスト／カンバン／カレンダー／タイムラインで **URL に持つ**。キーボードとまとめ操作。画面の言葉は「引き継いでもらう／引き継ぐ」 |
| API | 朝の確定・持ち越しの振り分け・詰まりの一手 を 1 本ずつ。見え方の切り替えは読み取りだけ（書き込み無し） |
| DB | `daily_plans`（新設）、`tasks.next_action / estimate_minutes / actual_minutes / planned_for / blocked_reason_id / blocked_since`。状態は 4 つのマスタ |
| 実行基盤 | AI社員の行の状態（実行中／承認待ち／止まっている）は `action_runs` から描く。「PC が閉じている」は Bridge の接続状態から |
| Bridge | PC が閉じている間の AI社員のタスクは「詰まっている（起きたら続き）」に落とす |
| 段階 | 段階 1（一人で回る）。カレンダーの外部予定（Google カレンダー）は段階 4 |

## 4. この表の使い方

- **新しい決定をするたびに、この表に行を足す。** 影響列を全部埋めるまで決定を確定しない
- 「◎」が付いた層は、その決定によって**設計が決まる**。後から変えられない
- 段階列が「◎」の決定は、**段階の順序そのものを変える**
