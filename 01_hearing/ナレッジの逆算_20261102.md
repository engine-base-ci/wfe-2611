# ナレッジの逆算（2026-11-02）

決定ログのナレッジ（D-125.20・.34・.108〜.114）と、知っていることを分身の部屋にまとめた D-128.40 をもとに、「人が何をしに来るか」から逆に出す。

## 1. なぜナレッジがあるか

会社のやり方を、人にも分身にも毎回聞かずに分かるようにするため。

- 人は、やり方が分からないときに読む
- 分身は、チケットを進めるたびに読む（チケットの「参照するもの」は必ず読み、ほかも必要なら探して読む）
- 仕事をするたびに、ページが少しずつ正しくなっていく（チケットの完了のときに分身が直す案を出す）

短い決まり・好み・実例（記憶）は分身の部屋の「知っていること」にある。ナレッジに置くのは、人が書く長めの文書（手順・仕様・会社のやり方）だけ。

## 2. 誰が、どれくらい来るか

| 人 | 来るとき | 頻度 |
|---|---|---|
| メンバー | やり方を調べる／自分のページを書く | 時々 |
| マネージャー・権限のある人 | グループやワークスペースのページを書く・直す／分身の直す案を確かめる | 週に数回 |
| 分身 | チケットを進めるたびに読む（人には見えないので、使われ方を見せる） | ずっと |

## 3. 来てすること（5 つ）

| すること | 頻度 | 置き場所 |
|---|---|---|
| 1 探して読む（「請求書の送り方は？」） | 多い | ナレッジのいちばん上は探す欄。ことばで聞くと、ページと該当する行が出る |
| 2 書く・直す | 時々 | ページはチケットの本文と同じ 1 枚の文書（「/」で部品・版つき）。読んでいる画面のまま直す |
| 3 分身がどう使っているか見る | 時々 | ページの右に「使われ方」：読まれた回数・どのチケットで・最後に読んだ日。長く直されていない・差し戻しに関わったページには印 |
| 4 分身の直す案を確かめる | 週に数回 | チケットの完了のときに出た案を「直す案」に集め、差分を見て 入れる・直して入れる・入れない（理由） |
| 5 置き場と直せる人 | まれ | ページごとに置き場（ワークスペース全体・層・グループ・自分）。直せるのは、自分のページは本人、ほかは権限のある人 |

## 4. 出さないもの

- 記憶（好み・事実・実例）・守ること・やり方 → 分身の部屋（D-128.40）。ナレッジからは「関わる決まり」として札で見せるだけ
- 外を調べたときの参照（URL・タイトル・見た時刻） → そのチケットの実行の記録に残す（ナレッジの画面には出さない）
- GitHub・外の Wiki とのつなぎ → 後のフェーズ（D-125.36）

## 5. 画面

| 画面 | 中身 |
|---|---|
| ナレッジ（ホーム） | 上に探す欄。左のパネルは置き場（すべて・ワークスペース全体・層・自分）と「直す案」「古くなっていそう」。右はページの一覧（題名・置き場・版・分身が使った回数・最後に直した日） |
| ページ | チケットの本文と同じ文書。上に置き場・版・直せる人・「直す」。右のパネルは「使われ方」と「版」のタブ |

| 新しいページ（小窓） | 題名・置き場・ひな形（手順・仕様・空）だけ |

## 6. ほかのナレッジのツールを調べて分かったこと（2026-11-02 追記）

| ツール | 仕組み | 取り入れること |
|---|---|---|
| Confluence | スペースの中にページの木（親子）。ページ情報に「このページへのリンク（被リンク）」が出る | 置き場の中にページの木を持つ。ページの下に「このページを参照しているもの」を出す |
| Notion（Wiki） | 持ち主（Owner）と「確かめ済み（Verification）」に期限を付けられる。期限が切れると持ち主に知らせる。AI の答えは必ず出典を示し、見られるページだけを使う | ページに持ち主と確かめ期限。探すと出典つきの答え。見えないページは答えに使わない |
| Guru | カードごとに確かめる人と間隔（30 日・90 日・期限なし）。期限が来ると知らせ、古いものは見られた数・コメントを見てしまう。エージェントが毎日点検して確かめ・確かめ外しをする | 確かめの間隔を選べる。分身が使われ方を見て「古くなっていそう」を出す（決めるのは人） |
| Document360 | 下書き → 公開 → 期限が来たら「古い」（公開のまま印が付く）。古いものは一覧で絞り込める | 状態を 下書き・公開・しまった の 3 つに、確かめの印を重ねる |
| Slab | 1 つのページを複数の話題（トピック）に入れられる。検索は読まれた数・リンク・言及で並ぶ | 置き場は 1 つ、話題（タグ）は横断で複数。検索はよく使われるものを上に |
| esa | 書きかけ（WIP）のまま共有でき、WIP の間は知らせが飛ばない。履歴が残るので気兼ねなく直せる | 下書きでも人に見せられ、知らせは公開のときだけ。版が残るので直すのをためらわない |
| Outline | コレクションの中に入れ子のページ。被リンクを下に出す。ひな形から作れる | 入れ子・被リンク・ひな形 |
| Obsidian | 書きながら [[ ]] でページをつなぎ、つないだ先には被リンクが自動で出る。タイトルが書いてあるのにリンクになっていない「まだつないでいない言及」も出る。ページのまわりのつながりを図（ローカルグラフ）で見る。フォルダより、ほかのページを集める「まとめのページ（MOC）」で整理する考え方がある。上の項目（properties）で表の見え方（Bases）を作る。中身はふつうの Markdown のファイル | 書くときに [[ でつなぐ（分身もつなげそうな所を教える）。ページの右に「つながり」：まわりの図とまだつないでいない言及（1 回でつなぐ）。木に加えて、形「まとめ」で横断の入口を作れる。Obsidian・Notion・Markdown から取り込み、いつでも Markdown で書き出せる |

## 7. ナレッジとして成り立たせる骨組み

### 1 ページが持つもの

| もの | 中身 |
|---|---|
| 置き場 | ワークスペース全体・層・グループ・自分 のどれか 1 つ（誰が読めて誰が直せるかが決まる） |
| 親ページ | 置き場の中の木。入れ子にできる（例：請求 › 請求のルール） |
| 持ち主 | 正しさに責任を持つ人（1 人かグループ）。既定は書いた人 |
| 状態 | 下書き（知らせない・分身は読まない）／公開／しまった（探しても出ない・分身も読まない） |
| 確かめ | 最後に確かめた日と次の期限（30 日・90 日・半年・期限なし）。期限が来たら持ち主に知らせ、印が付く（公開のまま） |
| 話題 | 横断のタグ（複数）。例：請求・インボイス・セイコー |
| 版 | 公開するたびに増える。ひとことを残す |
| つながり | このページが参照しているもの／このページを参照しているもの（ページ・チケット・決まり・取引先）。書くときに [[ でつなぐ。まだつないでいない言及を出す。まわりを図で見る |
| 使われ方 | 分身が読んだ回数・どのチケットで・よく読まれる箇所・差し戻しに関わったか |

### 正しさを保つ流れ

1. 書く：下書きで書き、公開する（ひとことを残す）
2. 使う：人が読み、分身がチケットのたびに読む（読んだものはチケットの記録に残る）
3. 直す案：チケットの完了で分身が直す案を出す → 持ち主が確かめる
4. 確かめる：期限が来たら持ち主が「確かめた」か「直す」か「しまう」を選ぶ。分身が使われ方から点検の結果を添える
5. しまう：使われなくなったものはしまう（版と記録は残る）

### 分身が読むときの決まり

- 公開のページだけ読む（下書き・しまったものは読まない）
- 確かめ期限が切れたページも読むが、そのことを実行の記録に残し、持ち主に知らせる
- 置き場の権限の中だけ（担当者が見られないページは読まない）

### 画面（作り直す）

| 画面 | 中身 |
|---|---|
| ナレッジ（ホーム） | 左のパネル＝置き場とページの木。上＝探す（出典つきの答え）。「自分が持ち主で確かめ期限が来た」「直す案」「最近見た」 |
| ページ | 道すじ（置き場 › 親 › ページ）・持ち主・確かめ・状態・話題。目次・本文・子ページ・このページを参照しているもの。右＝使われ方／版／やり取り |
| ページを書く（下書き） | 下書きの帯（知らせない・ほかの人には前の版が見える）。公開するときにひとこと |
| 確かめること | 期限が来たページの一覧。分身の点検の結果を添え、確かめた／直す／しまう |
| 直す案 | 差分・出たチケット・理由。入れる／直して入れる／入れない |
| 新しいページ（小窓） | 題名・置き場と親ページ・持ち主・確かめの間隔・形（手順・決まり・まとめ・白紙） |
| つながり（ページの右） | まわりの図（1 つ先まで）・まだつないでいない言及 |
| 取り込む | Obsidian・Notion・Markdown から。フォルダ→木、[[リンク]]→つながり、#タグ→話題。下書きで入れる |
