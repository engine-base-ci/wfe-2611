# 取引先の逆算（2026-11-02）

決定ログの N クライアント（D-125.43・.46・.47・.121〜.124）と、取引先のルール（D-126.12）をもとに、「人が何をしに来るか」から逆に出す。先に近いツールを調べた。

## 1. なぜ取引先があるか

Kaname を使う会社の多くは、取引先の仕事をしている（受託・代理・請求・問い合わせ）。取引先は 3 つの役目を持つ。

1. **その取引先のことが 1 か所に集まる**：チケット・依頼・検収・決まり・先方の人・関わるナレッジ
2. **先方の人の入口になる**：依頼を出し、進みを見て、成果物を確かめる（クライアントの場所）
3. **分身のふるまいを変える**：その取引先のチケットでは、取引先の決まり（宛名・CC・締め など）が効く

## 2. 誰が、どれくらい来るか

| 人 | 来るとき | 頻度 |
|---|---|---|
| 取引先の担当（社内） | 届いた依頼をさばく／取引先のいまを見る／検収を頼む | 毎日〜週に数回 |
| チケットを持つメンバー | 先方の宛先や決まりを調べる | 時々 |
| 分身 | その取引先のチケットを進めるたびに、取引先の決まりと先方の人を読む | ずっと |
| 先方の人（クライアント） | 依頼を出す／進みを見る／成果物を確かめる | 週に数回 |

## 3. ほかのツールを調べて分かったこと

| ツール | 仕組み | 取り入れること |
|---|---|---|
| Linear（Customers・Customer Requests） | 顧客ページに、その顧客の要望と、つないだ課題・プロジェクトが並ぶ。要望を課題につなぐ | 取引先のページに、依頼とそこから作られたチケットを並べる。依頼はチケットにつながったまま残る |
| Basecamp（Clients） | 何でも既定で社内だけ。見せるものだけ「クライアントに見える」にし、目のしるし（見える）と鍵（社内だけ）で区別する。ひな形に見せ方を持たせられる | 既定は見せない。見せる項目には目のしるし。種別ごとに既定の見せ方を決めておける |
| Zendesk（Organizations） | 既定は自分の依頼だけ見える。組織を「共有」にすると同じ組織の人の依頼も見える | 同じ取引先の人は互いの依頼が見える（D-125.121）。先方の人の役割は「依頼できる」「見るだけ」 |
| Attio（会社のレコード） | 左に会社の項目、真ん中にやり取りの時系列、関係（人・案件）をタブで持つ | 取引先のページ：右に取引先の項目と先方の人、真ん中に「いま」と時系列、タブでチケット・依頼・決まり |
| Moxo・Copilot（クライアントポータル） | 先方は迷わない簡単な画面。承認・催促・記録がそろう。部品を寄せ集めると先方の体験がばらける | クライアントの場所は Kaname の画面と別の、ごく簡単な 1 画面。確認してほしいもの・依頼・進み の 3 つだけ |
| Backlog（ゲスト） | 社外の人はゲストで招き、プロジェクトを分け、「課題の追加のみ」「閲覧のみ」に絞れる | 先方の人は取引先の中だけに入り、社内のチケット・メモ・検査・決定ログは見えない（D-125.122） |

## 4. 来てすること

### 社内

| すること | 頻度 | 置き場所 |
|---|---|---|
| 1 届いた依頼をさばく（分身の案で詳細・期限をやり取り → 受ける＝チケットにする／断る） | 多い | 取引先 › 届いた依頼（すべての取引先の依頼が集まる） |
| 2 取引先のいまを見る（検収待ち・期限の近いチケット・新しい依頼・最近のやり取り） | 多い | 取引先のページ › いま |
| 3 検収を頼む（成果物を選び、先方に確かめてもらう。OK が完了の条件） | チケットごと | チケットの詳細から（小窓） |
| 4 取引先の決まりと先方の人を整える（宛名・CC・締め） | 時々 | 取引先のページ › 決まり・人 |
| 5 先方の人を招き、見せ方を決める（既定は見せない） | 時々 | 取引先のページ › 人と見せ方 |
| 6 取引先を足す | まれ | 取引先の一覧の「＋ 取引先」 |

### 先方（クライアントの場所）

| すること | 置き場所 |
|---|---|
| 依頼を出す（書くと分身が足りないことを聞く・D-125.47） | ＋ 依頼を出す |
| 確認してほしいもの（検収）に答える：OK／直してほしい | いちばん上 |
| 依頼のやり取りと、見せてもらっている仕事の進み・期限・成果物 | その下 |

## 5. 見せ方の決まり

- 既定はすべて社内だけ。チケットの項目ごとに「見せる」を選ぶ（進み・期限・成果物・先方あての書き込み）。見せている項目には目のしるし
- 種別ごとに既定の見せ方を決めておける（例：請求は 期限・成果物 を見せる）
- 社内のメモ・テスト仕様と確認の結果・決定ログ・分身の実行の記録は見せない（選べない）
- 同じ取引先の人は互いの依頼が見える。役割は「依頼できる」「見るだけ」

## 6. 画面

| 画面 | 中身 |
|---|---|
| 取引先（一覧） | 左のパネル：すべて・届いた依頼・検収待ち。表：取引先・担当・動いているチケット・依頼・検収待ち・最後のやり取り |
| 取引先のページ | 見出しと担当。タブ：いま・チケット・依頼・決まり・人と見せ方。右に取引先の項目と先方の人 |
| 届いた依頼 | 左に依頼の一覧、右に先方とのやり取りと分身のチケットの案。受ける／詳しく聞く／断る |
| 人と見せ方 | 先方の人（役割・招く）と、種別ごとの既定の見せ方。「先方からの見え方」を見本で出す |
| 検収を頼む（小窓） | 成果物・確かめる人・期限・ひとこと |
| クライアントの場所（先方の画面） | 確認してほしいもの・依頼・進んでいる仕事 の 3 つだけ |
| 依頼を出す（先方） | 何をしてほしいか・いつまで・添付。分身が足りないことを聞く |
| 検収（先方） | 成果物を見て OK／直してほしい（どこを） |

## 7. 部署（層・グループ）との関係（2026-11-02 追記・高本さんと決めた）

会社によって、取引先を部署ごとに分けて持つことも、1 つの取引先に 2 つの部署が関わることもある（例：京蟻システムは 契約＝営業、作業＝受託開発）。そこで次のように持つ。

| こと | 決め方 |
|---|---|
| 持ち方 | 取引先はワークスペースに 1 社 1 つ。「担当グループ」をいくつでも付ける。先方の人と取引先の決まりは共通で、二重にしない。チケットは今までどおり、そのチケットのグループの権限で見える |
| 社内で見える人 | ワークスペースの管理 › 設定 で既定を選ぶ（ワークスペースの全員／担当グループの人だけ）。既定は全員。取引先ごとに「担当グループだけ」に絞れる（鍵のしるし） |
| 依頼の届け先 | 担当グループが 2 つ以上なら、担当の分身が中身を見て届け先のグループを案にする（例：作業報告書は保守の仕事なので営業）。取引先の担当者が確かめて変えられる。先方は部署を気にしなくてよい |
