## 2. 分かったこと

### 2.1 通し道が真ん中で切れている

```
登録 → PC をつなぐ → 自分のAIと話す → たたき台 → テストで動かす → 本番に切り替える
  ✅      ✅            ✅               ✅          ✅               ✅
                                                                     ↓
                                     今日 → 承認待ち → 台帳の1件 → 目標 → ふりかえり
                                      ❌      ❌          ❌         ❌       ❌
```

**本番に切り替えた後に、毎日使う画面が無い。** v1 の合格条件「高本さん自身の受託業務が実際に回る」は、
この 5 枚（＋台帳の一覧）が無い限り満たせない。

### 2.2 旧 jobrain の歯止めは「決定による引き上げ」に効かない

| 歯止め | 効く相手 | 効かない相手 |
|---|---|---|

## 3. 第1フェーズ（2026-11-01 user と確定）

> 前の版の「v1.0〜v1.4 の 5 段」は取り下げた。user の判断で、第1フェーズの軸を
> 「目標から逆算」から「チケットを作り込んで実行する」に変えたため。
> 目標はチケットを生成する側として後のフェーズで乗せる（user「チケットを作り込んで実行する状態ができていれば、
> その後の拡張として目標計画や設計からチケットを生成する状態は作れる」）。

### 問い

**自分の受託業務を、チケットに切って → 中身を作り込んで → 確認してOKを出したら AI が実行して →
実行した内容からチケットに戻れる。これが回るか。**
管理として回すための期間・スケジュール・チケットの詳細、ロールと層によるやり取り、運営・CS の運用を含む。

### user の判断（2026-11-01）

| 項目 | 判断 |
|---|---|
| スキルの中身（業務スキル・目標スキル） | アップロードで後から入れる。実装の対象外。必要なのは「アップロード → 装着 → 実行」の道 |
| 実行前の確認 | テスト・確認を入れる。確認結果を見て人が OK を出したら実行してよい。**テスト仕様書の作成と、CI/CD のような独自の検査ロジックが要る** |
| トリガー（時間・出来事） | 第1フェーズに入れない。本筋はチケット中心 |
| チケット | 分類・所属グループ・過去の遡り・最初の作り込みと振り分けをしっかり持つ |
| 層 | 0〜n。同じ層に並ぶ別のグループがある（人材部・営業部）。最下層は個人で、個人も並ぶ。**グループをまたぐ横渡しと、その確認・実行の見え方を設計する** |
| 会社をまたいで学ぶ仕組み | 必要。複数社がいるフェーズに置く |
| 次のフェーズの設計 | そのフェーズに入るときに考える。第1フェーズはそれだけで考える |
