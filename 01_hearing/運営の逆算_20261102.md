# 運営の逆算（2026-11-02）

決定ログ（D-073〜D-077・D-125.125〜.129・D-126.23・D-126.25・D-127.5・D-127.6・D-127.10）をもとに、「運営の人が何をしに来るか」と「顧客と運営の間で何が往復するか」から逆に出す。先に近いツールを調べた。

## 1. なぜ運営の場所があるか

Kaname を使うワークスペースが、止まらずに安心して使い続けられるようにするため。運営がすることは次の 4 つだけ。

1. **気づく**：詰まっている・お金が払われていない・使われていないワークスペースに、言われる前に気づく
2. **答える**：問い合わせに答え、障害やメンテを先に知らせる
3. **お金を回す**：月に 1 回請求書を出し、入金を記録し、払われていなければ知らせ、最後は止める
4. **配る**：全社向けの業務の型（とその版）とプランの中身を出す

## 2. 誰が、どれくらい来るか

| 人 | 来るとき | 頻度 |
|---|---|---|
| サポートの人 | 問い合わせに答える／ワークスペースの様子を見て原因を探す | 毎日 |
| お金の人 | 月初に請求書をまとめて出す／入金を記録する／未入金を追う | 月初と入金のたび |
| 運営の管理者（高本さん） | 気になるワークスペースを見る／止める・再開する／お知らせを出す／業務の型の版を出す／運営の人を足す | 週に数回 |

始めは 1〜2 人が全部を兼ねる。だから画面は少なく、1 社のことは 1 か所に集める。

## 3. 顧客と運営の間で往復するもの（両側から数える）

| 往復するもの | 顧客の側 | 運営の側 |
|---|---|---|
| 問い合わせ | 右上の顔 › 困ったとき・お知らせ › 問い合わせる。自分の問い合わせとやり取りが見える | 問い合わせ（受信箱）で答える。右にそのワークスペースの様子 |
| お知らせ（リリース・障害・メンテ） | ベルの横の「お知らせ」・障害とメンテは上に帯・メンテ中はメンテ中の画面 | お知らせを書く・予定して出す・障害は状態を足していく |
| 請求書と入金 | ワークスペースの管理 › 設定 › 請求書（請求書の一覧・振込先・払ったか） | 今月の請求でまとめて出す・入金を記録・未入金を追う |
| プランを変える | プランを変える（上げるとすぐ・下げると次の請求日から） | 1 社の「プランと請求」に出る。プランの中身は配るもの › プラン |
| 止める・再開 | 止められるとログインできない（先に知らせが届く） | 1 社から止める（理由・先に知らせる）。再開すれば元に戻る |
| 運営が中を見る | 顧客の画面には出さない（規約で先に許可・D-125.128） | 理由を書いて見るだけで開く。誰がいつ何を見たかは運営の記録に残る |
| 業務の型の版 | 業務の型に新しい版が届く（使う・使わないは顧客） | 配るもの › 業務の型 で上げる・検査・版を出す |

## 4. ほかのツールを調べて分かったこと

| ツール | 仕組み | 取り入れること |
|---|---|---|
| Intercom（Inbox） | 新しい会話は「未割り当て」に入り、担当に割り当てる。ビューは絞り込みを保存したもので、割り当ては変えない。右に顧客の情報 | 受信箱の左に「まだ誰も持っていない・自分・返事待ち・済み」。真ん中にやり取り、右にそのワークスペースの様子 |
| Front・Help Scout（共有の受信箱） | 状態は 進行中・返事待ち・済み。「後で」（スヌーズ）にすると指定した日に戻ってくる。共有の受信箱での操作は全員に効く | 状態は 3 つ。「後で」で日を決めて戻す。誰が持っているかを必ず出す |
| Stripe（顧客のページ） | 顧客を開くと、契約・支払い・支払い方法・請求書が 1 枚に並ぶ。請求書は 未払い・支払済・期限切れ で絞れ、CSV で出せる | 1 社のページの「プランと請求」に、プラン・請求書・入金を並べる。今月の請求は状態で絞り、CSV で出す |
| freee 請求書 | まとめて発行・送付。請求と入金の状態を一覧で見る。入金明細と請求を照合して消し込む | 月初に全社の請求書をまとめて出す。入金は 1 件ずつ記録（第1フェーズ）。銀行連携の自動の消し込みは後のフェーズ |
| Chargebee（督促） | 支払いが失敗すると督促の期間に入り、終わったら止める・解約するかを設定で決める | 期限を過ぎたら知らせ、7 日の猶予のあと止める案を出す。止めるのは人が決める |
| Atlassian Statuspage | 障害は 調べている → 原因が分かった → 様子を見ている → 直った と状態を足していく。どの部分に影響するかを選ぶ。メンテは予定して出す | 障害のお知らせは状態を足していく形。影響する部分（画面・分身の実行・PC とのつながり）を選ぶ。メンテは予定して出し、始まると帯とメンテ中の画面になる |
| Notion（管理者の停止） | 止めた人はログインできないが、中身は残り、戻せばそのまま。消すのとは別 | 止めるとログインできない・データは残る・再開すれば戻る（D-125.126 と同じ） |
| 管理画面の「中を見る」（ServiceNow・Pigment ほか） | 見る前に理由を書く・時間で切れる・始まりと終わりを記録・見ている間ははっきりした帯を出す・自分の権限とは別のしるしで動く | 中を見るときは理由を書き、1 時間で切れる。見るだけ（何も変えられない）。上に「運営として見ています」の帯。記録は運営の記録に残す |
| Retool の解約予測のひな形など | 担当・プラン・売上・開始日・活動の少なさで気にかけるべき会社を出す | ワークスペースの一覧に「気にかける」（詰まり・未入金・PC がつながっていない・使われていない）を出す |

## 5. 来てすること

| すること | 頻度 | 置き場所 |
|---|---|---|
| 1 問い合わせに答える（持つ・返す・後で・済み） | 毎日 | 問い合わせ |
| 2 気にかけるワークスペースを見る | 毎日〜週 | ワークスペース › 気にかける |
| 3 1 社の様子を見る（いまの状態・メンバー・プランと請求・問い合わせ・記録） | 問い合わせのたび | ワークスペース › 1 社 |
| 4 中を見る（理由・1 時間・見るだけ） | 時々 | 1 社の「中を見る」 |
| 5 請求書をまとめて出す・入金を記録・未入金を追う | 月初と入金のたび | 請求 |
| 6 止める・再開する | まれ | 1 社の「⋯」 |
| 7 お知らせを出す（リリース・障害・メンテ） | 月に数回 | お知らせ |
| 8 業務の型を上げる・版を出す（節目①） | 時々 | 配るもの › 業務の型 |
| 9 プランの中身と値段を変える（版で持つ・今の契約は変えない） | まれ | 配るもの › プラン |
| 10 運営の人を足す・できることを決める | まれ | 運営の人 |

## 6. 出さないもの

- 全社をまたぐ運営の記録の画面（D-127.6：1 社の「記録」タブで見る。全社の横断は後のフェーズ）
- カード払い・自動の引き落とし（Stripe・段階 2。第1フェーズは請求書払い＋運営が入金を記録・D-125.125）
- 公開の審査・記録した動かし方の一覧・会社向けの型・テスト 5 場面の画面（D-126.23 節目②）
- 運営マネージドの LLM・経路の切り替え（段階 2）

## 7. 画面

左のメニュー（運営の場所。顧客の画面とは別。左上は「Kaname 運営」）：ワークスペース／問い合わせ／お知らせ／請求／配るもの／（下に）運営の人

| 画面 | 中身 |
|---|---|
| ワークスペース（一覧） | 左のパネル：すべて・気にかける・止めている・やめる手続き中。表：名前・プラン・人数・PC がつながる人・今月の実行・詰まり・請求・状態 |
| 1 社 | 見出し（名前・プラン・状態）と「中を見る」「⋯（止める・お知らせを送る）」。タブ：いまの状態・メンバー・プランと請求・問い合わせ・記録。右に会社の情報 |
| 1 社 › プランと請求 | プランと上限の使い方・請求書の一覧（出した・払われた・期限を過ぎた）・入金を記録 |
| 1 社 › 記録 | このワークスペースに運営の誰が何をしたか（中を見た・止めた・入金を記録した・プランを変えた） |
| 中を見る（小窓） | 理由（問い合わせを選ぶか書く）・1 時間・見るだけ。運営の記録に残る |
| 中を見ている | 顧客の画面の上に「運営として見ています・見るだけ・残り 52 分・やめる」の帯 |
| 止める（小窓） | 理由・先に知らせる（すぐ／日を決めて）・止めると何が起きるか |
| 問い合わせ | 左：まだ誰も持っていない・自分・返事待ち・後で・済み。真ん中：やり取りと返す欄（社内メモも書ける）。右：ワークスペースの様子 |
| お知らせ | 一覧：種類（リリース・障害・メンテ）・状態（下書き・予定・出した）・誰に |
| お知らせを書く | 種類・題・本文・誰に（全員・プラン・指定）・出す場所（お知らせの一覧・上の帯・メンテはログイン画面にも）・いつ。障害なら影響する部分と状態 |
| 請求（今月の請求） | 月を選ぶ。まとめて出す・未入金・入金を記録・CSV |
| 入金を記録（小窓） | 入金日・金額・差（足りない・多い）・ひとこと |
| 配るもの › 業務の型 | 全社向けの業務の型の一覧（版・使っているワークスペースの数・検査）。上げる |
| 業務の型を上げる（小窓） | 一式を上げる → 機械の検査（必須の節・資格情報や固有名が入っていない・テスト場面 5 以上・版と変更点）→ 版を出す |
| 配るもの › プラン | プランの中身（人数・分身の実行・ファイルの容量・使える機能）と値段。版で持ち、今の契約は次の更新まで前の版のまま |
| 運営の人 | 運営の人と、できること（問い合わせ・お金・止める・配る・中を見る） |
