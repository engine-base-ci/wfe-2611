# k144.d（K-378）

共有の試験 `../k144-contract.test.ts` に葉が足す分は、本体に行を足さず、ここに `K-<自分の番号>.ts` を置く。
別のファイルなので、葉を同時に作ってもぶつからない。本体は試験を集める時に `../k144-leaves.ts`（readK144Leaves）で番号の順に読む。

- `K-378.ts` は、置き場そのもののつなぎの確かめ（本体が置き場を読み、準備を呼び、葉だけの試験に手助けを渡していることを、本体の回の中で見る）。置き場が在るかぎり消さない
- 置ける名前は `K-<数字>.ts`（0 で始めない）・`_base.ts`（葉の形の型）・`README.md` だけ。ほかの名前・中のフォルダは読む所が止める
- 葉のファイルは `export const leaf: K144Leaf = { … }` の 1 つだけを出す。鍵は 4 つ（どれか 1 つは要る）：
  - `setup(f)`：本体の準備の中で 1 回。自分の口の振る舞い（hooks）を土台に足す
  - `UUID_PARAM_CASES`：入口の uuid の行 `["K144-API-NNN", "<口>", "path" か "query", "<値の名前>"],`。1 行に 1 つ、字のまま書く（契約の形の検査 K144-SHAPE-017 が字で読む。組み立てた行・注にした行は止まる）
  - `BODIES`：その口を叩く時の体（鍵は口の名前）
  - `tests(k)`：葉だけの試験（describe・it）。本体の手助け（`def`・`count`・`writer` など・`_base.ts` の K144Kit）を引数で受け取る
- 止まるもの：同じ行 ID（`"K144-API-NNN…` で始まる字）が本体か別の葉にも在る・同じ葉の中で同じ行 ID が 2 回・同じ口の同じ値の行が 2 つ・BODIES の同じ鍵が 2 つ・知らない鍵・`leaf` のほかの export
- 行 ID の字（uuid の行と、葉だけの試験の題）は二重引用符で書く（`"K144-API-NNN …"`）。読む所の重なりの確かめは二重引用符で始まる字だけを拾うので、バッククォートや一重引用符で書くと重なりを見逃す
- 行 ID の番号は、本体と置き場の全部を見て次の空きを取る。葉のファイルは、その葉のチケットの頭の欄 `carry:` に書いて運ぶ（試験は切る段で書く）
- 動的 import（`await import(…)`）やファイルを読む字を書いたら、自分の `scripts/ci/ci_scope.d/K-<番号>.json` の reads_ok に、このファイルを 1 行足す（上の import で読めば要らない）
