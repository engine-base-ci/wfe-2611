# 多言語に備える決まり（2026-11-02）

第1フェーズは **日本語だけ**。ただし、あとで言語を足すときに作り直しにならないよう、はじめからこの決まりで作る（D-128.56）。

## 1. いまの扱い

- 画面・メール・知らせ・先方の画面（クライアントの場所）はすべて日本語
- 自分の設定の「言語」は「日本語」と出すだけで、選ぶ欄は出さない（言語が 2 つになったら出す）

## 2. 画面の文字

| 決まり | 中身 |
|---|---|
| 辞書から出す | 画面に出る文字は、すべて言語ごとの辞書（例：`messages/ja.json`）から出す。コードに日本語を直書きしない |
| 呼び名（キー） | 「場所.意味」で付ける。例：`ticket.detail.approve`（承認して送る）、`room.knows.addRule`（守ることを足す） |
| 言い回しは文ごと | 文を部品でつながない（語順は言語で変わる）。差し込む値は名前で書く。例：`「{name} さんが {ticket} を渡しました」` |
| 数で変わる言い方 | ICU MessageFormat で書ける形にする（日本語では同じでも、英語では 1 件／2 件で変わる） |
| 辞書の点検 | CI で、辞書に無いキー・使われていないキー・差し込みの名前の食い違い を落とす |

## 3. 日付・時刻・数・お金・並び順

- 日付・時刻・数・お金は、言語と地域の決まりで整える（JavaScript の `Intl`）。「11/2（月）」のような形も辞書の書式として持つ
- 時刻はアカウントの時間帯で出す（保存は UTC）
- 名前などの並び順は言語の決まり（`Intl.Collator`）。日本語で読みの順に並べたいものは、読み（ふりがな）を別に持つ

## 4. 見た目

- 文字が 1.5〜2 倍に伸びても崩れないようにする。幅を決め打ちしない。ボタン・札は省略（…）と折り返しのどちらにするかを部品ごとに決めておく
- 名前の長さはまちまち（外国の名前・長い会社名）。狭い所は短い呼び名、入りきらなければ「…」で切って指を乗せると全部出す。名前を姓と名に分けて持たない（言語で順が違う）
- 画像の中に文字を入れない（言語ごとに作り直しになるため）
- 書体は Noto Sans JP を基本に、ほかの言語の書体へ落ちる順を決めておく
- 右から左に書く言語（アラビア語など）は今は対象にしないが、左右を `start`／`end` で書いておく

## 5. 分身の言葉

- 分身が人に向けて書く文（返事・下書き・知らせ）は、相手の言語で書く（社内はその人のアカウントの言語、先方は先方の人の言語）
- 業務の型・守ること・ナレッジは、書かれた言語のまま分身が読む（勝手に訳して保存しない）
- 言語ごとに分身への指示文を分けない。指示文の中で「相手の言語で書く」と決める

## 6. 持ち方

- 言語はアカウントに持ち（`locale`）、ワークスペースに既定を持つ。いまはどちらも `ja` に決め打ち
- 検索は日本語の分かち書きに合わせつつ、言語を足せる作りにする

## 7. 言語を足すときの手順

1. `messages/ja.json` を写して `messages/en.json` を作り、訳す
2. CI の辞書の点検が通ることを確かめる
3. 自分の設定とワークスペースの既定に、言語の選び肢が出る
4. メールのひな形・先方の画面・知らせの文も同じ辞書から出ているので、追加の作業はない
