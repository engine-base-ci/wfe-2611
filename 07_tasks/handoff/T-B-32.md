# T-B-32 会話が変わったらサーバーから画面に知らせる（DB が member id だけを知らせる・API 1 台 1 本の専用接続で受ける・画面は知らせで読み直す・使えない間は見に行く形に戻る）

発注者が触って確かめる手順です。所要 15〜30 分。**dev（ローカル）で確かめます。** この 1 枚を触って確かめます。

## その前に

1. `bash scripts/dev/up.sh` を実行する（DB → API → 画面が立つ）
2. http://127.0.0.1:3124/signup で会社を作る（メールの確認リンクは `.dev-logs/api.log` の「verify →」の行をブラウザに貼る）
3. そのまま入った状態で下へ

## 手順

1. **http://127.0.0.1:3124/ai/chat** を開く。見出しが「分身の部屋：会話と知っていること」で、横にスクロールしない
2. **http://127.0.0.1:3124/onboard/interview** を開く。見出しが「自分のAIと話す」で、横にスクロールしない
3. 会話が変わると、その人の画面にだけ「変わった」が届いて読み直し、何もしていない間は見に行かない（前提：会話を開いて何もしていない）：別のタブで言う → **8 秒の間 /agent/state を見に行かず、別のタブで言ったことが 1.5 秒以内に出る**
4. 作業中の一言と返事は、知らせを受けて出る（前提：会話の仕事）：言って返事を待つ → **「考えています…」が出て、返事が出る**
5. 知らせの流れがつながらない間は、今までどおり見に行って出る（前提：知らせの流れがつながらない）：別のタブで言う → **6 秒ごとに見に行き、言ったことが出る**
6. サーバーの知らせの接続が落ちたら、画面はつなぎ直して、その後も知らせで出る（前提：知らせの接続を DB の側から切る）：別のタブで言う → **流れがもう一度つながり、言ったことが 1.5 秒以内に出る**
7. ほかの人の会話が変わっても、自分の流れには届かない（前提：2 人がそれぞれ流れを開いている）：もう 1 人が言う → **自分の流れに change が来ない**
8. ログアウトしたら、次の確かめで流れを閉じる（前提：流れを開いている）：ログアウトする → **end:unauthenticated が来て流れが閉じる**
9. 知らせの接続の通信が詰まって確かめの知らせが戻らなければ、落ちたことにして流れに伝える（前提：知らせの接続の通信が詰まる）：20 秒ごとの確かめ（試験では短く） → **受けている全員に down が伝わる**
