# T-B-10 ベクトルを入れる（境を越えたら）：Bridge がモデルを自分で取り・確かめ・直す（Bridge と同じ扱い）・本人の PC で作る・直された行と新しいモデルは裏で作り直す

発注者が触って確かめる手順です。所要 15〜30 分。**dev（ローカル）で確かめます。** この 1 枚を触って確かめます。

## その前に

1. `bash scripts/dev/up.sh` を実行する（DB → API → 画面が立つ）
2. http://127.0.0.1:3124/signup で会社を作る（メールの確認リンクは `.dev-logs/api.log` の「verify →」の行をブラウザに貼る）
3. そのまま入った状態で下へ

## 手順

1. **http://127.0.0.1:3124/search** を開く。見出しが「」で、横にスクロールしない
2. **http://127.0.0.1:3124/setup/bridge** を開く。見出しが「PC をつなぐ」で、横にスクロールしない
3. 人は何もしない。Bridge が自分でモデルを配布元から取り、sha256 が合えば使う。取っている間は進み具合が Bridge の窓と画面に出る（前提：モデルがまだ PC に無い・境を越えた）：何もしない（Bridge が始める） → **進み具合が出て、終わると自己診断の「検索のモデル」が OK になる**
4. 空き容量が足りなければ取り始めない。理由とあと何 GB 要るかを出す（前提：空き容量をわざと減らす）：Bridge が取り始めようとする → **取り始めず、理由が窓と画面に出る（途中で落ちない）**
5. 指紋が合わない・壊れているモデルは使わず、ボタン 1 つで取り直せる（前提：PC のモデルを壊しておく）：自己診断 → 「取り直す」を押す → **壊れていると出て、押すと取り直して OK に戻る**
6. ベクトルは本人の PC で作る（サーバーでは作らない）。本文を直すと、その行だけ作り直す（前提：ベクトルのある記憶が 3 件）：1 件の本文を直す → **直した 1 件だけ content_hash が変わる。サーバーに推論の呼び出しが無い**
7. 新しいモデルを作り直し中で足すと、Bridge が裏で全部作り直し、そろったら切り替わる。そろうまでは古いモデルで探す（前提：ベクトルのある記憶が 5 件・別のモデルを足した）：途中で検索する → 最後まで待つ → **途中は古いモデルの結果。そろった後は新しいモデルだけが active で、古いベクトルは消える**

## 結果

よければ次の 1 行を書いて保存してください（このまま貼って、日付と名前を変える）。

```
OK: YYYY-MM-DD 名前
```

違うところがあれば `NG: 何が違うか` を書いてください。1 行で構いません。
