# T-B-24 規約で自動操作が禁止のサービスと銀行を、全部許可でも本人の PC の上で止める（仕事ごとに使わない道具として渡す・道具を使う直前のフックでコマンドと宛先を調べる・止めたら理由と人への案内・証跡）

発注者が触って確かめる手順です。所要 15〜30 分。**dev（ローカル）で確かめます。** この 1 枚を触って確かめます。

3. そのまま入った状態で下へ

## 手順

1. **http://127.0.0.1:3124/ai/chat** を開く。見出しが「分身の部屋：会話と知っていること」で、横にスクロールしない
2. サービス台帳で forbidden と bank のドメイン（下の階層も）を止める。台帳の版が変わったら次の仕事から効く（前提：台帳に bank のドメイン）：仕事を渡す → **Bridge が受け取る禁止の一覧にそのドメインがある。台帳を変えると次の仕事の一覧が変わる**
3. 仕事を渡すたびに、禁止のドメインへの取り込みを使わない道具として Claude Code に渡す。全部許可でも効く（前提：全部許可の会話）：仕事を流す → **CLI の引数に --disallowedTools の WebFetch(domain:…) が付く**
4. 道具を使う直前のフックで Bash のコマンド・取り込み・ブラウザ操作の宛先を調べ、禁止のドメインなら止める（前提：全部許可の会話）：禁止のサービスを操作させる（curl・WebFetch・ブラウザ） → **フックが止め、止めた理由が自分のAI に返る**
5. 止めたら作業の行に「〇〇 は規約で自動操作が禁止のため止めました」と出し、返事で人への案内（正規の連携・手作業）を示す（前提：止まった仕事）：会話を見る → **作業の行に止めた理由と宛先が出る**
6. 止めたことは証跡（誰の仕事・どのサービス・どの道具）に残る（前提：止まった仕事）：証跡を見る → **bridge_job_events に blocked・audit_events に 1 行**
7. 文字を組み立てて宛先を作るコマンドなどは完全には見抜けないことを、台帳の説明と設計書に書いている（前提：設計書）：読む → **見抜けない形が書かれている**

## 結果

```
OK: YYYY-MM-DD 名前
```
