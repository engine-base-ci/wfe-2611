# T-B-39 2 段階認証（種類を選ぶ・認証アプリは鍵で自動・SMS／メール／スマホ承認はその場で本人に頼む・コードは Bridge だけに・ログインを覚えておく・10 分返事が無ければ止めて本人がいる時間に回す）

発注者が触って確かめる手順です。所要 15〜30 分。**dev（ローカル）で確かめます。** この 1 枚を触って確かめます。

## その前に

1. `bash scripts/dev/up.sh` を実行する（DB → API → 画面が立つ）
2. http://127.0.0.1:3124/signup で会社を作る（メールの確認リンクは `.dev-logs/api.log` の「verify →」の行をブラウザに貼る）
3. そのまま入った状態で下へ

## 手順

1. **http://127.0.0.1:3124/settings/credentials** を開く。見出しが「ログイン情報を預ける」で、横にスクロールしない
2. **http://127.0.0.1:3124/approvals** を開く。見出しが「承認待ち」で、横にスクロールしない
3. 預けるときに 2 段階の種類を選べる（認証アプリ／SMS／メール／スマホで承認／なし）（前提：ログイン情報を預ける（PC をつないで Bridge が動いている））：①「ログイン情報を預ける」で 追加する → サービスに http://127.0.0.1:3124/dev/fake-login?mode=totp → 2段階認証を「認証アプリ」にすると秘密鍵の欄が出る（SMS・なし では出ない） ② 鍵を空のまま 保存する → 文言 ③ JBSW Y3DP EHPK 3PXP を入れて 保存する → **種類が保存され、認証アプリのときだけ鍵の欄が出る。Bridge が 6 桁を作って入れ、行が「ログインできました」。あなたには頼まない**
4. SMS・メール・スマホ承認は、Bridge がコードの画面で止まって本人に頼む。入れたコードは Bridge だけに渡る（前提：SMS の 2 段階があるサービスにログイン）：①サービスに http://127.0.0.1:3124/dev/fake-login?mode=sms&dev=手元1・2段階認証「SMS で届くコード」で預ける ② 行に「…SMSのコードを入れてください」の欄が出たら 246810 を入れて 送る ③ ?mode=push を「スマホで承認」で預け、「スマホで承認した」を押す → **ログインが通り（行が「ログインできました」）、コードは AI の会話にも記録にも出ない（自動テストが DB の出来事・証跡・メッセージに無いことを確かめる）**
5. 通したログインの状態を本人の PC に残し、毎回は聞かない（前提：一度通したサービス（上の ②））：同じ的（?mode=sms&dev=手元1）をもう一度預ける → **コードを聞かれずに「ログインできました」（サービスが求めたときだけ聞く）**
6. 10 分返事が無ければ、その仕事は理由つきで止め、次に本人がいる時間に回す（前提：コードを頼んだまま 10 分（自動テストは 20 秒））：?mode=sms&dev=手元2 を預け、コードを入れずに待つ → 「もう一度試す」を押してコードを入れる → **仕事が理由つきで止まり（「返事が無かったので止めました」）、何度も試さない。押したときだけ 1 回試し直す**
