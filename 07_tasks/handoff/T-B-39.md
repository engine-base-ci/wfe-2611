# T-B-39 2 段階認証（種類を選ぶ・認証アプリは鍵で自動・SMS／メール／スマホ承認はその場で本人に頼む・コードは Bridge だけに・ログインを覚えておく・10 分返事が無ければ止めて本人がいる時間に回す）

発注者が触って確かめる手順です。所要 15〜30 分。**dev（ローカル）で確かめます。** この 1 枚を触って確かめます。

## その前に

1. `bash scripts/dev/up.sh` を実行する（DB → API → 画面が立つ）
2. http://127.0.0.1:3124/signup で会社を作る（メールの確認リンクは `.dev-logs/api.log` の「verify →」の行をブラウザに貼る）
3. そのまま入った状態で下へ

## 手順

1. **http://127.0.0.1:3124/settings/credentials** を開く。見出しが「ログイン情報を預ける」で、横にスクロールしない
2. **http://127.0.0.1:3124/approvals** を開く。見出しが「承認待ち」で、横にスクロールしない
3. 預けるときに 2 段階の種類を選べる（認証アプリ／SMS／メール／スマホで承認／なし）（前提：ログイン情報を預ける）：種類を選ぶ → **種類が保存され、認証アプリのときだけ鍵の欄が出る**
4. SMS・メール・スマホ承認は、Bridge がコードの画面で止まって本人に頼む。入れたコードは Bridge だけに渡る（前提：SMS の 2 段階があるサービスにログイン）：承認待ちでコードを入れる → **ログインが通り、コードは AI の会話にも記録にも出ない**
5. 通したログインの状態を本人の PC に残し、毎回は聞かない（前提：一度通したサービス）：もう一度ログインする → **コードを聞かれない（サービスが求めたときだけ聞く）**
6. 10 分返事が無ければ、その仕事は理由つきで止め、次に本人がいる時間に回す（前提：コードを頼んだまま 10 分）：待つ → **仕事が理由つきで止まり、何度も試さない**

## 結果

よければ次の 1 行を書いて保存してください（このまま貼って、日付と名前を変える）。

```
OK: YYYY-MM-DD 名前
```

違うところがあれば `NG: 何が違うか` を書いてください。1 行で構いません。
