# T-A-15 API 会社のやり方が、人が辞めても消えないようにしたい — データ・API（3 endpoint）

発注者が触って確かめる手順です。所要 15〜30 分。**dev（ローカル）で確かめます。** この 1 枚を触って確かめます。

## その前に

1. `bash scripts/dev/up.sh` を実行する（DB → API → 画面が立つ）
2. http://127.0.0.1:3124/signup で会社を作る（メールの確認リンクは `.dev-logs/api.log` の「verify →」の行をブラウザに貼る）
3. そのまま入った状態で下へ

## 手順

1. **http://127.0.0.1:3124/company-model** を開く。見出しが「会社モデル」で、横にスクロールしない
2. **http://127.0.0.1:3124/duties** を開く。見出しが「担当業務」で、横にスクロールしない
3. **http://127.0.0.1:3124/settings/ledgers** を開く。見出しが「台帳の形」で、横にスクロールしない
4. **http://127.0.0.1:3124/onboard/draft** を開く。見出しが「たたき台を確かめる」で、横にスクロールしない
5. **http://127.0.0.1:3124/onboard/golive** を開く。見出しが「本番に切り替える」で、横にスクロールしない
6. **http://127.0.0.1:3124/records** を開く。見出しが「台帳」で、横にスクロールしない
7. 本番に切り替えるとき、未設定（ログイン情報が無い担当業務・目標の無い AI社員）が残っている（前提：たたき台あり・ログイン情報未登録）：本番に切り替えるを押す → **文言「本番に切り替える前に 2 つ足りません：経理社員の freee のログイン情報／営業社員の目標。埋めると切り替えられます」が出て、一手「足りないものを埋める／その AI社員は止めたまま本番へ」が押せる。守っている層：UI／API／DB**

## 結果

よければ次の 1 行を書いて保存してください（このまま貼って、日付と名前を変える）。

```
OK: YYYY-MM-DD 名前
```

違うところがあれば `NG: 何が違うか` を書いてください。1 行で構いません。
