# T-B-14 資格情報の置き場を Infisical に（会社ごとの置き場・暗号文だけ・Machine Identity で入る・起動時に確かめる）

発注者が触って確かめる手順です。所要 15〜30 分。**dev（ローカル）で確かめます。** この 1 枚を触って確かめます。

## その前に

1. `bash scripts/dev/up.sh` を実行する（DB → API → 画面が立つ）
2. http://127.0.0.1:3124/signup で会社を作る（メールの確認リンクは `.dev-logs/api.log` の「verify →」の行をブラウザに貼る）
3. そのまま入った状態で下へ

## 手順

1. **http://127.0.0.1:3124/settings/credentials** を開く。見出しが「ログイン情報を預ける」で、横にスクロールしない
2. 資格情報を保存すると、Infisical の会社の置き場（/tenants/<会社>）に暗号文だけが入る（前提：Infisical を設定した staging）：資格情報を保存する → **Infisical の画面で見ても中身は暗号文。表（credentials）には参照 ID だけ**
3. 別の会社の置き場は見に行かない（前提：会社 A と B が預けた）：A の文脈で B の参照 ID を解く → **見られない（この参照は見られない）**
4. Infisical に入れない設定では staging／本番は起動しない（黙ってメモリに落とさない）（前提：INFISICAL_CLIENT_SECRET を間違える）：API を起動する → **起動時の確認 secrets:vault で落ち、/health は 503 と理由**
5. 秘密の操作が毎分 96 回（上限の 8 割）に来たら、運営（info@）にメールが届く（1 時間に 1 回まで）（前提：上限を小さくした設定（secretPerMinute））：資格情報を続けて読む → **運営にメールが 1 通届く。同じ 1 時間には繰り返さない**

- 退会・停止で、その会社の置き場の資格情報が全部失効する … 会社を停止する口は T-I-05（出来事の依存処理 → 全失効）で作る。置き場側の一括失効（revokeTenant）は本物の Infisi
