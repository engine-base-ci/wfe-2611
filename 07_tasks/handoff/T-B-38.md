# T-B-38 ログイン情報を預けたらその場で 1 回ログインだけ試す（入れたらそのまま出る・ほかの操作はしない・結果を預けたものの行に出す）

発注者が触って確かめる手順です。所要 15〜30 分。**dev（ローカル）で確かめます。** この 1 枚を触って確かめます。

## その前に

1. `bash scripts/dev/up.sh` を実行する（DB → API → 画面が立つ）
2. http://127.0.0.1:3124/signup で会社を作る（メールの確認リンクは `.dev-logs/api.log` の「verify →」の行をブラウザに貼る）
3. そのまま入った状態で下へ

## 手順

1. **http://127.0.0.1:3124/settings/credentials** を開く。見出しが「預けたログイン情報」で、横にスクロールしない
2. 預けたら 1 回ログインし、入れたらそのまま出る。ほかの操作はしない（前提：正しいログイン情報を預けた（PC をつないで Bridge が動いている））：①「ログイン情報を預ける」で 追加する → サービスに http://127.0.0.1:3124/dev/fake-login?mode=ok → ログイン名 me@example.com・パスワード S3cret-Plain! を入れて 保存する ② 行の「1 回のログイン」が「順番待ち／試しています」になり、PC で Chrome が開いて閉じる → **預けたものの行に「ログインできました」と出る。読み直しても同じ。Chrome はそのまま閉じ、ほかの操作はしない**
3. 入れなければ理由を出す（パスワードが違う／2 段階が要る／CAPTCHA／規約で禁止なので試さない）（前提：違うパスワード・2 段階・CAPTCHA・禁止のサービス）：①同じ的で違うパスワード（wrong-1234）を預ける ② ?mode=2fa を預ける ③ ?mode=captcha を預ける ④ 台帳で禁止のサービス名で預ける ⑤ PC をつながずに預ける → **①「ログイン名かパスワードが違うようです」＋預け直しの一手 ②「2 段階認証が要ります」③「CAPTCHA が出ました」④「規約で自動操作が禁止なので試しません」⑤「PC をつなぐと試します」。どれも 1 回で止まり、何度も試さない**
4. 鍵は実行の間だけ受け取り、入力したら捨てる。ディスクにも AI にも渡らない（前提：預けたログイン情報）：ログインを試した後、画面を Cmd+F でパスワードを探す。DB（credentials・bridge_jobs・audit_events）と Bridge の置き場（browser-profile）にも無いことを自動テストが確かめる → **入力された後、鍵がメモリにもファイルにも残っていない（画面・DB・証跡・Chrome の置き場のどこにも値が無い）**

## 結果

よければ次の 1 行を書いて保存してください（このまま貼って、日付と名前を変える）。

```
OK: YYYY-MM-DD 名前
```

違うところがあれば `NG: 何が違うか` を書いてください。1 行で構いません。
