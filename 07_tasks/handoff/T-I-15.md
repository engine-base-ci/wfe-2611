# T-I-15 流れ J-07 P6 人が増えたら を最後まで通す（L2）

発注者が触って確かめる手順です。所要 15〜30 分。**dev（ローカル）で確かめます。** 登録から最後まで、止めずに続けて通します。

## その前に

1. `bash scripts/dev/up.sh` を実行する（DB → API → 画面が立つ）

招待の URL は画面がまだ無いので、次で作ってください（出た URL をブラウザに貼る）。

```bash
bash scripts/dev/invite.sh
```

## 手順

1. 人を招いて見える範囲を決める（http://127.0.0.1:3124/members） → **招待を発行、スコープを結ぶ**
2. 抜ける人の依存を片づける（http://127.0.0.1:3124/members/:id） → **依存の表どおりに移す／失効させる。証跡に残す**
3. 問い合わせを書く（http://127.0.0.1:3124/inquiry） → **問い合わせを保存。運営の受信箱へ。証跡に残す**
4. お知らせを読む・通知の届け先を選ぶ（http://127.0.0.1:3124/notices） → **お知らせと稼働状況を読む。通知の設定を保存**
5. プランと請求書を見る（http://127.0.0.1:3124/billing） → **プラン・利用量・請求書を読む。プラン変更を申請**
6. 自分のアカウントを整える（http://127.0.0.1:3124/account） → **名前・メール・パスワード・2 段階認証・端末を保存。変更は即失効の対象（G-14）**
7. 会社の設定を決める（http://127.0.0.1:3124/settings/company） → **会社名・請求先・データの所在・タイムゾーンを保存**
8. 取り込む（http://127.0.0.1:3124/import） → **添付を保存し、台帳の下書きレコードを作る（本番には人が押してから）**
9. 外部サービスの連携と可否を見る（http://127.0.0.1:3124/services） → **サービス台帳を読む。正規連携（OAuth）を関門経由で結ぶ**
10. 運営にサポートアクセスを許可する（http://127.0.0.1:3124/audit） → **範囲・期限つきの許可を保存。運営が見た記録を顧客の証跡に残す**
11. 1人の権限を決める（http://127.0.0.1:3124/members/:id） → **層への所属・役割・権限の表を保存。既存セッションを無効化**
12. AI社員を増やす・人に託す（http://127.0.0.1:3124/ai-staff） → **AI社員を作成・付与。プラン上限を判定**
13. 誰が何をしたかを確認する（http://127.0.0.1:3124/audit） → **証跡を人・期間で集計**
14. このAI社員の中身を見る（http://127.0.0.1:3124/ai-staff/:id） → **担当業務・託し先・ルール・証跡を読む**

## 結果

よければ次の 1 行を書いて保存してください（このまま貼って、日付と名前を変える）。

```
OK: YYYY-MM-DD 名前
```

違うところがあれば `NG: 何が違うか` を書いてください。1 行で構いません。
