# T-B-11 探す（自分のAI が PGroonga で言い換えを広げて探し、読んで選ぶ・人は言葉の一致で探す・探した件数と時間を記録して境を越えたら運営に知らせる）

発注者が触って確かめる手順です。所要 15〜30 分。**dev（ローカル）で確かめます。** この 1 枚を触って確かめます。

## その前に

1. `bash scripts/dev/up.sh` を実行する（DB → API → 画面が立つ）
2. http://127.0.0.1:3124/signup で会社を作る（メールの確認リンクは `.dev-logs/api.log` の「verify →」の行をブラウザに貼る）
3. そのまま入った状態で下へ

## 手順

1. **http://127.0.0.1:3124/search** を開く。見出しが「探す」で、横にスクロールしない
2. 言い換えでも見つかる（「請求の件」で「インボイスの送付」が出る）。自分のAI が検索語を広げて何度か探す（前提：記憶・台帳がある・Bridge がつながっている）：自分のAI に「請求の件どこ？」と聞く → **言葉が一致しない「インボイスの送付」も出て、どう探したか（使った言葉）が 1 行で出る**
3. 言葉がそのまま一致するものは必ず出る（前提：本文に「KNM-1234」を含む台帳の行）：探す画面で「KNM-1234」と入れる → **その行が出る**
4. 自分のAI が候補を読んで並べ、なぜそれかを添える。見えない行は候補にも理由にも出ない（前提：候補が 10 件以上）：自分のAI に聞く → **並びと理由が出る**
5. 探すたびに件数と時間が残り、境（5 万件・20 秒以上が週 10 回）を越えたら運営に知らせが出る（前提：テスト会社で境を越える記録を作る）：運営の画面を開く → **その会社に「ベクトルを入れる判断」の知らせが出る**
6. 高本さんの実データで答えが分かっている質問 20 個（言葉が一致しないものを半分以上）を自分のAI に探させ、当たった数を記録する。17 問に届かなければ T-B-10 を前倒しにする（前提：高本さんの実データ・質問 20 個と正解）：自分のAI に 1 問ずつ聞く → **当たった数と外れた質問が 07_qa/test-specs/search-eval.md に残る。17 問以上ならベクトルなしで完了**
