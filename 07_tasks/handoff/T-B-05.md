# T-B-05 鍵を受け取る（Bridge は Infisical に入らない。Kaname の関門 C8 が解いた値を実行の間だけ受け取り、入力したら捨てる。ディスクに書かない）

発注者が触って確かめる手順です。所要 15〜30 分。**dev（ローカル）で確かめます。** この 1 枚を触って確かめます。

## その前に

1. `bash scripts/dev/up.sh` を実行する（DB → API → 画面が立つ）
2. http://localhost:3124/signup で会社を作る（メールの確認リンクは `.dev-logs/api.log` の「verify →」の行をブラウザに貼る）
3. そのまま入った状態で下へ

## 手順

1. **http://localhost:3124/setup/bridge** を開く。見出しが「PC をつなぐ」で、横にスクロールしない
2. 鍵を受け取る（Bridge は Infisical に入らない。Kaname の関門 C8 が解いた値を実行の間だけ受け取り、入力したら捨てる。ディスクに書かない）（前提：Bridge を入れた PC）：①「ログイン情報を預ける」（/settings/credentials）で 追加する → サービス「発注ナビ」→ ログイン名・パスワード・2段階認証の鍵を入れて 保存する ② 一覧に「預けた · 預かり先の番号 …」の行が出る。読み直しても同じ ③ 画面のどこにも入れたパスワード・鍵の文字が出ない（Cmd+F で探す） ④ この行の結果列が PASS（実 Chrome の自動確認：本人の Bridge が動いている仕事のためにだけ受け取り、使った後に消え、証跡 credential.bridge_resolve（C8）が 1 行。他人の鍵・終わった仕事・届かない・欠けた応答は成功にしない） → **画面と DB と証跡に値が無い（預かり先の番号だけ）。Bridge は動いている仕事のためにだけ受け取り、使った後は消え、証跡は関門 C8 で 1 行。※実際のログインに使うのは T-B-38（その場で 1 回試す）で触れる**

## 結果

よければ次の 1 行を書いて保存してください（このまま貼って、日付と名前を変える）。

```
OK: YYYY-MM-DD 名前
```

違うところがあれば `NG: 何が違うか` を書いてください。1 行で構いません。
