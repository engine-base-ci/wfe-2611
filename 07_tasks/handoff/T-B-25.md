# T-B-25 自分のAI が Kaname の道具（MCP）で聞き取ったことをたたき台に置く（目標・台帳・担当業務とAI社員を置く・直す・外す・覚える・読む。鍵はその仕事の間だけ・聞かずに使える・証跡。Bridge は答えを待つ間を上限に数えない）

発注者が触って確かめる手順です。所要 15〜30 分。**dev（ローカル）で確かめます。** この 1 枚を触って確かめます。

## その前に

1. `bash scripts/dev/up.sh` を実行する（DB → API → 画面が立つ）
2. http://localhost:3124/signup で会社を作る（メールの確認リンクは `.dev-logs/api.log` の「verify →」の行をブラウザに貼る）
3. そのまま入った状態で下へ

## 手順

1. **http://localhost:3124/onboard/interview** を開く。見出しが「自分のAIと話す」で、横にスクロールしない
2. **http://localhost:3124/onboard/draft** を開く。見出しが「たたき台を確かめる」で、横にスクロールしない
3. 会話の仕事ごとに、Bridge が本人の Claude Code に Kaname の道具（kaname）を渡す。会話でない仕事には渡さない（前提：会話の仕事・まとめの仕事）：仕事を渡す → **会話の仕事だけ --mcp-config の kaname とその仕事の鍵が付く**
4. はじめの設定で会社のことを話すと、自分のAI が目標・台帳・担当業務とAI社員を置き、たたき台の画面にそのまま出る（前提：Bridge をつないだ）：「たたき台を置いて」と話す → たたき台を開く → **目標・台帳・担当業務とAI社員のカードに置いたものが出る**
5. 鍵はその仕事の間だけ・本人の会社にだけ効く。終わった仕事の鍵・別の会社の物・知らない道具では書けない（前提：終わった仕事の鍵・別の会社の目標）：道具を呼ぶ → **401／422 で書けない。別の会社の目標は変わらない**
6. 許可のモードが毎回聞くでも、Kaname の道具は許可の問いを出さずに使える（前提：毎回聞くの会話）：たたき台を置かせる → **許可の問いが出ずに置かれる**
7. 道具で書いたことは証跡（誰の仕事・どの道具・何を）に残る（前提：置いた後）：証跡を見る → **audit_events に agent.goal_created 等が 1 件ずつ**
8. Bridge が仕事を止める目安は何も進まない時間で、本人の答えを待っている間は数えない（前提：問い合わせに 10 分以上答えない）：答える → **止まらずに続きが動く。何も出ないまま上限を過ぎたときだけ止まる**

## 結果

