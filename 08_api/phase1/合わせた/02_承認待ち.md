# 第1フェーズの API ── 承認待ち（案・2026-11-03）

キャンバスの承認待ちの画面 1 枚ずつ「何を読み・何を押すか」から逆に出した（D-128.78）。チケットの詳細の承認の帯（D-128.20）も同じ API を使う。

## 1. 画面 → 読むもの・押すこと → API

#### 段 6 の口の書き足し（葉ごとの段落）

<!-- 段6:K-739 -->
承認の「確認」は、そのチケットの確認項目（`test_specs`・消していない行）から読むたびに出す（D-153.3・数だけ）。口の鍵・型は変えず、値の中身だけが変わる。

| 口 | 鍵 | 中身 |
|---|---|---|

- 済み＝チェックが付いている行（付けたのが AI でも人でも同じ）。承認の後に付けた・外した・足した結果も、読むたびに今の確認項目で数える（履歴は持たない）
- だれが・いつ確かめたか・AI の根拠は答えに出さない（やり取りの記録の行に在る・D-150.39・D-150.40）
- 読めない人は前のとおり（詳細は 404・一覧に出ない）。口の文の数・取引の数は増えない（DB の関数 `app.approval_checks_overlay`・`app.approval_detail_checks`・`app.approval_page_checks` を同じ 1 つの文の中で重ねる）

<!-- 段6:K-768 -->
まとめて承認（D-153.11・D-153.5）は、確かめと承認の 2 つの口で通す。条件（D-128.86 の「取り消せる物だけ」）の縛りは外した：取り消せない物も対象。

| 口 | 体 | 答え（201） |
|---|---|---|
| `POST /approvals/bulk/preview`（previewBulkApproval・何も書かない） | `approval_ids`（任意・uuid の並び 1〜50 個）。無ければ自分が承認する承認待ちの成果物の全部 | `{ eligible: [{ approval_id, ticket_id, number, title, irreversible, unchecked }], excluded: [{ approval_id, reason }], count, irreversible_count, unchecked_count }` |
| `POST /approvals/bulk`（bulkApprove） | `approval_ids`（必須・uuid の並び 1〜50 個）。画面は確かめの `eligible` の並びを渡す | `{ updated: [{ approval_id, ticket_id, number, run_id, pc }], skipped: [{ approval_id, number, title, reason }] }` |
| `GET /approvals/queue`（listApprovalQueue） | 各行の `check_summary`（字） | 成果物の承認は「4 ／ 5 済み」、確認項目が無ければ「検査なし」。渡しの行は前のまま `""`。札・並べ替えを付けた一覧（K-748）も同じ字 |
| `GET /approvals/{id}`（getApproval） | `checks`（配列）・`check_summary`（字） | 確認項目 1 行ずつ `{ id, text, checked }`（作った順）・一覧と同じ字 |
| `GET /action_runs/{id}`（getActionRun） | `checks`（object） | `{ state: none／partial／all, counts: { done, total }, summary, rows }` |
| `GET /tickets/{id}/runs`（listTicketRuns） | 各行の `checks` | `{ state, counts, summary }`（行は持たない） |

- 1 件ずつ取引を分け、古い物から順に 1 件承認する口と同じ関数 `app.approval_decide` で承認する（守りは関数のまま）。一部が決まっていても、通った物は承認される
- できなかった理由は 4 つ：`decided`（先に決まった・取り下げた）・`not_approver`（担当者でない）・`not_writable`（書けない）・`unavailable`（無い・見えない。番号と題名は null）
- 「全部」が 50 件を超えたら 409・E-APR-030（選んで承認する）。確かめの後に増えた承認待ちは、その回には入らない
- 途中の 1 件で守りの判定か DB が落ちたら 503・E-PAGE-003。それまでに承認した物は承認のまま（画面は承認待ちを読み直す）
- チェックの無い確認項目が残っていても承認できる（件数を出すだけ）。まとめての証跡 `approvals.bulk` は 1 回 1 行・件数だけ（書けなくても承認は残る）
