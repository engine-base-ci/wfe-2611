画面ごとの API の表（01〜10）がそろったので、契約（08_api）を第1フェーズの画面だけで作り直し、守りの漏れを CI で止める形にした。

## 1. 契約を作り直した

| こと | 数・場所 |
|---|---|
| 画面から出した API | **361 本**（35 画面・数だけの API とチケットの形をまとめて 13 本減らした・D-128.111） |
| 外した API | 49 道すじ（53 行）。1 本ずつ根拠の決定と理由を `08_api/retired-endpoints.json` に書いた。後のフェーズの画面の推測の API は D-128.112、画面から出した API に置き換えた汎用の API は D-128.78 |

## 2. 入口で直した穴（fail-closed）

| 穴 | 直し方 |
|---|---|
| API の入口は「ログインしているか」と「運営か」しか見ておらず、**取引先の人や PC の印でも社内の API を通れた** | 入口（`apps/api/src/contract/op.ts`）が契約の役（社内・運営・取引先・PC・ログイン前）と合わない人を 401／403 で止める |
| **まだ作っていない API が、表の素の読み書きとして動いた**（「メンバーを止める」がメンバーの行を作る、「外す」が行を消すだけ、など） | 素の読み書きで動かしてよいのは `08_api/generic-ok.json` に理由つきで書いた 9 本だけ。ほかは振る舞い（hooks）を書くまで 501 |
| **道すじが別の API に吸われた**（`/approvals/history` が `/approvals/:id` に、`/clients/link-candidates` が `/clients/:id` に） | 決まった名前の段を変数の段より先に登録し、道すじのファイルを最初の段ごとにした |

`pnpm audit` で critical 5・high 11 が見つかった（Next.js の画像の最適化から外の人がコードを動かせる、better-auth で別の人としてログインできる、DOMPurify・Tinypool など）。どれも同じ大きな版の中で直った版に上げ、high 以上は 0 になった（low 2・moderate 5 が残る。本番の前の関門で 0 にする）。型の検査・Web のビルドは通った。

## 6. 試験の結果

- DB（pgvector つきの Postgres）で全部の試験を回した。今回の変更で落ちたものは全部直した
- 元から落ちているもの（今回の変更の前から同じ）：Bridge のログインの確認（実ブラウザの環境）・成果物の置き場の 1 件・DB の役割のパスワードの 1 件・Bridge の配布物の 1 件。`ci:choke` と `ci:errors-used` も前から赤
- 古いテスト仕様の行のうち、決定で外した口・意味が変わった口（預ける・外す）の行は、理由と決定 ID を名前に残して飛ばした。新しい画面のテスト仕様で書き直す
