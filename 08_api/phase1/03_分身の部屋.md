## 2. 守りの考え方（ゼロトラストの決まりから）

- **自分の分身のことは本人だけ**（`self`）。会話・記憶・覚えたいことは、管理者も運営も中身を見ない。運営が見るのは「中を見る」の 1 時間の許可のときだけ（ZT9）
- **分身は呼んだ人の権限の中でだけ動く**。本人が見られないチケットやページは分身も読めない。外に出る操作は承認を通る（ZT8）
- **上の層の決まりは本人が変えられない**。ぶつかるときは例外の申請（承認待ち）で、OK が出るまでは今の決まりで動く（D-128.43・D-128.89）
- **やり方の中身（裏のスキルの作り）は見せない**。欄と説明だけ（D-126.21）。機械の検査（鍵やパスワードの書き込みがないか など）が通らない版は使えない

## 作る時の会話をチケットへ移す（K-776・D-153.17）

| 何をする | 口 | 行為 | 役割の言葉 | だれが |

- 会話の id・持ち主・今までの行は変えず、種類を ticket・チケットの id を入れる。右のパネルの会話（K-763）として同じ会話が見つかる

### AI の案の道具 draft_propose（K-775）

- 道具の口 `POST /bridge/jobs/:id/tools/:name` の `name` に `draft_propose` を足した。使えるのはチケットを作る画面の会話（`talk_kind = 'draft'`）の仕事だけで、その仕事に出す道具は `draft_propose` だけ（会話の道具・チケットの道具・前の道すじの成果物の口 `/bridge/artifact` は 403）。
- 入力 `{ input: { title?, body?, checks?[] } }`（どれか 1 つは要る）：題（1〜200 字）・本文（空白だけでない・書いたとおり）・確認項目（50 件まで・1 件 200 字まで・空の行は捨てる）の案を、会話の行（`kind = 'proposal'`）として 1 つ付ける。欄にも作る口にも触らない（欄に入れるのは人）。答えは `{ ok, id, remaining }`。
- 1 つの仕事で 3 回まで。4 回目は 409・E-TALK-070（同じ会話の次の仕事は新しく 3 回）。形の誤りは 422（欄 title・body・checks・input）で数えない。
- 会話を読む口の答えの MessageView に、案は `who: "ai"`・`text: ""`・`proposal`（出した欄だけ）で出る。
